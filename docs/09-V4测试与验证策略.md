# V4 测试与验证策略

> 状态：`accepted`
> 适用阶段：Historical Episode Kernel 及其后续 V4 实现。

## 1. 目标

V4 以业务不变量覆盖为测试目标，不以测试数量、测试代码行数或统一覆盖率百分比为目标。
确定性测试、数据库契约、试点评估、运行健康和 shadow 审计必须分层，不得把所有验证都塞进 pytest。

## 2. 验证分层

| 层 | 入口 | 负责 | 不负责 |
| --- | --- | --- | --- |
| 默认快速套件 | `pytest -q` | 领域不变量、结构化契约、纯函数、极小纵向 smoke | 网络、模型、外部数据库、批量评估 |
| 数据库契约套件 | `pytest -q -m db` | 唯一键、幂等、活动版本、outbox、lease、lineage、增量失效 | 完整生产链和性能压测 |
| Pilot evaluation | `python -m emperor_v4.eval episode-pilot --manifest eval/episode_pilot_v1.yml` | source coverage、episode recall/precision、错误归并/拆分、成本和人工待审 | 单元测试通过与否 |
| Contract check | 独立确定性命令 | 外部服务 fixture 与 V4 contract 的兼容性 | 服务在线状态 |
| Runtime health check | 独立运行命令或报告 | 部署、连接、worker 和依赖健康 | 业务正确性 |
| Shadow audit | 独立报告 | V3/V4 差异分类、人工裁定和发布阻断 | 默认开发测试 |

## 3. pytest 边界

pytest 只测试：

- 领域不变量；
- 结构化输入输出契约；
- fingerprint、cache key 和其他纯函数；
- merge/split、completeness 和版本失效；
- 数据库幂等约束；
- 一个极小、离线、固定 fixture 的纵向 smoke test。

pytest 禁止：

- 真实网络抓取；
- 真实模型调用；
- 服务器部署检查；
- 外部 PostgreSQL 默认连接；
- 大规模史料覆盖评估；
- 整批人物或皇帝跑分；
- shadow comparison；
- 判断人工审核结论是否“历史上合理”。

pytest 可以验证合法模型输出是否符合 Schema，也可以拒绝缺行、重复行、越界值或未知字段；
不得验证模型在某次实时调用中是否识别正确人物或史实。

## 4. 默认快速套件

`pytest -q` 必须满足：

- 默认断网可运行；
- 模型调用数为零；
- 外部数据库连接数为零；
- 只读取仓库内小型 fixture；
- 目标运行时间约十秒；
- 第一纵向切片控制在约 50—100 个参数化 case 以内。

首阶段测试文件固定按业务不变量组织：

```text
tests/
  test_contracts.py
  test_episode_kernel.py
  test_versioning.py
  test_vertical_slice.py
  fixtures/
    episode_pilot_v1/
```

不得按实现文件建立镜像测试树，也不得因为一个新边界案例而新建测试模块；同类边界优先参数化。

## 5. 数据库契约套件

`pytest -q -m db` 只在 migration、唯一键、outbox、lease、version lineage 或增量失效逻辑变化后运行。
最低数据库不变量：

- 同一幂等键重复写入只有一条业务记录；
- 同一 episode 只有一个活动 semantic version；
- 同一 episode version 与 rule version 只有一个活动 projection；
- 一条活动 projection 最多一个当前 accepted judgment；
- lease 过期后可以安全回收；
- 同义证据只增加 evidence version，不使 judgment 失效；
- 无变化重跑产生零业务写入。

数据库测试只建立满足 contract 的最小 schema 和 fixture，不复制完整生产链。

## 6. 必测业务不变量

| 不变量 | 测试层 |
| --- | --- |
| 同义证据不创建新 episode | 默认快速套件 |
| 不同任务链不能错误合并 | 默认快速套件 |
| 跨皇帝任命不能合并 | 默认快速套件 |
| accepted episode 必须有 passage lineage | 默认快速套件 |
| 新增同义证据不改变 episode ID | 默认快速套件 |
| 责任主体变化产生新 semantic version | 默认快速套件 |
| 冲突证据不能被摘要抹掉 | 默认快速套件 |
| semantic version 与 evidence version 分离 | 默认快速套件 |
| 规则输出不能回写 episode | 默认快速套件 |
| 输入输出一一对应，缺行或重复行拒绝 | 默认快速套件 |
| 无变化重跑零模型调用 | 默认快速套件或 pilot evaluator |
| 无变化重跑零业务写入 | 默认快速套件和数据库契约 |
| 一条 projection 一个活动 judgment | 数据库契约 |

## 7. Pilot evaluation

Pilot evaluation 不是 pytest。它读取冻结 gold manifest 和服务响应 fixture，至少输出：

- `source_coverage`；
- `episode_recall` 与 accepted episode precision；
- 错误合并和错误拆分；
- 身份/评估上下文错误；
- `consumption_integrity`；
- 模型调用数与 cache 命中率；
- 墙钟时间；
- 人工待审条目；
- 失败归因层。

报告阈值和 Gate 以 `docs/06-覆盖度与验收标准.md` 为准。报告失败不能通过增加 pytest case
来伪装解决，必须归因到 source discovery、source cache、passage segmentation、assertion extraction、
episode reconciliation、identity/evaluation context 或 projection。

## 8. 退役纪律

功能脱离活动工作流、被替换或退役时，其实现测试必须在同一个提交中删除。只有承担当前数据迁移、
公开向后兼容或审计恢复职责时才可保留，并必须说明退出条件。

判断规则：

- 当前公开 contract 仍有效：保留 contract 测试；
- 只是旧实现方式：实现与专属测试一起删除；
- 旧数据仍需读取：只保留兼容输入 fixture 和 contract 测试；
- 旧脚本已不用：脚本和脚本专属测试一起删除。

V4 不建立 `current_workflow_tests.txt`、scripts registry、retired wrapper compatibility tests
或其他“纪念性测试”治理层。

## 9. 测试规模变更门禁

新增测试模块、引入真实外部依赖、扩大默认参数化 case 超过首阶段上限，或让默认套件超过目标时间时，
必须在变更说明中给出对应的新业务不变量和不能使用既有参数化测试覆盖的理由。

辅助 CLI、Markdown renderer、日志格式和参数包装器默认不单独测试；只有它们承担公开 contract 或曾导致
不可由核心测试捕获的回归时才例外。

## 10. Source Protocol Smoke 与盲测预算

Source Cache 契约或下游结构化协议变化时，默认快速套件维护一个 6—10 场景的离线 protocol smoke，至少串起：

```text
Source Cache v2
→ passage-scoped Assertion
→ Episode boundary payload
→ HistoricalEpisodeRelation
→ RuleEvidenceUnit
→ score schema
```

它只验证字段、lineage、角色边界和机械门禁，不宣称历史质量，也不调用网络或模型。当前固定为 8 个场景：
section/span、linked lineage、equivalent evidence、atomic component、context only、episode boundary、
historical relation、rule score schema。

G2.6I/J 及更早已开封数据只作为开放开发回归集。不得为日常调试连续制造新 blind holdout；Source、Assertion、
Boundary、Relation 和 Rule 的开发门禁全部通过后，只允许执行一次最终资格 holdout。
