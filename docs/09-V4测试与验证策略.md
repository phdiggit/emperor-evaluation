# V4 测试与验证策略

> 状态：`accepted`

## 目标

测试只覆盖当前业务不变量和当前公开契约，不为历史实现、阶段产物、旧报告或已退役入口提供兼容性保护。

## 默认套件

`pytest -q` 必须默认离线、零模型、零外部数据库连接，并在约十秒内完成。测试使用最小内嵌输入或 `tests/fixtures/` 下当前仍被消费的小型fixture，不读取 `eval/` 中的历史运行结果。

pytest负责：

- 领域不变量；
- 当前结构化输入输出契约；
- fingerprint、幂等键和纯函数；
- 数据库唯一键、lease和无变化零写入；
- 当前评分因子、投影和Gate的失败关闭行为。

pytest不负责：

- 真实网络、模型或生产数据库；
- 整批人物或皇帝跑分；
- 对某次历史运行报告做哈希复现；
- 证明旧artifact仍可读取；
- 验证人工史实裁决是否正确。

## 数据库套件

`pytest -q -m db` 仅在migration、唯一键、outbox、lease或持久化逻辑变化后运行。最低不变量：

- 同一幂等键只有一条业务记录；
- 同一episode只有一个活动semantic version；
- 同一projection最多一个当前accepted judgment；
- lease过期后可安全回收；
- 无变化重跑产生零业务写入。

## 收束纪律

- 功能退役时，实现、专属测试和fixture同提交删除。
- 当前测试不得依赖 `eval/` 下的checkpoint、resume、过程报告、旧run或旧版本结果。
- 不建立retired wrapper、历史兼容测试清单或纪念性测试模块。
- 需要追溯旧行为时使用Git，不恢复历史测试和产物到工作树。
