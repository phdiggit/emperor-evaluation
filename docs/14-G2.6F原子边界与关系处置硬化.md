# G2.6F 原子边界与关系处置硬化

状态：`contract_hardening_complete_new_holdout_pending`

## 1. 失败输入

G2.6E 的 5 个 catastrophic wrong merge 不是史源缺失：passage lineage 和 Assertion disposition 均为 100%，跨皇帝污染为 0。失败集中在 EpisodeBoundaryReview 对旧 Assertion 的解释。

错误分为两类：

1. 三个候选把不同 action、时间或责任子域的“任命—执行—结果”压入同一个 Episode；
2. 两个候选来自同一旧 claim 向多个 passage 扇出，但 Assertion 没有原子事件锚点，审查器把行动和后续反馈误当成同义证据。

Relation 的低召回和 RuleEvidenceUnit 的低召回主要是上述边界错误的下游后果，不能先通过扩大规则聚合或提高模型“敢连接”的程度修复。

## 2. v2.2 硬约束

`episode-boundary-policy-v2.3` 和 `episode-boundary-review-v2.3` 继承 v2.2 的 fail-closed 规则，并增加 reviewer-level 原子锚点：

- 一个 Episode core 内的 action、结构化时间、responsibility family/domain 与 focal role 必须一致；
- 跨结构签名只能拆成原子 Episode，再用 Relation 表达联系；
- 同一旧 claim 跨多个 passage 时，只有所有 Assertion 都声明同一个非空 `atomic_event_key`，或隔离 reviewer 在核对原文后冻结 group-level `atomic_event_key`，才允许合并；
- 每对候选 Episode 必须显式处置为 `related`、`distinct_unrelated` 或 `unresolved`；
- `related` 必须与同类型 EpisodeRelationDraft 一一对应；
- `unresolved` 阻断候选图物化，不允许静默漏掉关系。
- RuleEvidenceUnit exact precision/recall 分别低于 90%/85% 时不得放行 G3；`promotion_after` 与 `context_for` 不作为自动聚合边，避免把完整仕途或背景关系压成一个规则单元。

## 3. 分层责任

| 失败现象 | 责任层 |
| --- | --- |
| passage 中含多个原子事件但 Assertion 没有独立锚点 | assertion atomization |
| 不同结构签名被放入同一 core | boundary review |
| 已拆分 Episode 未逐对判断关系 | relation review |
| Episode/Relation 正确但 RuleEvidenceUnit 聚合错误 | rule aggregation |

## 4. 验收顺序

1. 用 G2.6E 冻结集验证新契约能阻断已知灾难合并，但不得重算或改写 G2.6E blind 分数；
2. 对 Assertion atomization blocker 形成 worklist，不在 Kernel 内补写史实；
3. 冻结另一批全新输入，由相互隔离的 boundary、Historical Gold 和 Rule Gold reviewer 处理；
4. 只在全部冻结后生成候选并评分；
5. 未达到 G2.6E 原阈值前，PostgreSQL G3 继续阻断。
