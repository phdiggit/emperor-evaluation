# 配置说明文件机制退役说明

本文件保留为历史兼容说明。#227 之后，`.comments.json` 配置说明机制已退出当前执行口径，不再作为新增配置或文档治理的必需机制。

## 当前结论

- 不再鼓励新增 `data/configs/配置说明/*.comments.json`。
- 不再要求新增配置同步旁路 comments 文件。
- `project_config.yml` 只保留小型人工运行入口，例如 active subitem、groups、defaults、每个 `workflow_code` 的本地 / 共享运行入口路径，以及少量本地工具开关。
- 候选池、关键词、抓取任务、检索日志、source passage 和展示字段不回到人工配置说明层。
- 旧 comments 机制若仍被历史材料提及，只作为兼容背景，不代表当前规范入口。

## 当前配置边界

`data/configs/project_config.yml` 的职责是回答“本轮人工要跑什么”。它可以包含：

- 当前启用子项。
- 人物组。
- 默认 group key。
- 必要的 `persons_ref` 或后续 `*_ref` 外置引用。
- 不承载业务事实的本地工具开关，例如 Wikisource 摘录召回缓存后端、连接环境变量和 schema。
- 采集层 workflow 入口路径，例如 `tooling.source_excerpt_pool.workflows.<workflow_code>.paths.query_profile`、`source_pack_root`、`jobs_dir`、`logs_dir` 和 `handoff_root`。

它不承载：

- 大规模候选池。
- 检索关键词和 query terms。
- 抓取、解析、索引、候选召回任务。
- 抓取、解析、索引、候选召回的任务状态或大规模任务清单。
- search log、source passage、review queue 状态。
- Markdown 表格列、warning 文案或展示策略。

这些内容应进入数据平台模型、生成逻辑、视图配置或对应规范文档。

## 历史兼容处理

如果后续扫描发现旧 `.comments.json` 文件或旧文档引用：

1. 先标记为 historical / compatibility lead。
2. 不在普通业务 PR 中新增同类文件。
3. 不把旧 comments 机制恢复为 validator 必需项。
4. 若确需清理，单独在配置治理或 docs 清理 PR 中处理。

本文件不要求修改 `data/configs/**`，也不要求新增、迁移或删除任何配置说明文件。
