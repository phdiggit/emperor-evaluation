## Schema Live Apply 边界

生产 schema live apply 只表示 schema-only baseline 已被允许并可验证，不表示 production migration 完成。执行前必须有显式人工批准；批准文本仍由工具检查为 `批准所有权限`。该路径允许读取 DSN、连接数据库和执行 schema SQL，但不得读取生产 seed/data manifest，不得写 target business table，不得发布评分、排名或榜单。

机器检查锚点：

```text
schema live apply execution pr
allows dsn read
allows db connect
allows sql execution
allows public schema write
does not execute seed/data apply
does not mark production migration complete
future target importer gate required
must not fake success
```

## Seed / Data Apply 边界

Epic 0 只保留 canonical seed manifest discovery 与 import-audit scaffold，不执行真实业务表迁移。missing canonical manifest 必须在 DSN 读取前 fail-closed；真实 target importer 留给 Epic 1。

`imports` 和 `import_rows` 是 audit tables，不是业务 target table。audit scaffold 写入必须使用 PostgreSQL 正式约束允许的状态：`imports.status=dry_run`、`import_rows.import_status=skipped`。文件级 SHA 不得伪装成逐行 payload hash，`target_table` 不得伪装成业务目标写入，audit header/count 不证明 production migration。

机器检查锚点：

```text
import-audit scaffold
audit-only
allows dsn read
allows db connect
expected_seed_manifest_sha256
pr #285 schema live apply
blocked_missing_seed_manifest
are audit tables
epic 1
does not log dsn
does not modify source data
must not fake migration success
```

以下成功语义在真实业务表写入和验证完成前永久阻断：

```text
production_data_rows_written=true
seed_data_apply_executed=true
verification_passed=true
ready_for_production_migration=true
```

## Canonical Manifest 边界

canonical seed manifest envelope 只包含顶层 `data/*.jsonl`。`data/batches/**` 和 `archive/data/**` 可以作为 discovery-only 线索出现在 excluded discovery 报告中，但不得进入 canonical manifest hash，也不得影响 `manifest_sha256`。

Epic 1 的 G1 canonical manifest approval 入口由只读工具生成：

```bash
python scripts/platform/canonical_manifest_gate.py --candidate-report
python scripts/platform/canonical_manifest_gate.py --markdown-report
```

该工具只扫描顶层 `data/*.jsonl`，不读取 `data/batches/**`、`data/*_batches/**`、`archive/data/**`、`exports/**`、`.env` 或生产 DSN，不连接 PostgreSQL，不修改 `data/**` / `archive/data/**`。报告固定停在：

```text
G1_REQUIRED
manifest_candidate: generated report: python scripts/platform/canonical_manifest_gate.py --candidate-report
covered_files:
  - data/*.jsonl only
excluded_files:
  - data/batches/**
  - data/*_batches/**
  - archive/data/**
  - exports/**

  - missing file / unexpected file / duplicate ID / orphan reference / schema mismatch
```

## Cutover 与回滚

正式迁移仍处于 proposal / contract 阶段。JSONL write source cutover 必须单独批准；不得设计长期 JSONL + PostgreSQL 双写，不得通过 SQLite 或 MongoDB 做第二次搬家。

上线前置条件包括：

- 所有 contract report 通过；
- opt-in apply smoke 使用显式 DSN 和隔离 schema；
- schema diff 已审；
- rollback plan accepted；
- seed strategy accepted；
- read path dual-run accepted；
- relationship table 的 manual review gate accepted。

回滚策略只允许在明确批准后执行，包括 isolated/proposed schema drop、pre-migration DB snapshot restore、配置回退、PR / commit 回退和人工复核。本文不授权读取生产 DSN、连接生产 PostgreSQL、执行 schema apply、执行 seed apply 或修改 `data/**` / `archive/data/**`。
