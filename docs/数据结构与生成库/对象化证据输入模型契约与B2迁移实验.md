# 对象化证据输入模型契约与 B2 迁移实验

## 定位

本文只定义 JSONL 过渡期的轻量对象化输入契约，供 B2 批次实验和后续人工复核对齐。它不改变评分规则，不新增公式引擎，不设计 PostgreSQL 迁移，不要求迁移既有 `data/evidence_cards.jsonl`。

本轮新增的实验存储位于 `data/experimental/objects.jsonl` 与 `data/experimental/object_evaluations.jsonl`。它们只承接 B2 小样本的平行建模和诊断聚合测试，不属于 canonical evidence store，不被 exporter、formal scoring 或正式定档流程读取。

当前事实层仍兼容既有 `evidence_card`。本契约描述的是未来可替代单张 `evidence_card` 的原子输入形状：把“稳定对象”和“对该对象的一次编码评价”拆开，避免一张证据卡同时承担出处、对象、裁量和聚合语义。

## 四层关系

- `source` / `source_pack` = provenance：只保存来源、出处定位、摘录、上下文和回源审计。它们回答“材料从哪里来、是否足以复核”，不回答“该不该入分”。
- `object` = stable entity：保存可复用的稳定实体。对象可以是人、团队、事件案、机制、机构、政策、关系或来源陈述。对象行不保存 `polarity`、`strength`、`eligible` 等评分输入。
- `object_evaluation` = atomic coded scoring input replacing `evidence_card`：保存一次“某对象如何影响某子项”的编码判断。它是未来可替代单张 legacy `evidence_card` 的原子评分输入。
- `evidence_cluster` = formula aggregation of `object_evaluations`：只聚合若干 `object_evaluation` 的公式结果和解释。它不是新史料，也不得脱离原子输入扩写强度。本轮只定义关系，不实现公式引擎。

推荐过渡链路：

```text
source / source_pack
→ object
→ object_evaluation
→ evidence_cluster
→ scoring rule / export view
```

`src_ids` 和 `sp_ids` 始终指向 provenance；`obj_code` 指向 JSONL 过渡期稳定对象 key；`oeval_code` 指向 JSONL 过渡期原子编码评价 key；`clus_ids` 只表示该原子评价被哪些聚合引用。

ID 规则采用 numeric id + stable code 分层：

- `obj_id` / `oeval_id` 是未来数据库内部 numeric id，只用于不可读内部主键；当前 JSONL 过渡期可以写 `null`。
- `obj_code` / `oeval_code` 是 JSONL 过渡期稳定可读 key，用于人工审阅、fixture、迁移审计和跨行引用。
- 过渡期不得把 `OBJ-I5B-...`、`OEVAL-I5B-...` 这类稳定可读 key 塞进 `obj_id` / `oeval_id`；它们必须进入 `obj_code` / `oeval_code`。

## 紧凑字段

### object 行

`object` 行的最小字段如下：

| 字段 | 含义 |
| --- | --- |
| `obj_id` | 未来内部 numeric id；JSONL 过渡期可为 `null`。 |
| `obj_code` | JSONL 过渡期稳定可读对象 key。 |
| `class` | 对象类别，使用下方枚举。 |
| `category` | 对象在当前项目中的粗类，例如“第五项B对象”“荐才链”。 |
| `label` | 人工可读对象名，例如“虞世基”“丙吉荐才链”。 |
| `src_ids` | 可选来源 ID 列表，只用于对象身份或命名依据。 |
| `sp_ids` | 可选 source pack ID 列表，只用于对象身份或命名依据。 |

对象行不得保存 `relation`、`polarity`、`strength`、`relevance`、`directness`、`scale`、`structurality`、`confidence`、`residual` 或 `eligible`。这些字段只属于 `object_evaluation`。

### object_evaluation 行

`object_evaluation` 行的紧凑字段如下：

| 字段 | 含义 |
| --- | --- |
| `oeval_id` | 未来内部 numeric id；JSONL 过渡期可为 `null`。 |
| `oeval_code` | JSONL 过渡期稳定可读原子评价 key。 |
| `obj_id` | 被评价对象的未来内部 numeric id；JSONL 过渡期可为 `null`。 |
| `obj_code` | 被评价对象的 JSONL 过渡期稳定 key，必须指向已存在的稳定对象。 |
| `src_ids` | 直接支撑本次评价的 source ID 列表。 |
| `sp_ids` | 直接支撑本次评价的 source pack ID 列表。 |
| `clus_ids` | 引用本评价的 evidence cluster ID 列表；无聚合时为空数组。 |
| `class` | 对象类别的冗余快照，便于人工扫读和迁移检查。 |
| `category` | 子项内证据类别，例如“授权专任”“容谏纳言”。 |
| `relation` | 统治者、子项与对象之间的关系短码，例如“专典机密授权”。 |
| `polarity` | 候选方向，沿用 `positive` / `negative`；不表示最终得分。 |
| `strength` | 候选证据强度，沿用现有 1-4 框架；不新增评分规则。 |
| `relevance` | 与当前子项的相关度短码，例如 `core`、`partial`、`boundary`。 |
| `directness` | 证据直接度短码，例如 `direct`、`contextual`、`indirect`。 |
| `scale` | 作用尺度短码，例如 `single_object`、`multi_object`、`chain`、`system`。 |
| `structurality` | 结构性短码，例如 `event_case`、`pattern`、`mechanism`、`structural_role`。 |
| `confidence` | 编码置信度短码，例如 `low`、`medium`、`high`。 |
| `residual` | 相邻项剥离后的剩余说明；无剩余风险时写 `none`。 |
| `eligible` | 是否可作为本子项原子评分输入的布尔值。 |

`object_evaluation` 不保存长引文、全文上下文或最终分值。长引文和上下文仍回到 source/source pack；最终定档仍回到评分标尺和聚合结果。实验存储里的 `diagnostic_only=true` / `feeds_formal_scoring=false` 只用于提示当前 B2 迁移样本不进入正式评分。

## object class enum

`class` 只能使用以下枚举：

- `person`
- `team`
- `event_case`
- `mechanism`
- `institution`
- `policy`
- `relationship`
- `source_statement`

枚举表达对象形态，不表达对象价值。比如 `person` 只是“虞世基”“周亚夫”这类稳定人物对象；`mechanism` 可以是“不可谏/无一言谏诤”这类反馈机制；`relationship` 可以是“丙吉荐才链”这类荐才链条。

## object-processing outcomes

迁移或回源处理可以使用以下结果：

- `objectized`：材料已经落到稳定对象，可创建 `object`，并在回源充分时创建 `object_evaluation`。
- `adjacent_only`：材料只用于相邻项切分或边界提醒，不得创建 object 行，不得创建可入分的 `object_evaluation`。
- `no_stable_object`：材料有方向或背景价值，但无法抽出稳定实体；只保留为回源说明或人工备注。
- `unresolved_lead`：疑似能形成对象或评价，但出处、上下文或切分不足；不得标为 `eligible=true`。
- `excluded_from_subitem`：对象可能稳定，但本材料被排除出当前子项；不得为当前子项创建可入分的 `object_evaluation`。

`adjacent_only` 是硬边界：相邻项 lane 是切分结果，不是对象本身。它可以记录在 source review log、迁移审计或 PR body 中，但不得为了“有记录”而制造 `obj_id` 或 `obj_code`。如果后续另有直接材料证明稳定对象，再用直接材料创建对象行。

以下示例只说明对象化方式，不代表正式强度、分值或最终裁判。

| B2 场景 | outcome | object | object_evaluation 关系 |

## 本轮不做

- 不修改现有评分规则、档位、公式或导出结论。
- 不实现 `evidence_cluster` 公式引擎。
- 不新增 PostgreSQL schema 或迁移。
- 不新增 dashboard 或 broad validator framework。
- 不迁移全部 `evidence_cards`。
- 不改写 canonical evidence batch 数据；本轮只有非 canonical fixture 与 `data/experimental/` 小样本。
