# 史料上下文管理机制

本机制补齐 #228 ADR 后的史源上下文边界。当前 `sources.jsonl` / `evidence_cards.jsonl` 继续服务 JSONL 试点；未来史源全文、段落定位和多史源引用必须进入 `source_documents`、`source_passages`、`evidence_source_links`。

## 1. 核心结论

- `source_passage` 是全文和段落检索核心，不是 `sources`。
- `sources` / `source_documents` 记录出处元信息；`source_passages` 记录可检索文本。
- `evidence_cards` 只保留 `quote_short`、解释、裁判、归项和强度，不保存大段全文。
- `quote_short` 是证据卡短摘，不等于完整上下文。
- `evidence_source_links` 承担多史源、多段落、多角色引用。
- 上下文不足不得入正式评分，只能进入 review queue 或派生后续 `search_tasks`。
- 相邻项切分材料可以作为 `context` / `adjacent_item_split` link，不直接改变本项强弱。
- 离线 source pack 是采集层到 `source_documents` / `source_passages` 的过渡包；它只承载本地页文、史源元信息和可选摘录，不承载评分裁判。

## 2. 四层模型

```text
source_documents
  史源文档层：书名、卷、篇、版本、URL、来源类型、抓取状态。

source_passages
  史源段落层：原文段落、规范化文本、卷次位置、段落序号、前后段指针、纪年、人物命中。

evidence_source_links
  证据-史源链接层：证据卡引用哪些 passage、引用跨度、引用角色、是否主证/旁证/反证/上下文。

evidence_cards
  原子证据卡层：短摘、解释、裁判、归项、强度；不承载全文上下文。
```

当前 JSONL 过渡期仍允许 `evidence_cards.source_id` 指向 `sources.jsonl`。这只是兼容字段，不是最终关系模型。进入 PostgreSQL 原型后，一张证据卡应通过 `evidence_source_links` 引用一个或多个 `source_passages`。

## 3. 推荐字段草案

### source_documents

```text
source_document_id
title
author
dynasty
source_type
edition
volume
url
canonical_location
raw_text_hash
fetch_status
note
```

`source_documents` 只描述文档和版本。它不保存证据裁判，也不直接表达某段是否入分。

离线 source pack 中的 `src_docs.jsonl` 是当前过渡形态：`src_key` 对应 `source_document_id` 的稳定输入键，`page_title` / `locator` / `url` 定位文本页，`text_path` 指向包内本地正文。导入对象池或生成摘录候选前，必须先审计 source pack，确认 src_key 唯一、正文可读、可选摘录不引用缺失 src_key。

### source_passages

```text
passage_id
source_document_id
volume
location
passage_order
original_text
normalized_text
previous_passage_id
next_passage_id
reign_year
mentioned_persons
keywords
parse_status
```

`source_passages` 是全文检索、上下文窗口和段落回源的核心层。段落可以被多个候选命中，也可以被多个证据卡引用。

### evidence_source_links

```text
evidence_id
passage_id
link_role
quote_span_start
quote_span_end
context_window
confidence
review_status
note
```

`link_role` 建议值：

- `primary_quote`：主证短摘所在段落。
- `context`：主证前后文。
- `counter_context`：反证或限制性上下文。
- `corroboration`：旁证、互证或同向增厚材料。
- `weakening`：削弱证据强度或限制适用范围的材料。
- `adjacent_item_split`：相邻项切分材料。

`context_window` 可使用 `previous_1_next_1`、`same_volume_window` 等稳定短值。窗口只是回源辅助，不得自动改变强弱。

### evidence_cards

证据卡保留原子裁判字段：

```text
evidence_id
person
item
subitem
polarity
strength
human_level
quote_short
interpretation
cross_item_split
scoring_effect
verification_status
adjudication_status
```

当前 JSONL 兼容字段 `source_id` 可以继续存在。未来 PostgreSQL 模型中，证据卡与来源段落的正式关系由 `evidence_source_links` 表达。

## 4. 数据库物理命名约束

本文中的 `source_documents`、`source_passages`、`evidence_source_links` 是逻辑模型名。进入 PostgreSQL schema 设计时，物理表名、字段名和索引名必须另行收短，不得机械照搬长逻辑名。

命名约束：

- 表名优先控制在 20 字符左右。
- 字段名优先控制在 20 字符以内。
- 索引和约束名必须手写短名，不依赖自动拼接长表名 + 长字段名。
- 文档中允许保留清晰逻辑名；schema 中可使用短物理名，并在表注释或字段注释中映射。

建议映射：

| 逻辑名 | PostgreSQL 物理名建议 |
| --- | --- |
| `source_documents` | `src_docs` |
| `source_passages` | `passages` 或 `src_passages` |
| `evidence_source_links` | `evd_src_links` |
| `source_document_id` | `doc_id` |
| `previous_passage_id` | `prev_id` |
| `next_passage_id` | `next_id` |
| `canonical_location` | `canon_loc` |
| `original_text` | `raw_text` |
| `normalized_text` | `norm_text` |
| `mentioned_persons` | `persons` |
| `quote_span_start` | `span_start` |
| `quote_span_end` | `span_end` |
| `context_window` | `ctx_window` |

## 5. quote 与 context 边界

- `quote_short`：证据卡短摘，只保留最能支撑该卡判断的短引文。
- `quote_context`：当前导出或过渡数据中可能出现的上下文摘录，只用于人工审核和回源复核；不得作为正式全文存储层。
- `context_summary`：对上下文作用的短说明，例如“前段说明对象身份”“后段限制行为范围”。
- `interpretation`：裁判解释，说明该证据为什么归入某项、强弱为何、哪些部分应切给相邻项。

证据卡不得承载全文上下文。大段原文、前后段、版本差异和可检索文本应进入 `source_passages`。

## 6. 多段落与多证据引用

一张 evidence card 可以引用多个 passage：

```text
EVD-I5B-XXX
  -> passage A as primary_quote
  -> passage B as context
  -> passage C as counter_context
  -> passage D as adjacent_item_split
```

一个 source passage 也可以支撑多个对象：

```text
passage A
  -> evidence card 1 as primary_quote
  -> evidence card 2 as corroboration
  -> candidate match 1 as review_pending
```

这种多对多关系必须由 `evidence_source_links` 或候选匹配层表达，不得通过复制全文或复制证据卡解决。

## 7. 上下文不足时的处理

上下文不足时不得直接入卡或入分。最低处理规则：

1. 若只有检索线索，写入 `search_log` 或未来 `search_tasks`。
2. 若已定位史源但段落不足，进入 review queue，`review_status=needs_context_review`。
3. 若主证成立但存在反证、削弱证或相邻项切分材料，使用对应 `link_role` 挂到同一证据链。
4. 若无法确认角色，保留为 `candidate_match`，不得写成正式 `evidence_card`。

正式评分只能读取已完成回源、上下文复核、相邻项切分和必要人工裁判后的净证据。

## 8. 与当前 JSONL 的过渡关系

当前 JSONL 层：

- `sources.jsonl` 继续记录来源元信息。
- `evidence_cards.jsonl.source_id` 继续作为兼容引用。
- `quote_short` 继续作为证据短摘。
- 过渡期出现的 `quote_context` / `context_summary` 只能服务人工复核，不代表最终上下文存储层。

未来 PostgreSQL 层：

- `source_documents` 替代单薄的来源元信息承载文档版本和抓取状态。
- `source_passages` 承载全文段落和检索文本。
- `evidence_source_links` 替代单一 `source_id`，表达证据卡与多个段落的多角色关系。
- `candidate_matches` 与 review queue 承接上下文不足、角色不明或待回源材料。

本 PR 不迁移 JSONL，不新增 parser，不实现 schema。#230 只盘点 JSONL 层级并打标签；#231 才执行 batch 删除、归档或重组。
