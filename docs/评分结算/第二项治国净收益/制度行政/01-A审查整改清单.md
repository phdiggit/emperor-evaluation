# A制度建设与实际运行方向卡：审查整改清单

> 审查对象：`docs/评分结算/第二项治国净收益/制度行政/01-A制度建设与实际运行方向卡.md/.json`
>
> 审查基线：`codex/single-ruler-session-control`
>
> 状态：持续审查中。本清单只记录已确认问题、待验证问题与整改要求；未确认事项不得直接改正式裁决。

## 一、总原则（锁定）

- A评价制度净贡献，不评价“动作大小”“改革声势”或抽象创新能力。
- 正向制度与负向制度必须同时计入；不得因为建设厚度高而获得保底高档。
- 只看实际运行、收益、代价和后果；面子工程、纸面创设、未运行改革不得抬档。
- 同一制度生命周期必须先合并正负事实，再形成唯一裁决；不得正负双计、材料条数堆分或同一机制重复计分。
- 本轮不因历史名望或直觉反差对任何人物设特例。

## 二、P0：必须先修的工程一致性问题

### [ ] A-ENG-001：解决03节点表与A正式快照版本冲突

**已确认问题**

- `03-重要制度发展节点链.json`明确标记`downstream_A_recalc_required.required=true`。
- 上游节点表存在实质性S属性调整，并非单纯状态位未清。例如朱元璋“宫妃殉葬成为宫廷继承礼制并延续”已由S−1改为严重文明倒退S−2。
- 当前A JSON仍标记`FORMAL_CURRENT_A_REMEDIATION_PHASE3`，同时继续沿用旧结算字段，说明A并未完整重新消费最新版03节点表。

**整改要求**

1. 以最新版03节点表active节点为唯一上游，重新生成185人A快照。
2. A不得直接复制旧`S_net/S_minus/S_total/S_depth_units`；必须由当前引用节点实时重算。
3. 新快照完成并通过一致性校验后，再把03中的`downstream_A_recalc_required.required`清为false并记录完成批次/哈希。
4. 若03仍存在`deferred_A_coupled_node_repairs`或未处理排除/alias节点，则A不得标记FORMAL_CURRENT。
5. A JSON写入所消费03节点表的内容哈希/版本标识；正式校验必须核对一致。

### [ ] A-ENG-002：统一生命周期去重，禁止JSON源数据重复profile

**已确认问题**

MD存在大量同机制重复展示，例如赵匡胤、赵光义、赵恒、赵顼、赵祯、朱允炆、赵构等；其中部分同一`institution_node_id`或同一机制在有效M链组合中重复出现。

当前校验器只在G4/G5的position重算阶段使用`seen_lifecycles`临时去重；G0—G3直接消费已写入的`A_independent_M_signed`，没有统一从canonical profile重算，也没有禁止profile本身重复。

**整改要求**

1. JSON生成前先按生命周期归并：首选`institution_node_id`；无节点ID时使用稳定`lifecycle_id`；不得仅靠文本机制名。
2. 同一生命周期重复材料合并`material_ids`，只保留一个profile。
3. 同一生命周期若出现M档、方向、S属性、节点角色冲突，构建阶段直接报错，不允许静默取值。
4. G0—G5全部从去重后的canonical profile重新计算`A_independent_M_signed`、position和direction_index；不再信任旧缓存值。
5. MD必须由去重后的JSON生成，表格和逐人段落均不得重复列同一生命周期。
6. 校验器新增：每人三组profile的生命周期键全局唯一。

### [ ] A-ENG-003：逐节点核对A消费字段与03登记表一致

**整改要求**

对每个A引用的active节点，强制核对：

- `institution_node_id`
- `major_node_role`
- `normative_direction/direction`

任一不一致直接阻断正式结算，避免上游S−1→S−2等修改未传导。

### [ ] A-ENG-004：正式状态机收紧

**整改要求**

A只有同时满足以下条件才可标记`FORMAL_CURRENT`：

- 上游03无`recalc_required`；
- active/alias/exclusion引用全部闭合；
- profile无重复生命周期；
- S/M/方向字段与03一致；
- JSON→MD生成校验通过；
- 185人覆盖、排名、position、direction_index重算一致。

否则使用明确的`RECALC_REQUIRED` / `AUDIT_PENDING`状态，不得同时出现“上游要求重算”和“下游正式当前版”。

### [ ] A-ENG-005：所有计分profile必须绑定A权威节点，堵住跨项材料直接进position

**已确认问题**

当前`verify_second_item_a_snapshot()`只检查`important_institutions`引用ID是否属于03 active节点；对`M_positive_profile / M_mixed_profile / M_negative_profile`本身只检查M档和少数泛化机制名，没有强制每个计分profile绑定03 active节点。

因此存在“不是A制度节点、但作为M profile直接改变position”的入口。现表已有疑似跨项污染，例如：

- 完颜亮：“宫室反复拆建、长期采珠和南伐征调形成极端财政民役负担”——首先属于财政民生/军事成本结果，不应直接作为A负M3。
- 司马炎：“制度交班与行政连续性”——直接属于D1边界，不应进入A position。
- 完颜亶：“后期酗酒妄杀官员、宗室、皇后与妃嫔，谏诤和规则失效”——若不能闭合为具体制度接口，应归B1/B2/政治素质，不应直接进A。
- 完颜璟：“边警预警被以生事处罚、军需摊派和权臣用事削弱反馈”——至少横跨B2/B1/财政民生，不能以打包负M3进入A。
- 耶律德光：“进入中原后纵兵大掠与括借，反馈恶化后纠正偏迟”——结果/反馈链，不等于A制度建设。

**整改要求**

1. 每个参与A计分的profile必须有`institution_node_id`且解析到03 active scoring node。
2. 若确有“非重大节点但可影响A position”的次级制度生命周期，也必须先在03登记为active A节点；禁止绕过03直接塞profile。
3. 纯B1/B2/D1/财政民生/军事结果只能作`cross_item_verification`，不得产生A signed M。
4. 校验器对三个M profile逐条验证active节点归属、人物归责和A使用角色。

## 三、P0：必须先修的规则净值问题

### [ ] A-RULE-000：禁止`mixed`或净零改革通过无符号C_A获得G2/G3保底

**已确认问题**

现行校验代码把`positive / mixed_positive / mixed`都列入`constructive_directions`，因此纯`mixed`节点也能支撑`C_A=1/2`；而G0—G3的主档结构厚度又包含无符号`C_A/2`。

这产生了明确的“净收益为0，但因为制度动作够大获得高档”路径：

- 宇文邕：仅“军士身份与军籍重构〔混M3〕”，仍为G3 middle 62.5。
- 海山：仅“武宗改制及迅速反转〔混M3〕”，仍为G3 middle 62.5。
- 蒙哥：仅“收牌印、限驿与禁止诸王擅招民户〔混M3〕”，仍为G3 middle 62.5。
- 窝阔台：仅混M2+混M3，仍为G3 middle 62.5。
- 陈霸先：单条混M2仍为G3 middle 62.5。
- 铁穆耳：仅混M2仍为G2 middle 47.5。

这与A的净贡献原则冲突。

**整改要求**

1. `mixed`（方向系数0）不得单独生成正向C_A，也不得作为G2/G3最低充分配置。
2. `mixed_positive`可否生成部分C_A需另定，但必须与其+0.5方向系数一致，不能按完整positive处理。
3. C_A必须改为方向敏感的净贡献量，或彻底退出主档保底；不得再作为纯“建设完成度奖励”。
4. 对所有当前由mixed节点单独/主要支撑G2/G3的人物全量重算。

### [ ] A-RULE-002：M0纸面/未完成尝试不应自动获得G1正收益档

**已确认问题**

现合同允许`PAPER_OR_INCOMPLETE_CONSTRUCTION → C_A=0.5 → G1`，当前刘骜、元恪、司马曜、姚苌、拓跋珪、王莽均因此得到G1 middle 30.0。

但M0定义本身包括“未运行、纸面命令、单点线索、未闭合事件”。若没有实际运行和可观察收益，仅凭提出/编定/尝试即从G0抬到30分，与“只看实际运行、收益与后果”冲突。

**整改要求**

1. 纯M0纸面创设、未执行倡议、未闭合尝试不得产生正向主档收益，原则上回G0。
2. G1若保留，只能用于“已经发生有限实际动作，但未达到M2完整闭环”的极窄过渡状态；需重新定义与M0/M2边界，不能继续奖励纯纸面动作。
3. 对现有6名G1逐一复核是否存在实际运行证据；没有则降回G0。

## 四、P1：高档规则审查

### [ ] A-RULE-001：验证“R3正向S为G4唯一入口”是否过窄

**当前合同优点**

- 强制要求后世实际接收，能过滤大量纸面改革、短命改革和声势大但未形成稳定收益的制度动作。
- 与项目“务实不务虚、只看运行收益和后果”原则高度一致。

**当前疑点**

- 可能出现：多条核心制度已经M3运行、跨阶段有效、净方向显著正，但因未达到R3而永久封在G3；同时单一R3正向骨架即可进入G4。
- 需判断这是否是合理的“耐久性奖励”，还是把“后世寿命”权重推得过高。

**审查方法**

1. 先完成最新版03→A全量重算、去重、跨项清洗和C_A净值整改，形成干净基线。
2. 不改正式档位，另跑影子门禁测试。
3. 重点检查G3高位/中位人物中，哪些具备：核心接口M3实际运行、跨阶段复验、净正、无同尺度未抵消重大负向。
4. 将影子晋档者与现有G4下半区（单S路线）横向比较实际收益、运行稳定性、代价和后果。
5. 若替代路线会大量奖励“动作大但短命”的改革，则维持现门禁；只有能稳定识别“实际运行充分但未到R3”的少数案例时才考虑开放第二路线。

**禁止的修改方向**

- 不得以“制度数量多”“改革规模大”“制度史名望高”直接进入G4。
- 不得因建设厚度高抵消明确负向后果。
- 不得为赵顼、朱元璋、拓跋宏等具体人物设置姓名特例。

### [ ] A-RULE-003：验证G4/G5中“非S重大负向只能降position、不能降主档”是否过弱

**当前机制**

G4/G5主档主要由`S_net`决定；未达到S−门禁的负向M2/M3，即使任内损害很大，通常只能进入`independent_M_signed`影响position，不能把人物从G4/G5降到下一档。

**风险样本**

- 奕詝：总理衙门S+，同时“就地正法绕过中央死刑复核〔负M3〕”，仍固定G4。
- 武则天：武举S+，同时“国家奖励告密、特别机关与酷吏罗织体系〔负M3〕”，仍固定G4。
- 司马炎：泰始律令S+，同时存在负M3，仍固定G4（其中D1污染需先剔除后再判断）。

**审查要求**

先清理跨项与归责错误，再做影子结算：比较“一个耐久S+ + 一个/多个重大任内负M3”与纯净单S+人物的实际净贡献。如果负向永远只能调position而不能降档，会形成新的耐久性偏置，则需给高档增加净负向降档门。
