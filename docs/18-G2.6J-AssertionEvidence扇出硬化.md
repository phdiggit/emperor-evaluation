# G2.6J AssertionEvidence 扇出硬化

状态：`accepted`  
日期：2026-07-13  
契约基线：`assertion-extraction-contract-v2` + `episode-boundary-review-v2.7`

## 1. 目标

G2.6I 的四个 catastrophic wrong merge 均来自完整 claim payload 向多个 evidence passage 的无条件复制。本阶段在新 holdout 冻结前修复输入契约，不修改 G2.6I 的任何冻结产物。

## 2. 新领域约束

每条 AssertionDraft 可以声明 `PassageSupport`：

```yaml
support_mode: single_passage | equivalent_evidence | atomic_component | context_only
assertion_semantic_key:
supported_fields: []
binding_provenance: {}
```

规则如下：

1. 核心支持至少包含 `identity` 和 `action`；
2. 同一 claim 的多个 passage 只有在明确声明同义证据、共享 semantic key 且语义完全一致时才能进入同一 Episode core；
3. 不同 atomic component 必须有不同 semantic key 和逐 passage payload；
4. `context_only` 不得成为 Episode core；
5. 缺少 binding 时 fail closed；
6. Reviewer atomic key 不能覆盖 Assertion atomization 缺口；
7. proposition 聚类必须以 claim 内的 `assertion_semantic_key` 为边界，不得再用旧 claim key 将不同 atomic component 重新拼回同一 proposition。

## 3. 兼容边界

V1 Adapter 仍可只读历史 fixture，以便保留 V3→V4 的早期回归证据；其 `legacy_multi_passage_claim_fanned_out` 输出不得进入 G2.6J 新 holdout。新输入必须声明：

```yaml
assertion_input_contract: passage-scoped-assertion-v2
```

Blind input validator 将拒绝：

- 缺少 PassageSupport；
- legacy fan-out flag；
- claim/assertion source key 缺失；
- 多 passage binding 不完整或重复；
- equivalent evidence 语义不一致；
- 单独 atomic component 未使用独立 semantic key。

严格输入由 `passage-support-materialize` 确定性生成。该命令要求 PassageSupport review 在 Episode Gold/candidate 之前冻结、完整覆盖 source snapshot 中的 claim，并校验 snapshot canonical hash；它不访问网络、不调用模型、不写数据库。

## 4. 测试覆盖

当前确定性测试覆盖：

- V2 Adapter 拒绝未绑定 multi-passage claim；
- atomic components 使用逐 passage overrides；
- equivalent evidence 仅在语义一致时接受；
- PassageSupport 值域和核心字段门禁；
- passage-scoped blind input 拒绝 legacy fan-out；
- v2.7 拒绝 Reviewer atomic key 覆盖未绑定 fan-out；
- v2.7 接受显式同义证据合并；
- v2.6 历史产物仍可读取。
- PassageSupport review hash、claim 覆盖和严格 blind input 物化。
- v2.7 proposition 聚类拆开同 claim 的不同 atomic/context component，并保留显式 equivalent evidence 聚合。
- v2.7 在领域门禁中拒绝任何 `context_only` Assertion 进入 Episode core。

## 5. 下一步

G3 继续禁止。
