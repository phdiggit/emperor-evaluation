# 证据与历史事件模型

> 状态：`accepted`
> 目标：在“保留来源差异”和“形成可消费事件”之间建立可审计边界。

## 1. 三层事实观

### 1.1 史源内容层

SourceDocument 和 SourcePassage 记录原文及其版本。该层回答：

> 原始或权威来源具体写了什么？

### 1.2 来源断言层

Assertion 记录从段落中识别出的可核验命题。该层回答：

> 这个来源在这一段声称了什么？

### 1.3 当前事件模型层

HistoricalEpisode 是在多断言比较、身份解析和冲突保留后形成的当前语义模型。该层回答：

> 在当前证据和版本下，我们把哪些断言视为同一事件，它的核心结构是什么？

三层不得互相覆盖。事件模型错误时可以修订，不修改来源原文和历史断言。

## 2. Assertion 原子度

Assertion 应足够小以便核验，但不得为了“原子化”拆掉必要的因果或角色关系。

适宜的断言示例：

- 皇帝任命某人为某职；
- 皇帝把某任务交给某人；
- 某人在该职责下完成某结果；
- 史源评价该任用得当或失当；
- 某次失败与该授权安排存在明确关联。

不宜拆成互不关联的碎片：

```text
任命
某官职
某人
成功
```

抽取结果必须保留同段关系和候选 episode linkage。

## 3. Episode 边界

一个 episode 通常同时满足：

- 核心人物或机构相对稳定；
- 行为/任务属于同一责任链；
- 时间范围连续或有明确阶段关系；
- 结果与该任务链可关联；
- 拆开后会丢失业务意义，合并后不会混入另一独立决策。

### 应合并

- 同一任命在《本纪》《列传》中不同措辞；
- 任命、职责和同一任务最终结果分别见于不同卷；
- 同一事件的纪年差异仅来自公历换算或异体表述。

### 应拆分

- 同一人物在不同年份承担独立任务；
- 同一战区内不同皇帝作出的独立任命；
- 先任用成功、后因新决策重新授权并失败；
- 相同关键词但责任链、地点或结果不同。

## 4. Episode 身份

`semantic_fingerprint` 至少基于：

- 评估上下文/统治者；
- canonical participants 与相关角色；
- episode type；
- 任务或责任域；
- 规范化时间范围；
- 必要时的地点/对象。

不得把完整自然语言摘要作为主身份键。摘要、结果细节和评价属于可修订属性。

fingerprint 只生成 merge candidate；以下情况必须进入人工或规则审查：

- 同名人物未解析；
- 时间范围重叠但可能是连续多次行动；
- 史源对主体或结果冲突；
- 一个广义叙述可能覆盖多个独立事件；
- 跨皇帝、跨政权或跨阶段的责任归属不清。

## 5. 证据关系

每个 EpisodeEvidenceLink 必须声明其用途：

- `supports_identity`
- `supports_action`
- `supports_responsibility`
- `supports_outcome`
- `supports_consequence`
- `contradicts`
- `context_only`
- `historiographical_evaluation`

规则判断不得只凭 `context_only` 建立核心事实。

## 6. 冲突与不确定性

冲突不能通过选择“最顺眼的一条”消失。事件包应保留：

- 冲突字段；
- 各自断言与来源；
- 当前处理状态；
- 采用、并列或阻断理由；
- 需要补查的来源。

事件状态：

- `proposed`
- `needs_identity_review`
- `needs_evidence_review`
- `accepted`
- `accepted_with_uncertainty`
- `rejected`
- `superseded`
- `split`
- `merged`

正式规则投影原则上只读取 `accepted` 和规则明确允许的 `accepted_with_uncertainty`。

## 7. 完整性

Episode completeness 不用单一百分比表达，至少分槽位：

- `identity`
- `time`
- `action`
- `responsibility`
- `outcome`
- `consequence`
- `source_diversity`
- `conflict_resolution`

每个槽位状态：

- `complete`
- `partial`
- `missing`
- `not_applicable`
- `conflicted`

例如 `appointment_delegation` 至少要求 action、responsibility 和可解释的 outcome/feedback；单纯官职记载不能自动视为完整。

## 8. 语义版本与证据版本

### 仅 evidence version 变化

- 增加同义史料；
- 增加更精确 locator；
- 增加支持同一字段的断言；
- 不改变事件核心结构的来源纠正。

### semantic version 变化

- 主体变化；
- 事件类型变化；
- 时间范围发生实质变化；
- 原先一个事件被拆为两个；
- 两个事件被合并；
- 责任或结果发生足以影响规则投影的变化。

证据变化不默认使 Judgment 失效；只有冲突状态或规则依赖字段改变时才进入失效评估。

## 9. 删除与退役

- SourcePassage 接受后不可物理覆盖；
- 错误 Assertion 标记 rejected/retired，保留来源和原因；
- Episode 合并/拆分保留 lineage；
- 规则消费只读取当前活动版本；
- 灾难恢复可以重建索引和物化视图，不能重写领域历史。
