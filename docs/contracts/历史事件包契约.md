# 历史事件包契约

> 状态：`review_ready`  
> 契约版本：`historical-episode-packet-v1`

## 1. 用途

HistoricalEpisodePacket 是断言层与规则投影层之间的稳定接口。它表示一个当前 canonical episode 及其证据、人物、版本和不确定性。

## 2. 最小结构

```yaml
episode_id:
episode_type:
episode_status:
evaluation_context:
semantic_version:
evidence_version:
semantic_fingerprint:

time:
  start:
  end:
  precision:
locations: []

participants:
  - person_ref:
    role_codes: []
    role_status:

action:
responsibility:
outcome:
consequence:

assertion_links: []
conflicts: []
uncertainties: []
completeness:
lineage:
provenance:
```

## 3. 必填语义

- 至少一个已解析核心 participant；
- episode type；
- evaluation context；
- 至少一个支持 action/identity 的已接受 Assertion；
- semantic/evidence version；
- completeness；
- lineage 或明确 `origin=created`。

## 4. semantic_fingerprint

由受控结构字段生成，不包含：

- 自然语言标题；
- 展示摘要；
- 数据库自增 ID；
- 文件路径；
- 模型措辞；
- evidence 数量。

fingerprint 变化生成 merge/split/revision 候选，不直接覆盖旧 episode。

## 5. Assertion link

每个 link：

```yaml
assertion_ref:
relation:
supported_fields: []
evidence_status:
representative: false
```

`relation` 至少支持：

- `supports`
- `contradicts`
- `context_only`
- `evaluation_only`

## 6. completeness

```yaml
identity: complete | partial | missing | conflicted
time: complete | partial | missing | conflicted
action: complete | partial | missing | conflicted
responsibility: complete | partial | missing | not_applicable | conflicted
outcome: complete | partial | missing | not_applicable | conflicted
consequence: complete | partial | missing | not_applicable | conflicted
```

不得只用一个总分隐藏关键槽位缺失。

## 7. merge/split

### merge 条件

- 核心 participant 与角色一致；
- action/责任链一致；
- 时间和地点不冲突；
- 结果可视为同一事件的不同描述；
- 合并不抹去实质冲突。

### split 条件

- 独立决策或任务；
- 不同统治者上下文；
- 不同时间阶段且可分别评价；
- 一个广义来源包含多个独立结果链；
- 规则会因合并而重复或扭曲计分。

merge/split 必须产生 lineage 和 review decision。

## 8. 版本

- 新同义证据：只增 evidence_version；
- 冲突证据：增 evidence_version，并可能阻断；
- 核心结构改变：新 semantic_version；
- 合并/拆分：生成新活动 episode，旧版本标记 superseded；
- 规则投影只指向明确版本。

## 9. 不变量

- 一个 assertion 在同一 semantic version 下最多作为一个 episode 的核心成员；背景链接可多处使用但必须标明；
- 同一 episode 的活动版本只有一个；
- 每个 episode 的 participant refs 指向活动 canonical person 或明确 unresolved；
- accepted episode 不得缺 passage lineage；
- 规则字段不得写进 episode 核心 payload。

## 10. 验收

- 同一事件不同史源归并后 episode 数不膨胀；
- 不同事件不因关键词相同合并；
- 新增同义证据 episode_id 不变；
- merge/split 可完整追溯；
- packet 可在不查询 V3 表结构的情况下被规则层消费。
