# 历史事件包契约

> 状态：`accepted`

## 1. 用途

HistoricalEpisodePacket 是断言层与规则投影层之间的稳定接口。它表示一个当前 canonical episode 及其证据、人物和不确定性。

## 2. 最小结构

```yaml
episode_id:
episode_type:
episode_status:
evaluation_context:
semantic_fingerprint:

time:
  start:
  end:
  precision:
locations: []

participants:
  - person_ref:
    role_codes: []
    role_status:

action:
responsibility:
outcome:
consequence:

assertion_links: []
conflicts: []
uncertainties: []
completeness:
lineage:
provenance:
```

## 3. 必填语义

- 至少一个已解析核心 participant；
- episode type；
- evaluation context；
- 至少一个支持 action/identity 的已接受 Assertion；
- completeness；
- lineage 或明确 `origin=created`。

## 4. semantic_fingerprint

由受控结构字段生成，不包含：

- 自然语言标题；
- 展示摘要；
- 数据库自增 ID；
- 文件路径；
- 模型措辞；
- evidence 数量。

fingerprint 变化触发边界复核；通过后原位更新当前 episode。旧值不在业务库保留，使用 Git 追溯。

## 5. Assertion link

每个 link：

```yaml
assertion_ref:
relation:
supported_fields: []
evidence_status:
representative: false
```

`relation` 至少支持：

- `supports`
- `contradicts`
- `context_only`
- `evaluation_only`

## 6. completeness

```yaml
identity: complete | partial | missing | conflicted
time: complete | partial | missing | conflicted
action: complete | partial | missing | conflicted
responsibility: complete | partial | missing | not_applicable | conflicted
outcome: complete | partial | missing | not_applicable | conflicted
consequence: complete | partial | missing | not_applicable | conflicted
```

不得只用一个总分隐藏关键槽位缺失。

## 7. merge/split

### merge 条件

- 核心 participant 与角色一致；
- action/责任链一致；
- 时间和地点不冲突；
- 结果可视为同一事件的不同描述；
- 合并不抹去实质冲突。
- 多个动作只是同一状态转换的互补角色描述，或同一最终命令的直接送达、执行与即时结果，且中间没有新决策或独立裁量；
- 人物称谓差异已被显式保留为 identity blocker，且其他边界字段足以确认同一事件。

### split 条件

- 独立决策或任务；
- 不同统治者上下文；
- 不同时间阶段且可分别评价；
- 一个广义来源包含多个独立结果链；
- 规则会因合并而重复或扭曲计分。
- 授权或移交之后，执行者进入可独立归责的调查、审讯、裁量、作战或治理阶段；
- 后续出现新的命令、重新授权或新的责任主体。

merge/split 必须产生 lineage 和 review decision。

直接断言当前 episode action、responsibility 或 outcome 的 Assertion 必须保留为 core evidence。不得仅因同义、重复抽取或同 passage 重叠而降为 context；context 只承载背景、动机、跨阶段因果或非当前原子动作。

## 8. 当前值更新

- 新同义证据或冲突证据：更新当前 evidence links，并按门禁决定状态；
- 核心结构改变：复核后更新当前语义字段和 semantic fingerprint；
- 合并/拆分：生成新的稳定 episode 身份并重新挂接当前成员；
- 相同输入零业务写入；业务库不维护历史版本表。

## 9. 不变量

- 一个 assertion 在当前状态下最多作为一个 episode 的核心成员；背景链接可多处使用但必须标明；
- 同一 episode 只保存一个当前值；
- 每个 episode 的 participant refs 指向活动 canonical person 或明确 unresolved；
- accepted episode 不得缺 passage lineage；
- accepted / accepted_with_uncertainty 的 participant 必须全部 resolved，并指向 canonical person；
- accepted / accepted_with_uncertainty 的核心 Assertion link 必须全部为 accepted evidence；
- accepted episode 必须包含规定 completeness 槽位，identity/action 必须 complete；
- accepted_with_uncertainty 必须保留 conflict 或 uncertainty，不得洗绿；
- accepted episode 的 evaluation context 必须是 canonical person context；
- 规则字段不得写进 episode 核心 payload。

## 10. 验收

- 同一事件不同史源归并后 episode 数不膨胀；
- 不同事件不因关键词相同合并；
- 新增同义证据 episode_id 不变；
- merge/split 可完整追溯；
- packet 可在不查询 V3 表结构的情况下被规则层消费。
