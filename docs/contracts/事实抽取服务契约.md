# 事实抽取服务契约

> 状态：`review_ready`  
> 契约版本：`assertion-extraction-contract-v1`

## 1. 职责

事实抽取服务从已缓存、可定位的 SourcePassage 产生 Assertion 草案和 episode linkage 建议。

它不负责：

- 接受历史事实；
- 合并 canonical person；
- 接受 canonical episode；
- 路由正式规则；
- 生成因子或分数。

## 2. 请求

```yaml
request_id:
idempotency_key:
target_context:
passage_refs: []
known_person_refs: []
extraction_profile:
extraction_schema_version:
model_policy_version:
```

请求只传 passage refs 和必要上下文，不复制无关全文。

## 3. Assertion 输出

```yaml
assertion_code:
source_passage_ref:
assertion_type:
subject:
predicate:
object:
time_expression:
location_expression:
qualifiers:
polarity:
source_attribution:
candidate_episode_key:
confidence:
ambiguity_flags: []
extraction_provenance:
```

`assertion_code` 是本次抽取输出身份；正式 `assertion_id` 由接受层生成。

## 4. 抽取原则

- 一条 Assertion 必须能指向具体原文；
- 保留原文语气，如“疑”“或曰”“未详”；
- 不把史家评价改写成客观行动；
- 不把后世总结反投射为当时事实；
- 不补齐原文没有的结果；
- 同段多个相关断言保留候选 episode linkage；
- 跨皇帝/跨时期必须显式标记，不强行归入请求目标。

## 5. 输出分类

- `event_fact`
- `identity_fact`
- `role_fact`
- `outcome_fact`
- `causal_claim`
- `historiographical_evaluation`
- `numeric_fact`
- `context_fact`

规则可以限制可消费类型，但抽取服务保持 rule-neutral。

## 6. 幂等与缓存

缓存键：

```text
passage content hash
+ extraction profile
+ extraction schema version
+ model policy version
```

相同输入命中缓存，不重复调用模型。模型版本变化不自动重抽；只有契约或质量评估要求时显式 refresh。

## 7. Schema 校验

- 必填字段完整；
- person refs 可解析或标记 unresolved；
- passage ref 必须存在；
- 值域有限；
- 时间、地点和结果不得由 summary 反推；
- 每个输出恰好一条 JSON 对象；
- 重复 assertion 候选在接受层去重。

## 8. 失败与门禁

输出可能为：

- `succeeded`
- `succeeded_with_warnings`
- `blocked_identity`
- `blocked_source`
- `failed_schema`
- `failed_model`
- `failed_timeout`

`succeeded` 只表示生成草案成功，不表示断言已接受。

## 9. 验收

- 每条 Assertion 100% 可回到 passage；
- 跨目标人物污染为 0；
- 无原文支持的 actor/action/outcome 为 0；
- 同输入重跑零模型调用；
- 服务输出中不出现 rule score、talent grade 或正式裁判。
