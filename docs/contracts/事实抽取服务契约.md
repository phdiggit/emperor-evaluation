# 事实抽取服务契约

> 状态：`accepted`
> 契约版本：`assertion-extraction-contract-v2`

## 1. 职责

事实抽取服务从已缓存、可定位的 SourcePassage 产生 Assertion 草案和 episode linkage 建议。

它不负责：

- 接受历史事实；
- 合并 canonical person；
- 接受 canonical episode；
- 路由正式规则；
- 生成因子或分数。

## 2. 请求

```yaml
request_id:
idempotency_key:
target_context:
passage_refs: []
known_person_refs: []
extraction_profile:
extraction_schema_version:
model_policy_version:
```

请求只传 passage refs 和必要上下文，不复制无关全文。

## 3. Assertion 输出

```yaml
assertion_code:
source_passage_ref:
assertion_type:
subject:
predicate:
object:
time_expression:
location_expression:
qualifiers:
polarity:
source_attribution:
candidate_episode_key:
confidence:
ambiguity_flags: []
extraction_provenance:
passage_support:
  support_mode:
  assertion_semantic_key:
  supported_fields: []
  binding_provenance: {}
```

`assertion_code` 是本次抽取输出身份；正式 `assertion_id` 由接受层生成。

### 3.1 PassageSupport

`passage_support` 说明当前 Assertion 的结构化字段由该 passage 支持到什么范围。允许模式：

- `single_passage`：单一 passage 独立支持该 Assertion；
- `equivalent_evidence`：多个 passage 支持语义完全相同的 Assertion；
- `atomic_component`：该 passage 只支持复合 claim 中一个独立原子分量；
- `context_only`：只提供上下文，不能作为 Episode core。

`supported_fields` 只能从以下值选择：

```text
identity
action
responsibility
time
location
outcome
consequence
attribution
context
```

除 `context_only` 外，至少必须支持 `identity` 和 `action`。`assertion_semantic_key` 是来源语义键，不是 Episode code，也不得来自 Gold 边界。

### 3.2 多 passage claim

一个上游 claim 引用多个 passage 时，禁止把完整 `fact_payload`、summary、outcome 和责任域无条件复制到每个 passage。

- 同一原子 Assertion 的同义证据必须共享 `assertion_semantic_key`，全部声明 `equivalent_evidence`，且结构化语义完全一致；
- 不同原子子事件必须使用不同 semantic key，声明 `atomic_component`，并给出逐 passage 的字段值；
- 只提供背景的 passage 声明 `context_only`；
- 缺少逐 passage binding、binding 重复、passage 未覆盖或同 key 语义不一致时必须 `failed_schema`；
- Reviewer 的 `atomic_event_key` 不能补救或覆盖缺失的 Assertion atomization。

V1 的 `legacy_multi_passage_claim_fanned_out` 只可读取历史 fixture，不得进入 G2.6J 及后续新 holdout，也不得成为生产输入。

## 4. 抽取原则

- 一条 Assertion 必须能指向具体原文；
- 保留原文语气，如“疑”“或曰”“未详”；
- 不把史家评价改写成客观行动；
- 不把后世总结反投射为当时事实；
- 不补齐原文没有的结果；
- 同段多个相关断言保留候选 episode linkage；
- 跨皇帝/跨时期必须显式标记，不强行归入请求目标。

## 5. 输出分类

- `event_fact`
- `identity_fact`
- `role_fact`
- `outcome_fact`
- `causal_claim`
- `historiographical_evaluation`
- `numeric_fact`
- `context_fact`

规则可以限制可消费类型，但抽取服务保持 rule-neutral。

## 6. 幂等与缓存

缓存键：

```text
passage content hash
+ extraction profile
+ extraction schema version
+ model policy version
```

相同输入命中缓存，不重复调用模型。模型版本变化不自动重抽；只有契约或质量评估要求时显式 refresh。

## 7. Schema 校验

- 必填字段完整；
- person refs 可解析或标记 unresolved；
- passage ref 必须存在；
- 值域有限；
- 时间、地点和结果不得由 summary 反推；
- 每个结构化字段必须在 `supported_fields` 中有 passage 级支持；
- multi-passage claim 必须完整绑定为 equivalent evidence、atomic component 或 context；
- 每个输出恰好一条 JSON 对象；
- 重复 assertion 候选在接受层去重。

## 8. 失败与门禁

输出可能为：

- `succeeded`
- `succeeded_with_warnings`
- `blocked_identity`
- `blocked_source`
- `failed_schema`
- `failed_model`
- `failed_timeout`

`succeeded` 只表示生成草案成功，不表示断言已接受。

## 9. 验收

- 每条 Assertion 100% 可回到 passage；
- 跨目标人物污染为 0；
- 无原文支持的 actor/action/outcome 为 0；
- 同输入重跑零模型调用；
- 服务输出中不出现 rule score、talent grade 或正式裁判。
