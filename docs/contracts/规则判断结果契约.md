# 规则判断结果契约

> 状态：`accepted`
> 契约版本：`rule-judgment-result-v1` / `score-contribution-v1`

## 1. 边界

Judgment 是对 RuleProjection 的结构化业务裁量。它不是史源，不修改 Episode，也不直接包含最终聚合分。

## 2. 输入引用

```yaml
projection_ref:
input_type:
input_semantic_fingerprint:
rule_code:
rule_version:
judgment_policy_version:
factor_schema_version:
```

## 3. 输出

```yaml
judgment_id:
projection_ref:
applicability:
direction:
factor_values:
evidence_assessment:
attribution:
uncertainties: []
supporting_episode_fields: []
supporting_assertion_refs: []
excluded_assertion_refs: []
review_status:
review_reason:
judgment_version:
provenance:
```

## 4. Applicability

允许值：

- `applicable`
- `supporting_only`
- `not_applicable`
- `blocked_identity`
- `blocked_evidence`
- `blocked_conflict`

不适用不是零分判断；Score 层不得把 blocked 或 not_applicable 当作已判零分。

## 5. Direction

- `positive`
- `negative`
- `mixed`
- `neutral_context`

方向必须由规则语义和事件责任决定，不得只靠关键词。

## 6. Factor values

- 只能使用 RuleDefinition 声明的有限值；
- 每个值必须有 evidence/episode field 支持；
- 缺失关键因子时阻断，不由模型自由补值；
- 人物画像因子必须引用明确 PersonProfileSnapshot 版本；
- 数值计算在 scorer 中完成。

## 7. Evidence assessment

至少包括：

- source sufficiency；
- attribution strength；
- context completeness；
- conflict status；
- negative evidence search status；
- rule boundary check。

## 8. Review status

- `draft`
- `needs_review`
- `accepted`
- `shadow_accepted`
- `rejected`
- `superseded`

只有 `accepted` Judgment 可产生正式 ScoreContribution。`shadow_accepted` 只可在 `result_scope=shadow_demo_only` 时产生 `contribution_status=shadow` 的只读贡献，不得写正式评分或排名。

## 9. 模型 provenance

若模型参与，必须记录：

- model family；
- prompt/policy version；
- input/output fingerprint；
- cache hit；
- token/latency；
- validation result；
- 人工或规则接受者。

模型原始文本不是正式字段；只有通过 Schema 和 Gate 的有限值进入 Judgment。

## 10. 幂等与缓存

活动唯一键：

```text
projection_ref + rule_version + judgment_policy_version + factor_schema_version
```

缓存键使用 input semantic fingerprint，不使用 binding ID、文件路径或生成时间。

## 11. Score 接口

ScoreContribution 读取：

- accepted judgment；
- deterministic scoring formula version；
- 必要的权重/衰减配置；
- evaluation context。

Judgment 不允许直接提供最终 score，只提供有限因子和方向。

## 12. 验收

- 一条活动 Projection 最多一个当前 accepted Judgment；
- 值域错误为 0；
- supporting/excluded evidence 可追溯；
- 规则版本和 input fingerprint 100% 存在；
- 相同输入重跑复用 Judgment；
- scorer 可在无模型参与下重复得到相同结果。

## 13. ScoreContribution v1

最小输出：

```yaml
score_contribution_id:
score_contribution_schema_version: score-contribution-v1
contribution_status: shadow | accepted
judgment_ref:
rule_evidence_unit_ref:
primary_settlement_rule:
supporting_only_rules: []
factor_points: {}
raw_factor_sum:
applicable_factor_count:
normalized_contribution:
scoring_formula_version:
duplicate_settlement_check:
excluded_from_other_rules_reason:
lineage:
  episode_refs: []
  assertion_refs: []
  source_passage_refs: []
semantic_fingerprint:
```

约束：

- `unknown` / `blocked_*` / `needs_review` 不得产生贡献；
- `not_applicable` 不计 0，必须从适用因子分母排除；
- `mixed` 可按规则公式计中性点，但不得丢失混合方向和证据；
- 幂等键由 Judgment fingerprint、公式版本和 evaluation scope 确定；
- 每个贡献必须完成重复结算检查并保留 Episode → Assertion → SourcePassage lineage；
- shadow contribution 不得换算为正式小项分、总分或排名。

## 14. EvidenceCoverage 与缺失推断

所有 rule 的因子判断共用 `rule-factor-evidence-coverage-v1`，不得只在单个规则中临时实现。每次评分输入必须声明 `scope_as_of`、覆盖状态、时间窗、史源族、停止原因和是否允许根据缺失作推断。

通用门禁：

- `open_snapshot` 表示开放世界开发或生产快照，`absence_inference_allowed` 必须为 `false`；
- `minimum_sufficient` 允许用已经出现的正证据确认判断，但仍不得把“未找到”解释为“不存在”；
- 只有 `reviewed_bounded_complete`、明确时间窗且 `absence_inference_allowed=true` 时，规则才可对预先声明的缺失敏感选项使用 `bounded_absence`；
- 任何因子覆盖不足时必须输出 `insufficient_coverage`、`option_code=null` 和 `coverage_insufficient`，进入 `needs_review`，不得生成 ScoreContribution；
- 高档、正向或长期判断若已有直接充分证据，可以在开放覆盖下确认，不要求穷尽全部史料；低档、一次性、从未发生等判断不得仅由当前输入缺少材料推出；
- 规则必须声明自己的缺失敏感选项。该机制适用于连续性、人才发现、容才、反任人唯亲及后续所有 rule，不绑定 `appointment_delegation`。
