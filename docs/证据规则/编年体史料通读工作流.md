# 编年体史料通读工作流

## 目标与验收优先级

本工作流的产物是**完整通读总结**，不是“主要事件摘要”或“重点战线概述”。

验收优先级固定为：

1. **内容覆盖完整**；
2. **只据本卷原文、锚点准确**；
3. **连续时序和战事关系清楚**；
4. 简洁、合并和版式美观。

任何实质事件因为“不是主线”“影响较小”“已属于某场大战”“后文还有更大事件”而被省略，均视为覆盖失败。宁可多保留一条次级行动，也不得自行按重要性筛选原文事实。

## 输入

每卷只读以下内容：

```text
docs/原始史料/<史书>/卷NNN.md
```

原文开头的 `source_unit_id`、`source_url`、`revision_ref`、`raw_sha256`、段落数和首尾锚点一并写入总结。方括号中的 `SRC-...-Pxxxx` 是原文段落锚点。

## 一、完整通读硬规则

### 1. 必须从首锚点线性读到末锚点

不得只搜索人物、战役或关键词后拼接摘要；不得读到“主要战线已经明确”后改为选择性摘录。

通读过程中，对每个原文段落形成临时覆盖判断：

- `META`：页头、目录、footer 等非正文元数据；
- `EVENT`：出现新的实质事实、行动、结果、数量、控制权变化或治理信息；
- `CONTINUATION`：延续前一事件，但新增过程、兵力、结果、后续或影响；
- `COMMENT`：史臣论赞、纯议论；如其中包含本卷可独立使用的事实，事实部分仍按 `EVENT` 处理。

这份逐段判断可以只作为临时工作账，不要求写入最终 Markdown，但**提交前必须重新从首锚点扫到末锚点核对一次**。

### 2. “合并连续事件”只允许合并表达，不允许删除事实

可以把同一战事、同一叛乱或同一政治事件的多个段落合并到一个标题下，但必须保留各段新增的独立行动和结果。

以下情况即使属于更大的连续战事，也必须写出：

- 一次单独的进攻、夜袭、伏击、追击、出援、撤退、受降、弃城、夺城、围城、解围；
- 兵力明显变化、援军到达、另一路部队行动；
- 战术动作导致胜败逆转，如伪装、诱敌、断路、设伏、纵火、决堤、地道、清野；
- 将领被杀、被俘、投降、逃亡或改换阵营；
- 一座州县、城寨、关隘或军镇的控制权发生变化；
- 大战内部另有一条可以独立表述的支线行动。

“已写某某之乱”“已写某某战线”本身不能覆盖这些具体事实。

### 3. 实质事件的最低收录标准

原文出现下列任一内容，原则上都属于应收录事实：

- 战争、围城、攻守、叛乱、兵变、武装政变；
- 征兵、募兵、援军、调军、分兵、戍守、撤军、逃亡、投降、受降；
- 兵力、死伤、俘虏、杀戮、屠城、军队疫病；
- 军粮、粮运、军资、马匹、兵器、舟舰、民夫、丁匠、驿传和后勤；
- 焚掠、清野、毁城、毁屋、迁徙、饥荒、人口损失、生产破坏；
- 赋役、税敛、仓储、赈济、工程、灾害、贸易和财政负担；
- 政变、谋杀、清洗、诱杀、处决、继承、权力交接、军政控制变化；
- 外交、结盟、婚姻、质子、进贡、求援、拒援及由此产生的实质后果；
- 原文明示的民生、社会秩序、地方控制和人口变化。

普通官员任免如无明显政治、军事、财政或秩序含义，可不逐条展开；但若任免直接体现权力控制、政变、继承、军镇归属或清洗，则必须收录。

## 二、怎么总结

从卷首读到卷尾，按时间顺序组织原文事实。

1. 先列出全卷连续时序导航。导航不是“精选大事表”，应覆盖本卷所有实质事件；可以把时间相近、内容连续的事实合并成一行，但不得因此漏掉独立行动。
2. 战争、围城、攻守、叛乱、受降、撤军、征兵、援军、边防和武装政变，按连续战事展开。保留原文明确的兵力、死伤、俘掳、征发、民夫、粮运、军资、城池、焚掠、迁徙、生产影响和控制权变化。
3. 赋役、钱粮、仓储、赈济、工程、灾害、人口迁徙和政治秩序，按原文事实记入对应章节。
4. 每个实质事件列出相关原文锚点；兵力、过程和结果分散在不同段时，把这些锚点一起列出。关键事实附同一锚点内的连续原文短引。
5. 一个锚点被列入总结，不等于该段已经覆盖；必须确认该段的**新增事实本身**已经写出来。禁止只把锚点并入一个大范围而不写其独立内容。
6. 只写本卷原文事实。跨卷未结束的事件写入“后卷边界”，不得用后卷知识补足本卷结果。
7. 不因篇幅主动删减次级战斗、支线叛乱或局部政治暴力。若同类事实很多，优先压缩措辞和重复背景，不压缩事实节点。

## 三、提交前覆盖审计：硬门禁

每卷 Markdown 写完后、提交前，必须执行一次从首锚点到末锚点的逐段复扫。

对每个正文 `Pxxxx` 逐项判断：

- 若为 `META` 或无新增事实的纯格式段，可跳过；
- 若为 `EVENT` 或带新增事实的 `CONTINUATION`，必须能指出最终总结中具体哪一句已经覆盖该事实，并且该句带有该段锚点；
- 若找不到对应事实，必须先补写，再继续审计；
- 不得以“已经写了所属大战”“已经写了人物”“该段不重要”作为通过理由。

### 覆盖审计必须特别检查的高风险段落

以下内容最容易在压缩时被误删，必须额外复核：

1. **大战内部的小支线**：另一路军、一次短促攻城、一次伏击或追击；
2. **叛乱内部的分阶段行动**：先袭一州、再增兵、再被击破；
3. **阴谋败露后的完整后续**：诱杀、部众处置、家属反应、财物或府舍变化；
4. **相邻战区的短事件**：前后都是更大的战事时，中间一段独立攻防最容易被跳过；
5. **过程与结果分段书写**：前段写出兵，后段写败退、被俘、斩杀或控制权变化；
6. **数量不大但事实完整的行动**：三千骑、万人一路军等不能因规模小于主战场而删除。

### 本次已出现过的错误类型，后续不得重复

- 不能把“安仁义之乱”概括后，省略其**袭常州以及徐温伪装增兵击破**的独立过程。
- 不能把“田頵、朱延寿叛乱”概括后，省略**朱延寿阴谋败露、杨行密诱杀、部兵听命及家属后续**。
- 不能因为正在总结魏博或河北大局，省略**李嗣昭以三千骑攻邢州七日不克并遭伏击败退**。
- 不能因为相邻段落还有更大战事，省略**刘守文以万人攻贝、冀等州及随后战局结果**。

上述例子说明：**合并的是标题和叙述，不是事件节点。**

### 提交失败条件

出现以下任一情况，不得提交：

- 任一实质正文段落没有对应总结事实；
- 只列锚点范围但没有写出该段新增事实；
- 以“主线”“重点”“代表性事件”为标准自行删除次级事件；
- 战争段漏掉原文明示的兵力、重要死伤、粮运、军资、民夫、城池、焚掠、迁徙或控制权变化；
- 前后卷事实混写；
- 来源身份、首尾锚点、段落数与原文不一致。

只有逐段覆盖审计通过后，才允许提交该卷，再开始下一卷。

## 四、输出

每卷写一份：

```text

```

保持以下五个章节；**不要为了覆盖审计另增长期“审计报告”文件**，逐段覆盖账只作为本次执行的临时门禁。

```markdown
# 《<史书>》卷<卷号>通读总结

- source_unit_id：……
- source_url：……
- revision_ref：……
- raw_sha256：……
- 通读范围：<首锚点> 至 <末锚点>；<段落数> 段。
- 前卷边界：……
- 后卷边界：……

## 一、连续时序导航
```

## 五、连续多卷执行纪律

用户要求顺序通读多卷时：

1. 只处理当前卷；
2. 线性读完整卷；
3. 写总结；
4. 做逐段覆盖审计并补齐所有缺口；
5. 提交当前卷；
6. 读回确认提交文件和目标分支；
7. **当前卷提交完成后才开始下一卷**。

不得先粗读多卷、最后统一总结；不得因为后续卷数较多而在后面的卷降低覆盖密度。
