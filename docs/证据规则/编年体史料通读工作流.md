# 编年体史料通读工作流

> 状态：`active`
>
> 目标：让 ChatGPT 网页端按卷阅读固定原文，产出可复核、可供后续战役/窗口/四域工作消费的**通读总结**。它不是评分、父卡裁决或数据库写入流程。

## 一、为什么改为网页端逐卷通读

过去把“读完一卷”理解为模型生成四域事实、战役线程和候选，并试图在同一步完成路由、拆合和验收。结果是叙事摘要看似完整，却常压掉了决定后续可结算性的细节：伤亡对象、动员人数与役期、民夫转输、粮饷军资、城邑生产损毁、控制权变化，以及实际发生于哪位皇帝窗口。

现在将职责拆开：

| 阶段 | 唯一职责 | 不得做的事 |
| --- | --- | --- |
| 原文发布 | 将固定修订原文按卷提供为可读文本 | 用摘要替代原文、混入既有裁决 |
| ChatGPT 网页端通读 | 按原文顺序抽取带锚点的中性事实，写逐卷总结 | 定分、估算未载人数、定父卡、绑定皇帝得分 |
| 本地 intake | 校验锚点、合并跨卷线索、登记共享战役/四域候选 | 把网页端自然语言静默改成正式事实 |
| 后置裁决 | 战役父卡、窗口绑定、统一链排除、P/S/M/A、SB/WR 与各项结算 | 重读已经合格的整卷原文 |

网页端承担的是最适合文本模型的“完整阅读与可定位摘录”；本地规则链承担最需要一致性和去重的“合并、裁决与计分”。任何阶段都不得以叙事流畅替代可回源性。

## 二、固定史源和公开阅读包

### 2.1 原文才是网页端输入

每卷原文应以 UTF-8、无 BOM 的 Markdown 或纯文本发布；一个文件只含一卷。推荐目录：

```text
docs/
└─ 原始史料/
   └─ <史书>/
      ├─ manifest.jsonl
      ├─ README.md
      ├─ 卷263.md
      ├─ 卷264.md
      └─ ...
```

`manifest.jsonl` 每卷至少记录：`work_title`、`volume`、`source_url`、`revision_ref`、`raw_sha256`、`text_path`、`published_at` 和来源许可/署名信息。原始网页或版本发生变化时，建立新 revision 记录，不覆盖旧记录。

SQLite 缓存仍可保留为本地抓取、全文检索和重现工具；它不是网页端的阅读介质，也不是唯一可读证据。网页端读取的是与缓存 `raw_text` 同 hash 的按卷文本；维基页面标记可以保留，但不得用会压扁段落的“清洗正文”替换原文。

### 2.2 段落锚点是必需输入

原文导出必须给每个非空段落一个稳定锚点，例如：

```markdown
[SRC-ZZTJ-263-1503001-P0042]
某年某月，……
```

锚点只标识原文位置，不解释史实，并必须在 GitHub 渲染页和原始文件中都可见。一个卷文件应在开头声明：作品、卷号、来源 URL、`revision_ref`、`raw_sha256`、段落数、首尾锚点。没有段落锚点时，网页端只能产出线索，不得声称“可直接 intake”。

### 2.3 输入大小与分卷原则

- 一次任务只读一卷完整原文；不能把相邻卷、既有总结和战役表混在同一阅读输入中。
- 长卷可以在同一任务中按原文锚点分段阅读，但最终只输出该卷一份总结；不得按模型方便随意省略中段。
- 跨卷事件只记录本卷所见阶段，并写明 `continues_from` 或 `continues_to`；不得在未读相邻卷时补写结局。
- 网页端通过已授权的 GitHub 访问或直接文件上传获取原文均可；实际输入必须能对应 `manifest` 的 hash 和 revision。
- 原文中可能保留 MediaWiki 模板、链接、分类和换行标记；它们不是史实。阅读时忽略其版式作用，但不得因为清洗或忽略标记而跳过相邻的史料正文。

## 三、网页端任务合同

### 3.1 每卷任务的最小输入

每次向 ChatGPT 网页端提供：

1. 一卷原文文件；
2. 该卷 manifest 行；
3. 本文中的“逐卷提示词模板”；
4. 上一卷**边界摘要**（仅最后一个未闭合事件的 ID、最后锚点和未决问题；没有则明确为空）。

不得提供既有皇帝评分、战役档位、人物好坏结论、成本档位或希望得到的结论。这些内容会污染中性抽取。

### 3.2 网页端必须完成的阅读动作

在写总结前，模型必须：

1. 从首锚点读到末锚点，确认卷首和卷尾都已覆盖；
2. 按时间顺序建立事件索引，不能只摘著名人物或大战；
3. 对每个武装、财政民生、工程、政治秩序的实质行动保留事实；
4. 对每个武装行动专门寻找成本、收益和窗口线索，而非只记胜败；
5. 重新检查卷末是否有未写入索引的续战、撤军、死亡、灾害、诏令落实或结果反转；
6. 输出后做一次“锚点覆盖与遗漏敏感词”自检。

模型不能访问、没有读到或无法确定的内容必须写 `unknown` 或 `未载`；禁止以常识、后世结论、人物名望或别卷内容填补。

### 3.3 武装事件的强制保留字段

所有出兵、会战、围城、攻守、追击、叛乱、武装政变、边防袭击、受降、撤军、和议、军队哗变和军事征发，都必须建立一个 `WAR-*` 事件段。一个大战可以有多段，但每段须说明与前后段的关系。

每个 `WAR-*` 段必须保留：

- 时间、地点、各方政权/部众、指挥者和原文所见行动；
- 目标、直接结果、控制权或威胁状态变化；
- 己方与敌方损失分开记录，绝不把敌军损失改写成己方成本；
- 人员线索：死、伤、俘、掳、逃散、流亡、降附及原文数字/比例；
- 动员线索：兵额、征兵、民夫、役期、转输、驻屯、逃役、反复征发；
- 军资线索：粮、钱、帛、马、舟、军械、府库、城堡、辎重和缴获；
- 地区生产线索：焚掠、屠杀、迁徙、失耕、荒废、城邑破坏、道路/漕运受阻、税源和行政失序；
- 安全/回报线索：威胁消除或恶化、边界/城池/要地控制、俘获军资、稳定或失去盟友；
- 当时在位者、继承人或政权转换线索；只记录事实，不作人物归责；
- 原文锚点、逐字短引和不确定性。

这些是“线索字段”，不是 P/S/M/A、SB、WR、D 或人物分数。数字不全时保留原句和未知项，不得自行补估。

### 3.4 非战役内容也要保留

通读总结还必须登记与后续评分有关的非战役事实：

- 财政民生：赋役、钱粮、仓储、物价、灾荒、赈济、迁徙、生产和交通；
- 工程：决策、征发、施工、完工、运行、维修、废弃、受益与损害；
- 政治秩序：实际权力转移、危机决策、政变、废立、官员任免后已经发生的可观察结果。

纯官职名单、礼仪、泛泛史论和未实施建议不独立成事件；但若它们直接引出军事、财政、工程或权力变化，应作为该事件的上下文锚点保留。

## 四、唯一输出格式：逐卷可消费总结

网页端输出必须是一份 Markdown，不要同时维护自由叙事、JSON、表格三套相互独立的事实。文件名为：

```text
volume-<三位卷号>.source-summary.md
```

模板如下。方括号字段必须填写；确实无内容时写 `无` 或 `unknown`，不得删除字段。

```markdown
# <史书> 卷<卷号>原文通读总结

## 0. 原文身份与覆盖回执

- source_unit_id: [例如 SRC-ZZTJ-263-1503001]
- source_url: [URL]
- revision_ref: [固定修订]
- raw_sha256: [manifest 中的值]
- read_range: [首锚点] 至 [末锚点]
- paragraph_count: [原文段数]
- complete_linear_read: [yes/no]
- previous_boundary_consumed: [无，或前卷未闭合事件 ID]
- next_boundary: [无，或本卷未闭合事件 ID + 最后锚点 + 未决问题]
- extraction_limits: [访问、缺页、文本损坏等；无则写无]

## 1. 时间顺序总索引

| 顺序 | 时间 | 事件 ID | 类型 | 一句话中性事实 | 锚点 |
| --- | --- | --- | --- | --- | --- |
| 001 | [最窄可知时间] | EVT-<卷号>-001 | WAR/FISCAL/WORKS/POLITICAL/CONTEXT | [只写本卷所载] | [Pxxxx] |

## 2. 事件事实

### EVT-<卷号>-001｜[中性标题]

- 类型：[`WAR`/`FISCAL`/`WORKS`/`POLITICAL`/`CONTEXT`]
- 时间与地点：[原文可知范围；未知明确写 unknown]
- 主体与实际行动：[谁做了什么；区分名义任命与实际动作]
- 直接结果：[本卷明确所载的结果；不把后果前置]
- 影响对象：[军队、居民、地区、政权、工程或财政对象]
- 原文锚点与短引：[`SRC-...-Pxxxx`：`逐字短引`；可多条]
- 前后关系：[新开/承接 EVT-.../本卷未闭合并续至下一卷/无]
- 不确定性与未载：[逐项列明]

#### 武装行动线索（仅类型为 `WAR` 时必填）

- 参战方、目标、指挥链：[事实]
- 己方人员损害：[事实、数字/比例、短引；无明确记载则 unknown]
- 敌方人员与威胁变化：[事实；不得写入己方损害]
- 动员、服役、运输：[事实、数字/持续时间；未知]
- 军资、财政资产：[投入/损失/缴获分列；未知]
- 地区与生产体系：[城邑、耕作、道路、漕运、税源、行政控制；未知]
- 安全状态与控制权：[威胁、边界、城池、主力、盟友变化；未知]
- 当期获得物：[土地、府库、军资、人口、控制权；未知]
- 当时统治/继承/政权变化线索：[只录原文事实；未知]

## 3. 卷末连续事件与跨卷提示

| 本卷事件 ID | 状态 | 下一步只需核对什么 | 末锚点 |
| --- | --- | --- | --- |
| EVT-... | closed/open/unknown | [无，或下一卷要核对的具体结果] | [Pxxxx] |

## 4. 覆盖自检

- 首尾锚点已读：[yes/no]
- 所有含“兵、军、击、围、守、叛、降、死、杀、俘、掠、焚、徙、饥、粮、运、役、钱、帛、城、灾、赈、修、罢、立、废”的段落已复查：[yes/no；若 no 列出锚点]
- 未被纳入事件的实质行动：[无，或逐项列出原因]
- 不可核验引用或疑似误读：[无，或逐项列出]
```

短引以精确定位为目的，必须逐字出自该卷并与锚点对应；不得引二手评论、检索摘要或模型改写。锚点可多于一条，尤其是动员、损失和结果分散出现时。

## 五、网页端提示词模板

将下列文本与当卷原文、manifest 行一同发送。方括号由任务发起者填入：

```text
你是固定史料的逐卷阅读员，不是史学裁判、评分器或人物评论者。

请完整线性阅读附件/仓库文件《[史书]》卷[卷号]，其身份为：
- source_unit_id: [ID]
- revision_ref: [revision]
- raw_sha256: [sha]
- 合法段落范围: [首锚点]—[末锚点]

只使用这卷原文和给出的上一卷边界摘要。不要使用常识补全、后世知识、其他卷内容、既有战役结论或人物评价。

原文可能含有 MediaWiki 模板、链接、分类或换行标记。把它们当作版式噪音，不把它们当作史实；但必须继续阅读其相邻正文，不得跳段。

输出严格采用《编年体史料通读工作流》的“逐卷可消费总结”Markdown 模板。先读至末锚点，再写总结。

尤其不得遗漏所有武装行动的以下原文线索：己方与敌方损失、征兵民夫转输、粮饷军资、城邑/耕作/道路/漕运/税源损害、安全和控制权变化、缴获或取得物、当时统治或继承变化。它们只记事实，不定 P/S/M/A、SB、WR、D 档，不判断皇帝功过，不定战役父卡，也不推断未载数字。

每个实质行动至少给一个段落锚点和逐字短引；无法确认时写 unknown。卷末请按模板完成敏感词复查和跨卷提示。若附件不完整、锚点缺失或 revision/hash 不符，停止抽取并在“extraction_limits”中报告，不要猜测。
```

## 六、接收与拒收规则

网页端输出首先是候选材料，默认写入 `tmp/**`。只有通过接收检查后，才可由本地工具/主控将其作为共享史料摘要发布；网页端不得直接改写战役登记、父卡、评分结算、数据库或排名。

### 6.1 最小接收检查

1. 文件名、卷号、`source_unit_id`、revision 和 `raw_sha256` 与 manifest 一致；
2. `complete_linear_read=yes`，且 `read_range` 等于该卷首尾锚点；
3. 总索引中的每个 ID 唯一，事件段均能在索引找到；
4. 每个实质行动至少有一个有效本卷锚点和逐字短引；
5. 所有 `WAR` 段都含十项武装行动线索字段，未知也已明确写出；
6. 己方成本、敌方损失、缴获/回报和安全状态没有混写；
7. 跨卷事件没有被虚构结局，开放问题有下一卷可执行的核对项；
8. 没有分数、档位、人物功过、父卡 ID 或统一链结论；
9. 编码为 UTF-8 无 BOM，Markdown 标题、表格和锚点可解析。

### 6.2 触发退回重做的情形

以下任一情形，整卷退回网页端重读，不做静默修补：

- 缺首尾、`complete_linear_read=no`、源身份不符或哈希不符；
- 大战只留下胜败叙述，而人员、动员、军资、生产、安全、回报或窗口线索被省略；
- 引文不在原文、锚点不对应、使用网页摘要/二手材料；
- 用“史书未详”掩盖未读段落，或把没有读到的结局补入本卷；
- 把敌军伤亡、缴获或对敌破坏错误写成己方成本；
- 自行估算伤亡、赋予成本收益档、判断人物责任或写入正式卡；
- 索引和事件段不一致，或卷末续战、结果反转、撤军、死亡等被漏掉。

局部错别字、格式错误或一两处可定位的漏锚，可在本地标记后要求定点补写；涉及覆盖、锚点真实性或成本线索遗漏，一律整卷重做。不得为了吞吐率接受“能读但不可消费”的总结。

## 七、后置合并的明确边界

通读总结可以为后续工作提供线索，但以下判断只能在原文、相邻卷和共享登记共同复核后作出：

- 多卷/多阶段事实是否属于同一个战争父卡；
- 实际归责主体与皇帝在位窗口如何分账；
- 统一、创业和兼并链是否排除；
- 伤亡、动员、资产、生产破坏的 P/S/M/A 取档及推断；
- 安全收益 SB、战争回报 WR、成本 WC 和 D 项；
- A/B/C/D 各项档位、人物分数、跨朝比较与总排名。

这条边界防止网页端摘要以“已经裁决”的形式冻结错误结论；也防止本地阶段因为缺原文锚点而把摘要常识化。

## 八、批量运行与质量抽检

### 8.1 批量节奏

- 发起者按卷顺序创建任务；同一史书可以并发阅读不相邻的卷，但相邻卷的边界摘要必须在前卷输出后补齐。
- 每完成 5 卷，随机抽取至少 1 卷，以及全部含高强度战争/大规模征发的卷，回原文检查覆盖和锚点。
- 抽检发现成本或窗口线索系统性遗漏时，停止后续 intake，修订提示词并重做受影响批次；不得只修被抽到的几卷。
- 已验收的原文和总结不会因后续计分需要而重新“通读”；后置任务只做锚点定点回源。

### 8.2 可量化质量记录

每卷接收记录至少保存：原文字符数、段落数、事件数、`WAR` 数、含明确人员/动员/军资/生产/安全/回报线索的 `WAR` 段数、未知数、无效锚点数、退回次数和下一卷边界状态。该记录只用于审计与改进，不是分数或史实。

不要以“事件数多”“四域齐全”或“模型说已读完”作为通过理由。关键指标是：每一条后来需要裁决的成本、收益或窗口事实，都能从总结回到原卷的一个确定锚点。

## 九、迁移规则

本文件取代旧的“模型直接构建 canonical 四域事实并发布共享史料”的流程。既有通读产物不因本文件自动失效，但在用于新的战役、成本收益或窗口裁决前，必须检查是否具备本流程要求的原文身份、段落锚点和武装行动线索。

不具备者只能当作检索线索；需要时按本流程重做相应卷，不能把旧摘要补几句后宣称完成。现有正式评分、共享战役登记和已经验收的秦至唐结算不因本文档变更自动重算。

## 十、禁止做法

- 上传 SQLite 后要求网页端自行查询表、过滤卷号或解释二进制内容；
- 把多卷原文、总结、卡片和评分表混成一个上下文，要求“一次讲清”；
