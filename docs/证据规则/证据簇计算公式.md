# 证据簇计算公式

## 定位

本文是跨子项的证据簇计算公式总表。它只规定已回源对象材料如何从 `obj_srcs` 聚合为规则级证据簇，不替代评分标准、不直接生成最终档位、不改写原始对象池。

后续所有子项的通用证据簇规则和公式入口进入本文。单个子项的 `rule_code` 材料公式写回对应 `docs/分项规则/` 文档；本文只保存通用聚合公式、落表流程和子项公式索引。

## 数据入口

证据簇的主参考表是 `obj_srcs`。每条 `obj_srcs` 代表一个已回源对象在某个子项规则下的一条材料。

标准分组键为：

```text
cluster_key = emp_objs.emp_id + obj_srcs.item_id + obj_srcs.rule_id
```

计算时至少联表：

```text
obj_srcs.emp_obj_id -> emp_objs.id
obj_srcs.obj_id -> raw_objs.id
obj_srcs.doc_id -> src_docs.id
obj_srcs.item_id -> eval_items.id
obj_srcs.rule_id -> eval_rules.id
```

按需联表：

```text
obj_attrs.obj_id -> raw_objs.id
obj_attrs.doc_id -> src_docs.id
obj_attrs.obj_src_id -> obj_srcs.id
```

执行边界：

- `raw_objs` 保持原始对象粒度，不做房杜合并、功臣群合并或价值预加工。
- 同一 `raw_obj` 可以在不同皇帝、不同规则、不同方向下形成多条材料。
- `emp_objs` 只表示某皇帝某子项下存在这个对象，不表示该对象被某个 `rule_id` 独占。
- `obj_srcs` 是对象在规则下的材料边；同一 `emp_obj_id` 可以、也应当在多个 `rule_id` 下重复出现，只要每条材料说明的是不同计入理由。
- 不得把单人的对象池按 rule 瓜分成互斥小池。复合型对象，例如同时体现发现、任用、授权、团队和容人的人物，应按回源材料拆成多条 `obj_srcs`。
- 同一对象跨规则重复不是重复入池；同一规则内的重复材料才交给“同对象去重”处理。后续若做子项总分聚合，再处理跨规则同对象带来的相关性或重复贡献。
- 没有 `obj_srcs` 的对象不得进入证据簇计算。
- 某皇帝某规则没有材料时，不生成该规则证据簇；只能在审计或缺口报告中标记 `no_material`。
- `obj_srcs.direction` 是材料方向的初判；结果敏感型公式可以把“存在授权”重算为负向错授。
- 可复用属性事实进入 `obj_attrs`，例如人才质量、税率、粮价、人口增长率；公式只把属性事实映射为计算参数，不在计算时临时拍脑袋。
- 当某个 `rule_code` 需要属性事实时，应在相关 `obj_srcs` 入库时尽量补齐；计算证据簇前必须检查必要属性，缺失时先补属性再计算。

## 证据簇落表流程

证据簇计算从已回源对象材料开始，到 `evd_clusters` 结束。它不直接生成子项分值、正式档位或排名。

标准流程：

1. 选定 `emp_id + item_id + rule_id` 作为一个 `cluster_key`。
2. 从 `obj_srcs` 读取该 `cluster_key` 下的全部已回源材料，并联出 `raw_objs`、`src_docs`、`eval_rules` 和必要的 `obj_attrs`。
3. 按 `obj_srcs.direction` 或规则专用口径拆成正负两侧；同一材料若同时有正负含义，必须拆开说明，不能只写成 `mixed` 后跳过。
4. 对每条材料计算 `material_score`。材料分数只表达该材料在本 `rule_id` 下的贡献，不代表对象本身价值。
5. 对同一 `obj_id`、同一方向的多条材料执行同对象去重，得到 `object_side_score`。
6. 对同一方向的多个对象执行跨对象聚合和覆盖系数调整，得到 `positive_signal` 与 `negative_signal`。
7. 由数据库生成 `net_signal = positive_signal - negative_signal` 与 `signal_intensity = max(positive_signal, negative_signal)`。
8. 按 `net_signal` 的符号写入 `cluster_direction`：正为 `positive`，负为 `negative`，零为 `mixed`。
9. 使用稳定的 `formula_code` 写入 `evd_clusters`，同一 `emp_id + item_id + rule_id` 只保留当前版本结果。
10. 将本次计算输入、主要参数、材料 id、`factor_refs` 和公式版本写入 `evd_cluster_calc_details`；该表是复算、筛选和审查的当前明细源，不再用 JSONL 日志承载计算过程。

缺口处理：

- 某个 `cluster_key` 没有可计入材料时，不生成 `evd_clusters` 记录。
- 子项正式定分若需要扫描固定 `rule_code` 集合，应把缺失簇视为 `positive_signal = 0`、`negative_signal = 0`，并在 `emp_item_result_calc_details` 或缺口报告中记录 `no_material`。
- 缺失必要属性时，不得临时拍脑袋补参数；应先补 `obj_attrs`，再重新计算证据簇。

版本处理：

- `formula_code` 标识“对象材料聚合为原始信号”的公式版本，例如 `evidence_cluster_signal_v1`。
- 若修改单条材料因子、同对象去重、覆盖系数或正负拆分口径，应提升证据簇公式版本并重算受影响簇。
- 若只修改子项定分响应函数或档位映射，不应回写 `evd_clusters` 信号；应提升对应子项的 `item_result_formula_*` 版本。

## 通用计算层

### 全局信号顺序

所有证据簇公式统一遵守“先算材料、再按对象去重、再跨对象聚合、最后正负分列入簇”的顺序。证据簇层不再把结果映射到 `[-4, +4]` 或“弱/中/强/极强”旧档位；它只保存某个 `rule_id` 下正负两侧的原始聚合信号。

```text
positive_signal = aggregate_positive_without_cluster_cap(...)
negative_signal = aggregate_negative_without_cluster_cap(...)

net_signal = positive_signal - negative_signal
signal_intensity = max(positive_signal, negative_signal)
```

这里的 `without_cluster_cap` 指不按证据簇上限提前截断；单条材料和同对象去重仍保留各自硬边界。若某个规则需要特殊折算，折算只能发生在单条材料、同对象去重或侧向聚合输入层。边际递减、正式分值、档位和负向加罚由后续子项定分公式处理，不在 `evd_clusters` 层提前压缩后再膨胀。

### 单条材料

非结果敏感型规则默认使用：

```text
material_score =
  direction_sign
  * core_value
  * object_weight
  * directness_factor
  * attribution_factor
  * source_factor
  * context_factor
```

其中：

| 字段 | 取值口径 |
| --- | --- |
| `direction_sign` | `positive = +1`，`negative = -1`，`neutral = 0`；`mixed` 应拆成正负两侧，或由规则专用 signed 公式直接给出正负。 |
| `core_value` | 规则专用核心强度，由下文各 `rule_code` 公式给出。 |
| `object_weight` | 普通对象 `0.6`，重要对象 `1.0`，关键对象 `1.3`，顶级人物、顶级团队或结构型机制 `1.6`。 |
| `directness_factor` | 边界材料 `0.5`，直接但单线 `0.8`，直接命中 `1.0`，核心结构材料 `1.2`。 |
| `attribution_factor` | 归因弥散 `0.6`，经荐举或制度链条间接归因 `0.8`，皇帝决策链清楚 `1.0`，皇帝亲自判断且逆阻力成立 `1.2`。 |
| `source_factor` | 低可信但保留 `0.5`，单一标准史源 `0.8`，标准史源且事件链清楚 `1.0`，多源可互证 `1.15`。 |
| `context_factor` | 关键上下文缺失且事实链很弱 `0.5`，上下文削弱 `0.8`，中性 `1.0`，上下文增强 `1.2`。该因子只评价当前 rule 的材料完整度，不承担跨项或跨 rule 路由。 |

单条材料硬边界为 `[-4.0, +4.0]`。达到或超过 `|3.5|` 的材料保留为极强单条材料并直接进入计算；但必须能从 `obj_srcs.note` 或后续计算说明中看出对象层级、相邻项切分和主要因子。

### 同对象去重

同一 `cluster_key` 下，同一 `obj_id` 同方向多条材料不得按条数线性叠加。

```text
object_side_score =
  strongest_abs_material
  + 0.35 * sum(other_abs_materials)

object_side_score = min(object_side_score, strongest_abs_material * 1.5, 4.0)
```

同一对象同时存在正负材料时，正负两侧分别计算，不先抵消。

### 跨对象聚合

同一方向的对象分数用平方和开方聚合，避免普通材料靠数量堆高，同时允许多个独立核心对象共同增强。

```text
side_signal = sqrt(sum(object_side_score_i ^ 2)) * coverage_factor
```

`side_signal` 写入 `evd_clusters.positive_signal` 或 `evd_clusters.negative_signal`。它是不封顶的原始信号，不直接等于正式证据强度。材料密度过高造成的通胀风险，交给子项定分公式中的响应函数处理。

通用覆盖系数：

```text
coverage_factor =
  min(1.30, 1 + 0.06 * (independent_object_count - 1)
            + 0.08 * (dimension_count - 1))
```

`independent_object_count` 只计算相互独立的对象。`dimension_count` 只计算规则内真实不同维度，不能把同一材料的同义表述拆成多个维度。

### 净信号与冲突信号

证据簇必须同时计算正负两侧：

```text
positive_signal = aggregate(positive object scores)
negative_signal = aggregate(negative object scores)
```

证据簇对后续公式输出两个信号：

```text
net_signal = positive_signal - negative_signal
signal_intensity = max(positive_signal, negative_signal)
```

其中：

- `positive_signal` 和 `negative_signal` 是正负两侧原始聚合信号，直接写入 `evd_clusters`，不封顶。
- `net_signal` 是原始信号差值，不做 `[-4, +4]` 限幅；后续公式不得把它直接当作正式得分。
- `signal_intensity` 是较强侧原始信号，用于识别材料厚度、强冲突或强单侧证据，不直接代表净效果。

方向由 `net_signal` 的符号决定：

```text
if positive_signal == 0 and negative_signal == 0:
    no_cluster
elif net_signal > 0:
    cluster_direction = positive
elif net_signal < 0:
    cluster_direction = negative
else:
    cluster_direction = mixed
```

`mixed` 表示净信号为 `0`；若 `signal_intensity` 仍然较高，说明正负两侧同强冲突，后续公式不得把它当作无材料。

### 信号解释

`positive_signal`、`negative_signal`、`net_signal` 和 `signal_intensity` 都不是最终分值或正式档位。它们只表达某个规则下已回源对象材料的聚合规模、方向和冲突程度。

信号解释只保留相对含义：

- `0` 表示该侧没有可计入材料。
- 同一公式版本下，数值越高表示该侧材料越厚、对象越强或维度覆盖越充分。
- 正负两侧都高时表示强冲突，不得先净掉后当作普通弱证。
- 跨子项、跨规则比较前，必须先看对应子项定分公式的响应函数和权重。

正式档位、正式分值和排名不得由本文公式直接写入；本文只产出规则级 `positive_signal`、`negative_signal`、`net_signal` 和 `signal_intensity`。

## 追加新子项公式

新增子项证据簇公式时，按以下顺序维护：

1. 先在规则原始表中确认 `eval_items.item_code` 和 `eval_rules.rule_code`。
2. 在对应分项规则文档中维护每条 `rule_code` 的材料公式，不在本文展开子项全集。
3. 在本文“子项公式索引”增加入口，指向该分项规则文档的证据簇公式与定分公式位置。
4. 明确哪些因子可为负，哪些只做倍率，哪些会触发信号边界或相邻项切分。
5. 明确相邻项结果能否作为反馈信号，以及必须排除哪些直接计入内容。
6. 公式变更必须更新对应分项规则文档和本文索引，不得只写在脚本、PR 说明或单个人物报告里。

公式层只负责已确认对象材料和计算明细到 `evd_clusters` 的聚合。I5B 当前从 `evd_cluster_calc_details.calc_detail` 重放材料因子，并通过 `rule_evidence_units` / `fact_relations` / `i5b_health_check.py` 审计规则承载对象；人物级总分、子项档位和跨子项排名应由后续定档公式另行说明。
