# 编年体史料战役通读与登记工作流（草案）

> 状态：讨论草案，尚未替代现有通读总结、战役底账或公共成果登记合同；不作为当前生成器输入。

## 一、目标与边界

本流程用于唐以后编年体史料的战争通读。目标不是逐卷写战争摘要，而是在首次通读时就形成可跨卷续接、可识别参战双方、可归责人物贡献、可进入战役成果裁决的结构化材料，减少后续重新通读和人工搬运。

本流程只负责四件事：

1. 从固定修订史料中提取战争原子事实；
2. 将原子事实续接到尚未结束的战争或战役群；
3. 在边界闭合后形成待裁决的战役候选；
4. 将宫廷政变、刺杀、小规模骚乱等非战役事项，以及明显低价值事项，尽早分流。

本流程不直接写入正式评分、人才等级或皇帝排名。战役成果等级、问题难度、人物贡献类型和负面归责仍由《公共成果登记与人物画像规则》裁决。史源定位与引文要求仍服从《史料检索与回源工作流》和《证据裁量总则》。“通读后直接登记”是指直接登记结构化事实和候选，不是把尚未闭合的跨卷战争直接定为正式 S、A 等成果。

## 二、工作对象

### 2.1 战争原子事实 `chronicle_war_fact`

原子事实是通读时最小的可核验记录，例如出兵、会师、交战、围城、解围、追击、投降、撤军、议和、主帅更换、军粮断绝或一方主力覆灭。它必须保留原文定位，不预先假定自己属于哪个最终战役群。

### 2.2 开放战役线索 `campaign_thread`

开放战役线索是跨页、跨卷续接的工作对象。它记录当前已知的目标、参战方、地域、时间、指挥链、阶段结果和仍待回答的问题，但在闭合前不得结算正式成果。

### 2.3 闭合战役候选 `closed_campaign_candidate`

当一项作战的目标和边界已经足够明确时，由开放线索闭合为战役候选。候选必须同时包含各方结果、主要人物的实际贡献与负面事实，供后续按照公共成果合同裁决父级成果、难度和人物消费。

### 2.4 身份解析记录 `identity_resolution`

身份解析记录把史料中的姓名、字、爵号、官号、旧名、即位前后称谓和政权别称，连接到时间有效的统一人物或政权标识。无法确认时保留“未知”，不得只凭同名或相近字符串合并。

## 三、开始一卷前必须取得的输入

通读者开始新卷前，应同时取得：

- 固定修订的史料正文、卷号和可复核定位方式；
- 上一卷已接受的原子事实与开放战役线索；
- 每条开放线索的“下一卷待确认问题”；
- 当前人物、政权、地名别名表及其有效时间；
- 已闭合战役候选的边界摘要，用于防止重复登记；
- 当前有效的公共成果合同，但不得用档位预期反向改写史料事实。

卷号只是阅读和恢复进度的边界，不是战役群边界。同一战争可以跨越多卷；同一卷也可以包含多个互不相干的战役群。

## 四、逐卷通读流程

### 4.1 锁定阅读范围

记录史书、卷次、固定修订、起止页或条目，以及与前后卷重叠的上下文范围。若正文不完整或定位不可复核，应停止正式提取并记录缺口。

### 4.2 按时间顺序提取原子事实

遇到军事行动即记录事实，不等待整场战争读完后凭印象总结。连续数条记载若包含不同地点、不同指挥者或不同结果，应拆成多个原子事实，再由线索层统合。

### 4.3 先解析人物、政权与阵营

每条事实保留史料原称，同时解析统一 `person_ref`、`polity_ref` 和当时所属阵营。改名、即位、降附、叛变或跨朝代效力必须按时间切分，不能把人物或政权在后来的身份反写到此前事实。

### 4.4 对参战各方分别记录目标和结果

一场战事只建立一个中性事实对象，但对胜方、负方和第三方分别记录目标、行动、结果、损失和责任。不得只因最终要消费胜方成果，就遗漏败方的战役目标、败因和负面事实。

### 4.5 路由到战役线索

每条原子事实完成以下一种路由：

- `OPEN_NEW_THREAD`：没有可合理续接的既有线索，建立新线索；
- `APPEND_EXISTING_THREAD`：目标、时空和参战主体连续，续接既有线索；
- `SPLIT_THREAD`：表面属于同一大战，但目标、指挥链或战区已经形成可独立结算的战役群；
- `MERGE_THREADS`：先前分开的线索后来证明属于同一作战目标和指挥闭环；
- `CLOSE_CAMPAIGN`：边界闭合，生成战役候选；
- `REDIRECT_NON_BATTLE`：转交政变、刺杀、宫廷冲突、单纯政治投降等其他底账；
- `BELOW_THRESHOLD`：确属武装事件，但规模和成果不足以进入公共战役登记。

不得因卷末、年末、皇帝更替或史书改称而自动关闭线索。

### 4.6 判断是否闭合

出现下列事实之一，且没有紧接着延续同一目标的行动时，可以考虑闭合：

- 既定战略目标完成或明确失败；
- 一方撤军、议和、投降或被逐出目标区域；
- 对手政权、主力集团或该战区统治结构终结；
- 作战因新的动员、目标、战区或指挥体系而转入另一阶段。

后续多年再次爆发同类冲突，不得反向取消此前已经完成的当次目标；反之，短暂停战、季节性撤军或同一动员下的换帅，也不得被误当作自然闭合。

### 4.7 卷末立即落盘和回读

每读完一卷，立即写入并回读校验：

- 本卷原子事实；
- 本卷对开放线索的新增、拆分、合并和关闭操作；
- 仍开放线索的当前摘要；
- 下一卷需要确认的问题；
- 已分流事项及其分流理由。

不得只保存一份自由文本总结，等待全书读完后再重建结构。

## 五、原子事实的最低字段

下列字段名是草案表达，不构成已冻结 Schema：

| 字段 | 要求 |
|---|---|
| `fact_id` | 稳定且不随文字润色变化的事实标识 |
| `time_range` | 已知最窄时间；不确定部分明确标注 |
| `locations` | 行动地点及其在当时的战略性质，不用跨时代固定州级换算 |
| `action_type` | 出兵、野战、围攻、守城、追击、投降、撤军等 |
| `belligerent_sides` | 参战各方及其当时所属政权 |
| `actors` | 参与人物、可确认的实际动作和指挥关系 |
| `side_results` | 各方当次结果，不只记录胜方 |
| `territorial_change` | 占领、恢复、丧失及是否形成稳定控制 |
| `force_effect` | 对主力、有生力量、指挥中枢或战争能力的影响 |
| `cost_and_constraint` | 兵力、补给、距离、地形、情报、内外夹击等问题难度事实 |
| `source_fact_ref` | 史书、固定修订、页或条目和最小充分引文 |
| `uncertainties` | 无法确认的人物、数量、因果或边界，未知保持未知 |

原子事实不得直接填入由后续裁决产生的 S、S-、D3、完整消费系数等结论。

## 六、双边与多方登记

每个参战方至少分别记录：

- `side_ref` 与当时的 `polity_ref`；
- 该方在本阶段的实际目标；
- 决策、统筹、临阵指挥、独立方面、关键执行等实际贡献；
- 胜利、失败、部分达成、胜而未克、撤退或未决；
- 获得或失去的稳定控制、敌军杀伤与自身损失；
- 换帅、违令、误判、救援不力、擅退等负面事实及证据；
- 本方结果与整个战役最终结果之间的关系。

这使同一战役候选可以同时投影出胜方正向成果、败方负面战绩和个人责任，而不需要复制出两场互相矛盾的“胜方战役”和“败方战役”。多方混战、盟军或先敌后友的情况，必须按时间有效的阵营关系拆段记录。

## 七、跨卷统合与战役群边界

### 7.1 续接的主要依据

是否续接主要看：

1. 战略目标是否连续；
2. 主要参战主体和对手是否连续；
3. 动员、战区和指挥链是否属于同一闭环；
4. 前一阶段结果是否直接构成后一阶段的前提；
5. 中断是否足以形成新的资源配置和决策问题。

名称相同、发生在同一区域或都被后世统称为某场大战，只能作为线索，不能单独决定合并。

### 7.2 应优先拆分的情形

- 持续多年、跨多个独立战区的大型战争；
- 前后阶段战略目标明显改变；
- 前任主帅交班时没有形成可消费的正向成果，后任重新组织并完成主要目标；
- 各方面军能够独立决定一块区域或一支主力的命运；
- 一段行动已经闭合，后续是新的动员和新的任务。

拆分后仍可通过上位战争线索关联，但不得把上位战争的全部体量重复赋给每个子战役群。

### 7.3 应优先合并的情形

- 同一目标下因卷次或月份被机械切开的连续作战；
- 追击、围歼、受降只是前次决战的直接完成环节；
- 同一指挥闭环内，各条记载单独看都不足以形成独立战略成果；
- 史料分别叙述敌我两方，实为同一场战役。

## 八、快速分流与人工复核

### 8.1 可快速分流的事项

下列事项可在事实和身份字段齐全后快速处理：

- 没有形成成建制作战的宫廷政变、刺杀、劫狱和局部兵变；
- 单次小规模骚扰、劫掠、捕斩或短暂据点争夺，且没有独立战略结果；
- 战争背景下的普通行军、驻防和无结果接触；
- 已被另一闭合战役候选完整包含、不能独立结算的环节。

`BELOW_THRESHOLD` 必须保存理由和来源，避免以后反复扫描；它不等于史实不重要，只表示对战役成果和武将能力评级贡献很低。

### 8.2 可形成快速候选的事项

边界完整、身份明确、双方结果清楚、无多人争功和重大负面争议的低档自足战役，可标为快速候选。快速候选仍只是后续登记输入，不在通读阶段擅自成为正式成果。

### 8.3 必须语义复核的事项

下列情形不得走快速结论：

- 可能达到 S-、S 或 S+；
- 跨卷、跨战区、多方参战或发生拆分合并；
- 结果为部分完成、胜而未克、先败后胜或胜负混合；
- 多名统帅先后接任，或身份主帅与实际关键贡献不一致；
- 涉及 D4 极端问题难度；
- 可能显著改变 elite、top 或 historic 人才边界；
- 对手强度、稳定控制或主力毁伤存在关键争议。

## 九、人物贡献与负面归责

通读阶段优先记录“做了什么”，而不是先用主帅、主将、从攻决定能消费多少。可记录的实际贡献包括但不限于：

- 制定或改变战争方案；
- 组织跨战区资源、军粮、盟军和增援；
- 独立负责一个方面并完成其战略目标；
- 临阵指挥决定性会战；
- 攻破关键据点、歼灭主力、截断退路或完成追击受降；
- 在败局中接任、重建战线并终结战局；
- 提供被采纳且直接改变战局的关键谋略。

官职、名义主帅、皇帝授权或参战名单只用于解释权责，不自动等于能力成果。普通授权而无实际军事统筹，不生成皇帝或人物的统筹成果。

负面事实同样按实际因果记录。前任主帅造成大败且交班时没有正向成果，应保留其负面责任；后任若重新组织、扭转并完成主要目标，可以形成完整的实际贡献候选。发生胜而未克时，应分别记录已经取得的敌军毁伤、区域成果和未完成目标，不能只写“胜”或只写“失败”。

## 十、建议输出

每卷通读产生下列可恢复产物：

1. 结构化原子事实文件：事实源；
2. 战役线索更新文件：记录新建、续接、拆分、合并、关闭和分流；
3. 当前开放线索快照：供下一卷直接接续；
4. 闭合战役候选文件：只包含已达到裁决条件的对象；
5. 卷级 Markdown 阅读视图：供人工快速检查，不作为反向解析的数据源。

正式实施时，结构化文件应有稳定标识、输入修订和幂等写入规则。Markdown 视图由结构化事实生成或同步校验，不允许成为另一套独立事实源。

闭合候选交给后续裁决时，至少应携带：

- 建议的父群边界及上位战争关系；
- 双方目标和结果；
- 土地、主力毁伤、政权或统治结构变化；
- 对手在当时体系中的位置；
- 问题难度事实；
- 各人物实际贡献和负面责任；
- 尚存争议及可能影响的裁决字段；
- 全部原子事实引用。

## 十一、卷级接受条件

一卷只有同时满足以下条件，才算完成通读：

- 阅读范围和固定修订明确；
- 所有军事事项均已形成原子事实或有明确排除理由；
- 每条事实均已记录参战方，不能只有胜方视角；
- 人物和政权身份已解析或显式标为未知；
- 每条事实均已路由到开放线索、闭合候选或分流结果；
- 卷末开放线索和下一卷问题已保存；
- 闭合候选没有因卷末被强行结算；
- 来源定位可以回读，结构化文件可解析且无重复稳定标识；
- 人工阅读视图与结构化数量、标识和状态一致。

验收关注语义覆盖和可恢复性，不以抽取条数、战役数量或高档成果数量作为进度指标。

## 十二、失败恢复

- 每卷接受后形成只读检查点；后续裁决失败时，不重扫已经接受的固定修订正文；
- 中断恢复从最后一个已接受卷和开放线索快照继续，只补未完成卷；
- 单条身份无法确认时保留未知并继续其他事实，不为补全官名或生平阻断整卷；
- 线索误合并或误拆分时，通过结构化路由更正，并保持原子事实标识和史源引用不变；
- 后续史料推翻早先判断时，更新当前线索和候选，不另存并行的旧业务值；历史追溯交给 Git；
- 任一恢复操作都不得把模型摘要、网页材料或后世评价替换成正式史源事实。

## 十三、试行与正式替换边界

本草案获确认后，正式实施前再完成以下工作：

1. 冻结结构化 Schema、稳定标识和线索路由枚举；
2. 选择少量连续卷试读，覆盖跨卷续接、双边结果、别名、换帅和快速分流；
3. 将闭合候选映射到现有公共成果合同，检查是否仍需人工重新通读；
4. 为身份解析、双边完整性、线索闭合和幂等恢复建立最小测试；
5. 试行通过后，才替换既有“先自由总结、后集中重建战役”的流程。

在上述工作完成前，本文件只用于讨论和试读设计，不改变当前秦至唐战役登记结果，也不启动唐以后正式登记。
