# 单皇帝主控会话工作流

> 状态：当前 shadow 工作流。目标是让任一新会话自行选择并主控一个皇帝，不依赖用户逐项调度；不开放正式数据库、正式评分、45分映射或排名。

主会话是当前皇帝链路的现场负责人，不是命令监控器。固定史源、史实与归责质量、单皇帝租约、共享写权、shadow-only 和正式写入边界属于硬约束；书目内的篇章取舍、确定性预筛、批次大小、任务数量、模型调用方式、执行顺序和 checkpoint 映射属于可调整策略。主会话必须以阶段目标为准自主选择最低返工成本的路径，不得把既有 task code、已经消耗的模型调用或监督器默认参数当成继续低效计划的理由。

## 一、启动口令与自动认领

用户只需说“按单皇帝工作流开始”或指定皇帝。新会话必须先读取：

1. 最近的 `AGENTS.md`；
2. 本工作流全文；`README.md` 只定向读取当前命令、运行边界和受影响模块，不要求为了启动通读无关章节；
3. `config/project.yml` 中当前皇帝配置；
4. `docs/证据规则/公共成果登记与人物画像规则.md`；
5. 当前工作树状态和目标皇帝 canonical 输入。

### 首次启动合同

“可认领皇帝”不等于“已经有上一轮产物”，也不等于已经写入公共配置。固定 release 只提供通用规则、Schema 和会话控制代码。用户显式指定尚未登记的皇帝时，入口仍须先原子领取皇帝名和全局模型槽位，复制隔离 workspace，并以 `bootstrap_required` 返回机器可读缺口；不得以“皇帝尚未进入当前链路”结束会话。

首次 bootstrap 在该皇帝 workspace 内依次完成身份、实际统治窗口、编年范围交集、固定 revision 索引、朝代政书 current、候选成员和最小 source pack。设施未齐时保持同一租约并进入 `bootstrap_assets_required`；补齐后通过 `emperor-session-bootstrap` 原地转为 `claimed`，不放弃会话。主会话可以直接修改 `tmp/**` 内的书目计划、筛选规则、分段、任务映射和审阅 payload，并在同一阶段重放；只有需要改变公共 Schema、跨会话共享语义、固定 release 代码或其他会话正在消费的配置时，才交集成会话一次性修复和发布。

朝代政书不是皇帝 bootstrap 的私有产物。`config/project.yml` 的 `dynasty_governance_catalog` 固定登记各时代可用政书、候选篇章组、治理域和朝代 token；它是召回目录和覆盖上限，不是“把所列史书全部下载并逐段调用模型”的命令。新会话先读取目录，再按当前阶段需要形成最小充分的篇章计划：优先复用 current，缺失治理域只补能改变该域覆盖或当前成果判断的篇章，静态目录、标题和全文关键词筛选必须在模型前确定性完成。最小充分只缩减无关文本和重复调用，不得预选正面成果或删去实施失败、代价、反复、废止等负面中性事实。首次 current 可以明确记录当前已覆盖时期、篇章和治理域，后续皇帝只增量扩展；不得为了声称“全朝完整”而预先全量抽取与当前阶段无关的全书。

领域标签命中不等于史源覆盖。若目录声明 `quality_requires_catalog_source_families`，current 必须保存并匹配当前目录指纹，且实际来源必须包含目录指定的专题篇章；不得用皇帝本纪中零散出现的官制、税赋、刑法或军制事项冒充《职官志》《食货志》《刑法志》《兵志》已经覆盖。某皇帝的治理成果审阅若得到零条负向结果，主会话必须先读回专题篇章中的失败、反复、废止、强制负担和制度性代价候选及其逐条处置，再判断确无可登记负向；不能把“没有扫描到”写成“没有负向成果”。

若固定 revision 索引缺页，会话只向中央 Source Cache 的 `requests/` 提交经篇章计划确认、去重后的 work/page 需求并保持原租约等待，禁止自行访问 Wikisource、CText 或其他公网载体。中央服务按 `config/workflow-source-cache.yml` 低速补齐并原子发布 LocalSourceTextIndex；载体确实缺页与限流冷却必须分别报告，不得无限重试。索引就绪后，当前会话再通过 `emperor-session-dynasty-governance` 用租约实际持有的模型槽位完成首次抽取或增量重建。产物只写朝代级共享根，不得写入、复制或改名保存到某个皇帝 workspace。另一皇帝命中相同目录指纹、来源 identity 和覆盖需求的 current 时必须零模型复用；只缺新增篇章时不得重抽已经验收的来源事实。

首次认领不得要求目标皇帝预先存在 `neutral-materials.json`、`result.json`、`result.md` 或窗口 binding；这些都是会话运行后才生成的派生值。公共成果总登记会读取所有已配置皇帝的 source pack，因此隔离 workspace 必须复制其他皇帝 source pack 作为只读输入，但不得复制或合并其他皇帝的派生 neutral/result。

新会话开始时必须先执行：

```text
git -c core.quotepath=false status --short
codex-win run -- python v4.py emperor-session-status --state-root <runtime状态根>
```

若状态显示 `running` 而对应进程已经消失，先确认进程确实停止，再精确 `abandon` 该 `session_id`。不得在遗留租约上直接启动第二个进程，也不得删除锁文件。

用户指定皇帝时只尝试该皇帝：已配置者按当前合同认领，未配置者认领隔离 bootstrap。未指定时仍只从当前已配置皇帝中自动选择，不凭空猜测目标。两个未登记皇帝只要名称不同即可并行 bootstrap；全局4槽位和共享编年 token 写锁仍照常生效。

新皇帝进入配置前，必须先按其实际统治窗口确定拟扫描的固定 revision 编年史书与连续页范围，再同 `neutral_material_reuse.shared_chronicle_materials` 的全部范围做交集检查。不得仅因新皇帝在前任末卷出现、出生、受封或被立储，就把前任的整段创业或统治 token 纳入新皇帝扫描范围。若交界卷中属于新皇帝的少量事实已经进入无窗口公共成果或共享人物画像，且可由本朝正史本纪、本传定向补齐皇帝归责，新皇帝主干应从下一完整编年卷开始，并在 source inventory 中列明交界卷的复用与回源处置。

书目扫描窗口按皇帝类型确定，而不是一律从登基开始：政权奠基人从其可核验的创业起点连续扫描到驾崩；非奠基皇帝从登基连续扫描到驾崩。创业起点由本会话依据首次形成独立政治、军事或政权组织行动的固定史源确定，不得机械扩大到出生、早年仕宦或尚未独立的从属经历。这里扩展的是中性史料扫描范围，不得把登基前事实自动标成“皇帝在位”；实际统治窗口、创业期主体身份和皇帝窗口归责仍分别保存并在投影阶段裁决。

史源层级按时代体量分流：

- 明、清实录体量过大，不得作为单皇帝连续中性主干整套扫描。皇帝主干只选择官修正史中对应皇帝本纪；本纪已经是当前链路的最高等级官方史源，默认不再回源实录，也不得以“对应皇帝实录”为页面需求、整书预热或第二条连续主干。臣子全生涯画像仍按候选名单定向扫描官修正史相关列传，例如从《明史》相关列传补齐徐达、常遇春、李善长等人物材料；列传不得扩成全书扫描。
- 宋及以前优先使用《资治通鉴》连续主干，再对事件签名定向回源本朝官修正史；不把正史全书作为第二条连续主干重扫。
- 目标朝代不存在《资治通鉴》覆盖且官修正史本纪不足以形成连续主干时，由皇帝会话选择一套体量可控的权威编年史，并在 source inventory 说明替代依据；不得因此默认升级为整朝实录扫描。

具体朝代的默认主干、事件回源书和臣子列传书固定登记在 `config/i5b-source-search-scope.yml` 的 `neutral_material_strategy`。新皇帝 bootstrap 必须先按皇帝所属朝代读取该表，不得每个会话重新设计书目。只有固定史源实际缺页、目标政权不在默认史书覆盖内或用户明确改变口径时，才允许在 source inventory 写明理由后采用替代书目。典型路由为：

- 嬴政：`资治通鉴`主干，`史记`事件回源及人物列传；
- 赵匡胤：创业期接续`资治通鉴`，建隆以后使用`续资治通鉴长编`，再以`宋史`回源及补人物列传；
- 朱元璋：《明史·太祖本纪》主干，人物使用《明史》列传，不默认扫描《明太祖实录》；
- 玄烨：《清史稿·圣祖本纪》主干，人物使用《清史稿》列传，不默认扫描《清圣祖实录》。

割据政权按同一配置中的 `fragmented_regime_routes` 处理，不要求臣子必须拥有一篇独立列传。人物材料按“本政权官修列传 → 后继或对手正史中的载记、世家、国传 → 本政权编年或专史按人名聚合”三级回退；每条事实仍须保存固定 revision、页段和 lineage，不得用网页人物传记代替。十六国优先《晋书·载记》及《十六国春秋》，十国优先《十国春秋》，西夏允许从《宋史》《辽史》《金史》《西夏书事》分散聚合，西辽从《辽史》《元史》《契丹国志》聚合，南明从《明史》《小腆纪年》《南疆绎史》《海东逸史》聚合。找不到独立列传只降低人物覆盖置信度，不得迫使会话全书扫描或凭空扩写人物事实。

书目、起止卷和候选臣子列传页仍由皇帝会话在 bootstrap 中确定，但必须服从朝代默认主干和每皇帝连续页上限；明清实录名称不得出现在 `neutral_scan_backbone_works`。公网抓取、固定 revision 缓存和索引建立统一由中央 Source Cache 承担。会话发现缺口时保持同一租约，写入 `workflow-source-cache-request-v1` 后读取对应 collection 的 `CURRENT.json` 等待，不得自己充当下载器。Source Cache 先复用所有既有 LocalSourceTextIndex，只补明确列出的页面；只有书名而没有页面需求时只允许缓存目录，不得下载整书正文。索引只增加未被既有治理 current 消费的页面时，必须按 current 已记录的实际来源页逐页重验证并零模型迁移，禁止因全库 index identity 改变而重扫已验收治理材料。

政书索引与皇帝编年索引是两份独立的固定史源身份，不要求合并为同一个 SQLite 或具有同一个 index identity。朝代 current 必须保存它实际消费的政书索引 identity、逐页 revision、引文和目录指纹；皇帝链保存并引用这个 identity，但不得拿自己的编年索引 identity 覆盖它。政书目录新增篇章时，只对该朝代 current 做增量抽取和质量验收，不得使已经验收的皇帝编年阶段失效。

实际统治窗口仍存在连续重叠页时，必须把新皇帝加入已有 token 的 `subjects` 并只在皇帝配置中引用该 token；不得另建 token，也不得保留皇帝级重叠范围。不存在实际窗口重叠时才允许使用皇帝级独占范围；后来出现第二个实际窗口重叠皇帝时，应把该范围提升为中央共享 token。这个检查适用于所有朝代和史书，不以人物名字是否在页面出现为判断标准。

运行时状态根按以下顺序解析：当前任务显式参数、已有服务环境、服务器标准状态根、由当前 LocalSourceTextIndex 所在 `runtime/active/source_text_indexes` 反推同级 `services/emperor-v4`。会话控制入口自行使用其下的 `session-control/`；候选不唯一或目录身份不匹配时失败关闭，不能把机器路径写回项目配置。

认领只能通过 `emperor-session-claim`，不得手工创建或删除租约。入口原子领取皇帝、全局模型槽位和共享编年 token 写权，并复制干净固定 release 的当前配置与皇帝 canonical 到隔离 workspace。默认领取2个模型槽位；同一 `session_id` 重放只返回当前租约。租约只保存皇帝、会话标识、release SHA、输入指纹、开始时间、当前阶段和当前资源，不保留历史日志。

未登记皇帝认领后，主会话在 `tmp/**` 编写 `emperor-session-bootstrap-v1` 规格，包含皇帝身份与别名、朝代、统治窗口、候选成员及其身份、独占编年范围或已登记共享 token、按上述时代分流确定的可选定向回源书目和治理 token。独占编年还必须提供 `neutral_scan_ruler_heading_terms`，列出该史书用于切换当前皇帝窗口的年号、庙号或帝号词；入口可从已核验的本朝 period terms 归一生成，但代码不得内置具体朝代或年号。提交规格只写隔离 workspace 与 runtime；固定索引或治理 current 缺失时返回缺项并保持租约，同时生成中央缓存需求而不是在会话内下载：

```text
codex-win run -- python v4.py emperor-session-bootstrap --state-root <runtime状态根> --session-id <会话ID> --spec <tmp规格.json> --source-index-root <索引根> --dynasty-governance-root <政书current根>
```

同一规格重放只重新核验缺失资产；不得重复生成已经就绪的索引/current或占用新的模型槽位。

中央缓存需求采用 `workflow-source-cache-request-v1`，一个 collection 覆盖当前皇帝将同时消费的连续主干、定向回源和候选臣子列传页。需求只写逻辑史书与页面，不指定网站；会话只允许写请求文件和读取 collection `CURRENT.json`。页面下载、固定 revision、载体级退避、多载体覆盖合并、离线固定快照导入和索引发布全部由 Source Cache 服务完成。中央载体目录按逻辑史书配置有序的已批准载体：首选载体缺页或暂时失败时自动尝试下一载体，只有所有已批准载体的覆盖并集仍缺页才报告 `carrier_missing_page_titles`。会话不得自行改写网站地址、抢占公网流量或重复抓取；确需新增网站时，由集成会话一次性增加适配器或导入经 hash 校验的固定快照。

```text
codex-win run -- python v4.py workflow-source-cache-request --request <需求.json> --request-root <runtime状态根>/source-cache/requests
```

bootstrap 报告中的 `dynasty_governance_assets` 是该朝代共享资产的召回清单。主会话先从中选择当前阶段最小充分的篇章覆盖并形成政书抽取计划；`source_catalog` 所列书目或篇章组不得自动等同于模型任务清单。固定索引可以覆盖更大范围，但模型只消费确定性筛选后的相关连续材料。随后执行：

```text
codex-win run -- python v4.py emperor-session-dynasty-governance --state-root <runtime状态根> --session-id <同一会话ID> --release-root <同一干净release> --source-index-root <政书固定索引根> --dynasty-governance-root <朝代政书共享current根> --dynasty <朝代> --codex-bin <固定Codex可执行文件>
```

命令按朝代 token 取得独占锁，只使用本租约的模型槽位。缺少当前计划明确需要的书页时返回 `awaiting_governance_source_assets`，模型调用为零；不得因为目录中存在尚未消费的候选篇章就把整个朝代判为缺资产。通过后返回 `quality_accepted`，无变化重跑返回 `reused` 且模型调用为零。随后重放 `emperor-session-bootstrap`，不得 abandon 或重新 claim。

### 模型启动前的计划审查

任何连续编年、朝代政书或多人本传在首个模型调用前，主会话必须读回一份计划摘要，至少包含：阶段目标、固定来源页数与字符数、确定性筛选前后字符数、候选片段数、预计模型调用数、租约槽位数、预计墙钟、可复用事实或片段数，以及完成后将接受什么质量检查。监督器不得在计划摘要尚未由主会话判断合理时自动 canary 或 fanout。计划摘要可以由现有 prepare/dry-run 输出，也可以由主会话用 `tmp/**` 的只读脚本从固定索引和任务清单计算；当前命令没有专门 preview 参数不构成停机理由，也不得为此新增长期状态层。

计划审查只用于识别错误执行策略，不是新的用户审批门。主会话应自行判断并继续；出现以下任一信号时原则上先重规划，而不是机械运行：

- 大量页面尚未经过目录、标题、年代、主体或治理域的确定性筛选便全部进入模型；
- 模型任务数明显高于可形成的独立事实或成果数量；
- 预计调用超过64次、预计墙钟超过60分钟，或单个阶段预计占用全局槽位超过其他会话可接受的时间；
- 每个小片段单独调用模型，而同一语义完整篇章可以一次输出多条事实；
- 无变化来源因批次指纹或 index identity 改变而准备整批重抽。

超过上述参考线不等于降低史源或覆盖目标。主会话应优先扩大语义完整批次、合并同类篇章、增加确定性预筛、复用已验证事实或调整执行顺序；只有史源结构确实不可合并且缩减会造成明确质量缺口时，才保留较大计划，并在 runtime 计划摘要中写明原因。禁止只因 canary 通过就认为整个任务计划合理。

首次 bootstrap 已进入中性阶段后，如果 source inventory 证明书目层级或起止范围选错，允许在 `failed_reusable` 状态下用同一 session 修订 bootstrap 的史源范围并重放；皇帝、朝代、统治窗口、人物身份和租约资源不得改变。修订只使 source inventory 与 neutral materials 失效，既有可按 `segment_ref` 验证的 checkpoint 继续复用，不得 abandon 后重新认领。

租约不会按时间自动抢占。异常遗留会话必须先确认原会话已停止，再使用 `emperor-session-abandon` 精确释放指定 `session_id`；禁止按 mtime 删除锁。未指定皇帝时，入口按配置顺序跳过已占用对象并认领第一个可运行皇帝。

```text
codex-win run -- python v4.py emperor-session-claim --state-root <runtime状态根> --release-root <干净release> --session-id <唯一会话ID>
```

## 二、隔离与共享

每个皇帝会话独占：

- 当前任务计划的 `task_code` 命名空间；计划重组时允许在本 session 内重新生成；
- job workspace；
- runtime、checkpoint 和临时导出；
- 皇帝候选 source-pack、neutral-materials 和 result。

只读共享：

- LocalSourceTextIndex；
- 已质量验收的朝代政书 current；
- 已质量验收且输入身份一致的共享编年中性材料；
- 固定 release 中的源码、Schema 和规则。

朝代政书共享根固定采用 `<dynasty-governance-root>/<dynasty_token>/current.json`；其 `.work/`、`.resume/` 和 `.locks/` 也只能位于该共享根。皇帝 workspace 可以保存本次 bootstrap 规格和未完成调用的阶段状态，但不得保存第二份政书事实、朝代 current 或“本皇帝专用治理材料”。政书 current 的历史由 Git 中的目录合同和 current 的固定 revision lineage 追溯，运行目录只保留当前值。

### 共享编年只抽取一次

共享编年 token 表示一份中性材料原子集，不表示“从另一个皇帝复制一份已经投影过的 neutral”。共享史书、连续页范围、主体闭包和抽取合同版本只能在 `neutral_material_reuse.shared_chronicle_materials.<token>` 定义一次；皇帝配置只允许引用 token，不得复制这些字段。中央目录合同包含：

- 史书集合与连续页范围；
- 抽取合同版本；
- 主体闭包，即 token 下全部引用皇帝的集合。

运行时有效 identity 再把中央目录合同与实际 LocalSourceTextIndex identity 合并。固定 revision 索引或抽取合同任一变化都不得命中旧 current。

例如当前《资治通鉴》184—199 共享 token 同时覆盖李渊、李世民时，扫描与结构化中性抽取只运行一次；同一批中性事实可以同时带有两人的主体引用。随后分别生成李渊视图和李世民视图，只做身份、在位窗口、责任和规则投影，不再调用编年抽取模型。页范围以 `config/project.yml` 的当前中央 token 为准，文档示例不得反向覆盖配置。

取得共享 token 写权的会话必须在同一次抽取中完成 `subjects` 全部皇帝的中性材料覆盖，而不只是当前主控皇帝。每位主体都必须至少识别出一个编年皇帝窗口，并对其窗口内以及明确点名该主体的全部可抽取片段形成 accept 或 reject 审阅；确定性无事实片段也必须登记为已处理。某位主体可以在质量审阅后得到零条合格事实，但不能没有窗口、没有处理记录或留有未决片段。

共享 current 必须保存逐主体 `subject_coverage`：主体引用、窗口片段数、可抽取片段数、已处理片段数、合格事实数和缺失片段。只有全部主体 `coverage_complete=true` 才能写入 `quality_contract_valid_shadow`。旧 current 缺少该清单、主体集合不完整、清单不能由当前 plan 与 materials 重算复现，或任一主体存在缺失片段时，只能作为待重建输入，不能声明零模型复用或供下一皇帝直接投影。

当前皇帝视图只保留两类共享编年事实：当前皇帝本人的行动，以及 `chronicle_ruler_ref` 指向当前皇帝时臣子的行动。另一皇帝在其自身窗口内的事实仍留在共享原子层，通过无窗口公共成果和全生涯人物画像复用，但不得进入当前皇帝的定向回源队列或成果模型批次。朝代政书同理：可以一次抽取全朝事实，但当前皇帝成果投射只消费纪年命中本窗口的事实。

皇帝级独占编年范围没有中央 token 的主体闭包，plan 必须保留当前 source pack 的完整成员，并为明确处在任命、出使、统兵或失败责任位置但尚未入人物目录的姓名建立仅供中性事实使用的 provisional actor；这不等于自动纳入共享人物画像或计分。带公元年份的编年标题必须按 source pack 实际窗口截断，同一标题延续到身后年份时不得继续绑定；末年出现“上崩/帝崩”后，同段后续及继任事件也必须在模型调用前排除。

以下做法一律禁止：

- 在皇帝配置中重复定义中央 token 的史书、页范围或共享主体；
- 让两个 token 或一个 token 与皇帝独占范围占有同一史书的重叠页；
- 新增皇帝时跳过中央范围交集检查，按皇帝名字重新扫描已登记页；
- 只抽取当前主控皇帝，便把共享 current 标成完整；
- 把当前皇帝团队成员加入共享 token 身份，导致换一个团队就重新抽取；
- 新增 `neutral_material_reuse_rulers` 一类“整包复制另一皇帝 neutral”的路径；
- 把另一皇帝已经绑定窗口的 disposition 当作当前皇帝的窗口判断；
- 因当前皇帝 source pack 尚不完整而覆盖或降级共享 current。

`emperor-session-claim` 必须在取得租约和任何模型调用前验证全库编年范围所有权。token 未登记、皇帝级重复定义、主体闭包不一致、跨 token 重叠或未复用 token 的重叠范围都直接失败，并指出冲突所有者、史书和交集页；不得静默生成第二份共享材料。共享 current 命中相同 identity 后，编年抽取的模型调用数必须为零。人物全生涯画像与公共成果从无窗口公共层复用，不能靠合并另一皇帝派生 neutral 来代替。

同一共享编年材料 token 只能由取得写权的会话生成；写权在该会话重建完成后释放。其他会话认领失败即等待，不得绕过入口并发覆盖。运行会话不得在其他会话同时消费时直接修改公共源码、配置或规则，但这不限制主会话调整本 session 的 `tmp/**` 计划、确定性筛选、批次、checkpoint 映射和审阅输入。发现普通效率问题或任务内可验证错误时，主会话直接在当前阶段改道并继续；只有必须改变公共合同或共享实现时才停止受影响阶段并交给集成会话修复。需要公共源码试验时使用独立 Git worktree，不能在共享脏工作树上互相覆盖。

canonical 只能通过 `emperor-session-publish` 发布。入口先校验全体臣子详情、皇帝详情、中性材料、source-pack 与 result 一致性，再比较认领时记录的目标文件 SHA；任一目标在运行期间变化即失败关闭。发布按皇帝取得独占锁并逐文件原子替换，异常时回滚本次已替换文件。成功后删除会话 workspace、runtime 和全部租约。

## 三、全局资源约束

模型并发是所有会话的合计值，不是每个会话各自的额度。当前全局固定4个槽位；两会话同时运行时默认各2。`emperor-session-run` 只能使用租约实际持有的槽位数，不接受会话自行扩大 `model_workers`。

运行时子模型只允许承担两类高吞吐、可逐字核验的草案工作：

1. 固定 revision 连续编年与朝代政书的首次中性事实抽取；
2. 多人物全生涯本传的 Assertion 草案抽取。

公共成果登记、跨书归并、战役父子层级、人物责任、皇帝窗口、人才等级、政治风险严重度、I5B 规则适用性和 Gold 冻结均由主会话直接负责。子模型不得控制这些阶段能否完成。大批量固定引文的任用授权观察可以显式请求子模型生成草案，但最终 `counted/supporting/excluded` 仍由主会话统一裁决，且失败不得阻断主链。

Codex 并行智能体只用于只读审计。推荐一个主会话加至多三路审计：史源覆盖与 lineage、业务语义与重复结算、代码测试与零写入。主会话是唯一业务编辑者、唯一 canonical 发布者；多个智能体不得同时修改同一 source pack、公共成果登记、人物档位或 Gold。

单批进程执行以下防回归顺序：

1. 先由主会话通过上述计划审查，再验证 repository schema 与 transport schema；禁止把 `allOf`、条件分支或非 required object properties 直接交给不支持的结构化传输层。
2. 计划合理后完成一个 canary，再并发 fanout；canary 只验证单任务合同和传输，不证明任务数量、分段或总成本合理。
3. 同类可比成功样本至少3个后才能启用自适应耗时基线；阈值取“中位数两倍”和45秒绝对下限中的较大者，仍受120秒单批硬超时约束。
4. 中性抽取的传输或超时异常先保留已完成的可验证事实与片段。主会话可以扩大、缩小、合并或重组后续批次，只恢复仍需处理的材料；task code 和原批次边界不是业务事实，也不是必须维持的恢复合同。内容或 Schema 校验失败只对失败事实或片段做严格引文修订，仍失败才停止当前阶段。不得把模型合同失败伪装成“无事实”，也不得在单批内部递归拆分重复抽卡。成果子模型草案不是默认路径；显式启用时只运行一次，失败立即交主会话。
5. 确定性目录筛选、事件切分、固定 revision 定位、已登记成果查重和窗口排除不得交给模型，以免结构化模型吞吐成为全链硬墙。
6. 模型拒绝片段必须经过确定性高价值信号复核。命令出使、请兵、任命、将兵、便宜从事、溃败、失亡略尽、弃州弃城和城陷等片段不得仅凭 `reject` 计作已覆盖；入口写出 `neutral-reject-review.json`，主会话只修正相关片段并复用其余已验证事实。若拒绝模式明显系统化，主会话先调整当前阶段的提示、分组或主体输入，禁止逐条机械补写数十个同类错误。

这些约束必须由 focused tests 覆盖，不能只写在文档或临时运行说明中。范围所有权测试必须使用任意朝代、任意人物的通用样例覆盖“新皇帝撞已有 token”和“两个 token 相互重叠”，不得只验证当前唐初配置。墙钟和预计调用数不得用于牺牲质量、删除必要史源或绕过共享材料，但必须作为计划质量信号：明显超出预估时，主会话应检查是否发生全书误扫、过细分段、重复模型调用或错误恢复，而不是只持续播报进度。

### 阶段监督与主会话自主矫正

`emperor-session-run` 是单一监督入口，但不得把全链视为一个不可分割批次。运行必须依次通过以下质量阶段：

1. `source_inventory`：固定索引、史书范围和召回清单；
2. `neutral_materials`：共享主体闭包、按时代策略选择的可选定向回源和朝代政书合并后的中性材料；
3. `outcome_projection`：逐事实成果处置、无窗口公共成果总登记、共享人物全生涯画像总登记及 source pack 增量；
4. `current_projection`：皇帝窗口绑定、窗口政治风险、I5B shadow 和详情自审。
5. `gold_freeze`：仅在用户通过当前结果后，冻结本皇帝完整 Gold、逐条验证固定史源并执行生成后盲比。

每个阶段完成后在 session runtime 写唯一 `current.json`，记录 `input_fingerprint`、`producer_contract_fingerprint`、质量检查、产物 hash 和零正式写入声明。只有 `quality_accepted` 才能开启下一阶段。会话租约只显示当前阶段和当前状态，不复制阶段历史。

默认单皇帝运行在中性材料验收后生成 `outcome-worklist.json` 并进入 `awaiting_review`，不调用成果子模型。进入该阶段前必须确认本朝政书 current 已覆盖当前计划要求的治理域；缺失时先增量扫描政书并抽取共享中性事实，禁止先登记成果、事后再补扫。主会话完整审查 worklist 后，在 `tmp/**` 写符合 `current-outcome-candidate-output-v3` 的审阅 payload，再用 `--outcome-review <path> --stop-after-stage outcome_projection` 确定性应用和验收。

政书 current 可以保留静态制度和行政运行背景，但成果 worklist 必须按逐字引文的 `evidence_roles` 确定性分流：同一事实链至少含 `public_result` 或 `cost_or_burden` 才进入四轴成果审阅，其余标为 `context_only`，不得把链级结果摘要复制给未标 `public_result` 的引文。普通官署运转、审核文书、官员俸禄和被裁官员失去职位不自动构成公共代价。地理志不作各朝默认全扫范围，仅在行政区划实际调整、人口迁移、交通水利、边疆设治或区域安全结果需要时定向抽取。

治理审阅按“历史基线事实 → 举措 → 实际运行 → 公共结果 → 代价或反复 → 持续性 → 人物责任”组装跨书证据链；各环节可以来自政书、本纪或列传，不要求一条引文独自证明全部合同。无人物的宏观结果必须先保留，之后再接责任事实。价值判断以举措前同一社会状态为基线，分别审生产力与民生、文明与制度进步、国家与民众安全、文化教育与思想活力四轴；皇权自身安全不计。`scale` 只表示覆盖范围，不得换算进步强度或人才档位。人物只有具备政策或制度设计、实施主导、运行交付、纠偏监督等责任事实才消费治理人才信用；文化档只消费学术创作或最终定稿责任。

入口必须在隔离 workspace 内调用公共层导出器，先按朝代 token 生成 `eval/historical_outcome_registry/<DYNASTY>/current.*` 与 `eval/historical_person_profiles/<DYNASTY>/current.*`，验证对象全局唯一且可无损合并后，再生成顶层全局 `current.*` 只读视图；两层总登记都不得含皇帝窗口、团队预算或窗口政治风险。成果 `current.md` 展示稳定 `HOUT-*` 登记号及中文业务指标，人物 `current.md` 展示稳定 `PROFILE-*` 画像号、全生涯档位、本传固定版本及人才定级排除；机器枚举只保留在 JSON，禁止主会话手工拼接审计表或展示 `OUTCOME-AUTO` 临时号。皇帝本人在位治理保留为完整生涯事实，但必须以 `ruler_own_reign_governance` 排除出本人治理人才档位。任一分区、合并视图或公共登记导出失败即成果阶段不通过。成果阶段通过后仍保持 `awaiting_review`，不得生成皇帝窗口绑定、启动 `current_projection` 或发布 canonical。用户审阅通过后，对同一会话携带同一 `--outcome-review` 去掉暂停参数重跑；入口必须复用已经验收且指纹一致的源清单、中性材料、公共成果和共享人物画像，再继续窗口政治风险与 I5B。

审阅未通过时只修改审阅 payload 或补当前成果所缺固定引文，再确定性重跑成果阶段。审阅 payload 指纹属于成果阶段输入，因此修改它只能使成果阶段失效，不得使中性材料失效。业务候选修订不得要求修改公共源码、升级 release、放弃会话或重新领取模型槽位。只有完成本阶段全字段审计后确认存在通用确定性引擎缺陷，才允许一次性修改代码、补测试并升级成果合同；禁止按“发现一个字段—升级一次 release—重新跑一次”的方式修补。

失败后的自主矫正只能使当前失败阶段失效：中性抽取只处理仍缺或需要重验的材料，旧共享 current 作为可验证 seed；成果阶段由主会话修改审阅 payload，不得自动重新生成已经审过的候选。不得因下游失败重扫已经验收的共享编年，也不得以自动矫正修改史源、事实方向、Gold 或正式评分边界。

checkpoint 的保护对象是已验证的来源定位、逐字引文、事实和裁决，不是某次执行计划本身。主会话发现当前计划明显低效时，可以在同一 session 和同一阶段停止旧 fanout、废止未完成 task code、重新组合剩余材料，并把已完成结果按稳定来源片段重新校验后复用。不得以“已经完成一部分”为理由让错误计划继续占用数小时，也不得为了保留 checkpoint 而降低阶段目标。

中性合同修复造成 subject binding 或 batch 分组改变时，恢复器必须从同一会话旧 checkpoint 按稳定 `segment_ref` 读取未信任 seed，并逐片段重新执行引文、主体归属和 Schema 校验；通过者复用，新增或变更片段才调用模型。不得因为整批指纹变化就放弃仍可验证的片段级 checkpoint。

成果审阅必须一次检查完：独立成果拆分、跨书去重、战役父子层级、战役/治理/谋略分类、夺权与清洗排除、时间与皇帝窗口、指挥及授权责任、战役等级与难度、战争成本、目标未完成、可归责失败、治理实施与持续性、共享政书逐条处置、逐字引文与 revision、settlement scope、人才 credit 和既有公共登记冲突。不得只修当前报错字段后立即重新运行。

每个达到登记门槛的战役还必须一次填写三项独立背景字段：`prewar_context` 只写开战前形势，`failure_stakes` 写失败会失去什么，`strategic_stakes` 归入 `bounded / major / critical / existential`。这些字段可以供 C1 重要性和任用责任重要度复用，但不得抬高只表示已实现结果的 `campaign_tier`。Gold 必须同时冻结这三项和完整战役成员角色，否则背景信息仍可能在后续重建中漂移。

当前皇帝窗口内由国家军队主帅或主要独立方面将领实际统领的战役不得因史书省略重复任命文字而丢失任用投射：有任命引文时登记正式授权；无任命引文但主帅责任和无阻挠状态明确时，编译器按 `major_affairs` 上限登记默示授权。每个合格战役必须先枚举全部 `commander_in_chief / principal_commander`，逐人形成 `counted / supporting / excluded` 处置，再允许成果阶段通过；普通参战者、从攻者、下级副手和盟军不得自动取得授权。每项 `delegated_responsibility` 必须绑定事件当时的实际 `authorizer_ref`；亲王时期对自有幕府的调配可以保留为人物履历，但不得倒算为其后来皇帝窗口的任用得分，共享战役在后来称帝者窗口同样不得反算。

人物本传扫描名单不得只从当前计分池、当前皇帝成果或已有规则材料反推。它属于共享人物画像构建，不属于皇帝窗口绑定后的补录。公共层导出前，主会话必须一次闭合三类候选：所有已配置皇帝窗口内有任用关系者、公共成果参与者、虽主要成果发生在另一皇帝窗口但完整生涯可能达到 `top` 或 `historic` 者。候选审阅需记录纳入者和排除理由；只有 `candidate_roster_review.status=complete` 且覆盖 `ruler_window_appointments`、`outcome_participants`、`potential_top_full_career`，共享 `profile_ref` 已唯一生成，才能进入当前皇帝投影。后续皇帝只引用同一共享画像，不得重新扫描或按本窗口成果重算档位。这一步专门防止苏定方一类“窗口内已任用、巅峰成果在后朝”的人物漏扫，也防止侯君集、高士廉等人在不同皇帝结果中出现不同全生涯画像。

未发布任务可在状态根的皇帝级 `stage-cache` 暂存已验收阶段。新 release 或新 session 只能在阶段输入指纹和生产者合同指纹同时完全一致、产物 hash 读回一致时继承；任一不一致即拒绝该阶段缓存，但不删除其他独立阶段。旧会话 `abandon` 保留该临时缓存以便修复后续跑，成功 `publish` 后必须删除该皇帝 stage-cache。共享编年 current 仍由共享 token 存储，不复制进皇帝缓存。

修改某阶段的事实语义、验收语义或输出结构时必须同步升级该阶段的 `STAGE_CONTRACTS` 版本；只修改下游阶段不得升级上游合同。批次大小、task code、模型并发数、超时、导出并发和执行顺序不是历史内容输入，主会话可以在当前阶段调整且不应使已验证事实失效；召回上限、史源、主体、规则、Schema 和模型政策变化仍必须改变相应阶段指纹。

## 四、单皇帝执行顺序

1. 先领取皇帝名和模型槽位。已配置皇帝核验 release、史料索引、朝代政书 current 和共享编年材料身份；未配置皇帝在隔离 bootstrap 中先确定身份与实际窗口、完成全库编年范围交集检查，并按 `dynasty_governance_catalog` 形成最小充分政书篇章计划、补齐该计划所需固定索引和共享 current，再原地取得所需共享写权。已有同目录指纹、固定 revision、覆盖需求和质量合同的朝代 current 直接零模型复用。
2. 解析共享 token；若存在同 identity 且逐主体覆盖清单可重算通过的共享 current，则直接读取并声明编年抽取零模型调用，否则由唯一写者扫描一次完整连续范围，同时抽取 token 主体闭包内各皇帝的中性事实；任一主体覆盖不完整不得进入下一步。
3. 从共享中性事实分别建立当前皇帝投影视图；宋及以前从当前事件签名定向回源本朝正史，明清官修正史本纪直接作为主干且默认不再回源实录；政书只消费朝代 current。任何定向回源都不得升级为第二条连续主干，不得重新扫描共享编年，也不得导入另一皇帝整包 neutral。
4. 跨书归并 HistoricalEpisode；战役先按《公共成果登记与人物画像规则》的后置用途晋升门处置，普通战事停在中性事件层，晋升项再按最多三级战争树归并并执行祖先—后代防重；治理按独立公共结果归并。
5. 先更新无皇帝窗口的 HistoricalOutcomeCluster 总登记；战役审事件层级、结果、规模、参与责任和史源，治理另审跨书证据链、四轴方向与进步强度、贡献类型。窗口不明不得删除成果。此阶段必须完成全部合格战役登记，不得查询人物当前档位后以“已经够档”提前停止；普通小战和从攻经历仍停在中性事实层。
6. 立即以全部公共成果和已完成的全生涯本传扫描更新共享人物画像总登记；人才档位、分领域档位、本传凭据和权威校准只在这里计算一次。画像同时保存全部具备定级资格的成果事实清单，当前规则命中的成果只决定档位，不得裁剪该清单。公共成果或画像任一未通过质量门，不得生成皇帝窗口绑定。
7. 两份公共总登记通过质量门后，单独生成当前皇帝窗口绑定；绑定只追加任用关系、团队选择和本窗口政治风险，不得复制或改写共享人才档位。绑定失败只阻断该皇帝后续投影。
8. 规则材料只能消费“公共成果＋共享人物画像＋皇帝窗口绑定”的显式连接结果，再计算当前分项投影；停在 PostgreSQL 写入之前。
9. 导出两份公共总登记、皇帝详情及臣子详情，执行质量审计和 focused tests，并交用户审阅当前结果。
10. 用户明确通过后才建立本皇帝 `full_ruler` Gold：先冻结固定 revision 史源和业务期望，再运行史源核验，最后执行“先内存生成、后读取 Gold”的盲比。Gold 失败时修生成链，禁止反向削弱期望；新皇帝会话不得自动改写其他已冻结皇帝 Gold。若共享公共层的确定性修复使旧 Gold 失配，应停止并交集成会话统一复核受影响皇帝。
11. Gold、focused tests 和零副作用声明全部通过后，取得发布租约并覆盖当前公共总登记、皇帝绑定、该皇帝 canonical 当前值及该皇帝 Gold；成功后删除 checkpoint、失败运行和旧导出。

认领后先运行到主会话成果登记 worklist。若前置政书或中性抽取尚无合理的模型计划摘要，主会话应先完成计划审查，不得直接长时间 fanout：

```text
codex-win run -- python v4.py emperor-session-run --state-root <runtime状态根> --session-id <会话ID> --release-root <同一干净release> --source-index-root <索引根> --dynasty-governance-root <政书current根>
```

主会话完成审阅 payload 后，确定性应用并停在用户成果审阅门：

```text
codex-win run -- python v4.py emperor-session-run --state-root <runtime状态根> --session-id <会话ID> --release-root <同一干净release> --source-index-root <索引根> --dynasty-governance-root <政书current根> --outcome-review <tmp审阅payload> --stop-after-stage outcome_projection
```

用户通过后携带同一审阅 payload 继续后续链路：

```text
codex-win run -- python v4.py emperor-session-run --state-root <runtime状态根> --session-id <会话ID> --release-root <同一干净release> --source-index-root <索引根> --dynasty-governance-root <政书current根> --outcome-review <tmp审阅payload>
codex-win run -- python v4.py emperor-session-publish --state-root <runtime状态根> --session-id <会话ID> --canonical-root <canonical仓库>
```

Gold 冻结前后的固定顺序为：

```text
codex-win run -- python v4.py historical-gold-sources-verify --manifest eval/historical_quality_gold/<皇帝>.json --source-index <固定revision索引>
codex-win run -- python v4.py historical-gold-blind-run --ruler <皇帝>
```

盲跑报告必须同时满足 `status=passed`、`result_persisted=false`、`runtime_model_call_count=0`、`database_write_count=0` 和 `formal_score_write_count=0`。只通过普通 compare 不足以声明 Gold 已封存。

只有主会话明确需要一个非阻断性的候选草案时，才允许显式运行：

```text
codex-win run -- python v4.py emperor-session-run --state-root <runtime状态根> --session-id <会话ID> --release-root <同一干净release> --source-index-root <索引根> --dynasty-governance-root <政书current根> --allow-outcome-model-draft --stop-after-stage outcome_projection
```

该模式不是默认生产路径；草案失败不得递归重试，主会话必须直接接管。

失败后保持同一 `session_id` 重跑 `emperor-session-run`。输入与事实合同匹配的 checkpoint 可以直接复用；批次或 task code 改变时，按稳定来源片段重新验证后复用其中事实，不要求维持旧计划。明确放弃整个皇帝会话才执行：

```text
codex-win run -- python v4.py emperor-session-abandon --state-root <runtime状态根> --session-id <会话ID>
```

若失败原因是通用代码或 Schema 缺陷，集成会话发布修复后的干净不可变 release 后，可以对 `failed_reusable` 租约执行受控升级；首次 bootstrap 尚停在 `bootstrap_assets_required` 时，也允许在同一 bootstrap session 内受控升级，以便采用修复后的资产或书目合同。入口必须确认皇帝租约和模型槽位仍归同一 session、canonical 输入 SHA 未变、workspace source pack 未漂移，然后只替换租约中的当前 release 身份并保留原阶段、workspace/runtime/checkpoint：

```text
codex-win run -- python v4.py emperor-session-upgrade-release --state-root <runtime状态根> --session-id <会话ID> --release-root <修复后的干净release>
```

禁止手改租约 SHA、复制 checkpoint 到新 session 或先 abandon 再重领来规避合同校验。

无变化重跑必须零模型调用、零业务写入。任何阶段出现输入指纹变化、跨会话写入冲突、共享材料写者不唯一、史源缺层或成果归并未闭合，均停止发布；只保留输入与生产者合同仍匹配的已验收阶段，当前失败阶段按最小缺口恢复。`abandon` 只释放租约和会话 workspace，不代表删除皇帝级已验收 stage-cache；成功发布才清理。

## 五、会话交付

每个会话只交付当前状态：皇帝、release SHA、输入指纹、当前阶段、阶段质量清单、史源覆盖、模型调用与异常、成果登记数量、未解决质量缺口、验证结果、canonical 是否发布。声明阶段恢复时必须读回阶段输入指纹、生产者合同指纹和产物 hash；声明共享生成或复用时必须读回 `shared_backbone_material_token`、新旧 identity、`shared_backbone_zero_model_reuse`、`shared_backbone_subject_coverage`、共享事件签名数和当前皇帝事件签名数。逐主体覆盖清单必须列出 token 全部主体且全部完成，缺少这些机器字段不得仅凭运行速度声称“已复用”。不得新增长期阶段报告、历史状态镜像或失败运行档案。

最低启动语句：

```text
按《单皇帝主控会话工作流》通过 emperor-session 入口自动认领并启动一个可运行皇帝；主会话按阶段目标自主规划、审查模型成本并在当前阶段及时改道；保持 shadow-only，不绕过全局模型槽位、共享 token 写权和 canonical CAS 发布；只有需要改变公共合同或共享实现时才停止受影响阶段并报告给集成会话。
```
