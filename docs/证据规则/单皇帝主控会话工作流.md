# 单皇帝主控会话工作流

> 状态：当前 shadow 工作流。目标是让任一新会话自行选择并主控一个皇帝，不依赖用户逐项调度；不开放正式数据库、正式评分、45分映射或排名。

## 一、启动口令与自动认领

用户只需说“按单皇帝工作流开始”或指定皇帝。新会话必须先读取：

1. 最近的 `AGENTS.md`；
2. `README.md`；
3. `config/project.yml` 中当前皇帝配置；
4. `docs/证据规则/公共成果登记与人物画像规则.md`；
5. 当前工作树状态和目标皇帝 canonical 输入。

### 首次启动合同

“可运行皇帝”不等于“已经有上一轮产物”。新皇帝首次进入链路时，release 只必须具备：

- `config/project.yml` 中完整的皇帝入口配置；
- 可校验 hash 的最小 bootstrap `source-pack.json`；
- 可用的固定 revision 史料索引；
- 对应朝代已验收的政书 current；
- 若声明共享编年 token，则该 token 已在 `neutral_material_reuse.shared_chronicle_materials` 中登记唯一共享抽取合同。

首次认领不得要求目标皇帝预先存在 `neutral-materials.json`、`result.json`、`result.md` 或窗口 binding；这些都是会话运行后才生成的派生值。公共成果总登记会读取所有已配置皇帝的 source pack，因此隔离 workspace 必须复制其他皇帝 source pack 作为只读输入，但不得复制或合并其他皇帝的派生 neutral/result。

新会话开始时必须先执行：

```text
git -c core.quotepath=false status --short
codex-win run -- python v4.py emperor-session-status --state-root <runtime状态根>
```

若状态显示 `running` 而对应进程已经消失，先确认进程确实停止，再精确 `abandon` 该 `session_id`。不得在遗留租约上直接启动第二个进程，也不得删除锁文件。

用户指定皇帝时只尝试该皇帝；未指定时，按 `config/project.yml` 中皇帝顺序选择第一个同时满足以下条件的对象：配置完整、史料索引可用、朝代政书 current 已验收、没有其他有效主控租约、尚需重建或质量复核。没有可运行对象时报告具体缺口，不自行新增皇帝配置。

用户指定的皇帝尚未配置时，不得一边运行一边临时补设施。先由集成会话一次性完成 bootstrap：确认编年范围及共享 token 归属、固定索引覆盖、本朝正史与政书 current、最小 source pack、皇帝入口配置和 canary；focused preflight 全部通过并形成干净 release 后，新的单皇帝会话才允许认领。缺任一项时应在启动阶段快速失败并列出缺口，不得进入数小时扫描后再逐层暴露配置合同问题。

新皇帝进入配置前，必须先按其实际统治窗口确定拟扫描的固定 revision 编年史书与连续页范围，再同 `neutral_material_reuse.shared_chronicle_materials` 的全部范围做交集检查。不得仅因新皇帝在前任末卷出现、出生、受封或被立储，就把前任的整段创业或统治 token 纳入新皇帝扫描范围。若交界卷中属于新皇帝的少量事实已经进入无窗口公共成果或共享人物画像，且可由本朝正史本纪、本传定向补齐皇帝归责，新皇帝主干应从下一完整编年卷开始，并在 source inventory 中列明交界卷的复用与回源处置。

实际统治窗口仍存在连续重叠页时，必须把新皇帝加入已有 token 的 `subjects` 并只在皇帝配置中引用该 token；不得另建 token，也不得保留皇帝级重叠范围。不存在实际窗口重叠时才允许使用皇帝级独占范围；后来出现第二个实际窗口重叠皇帝时，应把该范围提升为中央共享 token。这个检查适用于所有朝代和史书，不以人物名字是否在页面出现为判断标准。

运行时状态根按以下顺序解析：当前任务显式参数、已有服务环境、服务器标准状态根、由当前 LocalSourceTextIndex 所在 `runtime/active/source_text_indexes` 反推同级 `services/emperor-v4`。会话控制入口自行使用其下的 `session-control/`；候选不唯一或目录身份不匹配时失败关闭，不能把机器路径写回项目配置。

认领只能通过 `emperor-session-claim`，不得手工创建或删除租约。入口原子领取皇帝、全局模型槽位和共享编年 token 写权，并复制干净固定 release 的当前配置与皇帝 canonical 到隔离 workspace。默认领取2个模型槽位；同一 `session_id` 重放只返回当前租约。租约只保存皇帝、会话标识、release SHA、输入指纹、开始时间、当前阶段和当前资源，不保留历史日志。

租约不会按时间自动抢占。异常遗留会话必须先确认原会话已停止，再使用 `emperor-session-abandon` 精确释放指定 `session_id`；禁止按 mtime 删除锁。未指定皇帝时，入口按配置顺序跳过已占用对象并认领第一个可运行皇帝。

```text
codex-win run -- python v4.py emperor-session-claim --state-root <runtime状态根> --release-root <干净release> --session-id <唯一会话ID>
```

## 二、隔离与共享

每个皇帝会话独占：

- `task_code`；
- job workspace；
- runtime、checkpoint 和临时导出；
- 皇帝候选 source-pack、neutral-materials 和 result。

只读共享：

- LocalSourceTextIndex；
- 已质量验收的朝代政书 current；
- 已质量验收且输入身份一致的共享编年中性材料；
- 固定 release 中的源码、Schema 和规则。

### 共享编年只抽取一次

共享编年 token 表示一份中性材料原子集，不表示“从另一个皇帝复制一份已经投影过的 neutral”。共享史书、连续页范围、主体闭包和抽取合同版本只能在 `neutral_material_reuse.shared_chronicle_materials.<token>` 定义一次；皇帝配置只允许引用 token，不得复制这些字段。中央目录合同包含：

- 史书集合与连续页范围；
- 抽取合同版本；
- 主体闭包，即 token 下全部引用皇帝的集合。

运行时有效 identity 再把中央目录合同与实际 LocalSourceTextIndex identity 合并。固定 revision 索引或抽取合同任一变化都不得命中旧 current。

例如当前《资治通鉴》184—199 共享 token 同时覆盖李渊、李世民时，扫描与结构化中性抽取只运行一次；同一批中性事实可以同时带有两人的主体引用。随后分别生成李渊视图和李世民视图，只做身份、在位窗口、责任和规则投影，不再调用编年抽取模型。页范围以 `config/project.yml` 的当前中央 token 为准，文档示例不得反向覆盖配置。

取得共享 token 写权的会话必须在同一次抽取中完成 `subjects` 全部皇帝的中性材料覆盖，而不只是当前主控皇帝。每位主体都必须至少识别出一个编年皇帝窗口，并对其窗口内以及明确点名该主体的全部可抽取片段形成 accept 或 reject 审阅；确定性无事实片段也必须登记为已处理。某位主体可以在质量审阅后得到零条合格事实，但不能没有窗口、没有处理记录或留有未决片段。

共享 current 必须保存逐主体 `subject_coverage`：主体引用、窗口片段数、可抽取片段数、已处理片段数、合格事实数和缺失片段。只有全部主体 `coverage_complete=true` 才能写入 `quality_contract_valid_shadow`。旧 current 缺少该清单、主体集合不完整、清单不能由当前 plan 与 materials 重算复现，或任一主体存在缺失片段时，只能作为待重建输入，不能声明零模型复用或供下一皇帝直接投影。

当前皇帝视图只保留两类共享编年事实：当前皇帝本人的行动，以及 `chronicle_ruler_ref` 指向当前皇帝时臣子的行动。另一皇帝在其自身窗口内的事实仍留在共享原子层，通过无窗口公共成果和全生涯人物画像复用，但不得进入当前皇帝的定向回源队列或成果模型批次。朝代政书同理：可以一次抽取全朝事实，但当前皇帝成果投射只消费纪年命中本窗口的事实。

以下做法一律禁止：

- 在皇帝配置中重复定义中央 token 的史书、页范围或共享主体；
- 让两个 token 或一个 token 与皇帝独占范围占有同一史书的重叠页；
- 新增皇帝时跳过中央范围交集检查，按皇帝名字重新扫描已登记页；
- 只抽取当前主控皇帝，便把共享 current 标成完整；
- 把当前皇帝团队成员加入共享 token 身份，导致换一个团队就重新抽取；
- 新增 `neutral_material_reuse_rulers` 一类“整包复制另一皇帝 neutral”的路径；
- 把另一皇帝已经绑定窗口的 disposition 当作当前皇帝的窗口判断；
- 因当前皇帝 source pack 尚不完整而覆盖或降级共享 current。

`emperor-session-claim` 必须在取得租约和任何模型调用前验证全库编年范围所有权。token 未登记、皇帝级重复定义、主体闭包不一致、跨 token 重叠或未复用 token 的重叠范围都直接失败，并指出冲突所有者、史书和交集页；不得静默生成第二份共享材料。共享 current 命中相同 identity 后，编年抽取的模型调用数必须为零。人物全生涯画像与公共成果从无窗口公共层复用，不能靠合并另一皇帝派生 neutral 来代替。

同一共享编年材料 token 只能由取得写权的会话生成；写权在该会话重建完成后释放。其他会话认领失败即等待，不得绕过入口并发覆盖。运行会话不得修改公共源码、配置或规则；发现通用缺陷时停止受影响阶段并交给集成会话修复。需要源码试验时使用独立 Git worktree，不能在共享脏工作树上互相覆盖。

canonical 只能通过 `emperor-session-publish` 发布。入口先校验全体臣子详情、皇帝详情、中性材料、source-pack 与 result 一致性，再比较认领时记录的目标文件 SHA；任一目标在运行期间变化即失败关闭。发布按皇帝取得独占锁并逐文件原子替换，异常时回滚本次已替换文件。成功后删除会话 workspace、runtime 和全部租约。

## 三、全局资源约束

模型并发是所有会话的合计值，不是每个会话各自的额度。当前全局固定4个槽位；两会话同时运行时默认各2。`emperor-session-run` 只能使用租约实际持有的槽位数，不接受会话自行扩大 `model_workers`。

运行时子模型只允许承担两类高吞吐、可逐字核验的草案工作：

1. 固定 revision 连续编年与朝代政书的首次中性事实抽取；
2. 多人物全生涯本传的 Assertion 草案抽取。

公共成果登记、跨书归并、战役父子层级、人物责任、皇帝窗口、人才等级、政治风险严重度、I5B 规则适用性和 Gold 冻结均由主会话直接负责。子模型不得控制这些阶段能否完成。大批量固定引文的任用授权观察可以显式请求子模型生成草案，但最终 `counted/supporting/excluded` 仍由主会话统一裁决，且失败不得阻断主链。

Codex 并行智能体只用于只读审计。推荐一个主会话加至多三路审计：史源覆盖与 lineage、业务语义与重复结算、代码测试与零写入。主会话是唯一业务编辑者、唯一 canonical 发布者；多个智能体不得同时修改同一 source pack、公共成果登记、人物档位或 Gold。

单批进程执行以下固定防回归顺序：

1. 在首个模型调用前验证 repository schema 与 transport schema；禁止把 `allOf`、条件分支或非 required object properties 直接交给不支持的结构化传输层。
2. 先完成一个 canary，再并发 fanout；canary 失败不得启动整批。
3. 同类可比成功样本至少3个后才能启用自适应耗时基线；阈值取“中位数两倍”和45秒绝对下限中的较大者，仍受120秒单批硬超时约束。
4. 中性抽取的传输或超时异常先保留已完成 checkpoint，可按批准批宽最多缩小两次且只恢复未完成批次；内容或 Schema 校验失败只对失败片段允许一次严格引文定向修订，仍失败即停止当前阶段并把失败片段交主会话。不得把模型合同失败伪装成“无事实”，也不得在单批内部递归拆分重复抽卡。成果子模型草案不是默认路径；显式启用时只运行一次，失败立即交主会话。
5. 确定性事件切分、固定 revision 定位、已登记成果查重和窗口排除不得交给模型，以免结构化模型吞吐成为全链硬墙。
6. 模型拒绝片段必须经过确定性高价值信号复核。命令出使、请兵、任命、将兵、便宜从事、溃败、失亡略尽、弃州弃城和城陷等片段不得仅凭 `reject` 计作已覆盖；入口写出 `neutral-reject-review.json` 并停止中性阶段，由主会话修正该片段后复用其余 checkpoint，禁止整批重扫。

这些约束必须由 focused tests 覆盖，不能只写在文档或临时运行说明中。范围所有权测试必须使用任意朝代、任意人物的通用样例覆盖“新皇帝撞已有 token”和“两个 token 相互重叠”，不得只验证当前唐初配置。皇帝总墙钟只作观测，不作为牺牲质量、删除史源或绕过共享材料的理由。

### 阶段监督与有限自动矫正

`emperor-session-run` 是单一监督入口，但不得把全链视为一个不可分割批次。运行必须依次通过以下质量阶段：

1. `source_inventory`：固定索引、史书范围和召回清单；
2. `neutral_materials`：共享主体闭包、定向回源和朝代政书合并后的中性材料；
3. `outcome_projection`：逐事实成果处置、无窗口公共成果总登记、共享人物全生涯画像总登记及 source pack 增量；
4. `current_projection`：皇帝窗口绑定、窗口政治风险、I5B shadow 和详情自审。
5. `gold_freeze`：仅在用户通过当前结果后，冻结本皇帝完整 Gold、逐条验证固定史源并执行生成后盲比。

每个阶段完成后在 session runtime 写唯一 `current.json`，记录 `input_fingerprint`、`producer_contract_fingerprint`、质量检查、产物 hash 和零正式写入声明。只有 `quality_accepted` 才能开启下一阶段。会话租约只显示当前阶段和当前状态，不复制阶段历史。

默认单皇帝运行在中性材料验收后生成 `outcome-worklist.json` 并进入 `awaiting_review`，不调用成果子模型。主会话完整审查 worklist 后，在 `tmp/**` 写符合 `current-outcome-candidate-output-v2` 的审阅 payload，再用 `--outcome-review <path> --stop-after-stage outcome_projection` 确定性应用和验收。入口必须在隔离 workspace 内调用公共层导出器，依据全部已配置 source pack 依次生成 `eval/historical_outcome_registry/current.json`、`current.md` 和 `eval/historical_person_profiles/current.json`、`current.md`；两份总登记都不得含皇帝窗口、团队预算或窗口政治风险。成果 `current.md` 展示稳定 `HOUT-*` 登记号及中文业务指标，人物 `current.md` 展示稳定 `PROFILE-*` 画像号、全生涯档位和本传固定版本；机器枚举只保留在 JSON，禁止主会话手工拼接审计表或展示 `OUTCOME-AUTO` 临时号。任一公共登记导出失败即成果阶段不通过。成果阶段通过后仍保持 `awaiting_review`，不得生成皇帝窗口绑定、启动 `current_projection` 或发布 canonical。用户审阅通过后，对同一会话携带同一 `--outcome-review` 去掉暂停参数重跑；入口必须复用已经验收且指纹一致的源清单、中性材料、公共成果和共享人物画像，再继续窗口政治风险与 I5B。

审阅未通过时只修改审阅 payload 或补当前成果所缺固定引文，再确定性重跑成果阶段。审阅 payload 指纹属于成果阶段输入，因此修改它只能使成果阶段失效，不得使中性材料失效。业务候选修订不得要求修改公共源码、升级 release、放弃会话或重新领取模型槽位。只有完成本阶段全字段审计后确认存在通用确定性引擎缺陷，才允许一次性修改代码、补测试并升级成果合同；禁止按“发现一个字段—升级一次 release—重新跑一次”的方式修补。

失败后的自动矫正只能发生在当前阶段：中性抽取缺失片段只补缺片段，旧共享 current 只作 seed；成果阶段由主会话修改审阅 payload，不得自动重新生成已经审过的候选。不得因下游失败重扫已经验收的共享编年，也不得以自动矫正修改史源、事实方向、Gold 或正式评分边界。

成果审阅必须一次检查完：独立成果拆分、跨书去重、战役父子层级、战役/治理/谋略分类、夺权与清洗排除、时间与皇帝窗口、指挥及授权责任、战役等级与难度、战争成本、目标未完成、可归责失败、治理实施与持续性、共享政书逐条处置、逐字引文与 revision、settlement scope、人才 credit 和既有公共登记冲突。不得只修当前报错字段后立即重新运行。

每个达到登记门槛的战役还必须一次填写三项独立背景字段：`prewar_context` 只写开战前形势，`failure_stakes` 写失败会失去什么，`strategic_stakes` 归入 `bounded / major / critical / existential`。这些字段可以供 C1 重要性和任用责任重要度复用，但不得抬高只表示已实现结果的 `campaign_tier`。Gold 必须同时冻结这三项和完整战役成员角色，否则背景信息仍可能在后续重建中漂移。

当前皇帝窗口内由国家军队主帅或主要独立方面将领实际统领的战役不得因史书省略重复任命文字而丢失任用投射：有任命引文时登记正式授权；无任命引文但主帅责任和无阻挠状态明确时，编译器按 `major_affairs` 上限登记默示授权。每个合格战役必须先枚举全部 `commander_in_chief / principal_commander`，逐人形成 `counted / supporting / excluded` 处置，再允许成果阶段通过；普通参战者、从攻者、下级副手和盟军不得自动取得授权。每项 `delegated_responsibility` 必须绑定事件当时的实际 `authorizer_ref`；亲王时期对自有幕府的调配可以保留为人物履历，但不得倒算为其后来皇帝窗口的任用得分，共享战役在后来称帝者窗口同样不得反算。

人物本传扫描名单不得只从当前计分池、当前皇帝成果或已有规则材料反推。它属于共享人物画像构建，不属于皇帝窗口绑定后的补录。公共层导出前，主会话必须一次闭合三类候选：所有已配置皇帝窗口内有任用关系者、公共成果参与者、虽主要成果发生在另一皇帝窗口但完整生涯可能达到 `top` 或 `historic` 者。候选审阅需记录纳入者和排除理由；只有 `candidate_roster_review.status=complete` 且覆盖 `ruler_window_appointments`、`outcome_participants`、`potential_top_full_career`，共享 `profile_ref` 已唯一生成，才能进入当前皇帝投影。后续皇帝只引用同一共享画像，不得重新扫描或按本窗口成果重算档位。这一步专门防止苏定方一类“窗口内已任用、巅峰成果在后朝”的人物漏扫，也防止侯君集、高士廉等人在不同皇帝结果中出现不同全生涯画像。

未发布任务可在状态根的皇帝级 `stage-cache` 暂存已验收阶段。新 release 或新 session 只能在阶段输入指纹和生产者合同指纹同时完全一致、产物 hash 读回一致时继承；任一不一致即拒绝该阶段缓存，但不删除其他独立阶段。旧会话 `abandon` 保留该临时缓存以便修复后续跑，成功 `publish` 后必须删除该皇帝 stage-cache。共享编年 current 仍由共享 token 存储，不复制进皇帝缓存。

修改某阶段的生产逻辑、验收语义或输出结构时必须同步升级该阶段的 `STAGE_CONTRACTS` 版本；只修改下游阶段不得升级上游合同。模型并发数、超时和导出并发不是历史内容输入，可以在监督重试时调整且不应使已验收材料失效；召回上限、史源、主体、规则、Schema 和模型政策变化仍必须改变相应阶段指纹。

## 四、单皇帝执行顺序

1. 核验 release、史料索引、皇帝配置、朝代政书 current 和共享编年材料身份；先完成全库编年范围交集检查，再领取皇帝、模型槽位和共享写权。
2. 解析共享 token；若存在同 identity 且逐主体覆盖清单可重算通过的共享 current，则直接读取并声明编年抽取零模型调用，否则由唯一写者扫描一次完整连续范围，同时抽取 token 主体闭包内各皇帝的中性事实；任一主体覆盖不完整不得进入下一步。
3. 从共享中性事实分别建立当前皇帝投影视图，再从当前事件签名定向回源本朝正史；政书只消费朝代 current。不得重新扫描共享编年，也不得导入另一皇帝整包 neutral。
4. 跨书归并 HistoricalEpisode；战役先按《公共成果登记与人物画像规则》的后置用途晋升门处置，普通战事停在中性事件层，晋升项再按最多三级战争树归并并执行祖先—后代防重；治理按独立公共结果归并。
5. 先更新无皇帝窗口的 HistoricalOutcomeCluster 总登记；只审事件层级、结果、规模、参与责任和史源，窗口不明不得删除成果。此阶段必须完成全部合格战役登记，不得查询人物当前档位后以“已经够档”提前停止；普通小战和从攻经历仍停在中性事实层。
6. 立即以全部公共成果和已完成的全生涯本传扫描更新共享人物画像总登记；人才档位、分领域档位、本传凭据和权威校准只在这里计算一次。画像同时保存全部具备定级资格的成果事实清单，当前规则命中的成果只决定档位，不得裁剪该清单。公共成果或画像任一未通过质量门，不得生成皇帝窗口绑定。
7. 两份公共总登记通过质量门后，单独生成当前皇帝窗口绑定；绑定只追加任用关系、团队选择和本窗口政治风险，不得复制或改写共享人才档位。绑定失败只阻断该皇帝后续投影。
8. 规则材料只能消费“公共成果＋共享人物画像＋皇帝窗口绑定”的显式连接结果，再计算当前分项投影；停在 PostgreSQL 写入之前。
9. 导出两份公共总登记、皇帝详情及臣子详情，执行质量审计和 focused tests，并交用户审阅当前结果。
10. 用户明确通过后才建立本皇帝 `full_ruler` Gold：先冻结固定 revision 史源和业务期望，再运行史源核验，最后执行“先内存生成、后读取 Gold”的盲比。Gold 失败时修生成链，禁止反向削弱期望；新皇帝会话不得自动改写其他已冻结皇帝 Gold。若共享公共层的确定性修复使旧 Gold 失配，应停止并交集成会话统一复核受影响皇帝。
11. Gold、focused tests 和零副作用声明全部通过后，取得发布租约并覆盖当前公共总登记、皇帝绑定、该皇帝 canonical 当前值及该皇帝 Gold；成功后删除 checkpoint、失败运行和旧导出。

认领后先运行到主会话成果登记 worklist：

```text
codex-win run -- python v4.py emperor-session-run --state-root <runtime状态根> --session-id <会话ID> --release-root <同一干净release> --source-index-root <索引根> --dynasty-governance-root <政书current根>
```

主会话完成审阅 payload 后，确定性应用并停在用户成果审阅门：

```text
codex-win run -- python v4.py emperor-session-run --state-root <runtime状态根> --session-id <会话ID> --release-root <同一干净release> --source-index-root <索引根> --dynasty-governance-root <政书current根> --outcome-review <tmp审阅payload> --stop-after-stage outcome_projection
```

用户通过后携带同一审阅 payload 继续后续链路：

```text
codex-win run -- python v4.py emperor-session-run --state-root <runtime状态根> --session-id <会话ID> --release-root <同一干净release> --source-index-root <索引根> --dynasty-governance-root <政书current根> --outcome-review <tmp审阅payload>
codex-win run -- python v4.py emperor-session-publish --state-root <runtime状态根> --session-id <会话ID> --canonical-root <canonical仓库>
```

Gold 冻结前后的固定顺序为：

```text
codex-win run -- python v4.py historical-gold-sources-verify --manifest eval/historical_quality_gold/<皇帝>.json --source-index <固定revision索引>
codex-win run -- python v4.py historical-gold-blind-run --ruler <皇帝>
```

盲跑报告必须同时满足 `status=passed`、`result_persisted=false`、`runtime_model_call_count=0`、`database_write_count=0` 和 `formal_score_write_count=0`。只通过普通 compare 不足以声明 Gold 已封存。

只有主会话明确需要一个非阻断性的候选草案时，才允许显式运行：

```text
codex-win run -- python v4.py emperor-session-run --state-root <runtime状态根> --session-id <会话ID> --release-root <同一干净release> --source-index-root <索引根> --dynasty-governance-root <政书current根> --allow-outcome-model-draft --stop-after-stage outcome_projection
```

该模式不是默认生产路径；草案失败不得递归重试，主会话必须直接接管。

失败后保持同一 `session_id` 重跑 `emperor-session-run`，只复用输入指纹匹配的当前 checkpoint。明确放弃才执行：

```text
codex-win run -- python v4.py emperor-session-abandon --state-root <runtime状态根> --session-id <会话ID>
```

无变化重跑必须零模型调用、零业务写入。任何阶段出现输入指纹变化、跨会话写入冲突、共享材料写者不唯一、史源缺层或成果归并未闭合，均停止发布；只保留输入与生产者合同仍匹配的已验收阶段，当前失败阶段按最小缺口恢复。`abandon` 只释放租约和会话 workspace，不代表删除皇帝级已验收 stage-cache；成功发布才清理。

## 五、会话交付

每个会话只交付当前状态：皇帝、release SHA、输入指纹、当前阶段、阶段质量清单、史源覆盖、模型调用与异常、成果登记数量、未解决质量缺口、验证结果、canonical 是否发布。声明阶段恢复时必须读回阶段输入指纹、生产者合同指纹和产物 hash；声明共享生成或复用时必须读回 `shared_backbone_material_token`、新旧 identity、`shared_backbone_zero_model_reuse`、`shared_backbone_subject_coverage`、共享事件签名数和当前皇帝事件签名数。逐主体覆盖清单必须列出 token 全部主体且全部完成，缺少这些机器字段不得仅凭运行速度声称“已复用”。不得新增长期阶段报告、历史状态镜像或失败运行档案。

最低启动语句：

```text
按《单皇帝主控会话工作流》通过 emperor-session 入口自动认领并启动一个可运行皇帝；保持 shadow-only，不绕过全局模型槽位、共享 token 写权和 canonical CAS 发布；发现通用代码缺陷时停止受影响阶段并报告给集成会话。
```
