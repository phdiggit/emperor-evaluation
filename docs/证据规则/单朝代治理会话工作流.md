# 单朝代治理会话工作流

> 状态：当前 shadow 工作流。目标是在本朝任何皇帝评分链路启动前，一次完成朝代政书扫描、治理中性事实抽取和无皇帝窗口公共成果底账；不开放正式数据库、正式评分、45 分映射或排名。

单朝代治理会话只负责朝代共享治理底账，不负责皇帝编年、本纪、臣子列传、皇帝窗口绑定或评分。固定史源、逐字引文、朝代 token、治理域覆盖、成果归责和公共登记质量属于硬约束；篇章取舍、确定性预筛、批次大小、任务数量、模型调用方式和 checkpoint 映射可以按效率调整。同一朝代完成本工作流后才进入《单皇帝主控会话工作流》；同朝皇帝由用户串行调度，因此不增加朝代锁、协调器或排队状态机。

## 一、启动与输入

启动一个朝代治理批次前必须读取：

1. 最近的 `AGENTS.md`；
2. 本工作流全文；
3. `config/project.yml` 中 `dynasty_governance_catalog`、`dynasty_governance_scans` 与 `neutral_material_reuse`；
4. `docs/证据规则/公共成果登记与人物画像规则.md`；
5. 本朝现有政书 current、公共成果分区、固定索引身份和工作树状态。

`dynasty_governance_catalog` 固定登记各时代可用政书、候选篇章组、治理域和朝代 token。它是召回目录和覆盖上限，不是把全部书目下载并逐段调用模型的命令。会话先按当前治理域形成最小充分篇章计划：优先复用已验收 current，只补可能改变治理域覆盖、成果边界、价值方向或人物归责的篇章。静态目录、标题、全文关键词和重复页面必须在模型前确定性筛选。

最小充分只缩减无关文本和重复调用，不得预选正面结果，也不得删去实施失败、公共代价、制度反复、撤废和强制负担。目录声明 `quality_requires_catalog_source_families` 时，current 必须实际包含指定专题篇章；不得用皇帝本纪中的零散事项冒充《职官志》《食货志》《刑法志》《兵志》或相应政书已经覆盖。若治理审阅得到零条负向结果，必须先读回失败、反复、废止、负担和制度性代价候选及其逐条处置，不能把“没有扫描到”写成“没有负向成果”。

## 二、固定史源与索引

政书索引与皇帝编年索引是两份独立的固定史源身份，不要求合并为同一个 SQLite 或具有相同 index identity。朝代 current 必须保存实际消费的政书索引 identity、逐页 revision、正文 hash、逐字引文和目录指纹。索引新增未消费页面时，必须按 current 已记录的来源页逐页重验证并零模型迁移；不得因全库 index identity 变化重抽已验收页面。

若固定 revision 索引缺页，会话只向中央 Source Cache 的 `requests/` 提交经篇章计划确认且去重后的 work/page 需求，写入 `workflow-source-cache-request-v1` 后读取 collection `CURRENT.json` 等待。不得自行访问 Wikisource、CText 或其他公网载体，不得只给书名便下载整书正文。载体确实缺页与限流冷却分别报告，不无限重试；确需新载体时由集成会话增加适配器或导入经 hash 校验的固定快照。

目录新增作品或专题篇章时，已验收 current 按作品、页面、revision 和正文 hash 作为不可变 seed，只为新增页面生成模型任务，再将新增事实链合入同一朝代 current。索引或目录指纹变化本身不得触发旧页面重抽。既有 source pack、共享编年 current 或旧运行中固定的逐字事实可以作为迁移线索，但派生评分和旧归责判断不能直接成为共享治理事实。

## 三、扫描与中性事实抽取

朝代政书共享根固定采用 `<dynasty-governance-root>/<dynasty_token>/current.json`。皇帝 workspace 不得保存第二份政书事实、朝代 current 或“本皇帝专用治理材料”。current 的历史由 Git 中的目录合同与固定 revision lineage 追溯；运行目录只保留当前值。

首次模型调用前必须读回计划摘要，至少包含：阶段目标、固定来源页数与字符数、确定性筛选前后字符数、候选片段数、预计模型调用数、可用模型槽位、预计墙钟、可复用事实或片段数，以及完成后的质量检查。计划明显超出预估时先检查全书误扫、过细分段、重复调用和错误恢复，不得直接长时间 fanout。

抽取通过现有入口执行：

```text
codex-win run -- python v4.py emperor-session-dynasty-governance --state-root <runtime状态根> --session-id <准备会话ID> --release-root <同一干净release> --source-index-root <政书固定索引根> --dynasty-governance-root <朝代政书共享current根> --dynasty <朝代> --codex-bin <固定Codex可执行文件>
```

该命令可以复用准备会话的隔离 workspace 和模型槽位，但不得启动该皇帝的 `source_inventory`、编年、本纪、列传、窗口绑定或评分。另一运行命中相同目录指纹、固定来源 identity、抽取合同和覆盖需求时必须零模型复用；只缺新增篇章时不得重抽旧来源事实。

政书 current 可以保留静态制度和行政运行背景。事实链必须保存历史基线、举措、实际运行、公共结果、代价或反复、持续性和人物责任的已有环节；各环节不要求出现在同一条引文。领域标签命中不等于覆盖，模型摘要不等于史源，逐字引文必须回指固定 revision 正文。

## 四、治理成果底账

中性事实验收后，只消费 `dynasty_governance` 生成治理 worklist，不扫描皇帝编年、本纪和臣子列传，也不调用成果子模型。主会话逐项审阅后，在 `tmp/**` 写符合 `current-outcome-candidate-output-v3` 的 payload，确定性应用并导出 `eval/historical_outcome_registry/<DYNASTY>/current.*`。朝代成果分区通过质量门，才表示治理底账完成。

成果 worklist 按逐字引文的 `evidence_roles` 确定性分流：同一事实链至少含 `public_result` 或政书层 `cost_or_burden` 才进入四轴成果审阅，其余标为 `context_only`。政书 `cost_or_burden` 投射到通用成果层时统一为 `public_cost_or_harm`。普通官署运转、审核文书、官员俸禄和被裁官员失去职位不自动构成公共代价。

地理志不默认整书全扫，只在行政区划实际调整、人口迁移、交通水利、边疆设治或区域安全结果需要时定向抽取。治理审阅按“历史基线事实 → 举措 → 实际运行 → 公共结果 → 代价或反复 → 持续性 → 人物责任”组装跨书证据链，并分别判断生产力与民生、文明与制度进步、国家与民众安全、文化教育与思想活力四轴。国家安全不含皇权自身安全，`scale` 只表示范围，不得代替进步强度或人才档位。

价值方向可以为正向、负向、mixed 或 unclear。利弊共存时必须分别保存各轴方向、已发生收益、公共代价、反复和持续性，不得为了人才定级把 mixed 压成单向。无人物的宏观结果先保留，后续可由本纪或列传补责任证据。

逐字证据点名的制度开创者、重大变革者、关键实施交付者和重大纠偏者必须登记并进入共享人物候选，不受任何单一皇帝团队名单限制。沿用既有制度、普通参与、常规奉行、一般任职和仅在场者不登记。新增人物姓名无法回指本成果逐字引文时失败关闭。

## 五、验收与交接

朝代治理底账至少满足：

1. current 头部合同、朝代 token、目录指纹和固定索引 identity 一致；
2. 计划要求的治理域与专题来源覆盖闭合；
3. 每条事实已进入成果证据链、背景上下文或明确拒绝；
4. 每项成果完成独立结果去重、四轴方向、利弊、持续性和责任归属；
5. 公共成果分区可确定性重建，人物引用唯一；
6. 无变化重跑为零模型调用、零业务写入；
7. 数据库写入、正式评分、45 分映射和排名均为零。

验收通过后向单皇帝链路只交付：朝代 token、current 路径及 hash、目录指纹、固定索引 identity、覆盖治理域、公共成果分区路径及 fingerprint、未解决质量缺口。单皇帝链路只读消费这份底账，不得重新扫描政书或按皇帝窗口裁剪朝代事实。

皇帝本纪和臣子列传后来发现的治理材料属于公共登记增量：同一独立结果补 lineage、公共结果或责任成员；明确的重大变革、撤废或纠偏另立成果；普通沿用、任职和一般参与拒绝。这些增量更新公共成果分区，但不反向改写已验收的政书中性事实。

当前朝代底账完成后，本朝皇帝严格串行。前一位皇帝的治理增量、公共登记、窗口投影和质量门全部收口后，才启动下一位。该顺序由用户和主会话保证，不增加朝代锁或协调服务。

## 六、失败恢复与交付

失败只使当前未验收环节失效。已通过固定 revision、逐字引文、事实合同和目录覆盖验证的页面作为 seed 复用；新增或变更页面才调用模型。不得因成果审阅失败重扫政书，也不得因后续皇帝投影失败回滚朝代 current。

每次交付只报告当前朝代、目录指纹、固定索引 identity、来源页与治理域覆盖、模型调用数、治理成果数量、已归责与未归责数量、负向或 mixed 处置、未解决缺口、验证结果及是否允许进入本朝第一位皇帝。运行耗时、token 和批次状态只写 `tmp/**`，不新增长期阶段报告。
