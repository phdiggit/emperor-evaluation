# V4 试点范围与验收门禁

## 1. 试点目的

三人试点用于验证事件优先模型能否在不同王朝、政治环境和史料条件下稳定工作，不用于提前发布分数，
也不用于证明 V4 已可替换 V3。

## 2. 固定范围

| 维度 | 范围 |
| --- | --- |
| 人物 | 李世民、刘邦、朱元璋 |
| 规则 | 第五项统治者政治素质 / B 用人与授权 |
| 模式 | offline + report-only + shadow |
| 史源 | `config/source-policy.yml` 允许的正式来源 |
| 模型 | 仅限 `config/model-policy.yml` 允许的候选与草案用途 |
| 输出 | 事件、参与关系、主张、证据引用、裁判草案、差异报告 |

试点不包含其他人物、其他分项、正式分数、正式排名、生产写入或服务切换。扩围必须先修改本文件与
`config/pilot.yml`，并形成独立审查。

## 3. 最小工作集

每位人物应选择覆盖以下类型的事件样本：

- 明确正向用人或授权事件；
- 明确负向、失败或授权破坏事件；
- 史源相互冲突或归因不清事件；
- 容易与军事、治国、权力控制或历史负债混项的事件；
- V3 曾出现重复、漏召回、错误归因或材料过度切分的负面案例。

样本数量不在架构阶段预设。先形成事件清单和覆盖理由，再冻结试点 workset；不得为了满足数量指标
机械复制或拆分事件。

## 4. 门禁

### G0 范围冻结

- 三人、单一分项和明确排除项已写入配置。
- 试点 workset 有稳定标识、选择理由和冻结版本。
- 未混入 V3 正式业务数据；V3 样本均标记为只读对照来源。

### G1 史源与回源

- 每个正式候选事件至少有一条可定位的正式史源段落。
- 承载站、原书、版本和段落位置可区分。
- 百科、索引和二手文章只作为发现线索，不作为正式证据。
- 引文上下文足以判断主体、行为、时间和语义，不使用断章摘句。

### G2 事件建模

- 同一历史事件跨来源归并后仍保留各自证据引用。
- 不同事件没有因关键词相似被错误合并。
- 人物、角色、行为、对象、后果和归因链显式表达。
- 时间不确定、主体不确定和史源冲突没有被模型摘要抹平。

### G3 证据与裁判

- 每个 EventClaim 都有支持、反驳或不确定性状态。
- 正证与负证均完成检索和回源；缺失侧有可审计说明。
- 相邻项剥离与重复结算检查完成。
- 规则裁判固定语义、证据和规则版本，并保留人工复核状态。
- 模型输出没有直接成为已接受事实或正式裁判。

### G4 可重复性与审计

- 从冻结输入可重复得到相同事件标识、引用关系和裁判草案。
- 每个派生结论可以追溯到史源段落、事件版本和规则版本。
- 修订通过新版本和 lineage 完成，没有覆盖历史记录。
- 失败、排除、冲突和人工否决同样可追溯。

### G5 Shadow comparison

- 对同一冻结 workset 分别产出 V3 对照和 V4 结果。
- 差异按漏召回、误召回、错误合并、错误拆分、错误归因、证据冲突、规则差异分类。
- 每个差异有人工裁定，不以“与 V3 一致”作为正确性的唯一标准。
- V4 不得出现未解释的严重回归；剩余差异必须有已批准的处置或明确阻断结论。

### G6 发布前安全

- V4 没有生产写权限、V3 数据库写权限或自动服务替换路径。
- 凭据、部署路径、并发和超时均不在核心配置中。
- 正式评分和排名保持关闭。
- 已形成回滚与隔离检查清单，但未执行生产切换。

## 5. 验收结论

门禁结论只能是：

- `pass`：证据完整，所有阻断项关闭；
- `conditional_pass`：仅存在不影响下一阶段的明确限制，并有负责人和退出条件；
- `fail`：存在严重回归、不可追溯结论、范围漂移或生产隔离风险。

G0 至 G4 全部 `pass` 后才可进入 shadow comparison。G5 与 G6 全部 `pass` 只表示可以提出生产切换
设计评审，不等于授权切换。任何生产替换仍需单独任务、明确批准和可验证回滚方案。

## 6. 当前退出条件

本初始化阶段完成的退出条件仅为：

- V3 冻结点与 V4 分支关系明确；
- V4 核心文件树和配置边界明确；
- 领域模型与不可妥协约束已记录；
- 三人试点范围和验收门禁已记录。

它不代表 G0 已完成，因为冻结 workset、实现、数据和验收报告尚未建立。
