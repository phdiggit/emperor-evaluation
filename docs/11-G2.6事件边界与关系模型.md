# G2.6 事件边界与关系模型

> 状态：`accepted_and_hardened_by_minimum_sufficient_scoring`
> 目标：把原子历史事件、事件间关系和规则证据聚合拆成三层，禁止通过扩大 HistoricalEpisode 修复 recall。

## 1. 当前判定

blind_holdout_v3 的 20 个 Gold 中有 14 个精确命中；其余 6 个均为安全过拆，没有 wrong merge、灾难性合并、跨皇帝污染或 assertion/lineage 丢失。正式 blind 成绩保持 recall 70%、precision 50%，不得修改或重命名。

公开架构审计判定：六案均应改为多个原子 episode 加关系。施琅拆为“授水师提督”与“后续授靖海将军、授权攻台及首次受阻”，以 `renews_authority` 连接。六案诊断性重解释达到 28/28，仅证明 ontology/Gold alignment 问题，不是新 blind 成绩。

## 2. 三层边界

```text
HistoricalEpisode
→ EpisodeRelation
→ RuleEvidenceUnitDraft
```

HistoricalEpisode 只表示一次任命、授权、具体任务、对应结果或一次撤权处置。跨多年升迁、任命与罢免、授权与对象后续自主行为不得压成一个 episode。

EpisodeRelation 只表达 episode 之间的联系，第一版允许：

- `continues`
- `same_mandate_phase`
- `promotion_after`
- `renews_authority`
- `revokes`
- `outcome_of`
- `causal_followup`
- `context_for`

Relation semantic policy v2 使用下列互斥判定和优先级。只有 endpoint 证据直接建立状态转换、授权、结果或因果联系时才生成关系；同一人物、皇帝、时间、职位或宽泛主题本身只能判为 `distinct_unrelated`。

该细类型表自 2026-07-13 起只用于需要精确关系审计的可选解释层，不再是规则 shadow 的普遍硬 Gate。评分链优先使用：

```yaml
relation_family: authority_change | mandate_or_outcome | explicit_causal
relation_direction: grant | expand | transfer | reduce | terminate | restore | mandate | feedback | result | continuation | cause_to_followup
scope_match: exact_office | same_authority_domain | same_mandate | whole_person_status | decision_to_result | explicit_causal_chain
fine_type: optional
fine_type_status: resolved | not_required_for_scoring
```

只要 family、方向、范围、皇帝归责和 evidence 已足够支持评分，不得因 `fine_type` 为空而阻断。若两项事实属于同一评分决策弧，但逐对 Relation 对评分归责、方向、去重和追溯没有直接用途，则输出 `scoring_arc_only`，作为 RuleEvidenceUnit 成员建议而不伪造边。

| 优先级 | relation type | 判定边界 |
| --- | --- | --- |
| 1 | `revokes` | 后件撤销、缩减、暂停或终止前件中的授权/职位；接受辞任、降职和收回特权均属于撤权 |
| 2 | `renews_authority` | 后件对同一责任主体重新任命、追加职位、升迁、调任、扩权或实质续权；不能仅因“升迁”改记 `promotion_after` |
| 3 | `outcome_of` | 后件是前件行动直接报告的结果或反馈，且没有新的独立决策 |
| 4 | `causal_followup` | 前件导致、促成、触发或构成后件独立决定、行动或后果的明确阶段基础 |
| 5 | `same_mandate_phase` | 两件事属于同一持续授权内的不同履职、建议或反馈，但彼此不是直接因果，也没有新授权或撤权 |
| 6 | `continues` | 后件只是同一已下达命令或行动的继续、送达、恢复或完成，没有新授权和独立决定 |
| 7 | `promotion_after` | 只表示明确的职级先后，且不构成续权、调任或责任链；不得用它代替 `renews_authority` |
| 8 | `context_for` | 前件是理解后件所必需的明确背景，但不属于授权、结果或因果链 |

方向统一从较早的授权、命令、原因或状态指向后续的继续、变化、结果或后果。若已有直接路径完整表达同一关系，不额外创建纯传递边；史源另行明确陈述非相邻直接联系时除外。证据不足以建立直接关系时判 `distinct_unrelated`；只有证据相互冲突，或方向/类型在多个合法选项间确实无法裁定时才判 `unresolved`。

RuleEvidenceUnitDraft 是规则消费层的候选聚合，可以把授职、扩权、履职结果、再授权或撤任组合成一条规则证据单元。它不修改 episode，不是 Judgment，也不能直接给分。

## 3. EpisodeBoundaryReview policy v2.10 / schema v2.8

审查输出必须包含：

```yaml
episode_groups:
  - local_episode_code:
    core_assertion_refs: []
    boundary_reason:
    confidence:
    atomic_event_key:
relations:
  - from_episode_ref:
    to_episode_ref:
    relation_type:
    evidence_assertion_refs: []
    confidence:
pair_dispositions:
  - left_episode_ref:
    right_episode_ref:
    decision: related | distinct_unrelated | unresolved
    relation_type:
    reason:
context_assertions:
  - assertion_ref:
    applies_to_episode_refs: []
    reason:
unresolved_assertion_refs: []
```

每条 Assertion 最多属于一个 episode 的 core，但可以作为多个 episode 的 context。关系可以有自己的 evidence refs。历史细类型审查要求每对候选 Episode 都有且只有一个 pair disposition；当前评分最小充分审查则唯一处置为 `proposed_relation`、`scoring_arc_only` 或 `unresolved`。只有评分必要的方向、皇帝归责、结果或同一决策弧仍不明确时，`unresolved` 才阻断规则 shadow；仅 fine type 不明确不再阻断。审查器只提出结构化边界、关系或评分弧成员建议，不能接受 canonical episode、Relation 或 RuleEvidenceUnit。

v2.2 增加原子边界硬约束，v2.3 引入 reviewer-level `atomic_event_key`，v2.4 将该键提升为每个 EpisodeBoundaryGroup 的必填身份字段，v2.5 统一结构化时间等价，v2.6 将 responsibility-domain 展示措辞移出原子硬相等字段，v2.7 增加 passage-scoped Assertion 支持门禁，v2.8 增加零 Episode fail-closed review unit 与 support-key proposition identity。v2.9 收紧 core/context、决策阶段和直接结果链边界。v2.10 仍不改变 v2.8 输出 Schema，但把 ReviewUnit 从 focal-person 硬分区改为 participant/object-anchor 连通分区；旧 policy 缓存必须失效并重新审查。

原子 core 仍必须保持 action、responsibility family、focal role、normalized time/era 一致；domain 组合仍进入 semantic payload。对于同一上游 claim 的多 passage core，v2.7 只有在每条 Assertion 都声明 `equivalent_evidence`、共享同一 `assertion_semantic_key` 且语义载荷完全一致时才允许合并。`atomic_component`、`context_only` 或缺失 PassageSupport 的 fan-out 不得被 Reviewer 的 `atomic_event_key` 覆盖。Gold code 和临时 local code 严禁进入。

v2.10 审查必须应用以下通用边界政策：

- 直接陈述当前 action、responsibility 或 outcome 的 Assertion 是 core evidence；语义重复不等于 context，重复只在 PropositionCluster 层压缩审查输入；
- 同一状态转换的互补角色描述可以合并，例如同一时间和职位下的让位与继任任命；但必须证明它们不是两次可独立评价的决定；
- 授权、移交或任命与受托人后续独立调查、审讯、裁量、作战或治理原则上拆分，并用 `outcome_of`、`same_mandate_phase` 或 `causal_followup` 连接；
- 同一最终命令的签发、送达、直接执行和即时结果，在没有新命令、新授权或独立裁量时可以合并；出现新的决定阶段则必须拆分；
- title/name alias 尚未解析时保留 identity blocker，但不能仅因同一人的不同称谓拆分一个由其他字段已确认的原子事件。
- 同一 evaluation context、responsibility family 与相邻时间内，共享 focal、secondary participant 或规范化 object surface 的 PropositionCluster 必须进入同一连通 ReviewUnit；object anchor 只扩大可比较范围，不自动授权 merge；
- 多条直接 Assertion 若在同一 passage 或多来源中描述同一原子状态转换，必须共同成为一个 episode 的 core lineage，不能为了保留每条直接证据而创建平行 singleton episode。

## 4. 确定性微聚类和 Review Unit

模型调用前先把相同 `claim_key` 或相同结构化命题的 passage-specific Assertion 聚成 PropositionCluster。PropositionCluster 只用于减少审查输入重复，不授权正式 merge。相同旧 `claim_key` 若扇出到多个 passage，必须由 Assertion 层提供共同 `atomic_event_key`，或由隔离 reviewer 核对原文后冻结 group-level `atomic_event_key`，才能进入同一 Episode core；否则只能拆开或进入 assertion atomization worklist。多份原文始终保持独立 lineage。

Review Unit 由 evaluation context、责任族、相邻时间窗口和 participant/object-anchor 连通分量形成。单元可以包含多个 focal person；其稳定展示值是排序后的 focal ref 集合。缓存键只包含：

```text
proposition semantic hashes
+ boundary policy version
+ output schema version
+ model family
```

缓存按 unit 失效。新增张英史料只能使张英 unit 失效，其他人物 unit 必须保持命中。首次总调用次数不再硬编码为 1；要求是一个未命中 unit 至多一次调用，无变化 unit 零调用。

Episode 边界物化后，Relation 必须由独立的跨 Boundary ReviewUnit 层审查，并绑定 Episode basis hash、原始 blind input hash、Relation policy version 和输出 Schema；不得读取 Historical Gold、Rule Gold 或 score。G2.6K0 为审计 ontology 曾按 evaluation context 枚举并完整处置所有 pair；该 O(n²) 方式只作为已冻结的开发审计协议，不再是生产默认候选生成路径。

G3R 必须先用确定性 participant/object、时间、授权状态转换或 endpoint evidence blocking 生成有审查资格的候选；进入候选集的 pair 仍须唯一处置。评分必要语义 unresolved 时阻断对应规则 shadow；`fine_type_status=not_required_for_scoring` 不是 unresolved。未进入候选集不等于已证明 `distinct_unrelated`。Boundary ReviewUnit 内产生的旧关系只作为开发诊断保留，不直接成为独立 Relation graph 的正式候选。

## 5. Ambiguity Gate

ambiguity 必须结构化为 code、slot、severity 和适用的 blocking episode types。`missing_location` 对一般任官、入直、升迁、罢职和追赠为 informational；只在军事行动、领土行动等地点属于核心边界的类型上阻断。

`human_review_required` 只能由 blocking ambiguity、身份阻断或实质证据冲突触发，不能由任意 informational uncertainty 触发。

## 6. 分层指标

Episode 层同时报告 exact recall/precision、pairwise same-episode precision/recall、wrong merge/split、safe fragment、灾难性合并和跨皇帝污染。

Relation 层独立报告 relation type precision/recall、mandate-chain coverage、revocation/outcome linkage coverage 和 causal responsibility preservation。

安全过拆、危险过合并、事实漏失和关系漏失必须分别归因，不得再统一记为“错误候选”。

## 7. Gate

G2.6 的完整 Graph Gate 保持失败关闭：v1、v2、v3 与 I/J 永久作为开发与回归集，S4/S5 未达标前不得建立正式 Relation、规则投影或评分。2026-07-13 起按 `21-G2终止与G3A核心Shadow决策.md` 拆分 Gate：G2-Core 结束调试并允许进入隔离的 G3A/G3B Core shadow 实现；G2-Relation 转入独立 G3R，不再阻断 Episode Core Registry。新 blind holdout、V3 数据库连接、生产写入和正式评分继续禁止。
