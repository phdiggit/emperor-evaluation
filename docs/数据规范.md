# 数据规范

本项目以 `data/*.jsonl` 为事实源，SQLite 与 Markdown 均由事实源生成。`data/templates/*.json` 只作为填写模板，不进入 `build_db` 导入流程。`evidence_cache.sqlite` 是生成物，不进 Git。Markdown 是导出视图，不是主源。

本任务不得写入任何评分记录。未回源材料不得进入正式评分，只能保留为 `search_logs.jsonl` 的待回源线索。

## 0. 分层存储原则

采用“史料检索体系 + 证据裁量体系”后，数据必须分层保存，避免把线索、来源、原子证据、证据组结论和最终视图混写。

推荐层级为：

1. `search_logs.jsonl`：史料线索层，只记录检索和待回源线索，不得直接入分；
2. `sources.jsonl`：原始来源层，只记录史料或文献出处，不判断强弱；
3. `evidence_cards.jsonl`：原子证据层，只记录已回源、可归项、可裁量的单条证据；
4. `evidence_clusters.jsonl`：证据组裁量层，记录多条原子证据形成的综合裁量结论；
5. `thematic_anchors.jsonl`：专题锚点层，记录同类问题的横向锚点和比较案例；
6. `query_profiles.jsonl`：项目检索包层，记录每个项目/子项的检索关键词、反向检索要求和史源范围；
7. `exports/`：导出视图层，只服务阅读和定档，不作为主源。

线索库、证据库、证据组、专题锚点均不得直接等同于最终得分。最终定档定分只能读取完成回源、裁量、切分和必要人工裁判后的净证据。

## A. sources.jsonl

来源表记录史料或文献来源。每行一个 JSON object。

字段规范：

- `source_id`：稳定来源 ID。
- `title`：书名、文献名或资料名。
- `author`：作者。
- `dynasty`：时代或朝代。
- `volume`：卷、篇、章节等。
- `location`：页码、条目、纪年位置或其他定位信息。
- `url`：线上链接，没有则留空。
- `note`：补充说明。

## B. evidence_cards.jsonl

证据卡记录已回源、可解释、可复核的原子证据。每行一个 JSON object。

字段规范：

- `evidence_id`：稳定证据卡 ID。
- `person`：人物中文名。
- `item`：评价大项。
- `subitem`：评价子项。
- `polarity`：证据方向，只能是 `positive` 或 `negative`。
- `strength`：证据强度，只能是 `1`、`2`、`3`、`4`。
- `human_level`：人工层级。
- `source_id`：来源 ID，必须存在于 `sources.jsonl`。
- `quote_short`：短引文。
- `interpretation`：证据解释。
- `trigger_family`：触发词族。
- `trigger_terms`：命中的触发词，可用数组记录。
- `cross_item_split`：相邻项切分说明。
- `scoring_effect`：评分影响说明。
- `verification_status`：回源和复核状态。
- `case_classification`：负证分案类型，用于区分谋反、安全疑案、谏诤压制、意识形态压制、廷杖刑辱、政治案件扩大、死后信任逆转、司法处罚争议等。
- `risk_status`：风险状态，用于记录是否确有谋反、强嫌疑、弱嫌疑、未坐实争议、无谋反语境、确认案件但有扩大化，或不适用。
- `mitigating_factors`：减轻因素数组，例如确有谋反、强安全风险、死后事件、后续追悔、平反复碑、单案非系统、群臣请诛、证据有争议。
- `aggravating_factors`：加重因素数组，例如未坐实指控、罗织构陷、株连、案件扩大、死徙规模、压制谏诤、刑辱臣下、寒蝉效应。
- `reversal_or_rehabilitation`：反转或恢复评价数组，例如后续追悔、复碑、平反、信任恢复、未发现。
- `adjudication_status`：裁判状态，标明待人工裁判、仍需回源、仅切相邻项或已人工裁判候选。

后续扩展字段：

- `five_axis`：五轴裁量结果，可记录归项直接度、行为关键性、持续性/结构性、后果外溢度、相邻项剥离后剩余强度。
- `trigger_modules`：触发式裁判模块数组。
- `linked_cluster_ids`：若该原子证据被某个证据组引用，可记录证据组 ID。

规则：

- `polarity` 只能是 `positive` 或 `negative`。
- `strength` 只能是 `1`、`2`、`3`、`4`。
- `strength` / `human_level` 是候选证据强度，不是最终入分强度。
- `positive` + `1` -> `human_level=弱正`。
- `positive` + `2` -> `human_level=中正`。
- `positive` + `3` -> `human_level=强正`。
- `positive` + `4` -> `human_level=极正`。
- `negative` + `1` -> `human_level=弱负`。
- `negative` + `2` -> `human_level=中负`。
- `negative` + `3` -> `human_level=强负`。
- `negative` + `4` -> `human_level=极负`。
- 强负、极负必须填写 `cross_item_split` 或 `scoring_effect`。
- `evidence_card` 引用的 `source_id` 必须存在于 `sources.jsonl`。
- 未回源材料不得进入正式评分，只能保留为 `search_logs.jsonl` 的待回源线索。
- 高风险负证必须填写 `case_classification`、`risk_status`、`mitigating_factors`、`aggravating_factors`、`reversal_or_rehabilitation`、`adjudication_status`。
- 确有谋反链条且不是政治案件扩大化时，默认不得高于弱负候选。
- 死后信任逆转默认不得高于弱负候选。
- 有减轻因素却写强负或极负时，必须同时有明确加重因素。
- 强负或极负必须标明待人工裁判，不得直接写成最终结论。
- 单条证据卡不得伪装成证据组结论；多证据融合结论应写入 `evidence_clusters.jsonl`。

`case_classification` 建议值：

- `confirmed_rebellion_or_security_case`
- `suspected_rebellion_unproven`
- `remonstrance_suppression`
- `ideological_suppression`
- `corporal_humiliation`
- `political_case_expansion`
- `posthumous_trust_reversal`
- `judicial_or_punishment_dispute`
- `other`

`risk_status` 建议值：

- `confirmed_rebellion`
- `strong_suspicion`
- `weak_suspicion`
- `unproven_or_disputed`
- `no_rebellion_context`
- `mixed_confirmed_case_with_expansion`
- `not_applicable`

`adjudication_status` 建议值：

- `source_verified_pending_human_adjudication`
- `needs_more_source_review`
- `routed_to_adjacent_item_only`
- `human_adjudicated_candidate`

## C. events.jsonl

事件表记录可拆分的行为或处置事件。每行一个 JSON object。

字段规范：

- `event_id`：稳定事件 ID。
- `person`：主体人物。
- `target`：事件对象。
- `action_type`：行为类型。
- `attribution_type`：归因类型。
- `outcome`：结果。
- `severity`：严重度。
- `time_phase`：时间阶段。
- `event_name`：事件名称。
- `event_date`：事件日期或纪年。
- `description`：事件描述。
- `source_id`：来源 ID。

## D. trigger_terms.jsonl

触发词表记录正负证检索种子。每行一个 JSON object。

字段规范：

- `term_id`：稳定触发词 ID。
- `item`：评价大项。
- `subitem`：评价子项。
- `polarity`：方向，只能是 `positive` 或 `negative`。
- `trigger_family`：触发词族。
- `term`：触发词。
- `tier`：层级，只能是 `core` 或 `extended`。
- `note`：补充说明。

## E. search_logs.jsonl

检索留痕表记录人物、子项、正负方向、触发词矩阵的查证过程。每行一个 JSON object。

`search_logs.jsonl` 是史料线索库，不是证据库。未回源材料、疑似材料、待核材料均可保留在此处，但不得直接入分。

字段规范：

- `search_id`：稳定检索记录 ID。
- `person`：人物中文名。
- `item`：评价大项。
- `subitem`：评价子项。
- `polarity`：方向，只能是 `positive` 或 `negative`。
- `trigger_family`：触发词族。
- `query_terms`：检索词。
- `query`：实际检索式。
- `source_scope`：检索来源范围。
- `searched_at`：检索时间。
- `result_status`：检索结果状态。
- `result_summary`：结果摘要。
- `linked_evidence_id`：关联证据卡 ID，没有则留空。
- `note`：补充说明。

后续扩展字段：

- `search_mode`：检索模式，可为项目驱动、人物驱动、反向检索、专题横向、史源驱动。
- `query_profile_id`：项目检索包 ID。
- `target_person`：目标人物。
- `target_item`：目标项目或子项。
- `candidate_polarity`：候选方向。
- `lead_status`：线索状态。
- `source_review_status`：回源状态。
- `linked_evidence_ids`：可关联多张证据卡。
- `rejection_reason`：剔除理由。
- `next_action`：下一步动作。

`result_status` 限定值/允许值：

- `checked_no_hard_evidence`
- `evidence_found_card_created`
- `lead_needs_source_review`
- `routed_to_adjacent_item`

## F. evidence_clusters.jsonl

证据组裁量表记录多条原子证据融合后的综合裁量结论。每行一个 JSON object。

它不是新史料，不得脱离原子证据自行扩写。它只用于记录“多条证据共同证明了什么”。

建议字段：

- `cluster_id`：稳定证据组 ID，建议以 `ADJ-` 开头。
- `person`：人物中文名。
- `item`：评价大项。
- `subitem`：评价子项。
- `cluster_type`：证据组类型，例如人才生态、容谏反馈、错用将相、系统清洗等。
- `polarity`：综合方向，通常为 `positive` 或 `negative`，也可在待定阶段留空。
- `linked_evidence_ids`：引用的原子证据 ID 数组。
- `summary`：综合判断摘要。
- `five_axis_assessment`：证据组层面的五轴裁量。
- `candidate_strength`：证据组候选强度，仍为 `1`、`2`、`3`、`4`。
- `upper_probe`：是否上探极级或需人工裁判。
- `cross_item_split`：证据组层面的相邻项切分。
- `adjudication_status`：裁判状态。
- `note`：补充说明。

规则：

- `linked_evidence_ids` 必须引用已存在的 `evidence_cards.jsonl` 证据卡。
- 证据组强度不是最终档位。
- 证据组可以上探强级或极级，但极级必须人工裁判。
- 单条证据不得重复包装成证据组；证据组必须体现跨证据、跨维度或结构性意义。

## G. thematic_anchors.jsonl

专题锚点表记录同类问题的横向比较材料。每行一个 JSON object。

它主要服务裁量校准，不直接替代证据卡或最终评分。

建议字段：

- `anchor_id`：稳定专题锚点 ID。
- `theme`：专题名称，例如杀功臣、容谏、错用将相、民生崩坏、继承安排。
- `item`：主要关联大项。
- `subitem`：主要关联子项。
- `persons`：涉及人物数组。
- `linked_evidence_ids`：关联证据卡数组。
- `linked_cluster_ids`：关联证据组数组。
- `anchor_summary`：锚点摘要。
- `comparative_value`：横向比较价值。
- `note`：补充说明。

规则：

- 专题锚点不得作为单独证据入分。
- 专题锚点主要用于校准强弱边界、触发模块边界和横向一致性。
- 专题锚点若要影响某人定档，必须回到对应原子证据或证据组。

## H. query_profiles.jsonl

项目检索包表记录每个项目/子项的检索方案。每行一个 JSON object。

建议字段：

- `query_profile_id`：稳定检索包 ID。
- `item`：评价大项。
- `subitem`：评价子项。
- `search_modes`：适用检索模式数组。
- `positive_terms`：正证关键词数组。
- `negative_terms`：负证关键词数组。
- `reversal_terms`：反转材料关键词数组。
- `source_scopes`：优先史源范围。
- `reverse_search_required_when`：强制反向检索触发条件。
- `thematic_anchor_targets`：需要专题横向补查的主题。
- `cross_item_split_notes`：相邻项切分提醒。
- `note`：补充说明。

规则：

- 检索包不是证据，只是检索计划。
- 检索包应随项目细则和裁判模块更新。
- 每次项目启动时，应优先读取对应检索包，生成或更新 `search_logs.jsonl`。

## I. exports/

`exports/` 存放由事实源生成的阅读视图、矩阵视图和净证据池视图。

规则：

- `exports/` 不是主源。
- 不得手工把导出视图当成唯一事实依据。
- 导出视图应可由 `data/*.jsonl` 再生成。
- 最终定档前，可读取导出的净证据池，但若与 JSONL 主源冲突，以 JSONL 主源为准。
