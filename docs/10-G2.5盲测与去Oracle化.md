# G2.5 盲测与去 Oracle 化

> 状态：`accepted`

## 1. 当前判定

M1 HistoricalEpisode Kernel 为 `conditional_pass`：Oracle-assisted constructability 已通过；G2 正式验收重开。Gold-assisted packet 数量不得解释为 recall、precision 或 merge/split accuracy。

## 2. Kernel 输入禁区

Blind Kernel 不得读取或接收：

- `episode_code`；
- Gold boundary；
- `must_merge` / `must_not_merge`；
- expected participants；
- acceptance decision；
- Gold linkage；
- candidate boundary hint。

Kernel 只接收 SourcePassage、AssertionDraft、CanonicalPerson 候选和 evaluation context。`blind-holdout-run` 的函数签名和输入校验必须阻断 Oracle 字段。

## 3. 数据集

首个真实 holdout 目标为 16 个事件：至少包含李治、朱棣两位新皇帝，并包含韩信复合链、李善长复合链及第一阶段三人的未使用事件。数据覆盖多来源同事件、多次独立任用、跨皇帝、冲突结果、partial episode、应合并、应拆分、非人物 object 和别名身份。

Gold 在独立位置冻结。运行 Kernel 时关闭 Gold 文件访问；candidate artifact 冻结并记录 input hash 后，才允许 `blind-holdout-score` 打开 sealed Gold。

2026-07-12 已冻结首个真实输入与候选产物：59 条 AssertionDraft、60 个 SourcePassage、29 个 autonomous candidate；运行与确定性重跑均为零模型、零网络、零数据库写入。独立 reviewer 在未读取 candidate 的条件下冻结 16 个 Gold Episode。正式 v1 baseline 为 recall 31.25%、precision 17.24%、wrong split 10、wrong merge 0，因此 G2.5 未通过。

v1 失败归因后，通用 reconciler 在开发集诊断中达到 recall/precision 93.75%、wrong merge/split 0；唯一 miss 是“有韩信终局原文但无 AssertionDraft”。由于修复过程已经读取 v1 Gold，该结果不得重新命名为 blind 指标，v1 从此只作为开发回归集，正式放行必须使用未见的 blind_holdout_v2。

blind_holdout_v2 在任何 candidate 产生前，由另一独立 reviewer 先冻结了 20 个 Gold Episode；输入使用 v1 未出现的杨坚、刘秀及全新人物链。首次结果为 recall 30%、precision 46.15%、wrong merge 3、wrong split 2，且 3 个 wrong merge 均属灾难性错误。v2 同样未通过，并从评分后起只作为开发诊断集。

v2 表明字符、时间和局部主题启发式无法同时解决长链拆分与同人多任务污染。确定性层必须 fail-closed：清晰同义证据可自动合并，模糊的任命—行动—结果、多年处置链必须进入 `EpisodeMergeReview` / `EpisodeSplitReview`。语义建议需要独立缓存、结构化理由和输入 hash；无变化重跑必须零模型调用。实现该层并通过新的未见 holdout 前，G2.5 与 G3 均保持失败/阻断。

blind_holdout_v3 使用玄烨、李隆基的 76 条全新 AssertionDraft。EpisodeMergeReview 子 Agent 与 Gold 子 Agent 同时隔离冻结：前者禁止读取 v1/v2 Gold、v3 Gold、candidate 与 score，后者禁止读取语义审查及候选产物；Kernel 等两者完成后才首次运行。语义审查形成 28 组候选，独立 Gold 冻结 20 个事件。首次结果为 recall 70%、precision 50%、wrong merge 0、wrong split 6、跨皇帝污染 0、lineage 100%。缓存重跑为零模型调用且候选 fingerprint 完全一致。v3 证明可缓存语义审查能够避免本批灾难性合并，但仍偏保守并产生六个过度拆分，故 G2.5 仍未通过；该数据从评分完成起只作开发诊断，不得通过事后修补重新命名为 blind 证据。

Scorer 只接受独立冻结的 `gold_episodes[].expected_assertion_refs`，并由 assertion 集合机械计算 exact match、wrong merge 与 wrong split；禁止重新引入 `candidate_decisions` 让 candidate 自己定义正确答案。

## 4. 两套指标

人工接受前：

- autonomous boundary recall；
- candidate precision；
- wrong merge / wrong split；
- cross-ruler contamination；
- identity block rate；
- human review rate；
- passage lineage completeness。

独立人工接受后：

- accepted recall；
- accepted precision；
- lineage completeness；
- uncertainty preservation。

两套指标不得混写。

## 5. 放行条件

- passage lineage 为 100%；
- 跨皇帝污染为 0；
- 无变化重跑模型调用与写入均为 0；
- catastrophic wrong merge 为 0；
- blind recall 至少 85%；
- blind precision 至少 90%；
- 普通边界错误最多 1 个；
- 每个错误可归因到 source、assertion、identity 或 reconciliation 层；
- 不允许逐事件硬编码修复。

在真实 blind dataset 与 sealed Gold 均冻结并达标前，PostgreSQL G3、状态机和规则投影保持未授权。
