# 皇帝任期军事体系结算规则

本层消费战役账、军事体系观察账、战争成本引用及非战争军制材料，将事件证据结算为每位皇帝一条C项记录。C项只形成一个50分总体分；C1决定基础档，C2、C3只作封顶门禁，不分别加分。

共享计分材料从[`《资治通鉴》战争计分材料审计索引`](../../../史料通读产物/唐以前编年/00-战争卡审计索引.md)按`WAR-*`键回源；机器计分唯一读取入口为[`C秦至唐皇帝正式结算.json`](../../../评分结算/第三项军事与边疆净收益/军事体系有效性/01-皇帝C项正式结算.json)，同名Markdown只作人工阅读视图。

## 一、三层结构

| 层次 | 字段 | 回答的问题 |
|---|---|---|
| C1实战兑现度 | `combat_delivery_grade` | 面对不同难度对手时，军队实际能不能完成任务 |
| C2持续作战能力 | `operational_sustainability_cap` | 既有战果能否由动员、补充、后勤和恢复能力持续支撑 |
| C3体系可靠性 | `system_reliability_cap` | 战力能否跨将领、跨战场重复运行，而非依赖偶然或单一名将 |
| C总体档 | `C_overall_grade` | 国家军事体系在本人统治期内的实际有效性 |

事件观察账的三个证据槽分别为`combat_delivery、operational_sustainability、system_reliability`。观察槽不是事件分数，不得逐场累计。

## 二、C1实战兑现度基础档

| 档位 | 必要边界 |
|---|---|
| `C1-0` | 军队在核心任务上整体失去作战能力，主要战线普遍崩溃或无法形成有效抵抗。 |
| `C1-1` | 面对普通任务也反复失败，只能取得零星且不能改变战局的战果。 |
| `C1-2` | 胜负混杂且总体偏弱，能够完成部分局部任务，但主要任务经常失败。 |
| `C1-3` | 对普通和中等难度任务总体能够兑现，重要胜负并存，未形成稳定高水平表现。 |
| `C1-4` | 对主要或高难度任务多数能够兑现，跨多个战场保持较稳定实战表现，仅有少数重大失败。 |
| `C1-5` | 必须分别面对多个公共对手战争机器档位达到`O4—O6`的高难度对手，并长期表现出历史顶级兑现能力；`O1—O3`、同一`opponent_system_ref`的多阶段、同一战争链或同质弱对手的重复胜绩不能凑足。允许存在孤立失败，但不得形成反复重大失效模式。 |

C1只看作战体系实际表现。战略安全、控制规模和控制价值分别归A、B；歼敌或占地不能在C重复转换为战略收益分。父战役的`BCP/BCN`只服务A/B与D的实际控制收益判断，不作为C项的加分或扣分字段。

军队是否被有效启动也属于C1。外敌实际侵入并造成明确损害，而本方在同一主要方向长期未形成拒止、反击或能够终止损害的替代手段，记为“被动失守”；其严重度高于一次有组织应战、主力尚存且能够恢复的普通败战。避战若通过坚壁、撤民、诱敌、外交或后续反击实际控制损害，不按被动失守处理。史书只是不载交战时保持未知，不得据沉默判负。

## 三、C2持续作战能力封顶档

| 档位 | 必要边界 |
|---|---|
| `C2-0` | 动员、补充或后勤体系已经崩溃，无法维持基本作战。 |
| `C2-1` | 兵源、粮饷或运输反复发生致命失效，军队只能进行极短期或临时性行动。 |
| `C2-2` | 能维持有限作战，但重要行动经常受补充、运输、军需或恢复能力限制。 |
| `C2-3` | 通常能够支撑普通战争，较大规模或长期行动仍有明显缺口。 |
| `C2-4` | 能稳定支撑多路、大规模或较长期战争，但发生过一次战役群级保障失效，或仍存在少数足以中断主要行动的显著缺口。 |
| `C2-5` | 必须在多个相互独立、且各自至少有`O4—O6`对手战争机器实证的高难度战略方向长期保持历史顶级动员、补充、后勤与恢复能力；同一方向纵深推进或同一补给体系内的多场战争不能冒充多方向。可有局部、可控障碍，但不得发生任何一次战役群级保障崩溃。 |

C2只决定C项最高可以达到哪一档。大规模动员本身不加分；人员、财政和民生负担由财政民生账结算，投入是否值得归D。

## 四、C3体系可靠性封顶档

| 档位 | 必要边界 |
|---|---|
| `C3-0` | 国家级军令和军事组织持续、全面失去基本运行能力，且崩溃成为任期内的主导或长期状态，任内未形成有效恢复。 |
| `C3-1` | 发生中央级体系崩溃且任内未恢复，或军令、将帅协同及中央地方关系长期严重失灵；但任期其他阶段仍存在较长时间、有组织的军事运行。 |
| `C3-2` | 体系可以运作但反复出现重大组织失误，或明显依赖一名将领、单一集团及临时拼凑。 |
| `C3-3` | 军令和将帅体系通常有效，但跨将领、跨方向复制能力有限，仍有明显组织缺口。 |
| `C3-4` | 多名将领和多个方向能够在统一权责下稳定运行，但发生过一次战役群级组织失灵，或仍有少数显著组织缺口。 |
| `C3-5` | 形成历史顶级、可跨将领与跨战场重复运行的可靠体系；至少两名在公共武将人才等级中达到`top`或`historic`的将领，必须分别在本人评价窗口内取得一项`A`或更高档的显著成果。仅有多名普通将领、名将声望、同一顶级将领反复取胜或未闭合到人物成果的统帅名单均不足。可有局部将领失误，但不得发生任何一次战役群级组织崩溃。 |

C3只判断战力是否属于国家体系。军制的制度史影响归第二项A3；名将个人能力归相应人物或第一项，不直接冒充皇帝C项。

边防体系建设不等于军事体系作战能力。都护、屯戍、堡寨、防线、边疆行政和常态驻防首先证明A2安全体系；军事体系更强调军队在实际战争中的机动、协同、攻防、补充、运输、恢复和跨将领复制能力。防御战与进攻战都可以检验上述能力，但必须存在真实交战压力和可裁定的任务结果。边防结构只有在战争中进一步证明军队能够交付任务、持续行动并跨将领重复运行时，才能分别进入C1、C2、C3。边疆长期稳定可以作为持续性与可靠性的旁证，但不得脱离实际作战压力把C2或C3推到5档，更不得用A2的结构成果替代C1实战兑现。

没有至少一个可消费的实战体系压力父周期时，C1保持`UNKNOWN`，C总体不得计分。军制、动员、屯戍、堡寨或史料通读材料可以保留为C2、C3旁证，但不能单独使C项从`UNKNOWN`转为已结算。未达到实质任务门槛的低强度观察只保存为观察数，不得在实质任务为空时整批回填成`independent_task_groups`。

第一项已经消费的创业统一战争，不得把疆土、安全收益、控制成果和成本再次送入第三项A、B、D；但处于本人已经形成可评价政权或主政窗口内的战争表现，可以作为C的“能力专用证据”复用，用来检验国家军队的实战交付、持续作战和跨将领可靠性。该复用必须列入`capability_only_parent_refs`，只改变C轴事实判断，不进入第三项战略收益、控制量、D周期数量或成本收益组合。可评价政权形成以前的私人、联盟或流动军团表现仍只归第一项，不能冒充国家军事体系。

体系崩溃必须先作为事件事实登记，再按覆盖范围、持续时间、是否成为任期主导状态及本人任内是否恢复裁定C3；单次发生中央级崩溃不自动等于C3-0。

## 五、总体档与计分

```text
C总体档级别 = min(C1基础档级别, C2封顶档级别, C3封顶档级别)
```

任一必要档位为`UNKNOWN`时，C总体档和得分均保持`UNKNOWN`。C2、C3只能验证或压低C1，不能抬高C1。

总体档对应得分率区间：`C0=0%—29%、C1=30%—44%、C2=45%—59%、C3=60%—74%、C4=75%—89%、C5=90%—100%`。只用三轴整数会使所有`4/4/4`机械同分，但直接套用胜绩数量公式又会把不同规模、不同O档和重复登记的战争混为一谈。因此档内位置采用“轴差基础位置＋显式同档裁决”：设`g=min(C1,C2,C3)`，`s=(C1-g)+(C2-g)+(C3-g)`；当`g<5`时：

```text
a = s / [2 × (5-g)]
p = max(a, 显式同档位置)
显式同档位置：LOW=0.25、MID=0.50、HIGH=0.75；无裁决时等于a
得分率 = 区间下界 + (区间上界 - 区间下界) × p
C项得分 = 50 × 得分率 / 100
```

三轴均为5时得分率100%、C项50分。最低轴决定区间，其他两轴先决定档内基础位置；显式位置只能在本档内抬升，不能跨档。`4/4/4`必须逐人裁定LOW／MID／HIGH，理由至少同时交代去重后的重大胜负、O档或任务规模、方向跨度、持续性／组织反证中的相关维度；不得只按胜绩数量、任务数量、在位年数或战役卡数量赋位。由此，窝阔台凭灭金O5及跨东亚—西方的干净多方向交付处C4高位，杨坚因样本集中且保留高句丽重大失败处C4中位，二者不再机械同分；王建虽有多项胜绩，但主要限于单一宏区，也只处中位。当前批次以`4/4/4`全体为强制闭合范围；其他轴组合仍先沿用轴差基础位置，待同组合横向审计后再开放显式档内裁决。

`C1`、`C2`、`C3`各自都必须允许0—5六档由事实直接裁定，任何一轴不得因实现默认值、样本公式或封顶顺序形成永久不可达档。样本数只限制证据能支持的最高档，不替代事实裁决：任一轴取5均须至少三个跨期高难度父任务；这里的“高难度”不得由C结算者重新主观命名，必须引用公共战役登记统一组合或第一项A竞争格局中的`opponent_system_ref`，并由其`organization_grade`达到`O4—O6`证明。`C1-5`还必须闭合至少两个不同的上述对手体系；`C2-5`必须闭合多个独立战略方向、至少两个不同的上述对手体系，并证明各方向均能长期保持顶级动员、补充、后勤和恢复且无战役群级保障崩溃；`C3-5`必须闭合至少两名`top/historic`武将分别取得`A+`显著成果。对应的全面崩溃事实则分别允许三轴到0档。生成器和测试必须分别证明三轴六档可输入、可保存、可参与`min(C1,C2,C3)`，不得只证明`C-5`总体可达。

C4、C5另过重大胜绩门禁：C4必须至少有1项已经按主体与父级战役去重、且足以证明国家军事体系在高难度任务中兑现的重大胜绩；若保留`F`项重大体系失败，则重大胜绩至少也须有`F`项。C5必须至少有3项上述重大胜绩且重大体系失败为零，并另过分轴门禁：C1多个高难度对手、C2多个独立战略方向、C3多名顶级武将分别交付显著成果。普通守边、零散小胜和更多观察卡不能补足这些数量或维度。

## 六、证据合并

1. 按皇帝完整统治期合并主要战争系列，不按战斗、方向或将领数量累计。
2. 战争父树跨越两位皇帝时，仍引用唯一终局父事件作为稳定键，但只消费本人任期内已经发生的阶段事实；继任期战果、失败和收束不得倒灌前任。
3. 战役账提供任务、难度和结果；军事体系观察账组织三类事实；战争成本账只向C2提供动员与军资事实，不在C重复结算代价。
4. 同一失败可同时证明实战未兑现、保障失效或组织失灵，但最终只通过基础档和封顶关系影响一次C总体档。
5. `major_system_failure_refs`只登记足以改变任期军事体系判断的重大失败，并引用已经按同一主体结算、去重后的战役群；不得从P/M/A/WC成本档或单张负收益阶段机械推导，不收纳普通伤亡、民众受害和孤立战术波动。第一项C个人战果自动桥接为第三项重大体系胜负时只接收`S-／S／S+`，`A`及以下只进入能力证据；若某条`A`事实确实足以改变体系判断，必须由C人物裁决显式登记，不得依靠档位自动升级。
6. 战役群级失败至少满足其一：主力或关键集团军遭毁灭性损失；整组战略行动因动员、补充、运输、军需或军令失灵而崩溃；一个主要方向因组织失灵连续失效。单支部队失利、局部警戒错误或有序撤收不自动构成。
7. 未完成单次最高目标不自动构成战役群级失败；主力保存、撤收有序且后续战略仍能连续执行时，应按局部未兑现处理。
8. C的计分样本是已经形成实质军事投入、可检验体系交付的规范父周期（`independent_task_groups`），不是全部战术观察节点。它与D的`material_parent_cycle_refs`使用同一父级收束口径；另有足以改变C档的重大体系胜负时可以补入，并必须标记`c_only_major_parent_refs`；经上一节边界复用的统一链能力证据标记`capability_only_parent_refs`。原始观察父周期数和未进入计分的低强度观察数分别保存，不能混作样本厚度。只有一个体系压力父任务时，C1、C3原则上最高为3；至少两个才可支持4；至少三个跨期、跨方向的高难度任务才可支持5。
9. 单个战役群只有在跨多年、包含多个可独立失败的战略阶段，并经多个方向或将领更替检验时，才可人工裁定为“等价多任务”；必须列出阶段，不得由卡数自动推定，且不能单独支持5档。
10. 任一C轴拟取5时必须输出`c5_axis_gate`：C1逐一列出`opponent_system_ref`、公共O档及其父任务，C2逐一列出战略方向、该方向的`opponent_system_refs`及父任务，C3逐一引用至少两名`top/historic`武将档案及其本人`A+`成果。C生成器必须从公共O档事实源读回档位并校验任务归属，配置不得自行填写或覆盖`organization_grade`。任一轴未通过时只将对应轴封顶4档，不连带压低已经独立通过的其他轴。C4、C5的`major_system_success_refs`仍须满足上一节重大胜绩数量门禁。没有实战体系压力父周期时，即使存在持续性、军制或体系材料也保持`UNKNOWN`；有实战任务后，C2、C3所需材料仍须分别充分，不得以无记载推定正常。
11. 生成器必须拒绝C1或C3超过样本上限、没有体系压力父任务且没有非战争体系证据却直接结算，以及重大胜负引用不属于本人计分父任务的记录。薄样本可以在边界内保守结算，但不能因“没有记载失败”推定高可靠；厚样本只提高可检验上限，不自动加分，反复失败必须按实际表现压低C1或C3。C1、C2、C3档位来自事实裁决，不得由样本数公式机械抬高或平均稀释。
12. C项生成器必须输出父级周期合并裁决，并校验`independent_task_groups`只含收束后的规范体系压力父周期。任何被合并成员不得继续作为另一项任务或重大体系失败重复出现；同一主体AB的`parent_cycle_refs`和`defense_event_count`同步使用这一计分父周期集合。`settled_event_refs`只承担原始WAR卡追溯，不等于样本数；`major_system_failure_refs`必须引用`independent_task_groups`中的规范父周期，不得继续引用已吸收的WAR子卡。
13. `major_system_success_refs`和`major_system_failure_refs`只登记足以改变高档或崩溃判断的重大结果，二者同时为零不等于没有胜负事实，也不得自动推出C3。正式记录必须同时输出`task_outcome_profile`，按当前C体系压力父周期展示高收益、相称收益、低收益、负收益和未知数量，并声明剖面来源。C1、C2、C3仍由各自事实边界裁决，但批量3/3/3不得只以“无重大胜负”或样本上限作依据；裁决理由中的任务数必须与当前`independent_task_count`一致，父周期收束后不得保留旧数量叙述。

## 七、最小输出

每位皇帝只保留一条当前记录，至少包含：`ruler_id、reign_range、combat_delivery_grade、operational_sustainability_cap、system_reliability_cap、C_overall_grade、C_score_rate、C_score_points、C_score_band_position、C_score_position_method、C_score_within_band_adjudication（适用时）、observed_parent_cycle_count、independent_task_count、independent_task_groups、non_scoring_observation_count、task_selection_policy、task_outcome_profile、current_task_basis_reason、parent_cycle_merge_adjudications、cap_reasons、major_system_failure_refs、major_system_success_refs、major_victory_gate、settled_event_refs、non_war_evidence_refs、coverage_status、unresolved_gaps、score_ready=true`。正式文件顶层必须标明`canonical_status=FORMAL_CURRENT`；`database_write=false`只表示本底账不直接写数据库或排名，不影响其作为Git正式计分事实源。
