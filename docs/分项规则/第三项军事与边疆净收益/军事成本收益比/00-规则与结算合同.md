# 第三项D军事成本收益比规则与结算合同

本项以40分评价皇帝完整统治期内的军事投资是否值得。先按独立战略行动周期配对己方军事成本、战役结果与安全控制收益，再合并为皇帝军事投资组合；不按战斗次数平均，也不把档位序号相加。

共享计分材料从[`《资治通鉴》战争计分材料审计索引`](../../../史料通读产物/唐以前编年/00-战争卡审计索引.md)按`WAR-*`键回源；机器计分唯一读取入口为[`D秦至唐皇帝正式结算.json`](../../../评分结算/第三项军事与边疆净收益/军事成本收益比/01-皇帝D项正式结算.json)。

## 1. 事件范围

- `D_STANDARD`：对外战争、战略级内战，以及已经并入战争父卡完整行动周期的实际边防与驻军投入。独立`DEF-*`工程卡当前只服务国防状态与控制轴；未完成全体皇帝主体绑定和周期去重前，不得选择性混入D项。
- `D_INTERNAL_COST_ONLY`：未达到国防安全门槛、但实际消耗国家军事资源的地方镇压或兵变处置。
- 创业统一、兼并战争固定排除；宫禁政变、个人刺杀和未形成国家军事行动的政治暴力固定排除。
- 同一战略目标、连续动员与结果闭合链只结算一次；重新决策、重新动员、目标转换或前一周期已闭合时才拆分。

统一战争只服从战役底账的最终逐卡路由，不得按标题或整个战争群重新推断。跨皇帝周期只结算本人任内决策、投入和阶段结果。

## 2. 成本和收益

成本端分为两层：直接军事成本消费己方军事人员损耗P、军事动员M和军资资产A；战争外部成本消费能够归责于本人战争决策的S、平民P、民役和财政透支后果。敌方人员损失不是己方成本。

S的实际民生财政结果仍由第二项C完整结算；D读取同一事实只回答“军事收益是否值得付出该代价”。主动战争、本人诱发内乱的S从严；外来或继承性威胁造成的S先做责任切分，必要防御不得机械全责。WC只作为P/S/M/A综合严重度和复核门禁，不能与SB、BC或WR做序数加减，也不能在D内与四轴重复累计。

收益端消费战役实际结果、已经实现的WR、战略安全SB/SN和边疆控制BCP/BCN。杀敌、缴获、名义臣服或后任取得的成果，未转化为本周期实际结果时不得计入。

`BCP/BCN`仅记录父战役在“评价主体—任期阶段”视图内的实际净控制变化：`BCP`为取得、恢复或保持的边疆控制增益，`BCN`为丧失、撤离或被敌方夺回的边疆控制减益。二者均为`0—5`绝对档，具体边界、`UNKNOWN`条件和去重方式以[`战争成本安全收益与战争回报档位`](../../../证据规则/战争成本安全收益与战争回报档位.md)为准。战斗胜负、杀敌、缴获或名义关系不自动产生非零BCP/BCN；同一控制变化不得在父子卡、正负档或跨皇帝阶段重复消费。

事件统一分为`HIGH_RETURN、PROPORTIONATE_RETURN、LOW_RETURN、NEGATIVE_RETURN、UNKNOWN`。正式结果、通读卡和生成器不得再混用旧枚举`PROPORTIONATE`；旧枚举只能在当前正式视图中确定性迁移为`PROPORTIONATE_RETURN`，随后仍须按现行父级周期、主体阶段和档位合同重算，不保留旧周期数量、分值或排名。同一事件涉及多个政权或跨越统治转换时，必须建立“事件—评价主体—任期阶段”视图；事件公共行只作事实汇总，不能直接代替各主体的P/M/A、SB/SN、BCP/BCN和回报方向。人工覆盖必须同步给出主体成本、收益档和理由，不得只改`return_class`，更不得把收益未知的事件强制改成高收益。禁止把攻方成本配给守方，也禁止把继任者阶段结果倒灌前任。防御战争的必要成本从宽，但可避免的后勤崩溃、重复失败和本人政策诱发的内乱不得转化为正收益。

## 3. 皇帝组合档

| 档位 | 组合边界 | 40分区间 |
|---|---|---:|
| D-U | 无已闭合实质军事投资周期，成本收益能力未受检验；不赋中性分，不参与总分排名。 | 不计分 |
| D0 | 军事投资是全国性崩溃或覆亡的主导原因，国家级反复透支且几乎无补偿收益。亡国不自动归零。 | 0.0—7.9 |
| D1 | 高成本低收益或负收益长期占主导，反复大军覆没、无功重征或安全控制倒退。 | 8.0—15.9 |
| D2 | 总体明显失衡，存在国家级负收益周期或多项持续低收益，但仍有可确认成果。 | 16.0—21.9 |
| D3 | 成本收益混合且大体可解释，有明显浪费、保持不足或一次较重负收益。 | 22.0—29.9 |
| D4 | 主要投入取得相称或较高回报，成果能够保持，无反复国家级浪费和战略透支。 | 30.0—35.9 |
| D5 | 经多项重大或顶尖成果检验，组合净收益进入历史顶级区间；国家级负收益不得靠普通小胜平均稀释。 | 36.0—40.0 |

### 3.1 组合指标

定档只消费去重后的实质父级周期。P、M、A或归责后S任一成本档，或SB、SN、BCP、BCN任一收益绝对档达到3，视为实质周期。每个正向周期先取`G=max(SB, BCP, WR)`，不把三个轴相加；`HIGH_RETURN`且`G=4`视为重大高收益，`G=5`视为顶尖高收益，`G≤3`为普通高收益。`NEGATIVE_RETURN`且P达到5、M/A任一达到4、本人可归责S达到5、SN/BCN达到4，或已有完整主体阶段裁决明确认定国家级损失时，视为国家级负收益。顶尖高收益是重大高收益的子集，同一父级周期不得重复拆卡计数。

当前秦至北宋118位对象共有550个已闭合实质周期。权重结合当前样本比例与类别实际严重度确定，不采用等差数列，也不以简单逆频率放大稀有类别。当前执行权重均为整数：

| 周期类别 | 样本数 | 权重 |
|---|---:|---:|
| 国家级负收益 | 115 | -8 |
| 普通负收益 | 50 | -3 |
| 低收益 | 123 | -1 |
| 相称收益 | 168 | +1 |
| 普通高收益（`HIGH_RETURN, G≤3`） | 49 | +3 |
| 重大高收益（`HIGH_RETURN, G=4`） | 41 | +6 |
| 顶尖高收益（`HIGH_RETURN, G=5`） | 4 | +10 |

组合净收益指数`Q`为全部已知实质周期权重之和，不取平均。`HIGH_RETURN`直接按本周期的收益绝对档G选择+3/+6/+10，其他回报类别按表中固定权重进入；因此收益档位不是只用于重大门禁，而是Q的直接输入。这样新增正收益必然提高Q，新增负收益必然降低Q，不再出现“多一个相称收益反而降分”，也不把周期数量本身当作成绩。决定性成果指数`J = 重大高收益数 + 顶尖高收益数`；顶尖周期因同时属于重大周期，故贡献2个决定性单位。

### 3.2 统一升档门槛

机器先按Q和J形成原始档位：

| 原始档位 | Q门槛 | J门槛 |
|---|---:|---:|
| D1 | `Q < -16.0` | 无 |
| D2 | `-16.0 ≤ Q < 0.0` | 无 |
| D3 | `0.0 ≤ Q < 12.0`，或Q已达更高档但J不足 | 无 |
| D4 | `Q ≥ 12.0` | `J ≥ 2.0` |
| D5 | `Q ≥ 27.0` | `J ≥ 4.4` |

随后只应用以下通用证据门禁：

- 实质回报闭合率低于三分之二最高D3；存在实质`UNKNOWN`但闭合率不低于三分之二时最高D4。
- D0只由“军事投资是否为全国崩溃或覆亡主导原因”的单独因果裁决产生，亡国不自动归零。
- A/B和C不得再作为D的升降档门禁；相同事实可交叉审计，但不能用其他分项分数补偿或惩罚D。

### 3.3 档内分

D1、D2按Q在本档阈值区间内线性映射。D3—D5同时计算Q进度与J进度，档内位置取两者平均，再线性映射到本档40分区间。D5达到40分所需的Q上界为`36.4`，J满档上界为`7.3`。正式JSON与Markdown中的Q、J和升档门槛统一只保留一位小数。

周期厚度不另设人物专属封顶：Q是逐父周期加总，样本较薄者无法凭比例直接获得厚样本优势；极高质量的少数周期仍可按统一Q、J门槛升档。国家级负收益通过`-8`权重直接进入Q，不再叠加另一套按人数或事件数硬封档，避免同一负项重复惩罚。

`E≤1`标记`UNDER_TESTED`，`E=2—3`标记`LIMITED_EXPOSURE`，`E≥4`标记`SUFFICIENT_EXPOSURE`。D-U不赋分；人工D0覆盖必须保存因果理由。非实质观察节点只保留在审计计数中，不进入Q、J或证据厚度。

## 4. 当前事实链

战役底账决定准入、事件主键和结果；国防安全底账提供SB/SN与BCP/BCN；财政民生战争成本账提供P/M/A。BCP/BCN与SB/SN、WR共同说明收益方向，但不把各档位作加法；返还、成果保持与实际控制必须在同一主体—阶段视图中核对。独立`DEF-*`卡不在当前D项正式结果中选择性取样；以后若接入，必须先完成全量主体绑定、跨卡去重和同一公式复算。正式结算保存皇帝档位、40分、全部计分周期和证据缺口；事件级全量配对及重建程序保留在`tmp/**`，不另造战争事实。

本目录是Git中的当前正式读取入口，不写数据库，不产生总排名。

正式JSON和Markdown必须同时保存五类实质周期计数，且`HIGH_RETURN + PROPORTIONATE_RETURN + LOW_RETURN + NEGATIVE_RETURN + UNKNOWN`必须严格等于`material_cycle_count`；缺少分类或计数不闭合时生成器必须拒绝渲染，禁止把缺失值显示成0。
