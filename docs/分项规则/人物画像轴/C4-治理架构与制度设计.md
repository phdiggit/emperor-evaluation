# C4 治理架构与制度设计能力评估合同

> `FORMAL-V2.5 / ARCHITECTURE-EXTRACTION-GATE`。共同证据、档位与发布要求见[画像总合同](../../项目总纲/皇帝人物画像评估体系合同.md)和[共同数据合同](00-共同数据与发布合同.md)。

## 1. 对象与适用性

C4评价一个人**能否把治理问题转化为可运行的制度安排**：谁负责、谁决定、信息怎样传递、资源怎样分配、出问题怎样纠正。

可以是原创，也可以是选择、整合或改造别人的方案。只批准、改名或沿袭，不足以证明强设计能力；制度有名、工程宏大也不等于本人设计出色。

只要生涯中有实际制度选择机会，就适用，不限于正式在位时期。确无选择机会、纯属名义或完全被架空，才判`NOT_APPLICABLE`。材料不足不等于不适用，不适用也不等于零分。

## 2. 父链、归责与反证

围绕一个完整的制度问题整理证据，称为“父链”：**遇到什么问题 → 当时有哪些可行方案 → 本人怎样选择 → 改了什么安排 → 实际运行怎样**。发生重大故障时，再看是否修订以及修订效果。至少有本人选择、制度变化、运行和来源，不拆成固定子分。

本人贡献与前制、臣下设计、时代积累、继任改造分别说明。臣下提出方案不妨碍高档，关键是本人是否实质参与取舍和整合。其他项目的制度等级、收益或历史影响不能换算成C4档位。

工程建设、财政调整等材料，只有证明了常设的责任、核算、监督、信息或执行安排发生变化，才用于C4。工程规模、产能、税率调整和政策覆盖本身不算治理架构设计。

两项设计只有在问题、治理对象和主要责任关系都能分开时，才算独立验证。同一制度的施工、供给或运行阶段，不另算一项设计。

评估效果也要看制度自身的代价，如权责冲突、信息堵塞、无人负责、最高层过载，或长期依赖强人和非常动员。伦理问题、社会损害及外部冲击，只有与该设计存在直接联系时才作为本轴反证。

设计质量可以通过两种方式证明，具备一种即可：

- **设计后稳定运行**：在不同地区、阶段或压力下仍有效，不靠本人逐项补救。
- **发现故障后有效改造**：改了长期规则、权责或信息安排，并经再次运行验证。单纯督办、换人不算制度改造。

没有发生故障，不要求补出纠错经历；已知故障、本人有权也有可行替代方案，却长期维持或加剧问题，才构成明确反证。材料疏密影响置信度和结论适用范围，不自动升降档。

## 3. 架构量级

AM表示本人设计任务的复杂度，不表示制度在历史上有多重要。

| 量级 | 判断标准 |
|---|---|
| AM1 局部接口 | 改变一个部门、程序、地区或责任环节，通常支持G2/G3。 |
| AM2 全国重要子系统 | 改变全国性但功能较单一的系统，如考试、司法复核、仓储赈济或专项财政。 |
| AM3 国家核心系统 | 解决国家核心治理问题，实质重整至少两个相互制约的权责、信息、核算、监督或执行关系，并形成可运行的主干。 |
| AM4 国家基本运行架构重构 | 一套整合设计同时重写至少三个核心功能之间的关系；或至少两个AM3按同一治理思路协同改造，形成新的国家运行方式。 |

多个制度或AM2不能直接相加成AM4，必须有实际的跨系统整合。同一改革可以独立构成AM4，不必拆成多条，也不因无法拆分而降到G3。

## 4. 档位门槛

大档与档内位置均合看正反证的强度、厚度、本人作用和运行范围。强度看结构问题的难度、选择质量、接口改造及实际效果；厚度看独立问题、阶段、地区或压力下的复验和持续运行，不按制度名称、材料条数或任期长度累加。整合架构的组成部分不重复算独立设计，但其不同功能的实际运行仍能说明整合深度。反证同样核对严重性、持续范围、对主要机制的影响和修复，不能只看有无。

下列量级与角色条件约束可支持的档位，不替代整体能力判断。不得先用正证取得G5，再仅凭反证多少决定LOW/MID/HIGH；正证薄弱者也不因反例少自动取高位，正证厚重者也不因存在严重反例自动取低位。

| 档位 | 表现 |
|---|---|
| G0 | 主要阶段出现罕见的严重设计失能：关键安排广泛失效、制度大规模冲突，或持续推动已明确失败的系统，难以恢复。 |
| G1 | 主要设计反复失灵、反转，已知故障未有效修订，少量成功不足改变总体表现。 |
| G2 | 有真实尝试和局部有效安排，但协调、适配或持续运行明显受限，需要外部补救。 |
| G3 | 主要制度通常可用，但多依赖既有框架、臣下方案或局部修补，尚未显示稳定的突出设计能力。 |
| G4 | 设计能力强，按下列要求区分档内位置。 |
| G5 | 历史罕见的国家架构设计能力，须同时满足下列五项条件。 |

### G4

- **LOW**：一条强AM2/AM3加第二条独立、可归责的设计，或高质量的恢复修补型设计。
- **MID**：至少两条高质量AM2，或一条AM3加较弱但独立的设计。
- **HIGH**：至少一条AM3，加另一种结构问题上的独立AM2/AM3验证；或AM4尝试因本人贡献、稳定性或适配问题而未到G5。

一般需要两项独立设计，至少一项有真实运行反馈或复验。第二项仍须说清问题、本人选择、制度变化和运行；修补也须有实质改造。单一一体化AM4不因缺少第二项而被压回G3。

### G5全部硬门

1. **量级**：达到本人可归责的AM4，证明至少三个核心功能的关系被共同改造；说明去掉最著名制度后，其余安排之间仍有什么联系。不要求另有独立AM3，也不要求剩下另一套AM4。
2. **本人作用**：本人实质承担问题判断、方案选择与跨系统整合；主要是被动批准成熟臣僚方案，原则上最高G4。
3. **运行**：核心结构确实运行，至少一项经历跨阶段、跨压力或退出后的采用验证。
4. **反证**：同类重大结构失灵覆盖主要阶段，原则上最高G4；须说明其如何改变主要设计与运行模式，不要求所有国家功能同时失效。未改变总体模式的失败仍与正向表现共同决定档内位置，不能忽略其严重性或持续性。
5. **重要性验证**：长期采用，或当时国家基本运行直接依赖该安排，至少有一项证据。后世影响只验证设计量级与生命力，不直接换分。

**HIGH**：多个核心功能的共同改造有很强的本人作用，独立问题或不同压力下的高质量运行充分复验；合看成功、失误与修复，主要机制和阶段仍显示突出的协调、适配与稳定性。仅有很厚正证或反证不足以推翻G5，均不够支持HIGH。**MID**：历史级整合与较厚的高质量运行成立，正反表现合看普遍很强，但在设计深度、本人贡献、跨情境复验或主要接口的协调稳定性上，尚未形成HIGH的整体强度。**LOW**：整体已达到历史级整合，正向运行也真实成立，但可归责设计的深度、适用宽度、复验或实际适配仍明显有限；须说明这种整体限制，不能仅以“反证较重”定位。

## 5. 高档复核与发布

G4/G5重点查本人实际贡献、系统协调、信息与决策瓶颈、故障处理及长期运行。G5不能只靠一个著名制度的成果或后世声望维持；要能解释整套国家运行方式怎样改变，并与同量级设计比较。

G5的`architecture_review.basis`须同时说明正反表现的强度和厚度，以及合看后为何支持当前大档与位置；`horizontal_calibration`按共同数据合同保存同轴参照，比较设计问题、本人作用、运行复验及结构代价，覆盖同位置和相邻位置（无同位置或相邻位置对象时明确边界）。比较对象的分数不作公式，不预留任何位置的名额。

名望和档位分布只提供复核线索，不决定名额。发布来源、正反证、本人作用、设计量级及限制。E0或足以改变结论的未决证据问题，不得称为正式验收；E1/E2按共同合同说明置信度和适用范围。最新裁决替代旧档，池外人物单列。

## 6. 跨轴边界

| 相邻评价 | C4怎样区分 |
|---|---|
| 制度行政材料 | 制度贡献、收益和历史影响不换成C4等级；重新判断本人设计了什么、是否运行。 |
| C1 / C2 | 战略选择、认知更新归各自轴；C4看由此形成的制度安排。 |
| C3 / M4 | 个人用人、集团合作归各自轴；C4看固定岗位规则和集团纳入国家组织的制度安排。 |
| M5 | 现有制度内分任务、配资源、督办换人归M5；长期权责、组织和信息规则的改造归C4。临时编组须制度化后才计入。 |
| M1 / M2 / C5 | 军事、外交判断和权力伦理不能换C4；材料只有另能证明长期治理设计时才复用。 |

同一材料可以用于不同轴，但各自要回答不同问题，并说明如何避免重复评价。
