# 画像机器与阅读输出合同

> 共同字段与证据结构见[共同数据与发布合同](00-共同数据与发布合同.md)，上位规则见[画像总合同](../../项目总纲/皇帝人物画像评估体系合同.md)。

## 1. 文件与权责

正式目录为`docs/评分结算/人物画像/`：

| 文件 | 用途 |
|---|---|
| `00-已结算轴正式入口.json` | 唯一入口登记，只收已通过轴级验收的轴；登记来源，不另作裁决 |
| `{axis}/{registered_filename}.json`及同名`.md` | 逐轴正式机器裁决及同值阅读视图；文件名由`config/project.yml`投影到manifest，编号不表示发布顺序 |
| `{axis}/{audit_filename}.json` | 用`audit_kind`区分覆盖、差异、材料密度和事实处置审计，不作第二档位来源 |
| `人物/{ruler_id}.md` | 九轴或用户指定轴组合发布后按需生成，不作机器入口 |

逐轴正式JSON是唯一机器裁决源，不设跨轴哈希同步要求。生成器只按稳定ID投影和排序，不从分离分数数组、姓名表、默认值、上游总分或常量造档。

## 2. 共同输出

轴序为`M1、M2、M4、M5、C1、C2、C3、C4、C5`；轴内按`radar_value`降序、`ruler_id`升序展示，不适用记录列末尾且数值留空。

JSON保留版本、轴、真源声明、对象与来源、`axis_evidence_level`、`output_mode`、G档位置、雷达值、状态与置信度、父情境、典型/短板/阶段表现、冲突复核、标签及限制。逐人另保存`task_code`、代表情境、`typical_pattern`、`counterpattern`、`grade_basis`、`position_basis`和`axis_relevance_check`。

阅读页须与JSON同义同值。跨轴引用同一来源时，说明各轴分别评价什么；辅助投影显示`secondary_projection_reason`。跨轴审计只解释边界，不能替代正式档位。

## 3. 分轴要求

M1自`FORMAL-V1.1`起保留`m1_role_projection`、`m1_role_distribution`，并在G4/G5适用时保存`m1_role_gate_review`。角色分类、高难情境的分布说明及原始角色追溯按[M1合同](M1-军事判断与统帅能力.md#裁决理由与发布约束)执行。生成器不得丢弃`ROLE_SEMANTIC_CONFLICT`、`source_role_conflict_refs`或局部直接指挥阶段。

C5全池表用正式记录的`person_type`概括主要模式，不展示`latent_high_grade_hypothesis`列。逐人保留`political_conflict_scope_status`和`political_conflict_review`，说明冲突合并、去重和强触发线索未命中的筛查结论。

## 4. 生成边界

生成器离线、确定性运行，不使用模型、网络或数据库，只读正式裁决。史料、归责和例外须逐人维护；程序只报`REVIEW_REQUIRED`，不从自由文本或旧shadow自动改档。
