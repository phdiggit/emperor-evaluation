# 画像机器与阅读输出合同

> 本文是[画像总合同](../../项目总纲/皇帝人物画像评估体系合同.md)的职责拆分章节；共同字段与发布边界见[共同数据与发布合同](00-共同数据与发布合同.md)。本次拆分只改变合同物理位置，不改变评分语义、正式数据或验收结论。

共同字段、版本、入口权责、父链结构和阅读视图边界见[人物画像共同数据与发布合同](00-共同数据与发布合同.md)；本节只保留上位权责，不重复定义轴内数据格式。

正式目录`docs/评分结算/皇帝人物画像/`：

- `00-已结算轴正式入口.json`：已正式结算画像轴的唯一入口登记；只登记通过轴级门禁的轴，不拼接未结算轴；
- `{axis}/{registered_filename}.json`及同名`.md`：按入口登记的轴级机器结算与同值阅读视图。历史文件编号不代表发布顺序，实际文件名只从`config/project.yml`投影到manifest；
- `{axis}/{audit_filename}.json`：以`audit_kind`标识用途的轴级审计入口，保存规范入口覆盖、差异复核、材料密度复核和稳定事实单元处置；审计文件不是第二份档位来源；
- `人物/{ruler_id}.md`：待八轴或用户指定轴组合发布后按需生成，不作为机器入口。

入口只发现与登记来源 lineage，不生总分或默认值；逐轴正式JSON是唯一机器裁决源，不建立跨轴哈希同步门。

按正式入口登记的`M1、M2、M3、M4、C1、C2、C3、C5`顺序展示轴；轴内记录按`radar_value`降序、`ruler_id`升序展示，不设名次或其他同分键。

JSON保存版本、轴、真源声明、对象集合/来源 lineage、`axis_evidence_level`、`output_mode`、G档位置、雷达、状态置信、父情境、典型/下沿/阶段、冲突复核、标签与限制；逐人另有`task_code`、代表情境、`typical_pattern`、`counterpattern`、`grade_basis`、`position_basis`、`axis_relevance_check`。审计不是第二档位源。compiler仅按稳定ID投影和排序，不由分离分数数组、姓名表、默认值、上游总分或常量造档；阅读页与JSON同义同值。

compiler离线、确定性、零模型/网络/数据库，只读正式裁决。史料、归责、例外须逐人patch；程序只报`REVIEW_REQUIRED`，不自动改档或读自由文本/旧shadow。
