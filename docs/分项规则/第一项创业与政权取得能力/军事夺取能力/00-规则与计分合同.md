# 第一项C军事夺取能力规则与计分合同

本合同将公共战役登记中已经闭合的本人军事贡献结算为每位评价对象一条第一项C记录，满分100分。C只回答：本人在取得天下、建立政权或取得最高权力的创业战争中实际发挥了多少作用。

输出中的`C1原始值/raw_index`和`C2能力峰值/peak_quality_index`都是用于判档的指数，不是百分制得分率，也不以50为满值；实际分数分别见`C1.points`和`C2.points`。例如C1原始值达到42即进入5档HIGH并取得C1的50/50分，不能解读为“只得到42/50”。

当前公共输入为：

1. [`秦至唐战役公共登记`](../../../公共成果/军事/01-战役登记.json)：提供战役群、统一组合、战略结果档、难度、人物实际贡献、统治者控制、目标缺口和可归责失败；
2. [`秦至唐武将人才等级`](../../../公共成果/军事/02-武将人才等级.json)：只用于解析本人身份、复用本人能力情境并校准其全生涯军事能力上限，不消费其他人才形成团队分；
3. [`公共成果登记与人物画像规则`](../../../证据规则/公共成果登记与人物画像规则.md)：规定战役三轴、人物贡献、统治者控制和人才消费边界。
4. [`创业窗口区域控制与价值输入`](../../../../config/first-item-c-territorial-control-adjudications.json)：供A结算王朝级项目结果；C只读取其窗口边界，不消费净控制数值。

战役登记和人才登记是上游事实源。本合同只能声明创业窗口准入、本人贡献聚合、档位和数值映射，不得修改公共战役档位、人物贡献、人才等级或政治风险。

区域价值不是公共战役属性，不进入战役字母档、军事人才等级或第三项既有结算。王朝级净控制量已经在A评价创业项目规模，C不得再按区域面积或价值给本人重复换分。C1直接消费公共登记已经投影到本人的战役结果档；C2再消费本人实际承担的战斗难度、复验和败责。

## 一、两项结构

| 小项 | 满分 | 评价对象 |
|---|---:|---|
| C1 本人创业战争贡献与成果 | 50 | 本人在创业战役中实际承担的设计、统筹、独立方向和指挥贡献及其结果 |
| C2 本人前线指挥能力 | 50 | 本人作为前线核心统帅实际承担的问题、难度和解题质量 |

两个小项分别定一个`0—5`档和`LOW / MID / HIGH`档内位置，再换算分数。战役只是证据单元，不逐场打分；公共战役结果只有在已经闭合到本人实际贡献时才能进入C。

开国人才团队不属于C。招揽了谁、形成了什么人才与集团组合归B1；如何分工、授权、协调、制衡并维持共同目标归B2。名将受命后独立取得的战果可以证明B项团队实际运行，但不能回流为本人C分。

## 二、创业窗口与准入

### 2.1 合格窗口

只接受直接服务于下列目标、且发生在目标闭合前的军事事项：

- 从有限根据地建立新政权或完成统一；
- 复国、重建中央或从事实分裂中重新取得最高权力；
- 通过公开内战、正规军交战或持续武装竞争取得最高权力；
- 取得权力前已经启动、跨越即位边界但仍属同一未闭合战役群的连续军事行动。

窗口起点是本人开始对军事夺取承担可识别作战设计、战区统筹、独立方向或前线指挥责任的最早事件；终点是最高权力或本次政权创建目标实际闭合。跨即位的同一战役群只保留一个结果，并按本人在各阶段的实际贡献结算。

### 2.2 排除

- 普通继承、禅让仪式、宫廷政变、刺杀、清洗及未形成正规军事争夺的权力转移；
- 已取得最高权力后的普通平叛、边疆经营、对外扩张和常备军事体系运行；
- 只有动员、阅兵、计划或未实施建议而没有独立战役结果的事项；
- `war_terminal`、统一组合根、`SPLIT_CAMPAIGN_PORTFOLIO`父容器及其他不可消费上下文；
- `authorization_only / nominal_only`、制度性默认责任、普通遣将、名义最高统帅及他人独立完成的战果；
- 本人只负责政治联盟、后勤供给、合法性或集团协调而没有实际军事设计、统筹或指挥贡献的事项。

非军事取得权力者不补造战役。材料尚未覆盖与历史上确无本人军事贡献必须分开标记。

### 2.3 最小窗口绑定

每位评价对象必须先形成一条`acquisition_window`，至少保存：

- `ruler_id`、目标、起止边界和闭合状态；
- 纳入与排除的`campaign_group_id / public_outcome_ref`；
- C1创业战役结果清单与C2前线能力全样本清单分别声明；C1可包含幕后作战设计和战区统筹，C2只收本人前线核心指挥；
- 本人在每项战役中的实际贡献、指挥关系和结果范围；
- 跨即位、跨政权和共享战役的切分理由；
- 覆盖状态、证据缺口和来源指纹。

窗口绑定不反写公共登记。`sovereign_at_event=true`只能证明事件当时身份，不能自动证明本人军事贡献；`sovereign_at_event=false`也不能排除本人在称帝前已经承担的实际作战责任。

### 2.4 A所有、C只读的区域控制上下文

区域控制只覆盖创业窗口，不扩展到全部公共战役。当前范围是30个统一、建国或创业兼并组合，以及14个手工声明的创业窗口。其净控制数值由A消费；C只用同一窗口防止越界和跨项重复，输出中的窗口净控制表属于非计分审计上下文。

区域价值采用“时代基线＋窗口例外”两层结构。当前8个价值时代分别为秦楚汉、东汉统一、汉末三国、西晋十六国、南北朝前期、南北朝后期、隋唐创业和晚唐崩解；每个时代必须完整覆盖同一套15个区域。时代切分用于反映长期战争、人口迁徙、军镇结构、交通重组和财赋中心变化，不是王朝标签或人物加成。

每个窗口只保存：

- `baseline_snapshot / terminal_snapshot`：创业起点和目标闭合时的实际控制；
- `value_era_id`：窗口唯一引用的时代区域价值基线；
- `region_value_overrides`：仅当战争破坏、战后恢复、迁都、交通重组或窗口专属史源足以证明基线失真时覆盖，默认必须为空；
- `region_id / region_name / boundary_basis / spatial_scale`：稳定区域身份与范围；
- `control_fraction / control_form`：按`0、0.25、0.5、0.75、1`登记覆盖程度，并区分直辖、可执行宗主权、联盟、军事占领、争夺和无控制；
- `control_change`：首次取得、窗口内恢复、巩固、守成、短期取得、丧失或无持久控制。

每条时代区域基线保存：

- `strategic_importance / strategic_functions`：战略层级及都城、动员、纵深、交通、粮源、财赋、边疆或正统功能；
- `population_capacity / fiscal_supply_capacity`：分开评价当时人口动员与财赋军需承载，材料不足保持`unknown`；
- `profile_status / basis / source_refs`：画像校准状态、判断依据和史源。

窗口净控制只按同一`region_id`的终点覆盖减起点覆盖一次，正向增量与终点丧失都保留。区域很重要不等于战役档应提高，战役档很高也不能替代区域价值。上述数值只服务A的项目规模、效率和稳固，C不得再按本人“分得多少区域”换分。

## 三、统一计分映射

C1、C2使用同一档位—得分率映射：

| 档位 | LOW | MID | HIGH |
|---|---:|---:|---:|
| 0 | 0 | 15 | 29 |
| 1 | 30 | 37 | 44 |
| 2 | 45 | 52 | 59 |
| 3 | 60 | 67 | 74 |
| 4 | 75 | 82 | 89 |
| 5 | 90 | 95 | 100 |

`LOW`表示刚满足本档或存在明显限制；`MID`表示典型满足；`HIGH`表示充分满足并接近下一档但缺少下一档硬边界。不得用自由百分比或战役数量调整档内位置。

`NO_PERSONAL_MILITARY_CONTRIBUTION`表示史实上没有本人军事贡献，C1、C2统一取`0档LOW=0`；不得因“没有失败”取得0档内中高位。0档的`MID / HIGH`只用于本人确有军事尝试和可评价表现、但尚未达到1档正向边界的样本。

```text
C1分 = 50 × C1得分率 ÷ 100
C2分 = 50 × C2得分率 ÷ 100
C总分 = C1分 + C2分
```

每项保留一位小数，C总分使用未四舍五入的小项值相加后再保留一位小数。

## 四、C1本人创业战争贡献与成果

C1评价本人对创业战役的实际贡献及其已经兑现的结果。必须先闭合“本人做了什么—承担哪一部分—形成什么结果”，再按本人结果主峰、独立方向厚度和整个创业窗口中的贡献覆盖裁定一个档位。

### 4.1 合格贡献

- 本人持续统合完整战役群的`integrated_command`；
- 本人独立承担主要方向并形成结果的`independent_direction`；
- 本人提出、主导并持续控制实施的`operational_design`，只消费设计实际形成的结果；
- 本人承担最高现场指挥的`frontline_command`；
- `decisive_creator / decisive_successor / co_decisive`以及本人实际完成部分；
- 本人承担的正向、混合和负向结果，以及有逐字依据的`attributable_failure`。

`operational_direction`必须有详细路线、分路、阶段目标或持续战区统筹，并闭合到实际结果。单纯批准方略、同意出兵、任命统帅、提供兵粮或事后接受成果不进入C1。

### 4.2 六档

| 档位 | 必要边界 |
|---|---|
| `C1-0` | 无本人合格军事贡献，或正负结果相抵后没有形成正向创业战役成果。 |
| `C1-1` | 只形成一项C/B级本人结果，贡献局部且有限。 |
| `C1-2` | 形成一项S-级、若干A/B级或同等的可识别创业贡献。 |
| `C1-3` | 形成多项重要结果，承担一个主要方向或区域政权创业的显著军事份额。 |
| `C1-4` | 形成多项S-/A级成果，承担大型政权创业的军事主体份额。 |
| `C1-5` | 在多个不重复方向持续形成S-以上及A级成果，达到最高创业战役贡献组。 |

### 4.3 聚合规则

1. 只消费公共登记已经闭合到本人的`projected_result_tier`；授权、挂名、普通参与和他人独立成果为零。
2. `terminal_finisher / stage_executor`只消费本人实际完成部分；共同决定者只消费公共人物结果已裁出的个人档，不复制父战役群。
3. 同一`capability_episode_ref`只消费一次；统一组合根与子群、祖先与后代不得双算。
4. 正向和`mixed_review`结果按其已接受的个人结果档计入；明确负向结果按同档值扣除。可归责过失另在C2限制稳定性，同一负向事实不得重复放大。
5. C1不再读取战斗难度。难度只回答“这一仗本人解题有多难”，归C2；C1只回答本人实际交付了多少层级的创业战役成果。
6. 名将、盟军或其他创业成员的成果只保留为组合上下文。无论本人是否招揽、任命或授权，都不得进入本人C1。

### 4.4 战役成果值与C1确定性映射

```text
个人结果值：C=1、B=2、A=4、S-=6、S=9、S+=18
本人C1原始值 = Σ正向个人结果值 - Σ负向个人结果值
```

| C1档 | 原始值范围 |
|---|---:|
| 1 | `(0,4)` |
| 2 | `[4,9)` |
| 3 | `[9,16)` |
| 4 | `[16,28)` |
| 5 | `≥28` |

1—4档的档内位置按本档区间三等分确定；5档以`28—50`作为当前校准区间，并采用固定切点：`[28,36)`为LOW、`[36,42)`为MID、`≥42`为HIGH，不另造第6档。S+取18，是为了使一项已经闭合的时代级个人终局成果不会被三项普通A级成果或纯数量堆叠轻易反超；它仍须经过人物贡献投影，不能消费父战役群标题。原始值小于0的创业失败进入0档MID；有合格军事活动但正负相抵为0进入0档HIGH；没有本人合格军事贡献或采用缺材料默认值进入0档LOW。

### 4.4 档内位置

- `LOW`：刚满足本档；主峰之外缺少独立复验，或存在明显目标缺口、成果脆弱、共同贡献未能进一步拆分。
- `MID`：本档典型样本；本人责任、实际结果、正负贡献和组合去重完整。
- `HIGH`：本档边界充分成立，并有独立方向厚度、稳定兑现或接近下一档的本人结果；但缺少下一档硬边界。

## 五、C2本人前线指挥能力

C2只评价本人作为前线核心统帅的实际解题能力。必须同时具有现场最高或核心指挥责任、本人承担的军事问题、实际结果和本人难度；幕后作战设计和战区统筹即使进入C1，也不能自动进入C2。

### 5.1 合格贡献

- `frontline_command`且本人承担实际最高现场指挥；
- `integrated_command / independent_direction`中本人亲临前线并控制战局的结果；
- 本人作为`decisive_creator / decisive_successor / co_decisive`实际完成的前线部分；
- 本人承担的正向、混合和负向前线结果及可归责指挥失败。

`operational_design`、`operational_direction`、授权、挂名和普通参与若没有本人前线核心指挥事实，一律不进入C2。个人冲阵、受伤、突围、稳定军心和战场威望只有在已经闭合前线指挥责任时才作同档旁证。

### 5.2 六档

| 档位 | 必要边界 |
|---|---|
| `C2-0` | 无本人合格前线指挥结果，或只有幕后设计、授权、挂名和普通参与。 |
| `C2-1` | 有C/B级局部前线指挥或战术结果，但没有A级阶段成果。 |
| `C2-2` | 至少一项本人A级前线结果，或两项独立B级前线结果。 |
| `C2-3` | 至少一项`A/D2+`、`S-/D0—D1`，或多项独立A级前线结果，形成稳定的主要方向指挥能力。 |
| `C2-4` | 至少一项决定性`S-/D2+`、两项独立`A/D3+`，或同等的多方向高难前线复验；重大负向不能形成反复失效模式。 |
| `C2-5` | 满足以下任一路径：`S+/D3+`主峰并另有一项`S-`以上复验；`S/D3+`主峰并另有一项独立`A/D3+`复验；或至少两项`S-/D3+`并有第三项`A/D3+`，形成持续跨情境大统帅履历。单次高光、低难辅助项、纯数量或纯幕后统筹不得进入。 |

### 5.3 聚合与负向

1. C2必须直接消费创业窗口声明的全部战役群，不得只遍历产生区域控制变化的战役；无新增控制的败绩同样进入。
2. 同一能力情境只取一个最高前线结果，不固定取四项，也不把全部结果相加。
3. 最高峰决定能力上限，独立高难复验和跨方向厚度决定是否满足高档。辅助结果只证明厚度，不能与主峰相加后机械跨档。
4. 父级难度不得自动复制给本人；只消费本人实际承担的问题和难度。
5. 战败结果与可归责指挥过失分账：前者记录本人现场结果，后者只收主责错误决策、违令或执行失误；同卡同一事实必须去重。战争行为、政治清洗和普通后方责任不进入C2过失。
6. 一项`S-`以上前线败绩阻断C2-5；一项A级以上败绩通常降低一个档内位置，重复A级以上败绩再降低一个位置。若已经形成至少两项`S-`以上正向前线结果、至少两项`A/D3+`高难复验、至少三项A级以上正向成果且没有`S-`以上败绩或过失，则单项A级败责只保留为稳定性限制，不再机械降位；这只避免“豪华且反复验证的履历被一次普通重大败绩压平”，不适用于正绩稀少者。`S-`以上主责指挥过失封顶C2-3；重复A级以上主责指挥过失阻断C2-5。负向不能反写已经成立的单项能力峰值。
7. 本人全生涯军事等级低于本次C2判定所隐含的能力边界时必须复核身份、窗口、战役切分和贡献；复核前不得以皇帝身份覆盖公共人才档位。创业窗口之后的胜败只作该越界复核，不直接进入第一项C。

单项能力峰值仍将个人战役档映射为`C=1、B=2、A=3、S-=4、S=5、S+=6`，再加`0.3 × D档数字`。该值只描述最强单项，不再跨战役求和；自然上界为`S+/D5=7.5`，不存在溢出。C2档位严格按上述硬门槛裁决，档内位置再看主峰强度、合格复验、持续厚度及负向：仅靠持续多项`S-/D3+`路径进入5档者取LOW；MID须有`S/D4+`主峰及至少两项高难样本；HIGH仅用于`S+/D4+`主峰、至少三项`S-`以上样本、至少三项`A/D3+`样本且没有重大败绩或主责指挥过失。也就是说，正绩数量可以证明进入最高档，却不能代替更高的本人前线主峰取得MID/HIGH。4档中，单项`S/D4`但缺少最高档复验者可以取HIGH。这里使用的都是已经投影到本人且位于创业窗口内的结果，不复制公共父档，也不消费取得最高权力之后的履历。

C2独立采用较宽的百分率表，避免顶端人物在C2权重提高后仍挤在相邻2.5分内：0档为`0/8/16`，1档为`20/25/30`，2档为`34/40/46`，3档为`50/57/64`，4档为`68/74/80`，5档为`84/92/100`（依次对应LOW/MID/HIGH）。C1仍按50分换算，C2百分率乘以50分权重；两轴不再共用同一档位百分率表。

## 六、跨项边界

- A1/A2评价路线选择和总体推进；C1只评价本人已经兑现的军事贡献，不能用战役胜利重复奖励战略判断。
- B1评价非本人团队实际交付的开国成果；B2评价由创业窗口成果证明的顶端贡献者质量。开国团队及他人战果一律不进入C。
- A1评价创业起点、对手环境、资源约束和超额完成度；战役`combat_difficulty`只进入C2本人实际解题边界，不代替总体创业难度。
- 第三项评价取得最高权力之后的安全、边疆、军事体系和成本收益；同一战役必须按创业窗口切分，不能在第一项和第三项重复结算同一种收益。
- 第五项B评价一般性的识人、授权和驾驭素质；第一项B只评价创业阶段人才团队的形成与运行结果。
- 第六项评价关键节点决策质量；具体军事贡献仍只在C结算。

## 七、最小输出

每位评价对象只保留一条当前C记录，至少包含：

- `ruler_id`、`acquisition_window`、`window_status`、`source_registry_fingerprints`；
- `eligible_person_result_refs`、`excluded_campaign_refs`及逐项理由；
- `C1_grade / position / rate / points`、本人主峰、独立方向、贡献覆盖、负向与限制；
- `C2_grade / position / rate / points`、本人前线能力情境、最高峰、复验和负向；
- `C_score_points`、`coverage_status`、`unresolved_gaps`、`score_ready`；
- 机器读取源、同值Markdown阅读视图和`database_write=false`。

没有本人军事贡献时仍输出唯一记录。已有材料足以确认没有本人军事贡献者标记`NO_PERSONAL_MILITARY_CONTRIBUTION`；创业主链缺材料者不得伪装为事实确认的无贡献，必须显式标记`DEFAULT_ZERO_EVIDENCE_GAP`并采用`C1-0-LOW / C2-0-LOW`保守默认。默认记录是canonical当前值，但在补证前不得解释为正式史实裁决。

## 八、正式化门禁

正式结算前必须同时满足：

1. 评价名册全部建立唯一创业窗口，窗口起止、目标和闭合状态无未决；
2. 所有纳入结果都引用当前公共登记指纹，统一组合根与子群、祖先与后代不存在重复消费；
3. 本人身份、贡献、指挥关系和结果范围全部解析，其他人物结果没有回流；
4. C1、C2的0—5档均有实际样本校准，高档执行跨人物横向复核；
5. `DEFAULT_ZERO_EVIDENCE_GAP`必须显式保留默认性质，身份冲突、范围冲突和重复消费均为零；
6. JSON、Markdown链接、UTF-8无BOM、`git diff --check`和生成器幂等性通过；
7. 独立Rule Gold、ScoreContribution和shadow差异门通过，并得到正式评分写入授权。

在门禁开放前，本合同生成秦至清canonical当前值，但不得写正式数据库、第一项总排名或反向修改公共战役与人才登记。

## 九、当前canonical结算

旧版C1按本人分得的区域净控制量换分，与A对王朝级新增净控制规模的结算发生重复，因此已经撤销。当前C1直接累计公共登记已经闭合到本人的不重复创业战役结果，C2继续按前线主峰、复验、败绩和主责过失裁决；两项各50分。

当前控制输入覆盖30个组合窗口和14个手工创业窗口，其起点、终点和区域价值继续供A结算项目规模，并为C提供同一创业窗口边界；所有净控制数值在C输出中明确标为非计分审计上下文。

`first-item-c-registry`当前生成秦至清185人完整canonical记录，其中79名对本王朝建国或统一主链具有实际贡献者进入第一项，106名明确标记`NOT_APPLICABLE_NON_FOUNDER`。资格不按首位皇帝或在位年号判断。每人的C窗口与A统一贡献窗口一致：C1只累计本人actual-control结果，C2只累计本人前线或一体化指挥；授权、挂名、纯作战设计和部将独立成果不进入C2。当前公共人物结果未闭合时标记证据下限，不能把默认0冒充史实确认无贡献。
