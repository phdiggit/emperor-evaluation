## 评价对象

第五项B只评价统治者识人、择人、任人、授权、容纳谏诤、保护表达安全和维持人才生态的能力。评价对象可以是人物、人才群体、任用机制、授权链条或表达安全生态，但它们必须能回到“用人与授权”本项核心。

被任用对象层级只作为权重标签，不单独构成评分体系。顶级人物、制度关键岗位、跨地域或跨系统人才网络可以提高证据重要性；普通个案、低层执行者或偶发任免不得单独支撑高档位判断。

## 证据定级与对象锚点 rubric

本节是 #370 的 issue-level checklist，先用于 Codex 执行批次、PR 说明和人工复核。它不是新 schema、不是新评分引擎，也不改变通用四级证据强度框架。

### 1. I5B 证据强度口径

- 弱正 / 弱负：方向与第五项B有关，但主要是背景、低层个案、间接评价、单句概括或相邻项外溢，剥离后剩余强度较低。
- 中正 / 中负：能直接命中识人、任人、授权、容谏、表达安全或人才生态之一，但仍是单线事件、单个对象或短期材料。
- 强正 / 强负：直接命中第五项B核心，且至少具备稳定授权、结构性团队、反馈入口、人才安全生态、系统性破坏或明显外溢中的一项。
- 极正 / 极负：只作为人工裁判候选；必须呈现系统性、长期性、结构性和高价值对象覆盖，自动流程不得直接写入最终档位、最终分数或排名。

以下情况应停留在 `lead_needs_source_review`，不得转为证据卡：

- 无法定位原典、准原典或可靠 source passage；
- 只能证明人物整体名声、王朝光环、政策结果或战果，不能直接回到第五项B；
- quote/context 不足以判断任用、授权、容谏、表达安全或人才生态；
- 相邻项风险明显，但尚未完成切分；
- 高风险反向线索已经出现但尚未回源，且尚不能判断是否构成第五项B直接风险。

以下情况必须设置或说明 `upper_bound_flag`，默认不得继续上探：

- 证据直接但窄，只证明一次容谏、一次复用、一次任命或单个对象；
- 对象有名但不是第五项B顶级对象或结构型对象；
- 多条材料同类堆叠，只增加 metadata 厚度，不提供新核心；
- 负向反证、时间线逆转或高风险 lead 尚未完成复核；
- 相邻项剥离后第五项B只剩边界剩余。

以下情况必须设置或说明 `mitigation_flag`、`context_effect` 或相邻项切分：

- 同一对象存在追悔、平反、恢复评价、补救、复官、复碑等反转材料；
- 负向材料主要属于谋反、司法严酷、政权安全、行政威慑、战果或政策收益；
- 正向材料主要来自政策效果、军事成果、盛世光环或后世发挥；
- 材料可作为第五项B边界提示，但不足以支撑强证核心。

### 2. 对象锚点角色

对象锚点只能帮助回答对象重要性、I5B 直接度、事件性或结构性、核心覆盖和相邻项剥离问题。对象锚点只能作为定级辅助，不是自动评分、自动档位或对象本身排名。

- 顶级人才 / 团队锚点：可以提高强正候选的对象权重；不能把战果、政绩或整体名望回填为用人分。
- 强但狭窄的人才锚点：可以支撑中正到强正边界；若只证明单次容谏、单次复用或单人拔擢，默认强正封顶。
- 普通称职官员锚点：可以证明基本任用质量；不得单独支撑高档位或极正候选。
- 负向直接安全锚点：若直接破坏谏臣、能臣、表达安全或人才安全生态，可以支撑强负候选；不得把单纯私德、司法残酷或政权安全案未经切分地写成强负。
- 负向相邻案例锚点：可以触发相邻项切分、降温、上限和人工复核；剥离后无直接寒蝉、授权信用破裂或人才生态损害时，不得升为强负核心。
- 未决高风险 lead 锚点：只能保持待回源、待复核或 PR-body 风险说明；不得作为正向加权，也不得在未处理时放行历史顶级 / 历史极限。

### 3. 极正与历史极限门槛

单核心极正只允许在罕见场景中触发。即使只走单核心路径，也必须同时满足以下条件，才可列为极正人工裁判候选：

1. 至少 3 个相互独立的强直接 I5B 顶级对象 / 结构型证据成立；
2. 每个证据对象都指向顶级对象、顶级团队、结构型机制或足以定义人才生态的对象；
3. 三者合并后必须形成历史级团队或长期高质量人才网络，而不是三张事件型正证或同类材料堆叠；
4. 三者都直接落在同一 I5B 核心，不依赖政策结果、战果、王朝光环或对象名声；
5. 已完成正反两向检索、相邻项切分、时间线逆转检查和高风险 lead 处理；
6. PR 说明必须逐条列出对象、史源、证据卡、对象锚点作用和不得回填的相邻项。

以下情况不满足极正或历史极限门槛：

- 只有 3 张正向证据卡，但对象普通、同类重复或互相不独立；
- 只有 3 个正向维度，但没有 3 个顶级对象 / 结构型对象；
- 三张事件型正证不够，除非它们能共同证明历史级团队或长期高质量人才网络；
- 材料主要是事件型、窄幅反馈、个别复用、单次容谏或单人拔擢；
- 负向高风险 lead 尚未处理；
- 仍需要依靠政策收益、军事战果、治世光环或对象历史名望来抬高判断。

本门槛不得写成人物特例或 person-specific override。任何人物若材料主要是反馈、复用、人才通道或单次事件型材料，即使正向明确，也必须在补足至少 3 个强直接 I5B 顶级对象 / 结构型证据，并能合成历史级团队或长期高质量人才网络后，才可讨论历史极限候选。具体人名或高风险 lead 只能作为回源目标、风险说明或相邻项切分对象，不得成为评分豁免。

### 4. 高风险未决 lead gate

批次若识别出高风险未决 lead，应在 PR body 或批次 review log 中明确选择以下状态之一：

- `pending_source_review`：默认状态。线索可能直接影响第五项B高位判断但尚未回源，暂停转卡和正式高位发布。
- `eligible_but_flagged`：线索已初步判断为相邻项主导、弱相关或低可信，但仍需在 PR body 标明风险。
- `blocked_before_formal_score`：线索若属实会直接破坏人才安全、授权信用或表达安全；在回源前不得发布正式分值，不得进入历史顶级 / 历史极限。
- `allowed_with_pr_justification`：已完成回源、切分或排除，并在 PR body 中列明 source、切分理由和剩余风险。

拟进入优秀及以上的候选，至少要说明高风险 lead 的处理状态；拟进入历史顶级 / 历史极限的候选，必须完成高风险 lead gate。

### 5. 关键词补齐与 query lane 报告

关键词补齐、补搜词、对象锚点扩展和相邻项切分线不得写进 `project_config.yml`。这些研究输入必须通过以下持久化位置承载：

- `source_evidence_specs`：批次级 source/evidence 输入、对象清单、优先 search_id、coverage policy 和 evidence policy；
- `query_profiles`：人物或批次的正向、负向、反转 / 相邻项 query dimensions；
- `search_logs`：具体 query lane 的检索入口、结果状态、转卡关系、未决状态和排除理由；
- `source_review_log`：回源结果、未决 lead、排除理由、相邻项切分和 PR 复核说明。

每个 I5B evidence batch 必须报告正向、负向、相邻项 query lanes 的覆盖、转卡、未决和排除理由。报告可以写在 PR body、批次 manifest / review log 或 `source_review_log`，但必须能追溯到相应 `query_profile_id`、`search_id`、source、evidence card 或 exclusion / pending reason。

## 计入第五项B

可计入第五项B的材料包括：

- 识别、拔擢、信任和长期任用关键人才；
- 对能臣、谏臣、异质人才、旧敌或边缘人才的整合与保护；
- 授权专任、权责清晰、避免反复猜忌或任意掣肘；
- 建立或维持表达安全、反馈入口和纠错环境；
- 人才生态的结构性改善或结构性破坏；
- 处置核心人才时是否存在明确事实链条、程序边界、外溢影响和后续补救。

## 不直接计入第五项B

以下内容不得直接计入第五项B：

- 政策最终收益，主要归第二项或第四项；
- 军事战果，主要归第一项或第三项；
- 权力集中、制度控制本身，主要归第五项其他子项；
- 统治者道德残酷性本身，主要归第五项相邻子项或第七项；
- 认知、学习、纠错能力本身，主要归第五项相邻子项或治国能力项；
- 行政执行成效本身，主要归第二项相关子项；
- 后宫、男宠、宦官等身份因素本身，除非其实际干预核心任免、授权、表达安全或人才生态。

## 相邻项切分

材料明显涉及安全、司法、行政、政策或战果时，必须同时记录应切往的相邻项，不得强行纳入第五项B。

- 政权安全案：先判断谋反、叛乱、司法程序和政权安全归属；剥离后只保留对人才安全、表达寒蝉或授权信用的剩余影响。
- 军事失败或战功：战果归军事项；只有错用将帅、任将机制或长期授权失衡才可保留第五项B剩余。
- 政策成败：政策收益或损害归治国、文明或负债项；第五项B只记录用人链条本身。
- 私德与残酷性：道德评价不得直接转写为用人负证；只有实际破坏人才生态或表达安全才进入第五项B。

相邻项主导的大案，剥离后第五项B默认只留中负剩余；若只有轻微外溢或象征性影响，可降为边界负证或备注。

## 专用触发点

第五项B负证触发重点包括：

- 无明确谋反嫌疑而处置核心人才、能臣或谏臣；
- 强嫌疑但未坐实，且证据争议、追悔、恢复评价或反形未具；
- 大规模株连、系统清洗或人才生态污染；
- 身后追责造成现实外溢、信用撤销或群臣表达安全下降；
- 宠信佞臣、近幸用事、后宫/男宠/宦官实际干预核心任免；
- 错用将相导致长期授权失衡，或压制谏臣造成表达寒蝉；
- 强正、强负并存且不能机械抵消。

确有谋反链条的功臣处置，不得机械升格为强负；未坐实但有强嫌疑的疑案默认不得越过中负候选；死后信任逆转若出现公开信用撤销并直接命中谏臣或表达安全预期，默认按中负封顶。只有系统牵连扩大、群体外溢、表达寒蝉或授权可信度破裂等材料，才可支持强负候选；极负必须人工裁判。

## 专用自动结算敏感点

第五项B自动结算层先输出 `band_direction`、`confidence` 和 `rule_hits`；G8 正式算法版本再把同一结果确定为 V3.2 九档、45 分档内区间和可重复候选值。G9 已批准后，可以按同一算法版本发布第五项B人物正式分值和子项排名；阶段总榜、总榜或跨子项总排名仍不在本子项发布范围内。人工复核只检查规则是否误触发、算法是否解释得通、参数与锚点是否合理、数据是否回源完整、相邻项剥离是否正确。

当前专用敏感点包括：

1. 边界负证是否从弱负上调为中负，或从中负上调为强负；
2. 单核心强正是否满足“至少 3 个强直接 I5B 顶级对象 / 结构型证据”门槛；只有对象独立、第五项B直接、相邻项已剥离且高风险 lead 已处理时，才可列为极正人工裁判候选；
3. 相邻项强负剥离后，第五项B是否只剩中负或边界负证；
4. 强负核心是否压制强正底盘；
5. 强正、强负并存时，是否需要净证据池和定档前人工裁判清单。

自动结算替代的是常规人物级/证据簇级人工裁判，不替代规则级复核与最终正式定档确认。规则无法抽象化、schema/回源出现错误或自动结算明显无法解释时，才升级到人物级个案复核。

## 专用上下文字段使用场景

第五项B证据卡遇到以下情况，应使用上下文字段补充记录：

- 单句无法判断任用、授权或处置的前因后果；
- 涉及谋反、清洗、追责、恢复评价、表达安全或相邻项剥离；
- `quote_short` 不足以判断正负方向、强度或裁判桥接；
- 需要解释 `context_effect = strengthen / limit / reverse / split_only / neutral`；
- 需要通过 `adjudication_bridge` 说明上下文为何支持当前 `evidence_role`、`scoring_effect` 或 `cross_item_split`。

上下文机制不得直接用于自动升档或降档。`quote_context` 不是评分自动规则输入，只服务人工审核、回源复核和可追溯展示。长上下文字段展示规则引用 `展示与协作/人工阅读型Markdown导出规范.md`，不得在分项规则中另开展示规范。

## 工作流边界

第五项B执行时应先建立或更新人物级 `query_profile`，同步覆盖授权专任、反馈入口、表达安全、人才生态、异质人才整合和相邻项切分。人工审核只做数据质量、史料回源、上下文充分性、相邻项剥离、规则命中和算法版本审查；不得逐人改写自动结算方向，不得填入人物级人工最终档位、人物级人工最终分数或单人 override。

证据卡必须能直接归入第五项B，或剥离相邻项后仍有第五项B剩余。证据组必须完成相邻项切分，并说明候选强度和人工裁判状态。同类材料达到代表性覆盖后，不继续按条数抬高强度；只有提供新维度、强反证、反转材料或相邻项切分价值时，才更新证据组。

## 禁止事项

- 不得用第五项B规则覆盖其他项。
- 不得把政策收益、军事战果、私德评价或制度控制直接算作用人与授权。
- 不得由自动流程直接写入极负、最终档位、最终分数或排名。
- 不得为第五项B再新增专用分项规则文档或子目录。
- 不得复制通用证据、数据或展示规则长文；应通过链接引用。
