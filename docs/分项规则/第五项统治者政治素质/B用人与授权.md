# B用人与授权

## 定位

本文是第五项B《用人与授权》的唯一分项规则文档，只承载评分边界、规则材料口径、证据簇公式和正式定分公式。检索包、抓包、对象导入、回源状态、健康检查和调度流程见 [`../../数据结构与生成库/I5B数据链运行流程.md`](../../数据结构与生成库/I5B数据链运行流程.md)，不得在本文另写运行手册。

第五项B评价统治者识人、择人、任人、授权、容纳谏诤、保护表达安全和维持人才生态的能力。评价材料可以涉及人物、人才群体、任用机制、授权链条或表达安全生态，但最终必须回到“用人与授权”这一项的规则对象和材料因子。

## 评分边界

### 计入第五项B

可计入本项的材料包括：

- 识别、引入、拔擢、信任和长期任用关键人才；
- 对能臣、谏臣、异质人才、旧敌或边缘人才的整合与保护；
- 授权专任、权责清晰、避免反复猜忌或任意掣肘；
- 建立或维持表达安全、反馈入口和纠错环境；
- 人才生态的结构性改善或结构性破坏；
- 处置核心人才时，能落到具体对象、过错边界、程序边界、外溢影响和后续补救的第五项B剩余影响。

被任用对象层级只通过 `talent_quality_factor`、`object_weight`、`office_weight` 或团队聚合公式影响材料分。不得为顶级人物、开国身份、盛世身份、危局身份或材料密度另设额外档位。

### 不直接计入第五项B

以下内容不得直接计入本项：

- 政策最终收益，主要归第二项或第四项；
- 军事战果，主要归第一项或第三项；
- 权力集中、制度控制本身，主要归第五项其他子项；
- 统治者道德残酷性本身，主要归第五项相邻子项或第七项；
- 认知、学习、纠错能力本身，主要归第五项相邻子项或治国能力项；
- 行政执行成效本身，主要归第二项相关子项；
- 后宫、男宠、宦官等身份因素本身，除非其实际干预核心任免、授权、表达安全或人才生态。

### 相邻项切分

材料明显涉及安全、司法、行政、政策或战果时，必须先记录相邻项归属，再只保留第五项B剩余影响。

- 政权安全案：谋反、叛乱、司法程序和政权安全先切往对应项；剥离后只保留人才安全、表达寒蝉或授权信用影响。
- 军事战果或败绩：战果归军事项；只有错用将帅、任将机制、撤权掣肘或长期授权失衡可保留本项剩余。
- 政策成败：政策收益或损害归治国、文明或负债项；本项只记录用人链条本身。
- 私德与残酷性：道德评价不得直接转写为用人负证；只有实际破坏人才生态或表达安全才进入本项。

相邻项主导的大案，若剥离后只剩轻微外溢或象征影响，只作上下文，不进入信号计算。

### 负向触发点

第五项B负向材料重点包括：

- 无明确谋反嫌疑而处置核心人才、能臣或谏臣；
- 嫌疑明显但未坐实，且责任边界争议、追悔、恢复评价或反形未具；
- 大规模株连、系统清洗或人才生态污染；
- 身后追责造成现实外溢、信用撤销或群臣表达安全下降；
- 宠信佞臣、近幸用事、后宫、男宠或宦官实际干预核心任免；
- 错用将相导致长期授权失衡，或压制谏臣造成表达寒蝉；
- 同一规则下正负材料并存，不能机械抵消。

确有谋反链条的功臣处置，不得机械计为本项负向分。死后信任逆转只有出现公开信用撤销并直接命中谏臣、人才安全或表达安全预期时，才落入具体对象和规则因子。

## 材料策略

第五项B运行时代码只读取结构化表，不从本文临时推断材料筛选口径。规则材料选择策略由 `eval_rule_material_policies` 维护；对象事实由 `raw_objs`、`emp_objs`、`obj_srcs`、`obj_attrs` 和证据簇计算明细承载。

运行时边界：

- 第五项B当前正式计分链只认已回源对象、史源、规则、结构化因子和计算明细。
- `raw_objs` 保持原始对象粒度，不能合并加工；每个 `raw_objs` 至少有一条 `obj_srcs` 史料链。
- `talent_quality` 等对象属性必须来自 `obj_attrs`，不得在写 payload、重算或导出时临场判断。
- 第五项B当前计算链为 `obj_srcs` / `obj_attrs` → `evd_cluster_calc_details.calc_detail` → `evd_clusters` / `emp_item_results`。
- 规则承载对象另由 `rule_evidence_units` / `rule_evidence_unit_members` / `fact_relations` 做影子审计，不直接替代正式证据簇。
- `calc_detail.covered_material_ids`、`scored_material_ids` 和 `supporting_material_ids` 必须能解释材料为何入分、只作上下文或被排除。
- `query_profiles` / `data/query_profile_batches/**`、`search_logs`、`source_review_log` 只记录检索、回源、审查和缺口过程；正向、负向、相邻项 query lanes 的覆盖、对象化、入库、未决和排除理由应在这些链路中保留。
- 不得直接手写人物级分数或单人 override；所有人物分数必须由对象链、证据簇明细和结果公式重放得到。

| `rule_code` | 计分承载 | 特别口径 |
| --- | --- | --- |
| `talent_discovery` | 被发现、引入、召见或拔擢的具体人物 | 人才等级必须来自 `obj_attrs.talent_quality`，计算时不得临场定级。 |
| `appointment_trust` | 被信任、被复用或被错信的具体人物 | 不先套 `direction_sign`；正负由 `trust_validity` 决定。 |
| `delegation` | 被授权对象及其岗位/权责链 | 不先套 `direction_sign`；正负由 `result_feedback` 决定。 |
| `team_building` | 皇帝 I5B 对象池中的人才对象集合 | 使用 `team_core_member_policy`：候选来自带 `talent_quality` 的 `person` 对象，不要求另有 `team_building` 专属 `obj_srcs`。 |
| `tolerate_talent` | 被保护、被容纳、被损害或表达安全受压的具体人才 | 群体、机制、事件和施害者只能作上下文；不得按皇帝身份另设压力基线。 |
| `anti_nepotism` | 被任用、被排挤、干预任免或污染任用秩序的具体人物 | 亲属、私旧、近幸身份不是自动负证，必须有公共能力、岗位适配或任用秩序损害。 |

`obj_srcs` 仍记录对象、史料、分项、规则和方向的事实链，但最终是否作为计分承载、上下文或覆盖缺口，应由 `eval_rule_material_policies`、`rule_evidence_units`、`evd_cluster_calc_details.calc_detail` 和对应计算脚本共同决定。缺少材料的 `rule_code` 不生成证据簇，结果层按 0 处理。

## 证据簇公式

第五项B对应 `eval_items.item_code = I5B`。以下公式按 `eval_rules.rule_code` 维护。

当前证据簇公式版本：

```text
evidence_cluster_signal_v3
```

### 通用因子

通用因子定义见 [`../../证据规则/证据簇计算公式.md`](../../证据规则/证据簇计算公式.md)，本文件只说明其在第五项B中的边界。

- `attribution_factor`：衡量材料能否归因到皇帝本人或其可控制的任用、授权、保全、表达安全决策。
- `source_factor`：衡量史源可靠性和事实链清楚程度。
- `context_factor`：衡量材料在第五项B语境下的剩余相关度、边界强弱和情境修正。

专用因子不得重复承担史源可靠、事实链清楚、皇帝归因或语境边界职责。若材料只能通过通用因子解释强弱，应调整通用因子；若材料命中具体 `rule` 的业务结构，才使用专用因子。

### 共享业务因子

`object_weight` 衡量对象在当前 `rule` 和当前材料中的中心性。它不等同于 `talent_quality_factor`：人才质量评价对象本身的历史能力层级，`object_weight` 评价该对象在本条任用、信任、容谏、保全、处置或人才安全材料中的位置和影响范围。

`object_weight`：

| 值 | 口径 |
| --- | --- |
| `0.8` | 外围、辅助或同一事件中的次要对象，只能说明局部用人、表达安全或人才安全影响。 |
| `1.0` | 常规可计入对象。 |
| `1.3` | 核心岗位、核心能臣、谏臣、功臣、关键负向对象，直接影响本 rule 的任用质量、表达安全或人才安全。 |
| `1.6` | 国家级关键人才、继承或储备人才、历史级能臣名将、核心施害对象；该对象的任用、保全或受损足以显著改变本 rule 结构。 |

`object_weight` 不得替代 `source_factor`、`context_factor`、`attribution_factor`，也不得重复表达 `handling_severity`、`trust_depth`、`authorization_intensity` 或 `office_weight` 已经承担的事件强度和岗位强度。

### `talent_discovery` 发现人才

适用：识别、引入、召见、拔擢此前未进入核心视野的人才。

```text
material_score =
  direction_sign
  * discovery_level
  * talent_quality_factor
  * channel_factor
  * attribution_factor
  * source_factor
  * context_factor
```

本规则中，人才质量是最重要的单项参数。`discovery_level` 只判断发现链条是否成立、发现难度有多高；`talent_quality_factor` 判断被发现对象本身的历史能力层级。人才质量不能替代发现链条，只有已证明被识别、引入、召见或拔擢进核心视野的对象，才可进入本规则。

`talent_quality_factor` 必须由 `obj_attrs.attr_code = talent_quality` 映射而来，计算前若缺失，不得临时决定因子。

`discovery_level`：

| 值 | 口径 |
| --- | --- |
| `0.6` | 只是被动听闻或沿用已有名望。 |
| `0.8` | 接受荐举并纳入视野。 |
| `1.0` | 形成召见、试用或拔擢的完整发现链。 |
| `1.2` | 发现低位、异质、旧敌阵营或被遮蔽的关键人才。 |

`obj_attrs.value_text -> talent_quality_factor`：

| `obj_attrs.value_text` | 因子 | 口径 |
| --- | --- | --- |
| `普通人才` | `0.5` | 只有普通任职或局部能力线索。 |
| `可用人才` | `0.9` | 有明确职能能力或局部贡献。 |
| `重要人才` | `1.3` | 能支撑一条稳定政务、军事、谏议或技术线。 |
| `顶级人才` | `1.8` | 属于一代名臣、名将、核心谏臣或关键制度人才。 |
| `历史级人才` | `2.5` | 对时代格局、国家核心能力或后世评价有显著权重。 |

人才层级不得凭名望、传世光环或材料密度直接定级。修复或新增人才层级时，先补齐“硬通货事实”和“权威评价共识”两层依据：硬通货事实防止空泛称誉，权威评价共识用于低成本判断相对地位。二者只作为对象事实输入和人工定级依据，不直接入分，也不得替代发现链条。

`talent_profile_note` 只用于记录才具层级与公共后果分离的复合画像，不改变 `talent_quality_factor`。复合人物不得通过降低才具等级来表达负面影响；负面公共后果应进入对象链、相应 I5B 负向 rule 或第七项历史负债。

`channel_factor`：

| 值 | 口径 |
| --- | --- |
| `1.0` | 普通单线发现。 |
| `1.2` | 跨阵营、跨身份、寒门或异质人才通道成立。 |
| `1.5` | 形成可重复的人才发现机制或稳定荐才网络。 |

### `appointment_trust` 任人信任

适用：任用、信任、复用关键人才，并赋予可见职责。任人信任必须判断“信任是否合理”；信任佞臣、错信不适任者或把核心权力交给破坏人才生态的对象，应作为负向材料。

```text
material_score =
  trust_depth
  * object_weight
  * trust_validity
  * continuity_factor
  * attribution_factor
  * source_factor
  * context_factor
```

本规则不先套 `direction_sign`。`trust_validity` 可以为负；对象明显不适任、佞幸化、破坏公共任用秩序或造成核心人才生态损害时，深度信任会放大负向分。

`trust_validity` 衡量“信任关系是否产生了可验证的公共任用收益或损害”，不是人才等级代理。高人才等级只能帮助判断对象能力层级，不能直接推导高 `trust_validity`；只有任官、亲近、复用或名望，缺少任后结果、岗位适配或公共能力反馈时，默认不得高于低档。

`trust_depth`：

| 值 | 口径 |
| --- | --- |
| `0.7` | 普通任命或名义性信任。 |
| `1.0` | 有实际职责的任用。 |
| `1.2` | 中枢、军政关键岗位或核心职掌。 |
| `1.5` | 托孤、危局、旧敌转用、重大机密或国家级信任。 |

`trust_validity`：

| 值 | 口径 |
| --- | --- |
| `+1.2` | 旧敌、新进、异质人才或高风险岗位仍能任用，且材料能显示其任后结果、公共能力和岗位适格性较高。 |
| `+1.0` | 有明确任后表现、职责匹配、政策、军事、行政成果或持续复用反馈，能够证明这次信任合理。 |
| `+0.3` | 信任关系存在，但只见任官、亲近、复用或名望，缺少任后结果、岗位适配或公共能力反馈。 |
| `-0.6` | 错信、偏信或亲旧近幸色彩明显，已削弱任用质量。 |
| `-1.5` | 深度信任明显不适任、佞幸化或破坏人才生态的对象。 |
| `-2.0` | 长期信任核心负向对象，并造成系统性任用污染、表达压制或关键人才损害。 |
| `-3.0` | 把核心权力交给直接制造人才安全灾难、授权信用崩坏或大规模排斥称职人才的对象。 |

`continuity_factor`：

| 值 | 口径 |
| --- | --- |
| `0.8` | 短期任用或未形成持续复用。 |
| `1.0` | 稳定任用。 |
| `1.15` | 长期复用或多阶段持续信任。 |

亲属、私旧、近幸、宠臣或权相不是自动负证；只有公共能力链条不足、岗位不适格、排挤称职人才或污染任用秩序时，才转为负向。重大事件进入本项时必须绑定具体被信任对象和具体史料事实，不得只用事件名直接给总扣分。

### `delegation` 合理授权

适用：授权专任、权责配置、任将任相、机要托付。合理授权必须看人岗匹配和结果反馈。

```text
material_score =
  authorization_intensity
  * person_post_fit
  * result_feedback
  * attribution_factor
  * source_factor
  * context_factor
```

本规则不先套 `direction_sign`。`result_feedback` 可以为负；授权给明显不适任对象并造成损害时，材料应进入负向授权簇。战功、政绩或败绩不能作为抽象总分直接进入本项，必须拆到具体授权、撤权、权责配置及其对象。

`authorization_intensity`：

| 值 | 口径 |
| --- | --- |
| `0.6` | 名义授权或职责不清。 |
| `1.0` | 单一领域的真实授权。 |
| `1.3` | 重大军政事务授权。 |
| `1.6` | 国家级、危局或长期关键授权。 |

`person_post_fit`：

| 值 | 口径 |
| --- | --- |
| `0.5` | 人岗明显不匹配。 |
| `0.8` | 匹配关系较弱或只是普通称职。 |
| `1.0` | 人岗匹配成立。 |
| `1.2` | 顶级专长与岗位高度匹配。 |

`result_feedback`：

| 值 | 口径 |
| --- | --- |
| `+1.5` | 重大成功强烈体现授权合理。 |
| `+1.0` | 正常成功或职责履行良好。 |
| `+0.3` | 履职反馈较弱，不足以支撑高强度授权正证。 |
| `-0.7` | 效果较差，显示匹配或授权判断有问题。 |
| `-1.5` | 重大错授、长期错用或对人才结构造成明显损害。 |
| `-2.0` | 关键战机撤权、撤授权或权责反转，直接破坏授权信用或核心人才发挥。 |
| `-3.0` | 错授或撤权造成连续性人才安全灾难、关键团队崩坏或大规模后续损害。 |

结果只能作为 `result_feedback` 的具体履职反馈，且必须同时说明人岗匹配和皇帝归因。只有“授予高位”而匹配和结果都很差时，不得按授权存在记正分。

### `team_building` 建立团队

适用：形成互补团队、核心幕府、中枢班底、荐才网络或长期人才结构。

```text
positive_signal =
  team_quality_signal
  * role_complementarity_factor
  * long_term_stability_factor

team_quality_signal =
  sqrt(sum(positive_weighted_i^2))
  - sqrt(sum(abs(negative_weighted_i)^2))

weighted_i = talent_quality_factor_i * rank_decay_i
```

`team_quality_signal` 从该皇帝 I5B 对象池的具体人才对象计算。候选来自 `emp_objs` 中的皇帝关联人物对象，并要求已有 `obj_attrs.talent_quality`；不再要求对象另有 `team_building` 专属 `obj_srcs`。群体、机制或事件对象不作为单个人才进入排序。人才层级必须来自 `obj_attrs.talent_quality`，不得在证据簇计算时临场补写。

`talent_quality_factor`：

| 值 | 口径 |
| --- | --- |
| `2.00` | 历史级人才。 |
| `1.35` | 顶级人才。 |
| `1.00` | 重要人才。 |
| `0.55` | 可用人才。 |
| `0.55` | 普通人才。 |
| `-0.35` | 佞臣。 |
| `-0.75` | 大佞臣。 |
| `-1.15` | 历史级佞臣。 |

建立团队中的负向人才值只衡量团队结构被近幸、佞臣或破坏性权臣污染的程度，不承担完整历史负债或重大政治伤害扣分。信任、授权、任人唯亲、人才生态破坏和第七项历史负债已有独立负向通道时，不得让单个负向人物在 `team_quality_signal` 中压倒整个人才结构。

`rank_decay` 按 `abs(talent_quality_factor)` 从高到低排序后自动应用：

| 排序 | 衰减 |
| --- | --- |
| 第 1 位 | `1.00` |
| 第 2 位 | `0.90` |
| 第 3 位 | `0.80` |
| 第 4-6 位 | `0.45` |
| 第 7 位以后 | `0.25` |

`role_complementarity_factor`：

本因子只评价团队功能互补，不评价团队稳定性，也不替代 `talent_quality_factor`。判断时按四个粗功能面归类，避免按具体职业、头衔或个案光环碎片化裁量：

1. 决策与战略：大政方向、战略判断、制度方案、关键政策设计。
2. 行政与资源：行政组织、财政后勤、选官用人、执行体系。
3. 军事与安全：军事统帅、边防安全、危机处置、强制力组织。
4. 纠偏与整合：谏议监察、司法纠偏、文化秩序、政治整合。

| 值 | 口径 |
| --- | --- |
| `0.85` | 功能同质化明显，主要集中在单一文官、军功、近幸或地方执行序列。 |
| `1.00` | 常规互补，至少两个功能面有称职对象，但关键功能仍明显依赖同一类人才或同一系统。 |
| `1.15` | 较强互补，至少三个功能面有重要及以上对象承担，并能形成决策、执行和纠偏/安全之间的配合。 |
| `1.30` | 高度互补，四个粗功能面均有重要及以上对象支撑，且其中至少两个功能面有顶级或历史级对象承担核心作用。 |

高档互补必须同时看“功能面覆盖”和“高质量对象是否真正承担该功能”。开国、创业或危局团队若能覆盖决策、资源、军事和整合功能，不因成员后期不稳定而降低本因子；稳定性只进入 `long_term_stability_factor`。

`long_term_stability_factor`：

| 值 | 口径 |
| --- | --- |
| `0.80` | 零散、短期、临时组合。 |
| `1.00` | 稳定团队。 |
| `1.15` | 长期稳定核心班底。 |
| `1.30` | 长期可持续人才结构或成熟中枢团队。 |

同一合传、同一荐才链或同一事件中的对象必须先拆成原始对象，再由团队公式聚合团队质量。负向团队破坏材料不进入 `team_quality_signal`，仍必须绑定具体对象和具体史料。

### `tolerate_talent` 容人保全

适用：容谏、保全能臣、维护表达安全、避免滥杀能臣，以及相关负向反转。

正向材料：

```text
positive_material_score =
  feedback_entry
  * expression_safety
  * protection_repair
  * object_weight
  * attribution_factor
  * source_factor
  * context_factor
```

功臣保全、退场安排或授权信用修复必须落实到具体人物材料进入 `positive_material_score`；群体、机制和事件只能作为上下文或补源材料，不得直接作为本规则计分承载对象。不得按开国、中兴、女性统治者、少数族群、继位危局等皇帝身份另设压力基线。

`feedback_entry`：

| 值 | 口径 |
| --- | --- |
| `0.7` | 单次采纳或个案容忍。 |
| `1.5` | 多次谏诤、犯颜、纠错仍能保留。 |
| `2.0` | 反馈入口制度化，或谏臣能进入中枢议政链条。 |

`expression_safety`：

| 值 | 口径 |
| --- | --- |
| `0.8` | 能容忍但气氛紧张或依赖个案恩免。 |
| `1.0` | 表达安全基本稳定。 |
| `1.2` | 明确保护、保全或鼓励高质量反馈。 |

`protection_repair`：

| 值 | 口径 |
| --- | --- |
| `1.0` | 无特殊补救。 |
| `1.1` | 有恢复、平反、复碑、复官等补救。 |
| `1.2` | 主动保护人才安全或修复授权信用。 |

负向材料：

```text
negative_material_score =
  - handling_severity
  * target_fault_factor
  * object_weight
  * attribution_factor
  * source_factor
  * context_factor
```

`handling_severity`：

| 值 | 口径 |
| --- | --- |
| `0.6` | 象征性信用撤销或轻处分。 |
| `1.0` | 贬黜、压制、表达入口受损。 |
| `1.5` | 下狱、重罚、处死或严重人才安全事件。 |
| `2.5` | 大规模牵连、系统清洗或长期人才生态破坏。 |
| `3.0` | 针对核心能臣、储备或继承人才、功臣集团、表达对象造成灾难级安全破坏，并有具体连坐或处置对象。 |

`target_fault_factor`：

| 值 | 口径 |
| --- | --- |
| `1.5` | 无故构陷、冤杀，或因谏言、表达、纠错而受害。 |
| `1.2` | 过错轻微，处置明显不相称。 |
| `0.8` | 过错边界争议大，或嫌疑明显但未坐实。 |
| `0.4` | 违法乱纪、重大过错或危险行为基本成立，但处置仍显过重。 |
| `0.2` | 谋反、叛乱或严重危害基本坐实，但仍保留极弱的人才安全、表达安全或授权信用残余。 |

重大事件可以跨多个 `rule` 扣分，但每个 `rule` 必须绑定本规则维度下的具体对象、具体史料和具体后果。不得用抽象事件名直接给总扣分。负向计分材料必须绑定被处置、受损或表达安全受压的具体人才；人才群体、人才安全机制、诬陷事件和施害者只能作为上下文或补源材料，酷吏、近幸、佞臣等施害者本人不得作为本规则的受损对象。

### `anti_nepotism` 避免任人唯亲

适用：抑制亲旧、近幸、外戚、宦官、宠臣或小圈子对核心任免的污染；也适用于公开择才、制度化选任、跨身份用人等正向材料。

正向材料：

```text
positive_material_score =
  selection_openness
  * institutionalization
  * office_weight
  * attribution_factor
  * source_factor
  * context_factor
```

`selection_openness`：

| 值 | 口径 |
| --- | --- |
| `0.7` | 个案中能避免明显私旧干扰。 |
| `1.0` | 以能力、职掌或公议为主要任用依据。 |
| `1.2` | 跨宗族、跨身份、跨阵营或破格公开择才。 |
| `1.4` | 制度化、长期化地压制任人唯亲。 |

`institutionalization`：

| 值 | 口径 |
| --- | --- |
| `0.8` | 单次事件。 |
| `1.0` | 多次稳定做法。 |
| `1.2` | 形成制度、规则或可持续选任机制。 |

`office_weight`：

| 值 | 口径 |
| --- | --- |
| `0.8` | 普通岗位。 |
| `1.0` | 重要岗位。 |
| `1.2` | 中枢、军政或继承相关关键岗位。 |

负向材料：

```text
negative_material_score =
  - favoritism_intensity
  * office_weight
  * displacement_harm
  * attribution_factor
  * source_factor
  * context_factor
```

`favoritism_intensity`：

| 值 | 口径 |
| --- | --- |
| `0.7` | 亲旧、私人关系或近幸色彩明显。 |
| `1.0` | 明显以私关系任用不称职对象。 |
| `1.4` | 近幸、外戚、宦官或宠臣持续干预核心任免。 |
| `1.8` | 小圈子、裙带或私人集团系统性污染用人秩序。 |

`displacement_harm`：

| 值 | 口径 |
| --- | --- |
| `0.7` | 未见实际排挤称职人才，主要停留在道德观感或任用观感。 |
| `1.0` | 排挤称职人才或扰乱关键岗位。 |
| `1.35` | 损害团队结构、政策执行或表达安全。 |
| `1.70` | 形成长期制度性任用污染。 |

## 正式定分公式

本节规定 `I5B` 从 `evd_clusters` 生成 `emp_item_results` 的当前公式。证据簇计算见 [`../../证据规则/证据簇计算公式.md`](../../证据规则/证据簇计算公式.md)；本节只处理子项正式分值和 V3.2 档位。

当前公式版本：

```text
item_result_formula_i5b_v9
```

输入：

```text
positive_signal(rule) = evd_clusters.positive_signal
negative_signal(rule) = evd_clusters.negative_signal
max_score             = 45
```

`rule_code` 固定为六项：`talent_discovery`、`appointment_trust`、`delegation`、`team_building`、`tolerate_talent`、`anti_nepotism`。某个 `rule_code` 没有证据簇时，按 `positive_signal = 0`、`negative_signal = 0` 处理，并在计算明细或缺口报告记录 `no_material`。

规则响应函数：

```text
positive_response(signal) =
  5.5 * (1 - exp(-signal / 3.5))

negative_response(signal) =
  7.0 * (1 - exp(-signal / 4.0))

rule_net_effect(rule) =
  positive_response(positive_signal(rule))
  - negative_response(negative_signal(rule))
```

`evd_clusters` 保存未封顶原始信号。定分层只处理边际递减：原始信号越厚，增量越小；正负两侧必须先分别响应后再相减。第五项B只承担用人与授权维度内的直接人才安全、表达安全和人才生态损害；长期、结构性、灾难性的历史负债应切往第七项，避免重复扣分。

基础画像：

```text
base_core =
  0.19 * talent_discovery.rule_net_effect
+ 0.19 * appointment_trust.rule_net_effect
+ 0.17 * delegation.rule_net_effect
+ 0.21 * team_building.rule_net_effect
+ 0.18 * tolerate_talent.rule_net_effect
+ 0.06 * anti_nepotism.rule_net_effect
```

基础得分率：

```text
base_rate = 0.50
          + base_core / 7.5
```

这里使用整体线性校准，而不是给高端单独设置折点。`base_core = 2.25` 约进入优秀线，`base_core = 3.00` 约进入历史顶级线，`base_core = 3.45` 约进入历史极限线。各 `rule` 已在响应函数中完成一次边际递减，定分层不再额外把高材料密度人物压回普通优秀档。

最终得分率：

```text
score_rate = clamp(
  base_rate,
  0.00,
  0.98
)
```

正式分值：

```text
score = max_score * score_rate
```

档位映射沿用评分标准 V3.2：

| 档位 | 得分率 |
| --- | ---: |
| 历史极限 | 96%-98% |
| 历史顶级 | 90%-95% |
| 优秀 | 80%-89% |
| 良好 | 70%-79% |
| 合格 | 60%-69% |
| 一般 | 50%-59% |
| 较差 | 40%-49% |
| 很差 | 30%-39% |
| 极差 | 30%以下 |

公式实现按连续区间判断档位：`0.8956` 仍属“优秀”，`0.5927` 仍属“一般”，不得因百分制整数表述留下小数空档。`tier_band` 只记录档内位置：`高段`、`正常`、`低段`；不得把“优秀上段”“历史顶级上段”写成正式档位。

本公式不设置严重负向硬上限，也不在定分层追加事件补丁。负证已经进入各 `rule` 的 `negative_signal`、规则内部材料乘数和 `negative_response`；是否构成更强压档，应回到对应对象、史料、证据簇和规则内部因子调整。

## 禁止事项

- 不得用第五项B规则覆盖其他项。
- 不得把政策收益、军事战果、私德评价或制度控制直接算作用人与授权。
- 不得绕过已登记公式和回源数据直接写入最终档位、最终分数或排名。
- 不得从评分规则文档推断运行时材料筛选口径；运行时只读规则表、对象表、史料表和计算明细。
- 不得为第五项B再新增专用分项规则文档或子目录。
- 不得复制通用证据、数据、展示或运行流程长文；应通过链接引用。
