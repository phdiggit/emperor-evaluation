# 任务状态机与增量失效

> 状态：`accepted`
> 目标：组件成功不等于流水线成功；每个阶段必须可恢复、幂等、可审计。

## 1. 总状态机

```text
IntakeRequest
→ SourceDiscoveryJob
→ SourceCacheJob
→ AssertionExtractionJob
→ AssertionAcceptanceJob
→ EpisodeReconciliationJob
→ IdentityReviewJob
→ RuleProjectionJob
→ JudgmentJob
→ ScoringJob
→ CoverageEvaluationJob
→ ShadowComparisonJob
```

阶段可按对象并行，但不得跳过必要门禁。

## 2. 任务公共字段

每个 StageJob 至少具有：

- `job_id`
- `job_type`
- `idempotency_key`
- `input_ref`
- `input_fingerprint`
- `status`
- `priority`
- `attempt_count`
- `max_attempts`
- `locked_by`
- `locked_at`
- `lease_until`
- `started_at`
- `ended_at`
- `output_ref`
- `output_fingerprint`
- `blocked_reason`
- `error_type`
- `error_message`
- `policy_version`

## 3. 状态

- `ready`
- `running`
- `succeeded`
- `blocked`
- `retry_wait`
- `failed`
- `cancelled`
- `superseded`

`running` 的 lease 过期后必须可被安全回收；回收增加 attempt，但不得重复提交已完成业务写入。

## 4. 幂等

### 请求级

相同意图、输入版本和策略生成相同 idempotency key。

### 业务写入级

每个阶段必须有数据库唯一键；不能只在 Python 中“先查再写”。

### 输出级

相同 input fingerprint 和 policy version 应产生相同 output fingerprint，除非模型调用被明确标记为非确定性且经过人工门禁。

## 5. Outbox

业务事务完成时同步写出 OutboxEvent；下游从 outbox 消费，不依赖“脚本结束后再顺手执行下一条命令”。

Outbox 至少记录：

- 业务对象与版本；
- 触发原因；
- 下游阶段；
- 去重键；
- 发布状态；
- 失败与重试信息。

## 6. 增量选择

每次运行先计算 delta：

- 新 SourcePassage；
- 新/变更 Assertion；
- 新/变更 Episode；
- 新/变更 Projection；
- 失效 Judgment；
- 失效 ScoreContribution。

下游只处理 delta IDs。不得用“当前皇帝全部材料”代替 delta，除非灾难恢复任务明确批准。

## 7. 版本失效矩阵

| 变化 | Episode | Projection | Judgment | Score |
| --- | --- | --- | --- | --- |
| 新增同义证据 | evidence version | 默认不变 | 默认复用 | 默认复用 |
| 新增冲突证据 | evidence version | 复核适用性 | 可能失效 | 可能失效 |
| 主体/责任/结果改变 | semantic version | 失效 | 失效 | 失效 |
| 人物身份合并 | semantic version | 失效/重指向 | 失效评估 | 失效评估 |
| Rule version 改变 | 不变 | 新版本 | 新版本 | 新版本 |
| 评分公式改变 | 不变 | 不变 | 可复用 | 新版本 |
| 展示摘要改变 | 不变 | 不变 | 不变 | 不变 |

## 8. 快慢通道

### 确定性快通道

- source hash 已存在；
- passage 已接受；
- assertion 完全重复；
- episode fingerprint 命中且无冲突；
- person identity 已确认；
- projection 适用性规则明确；
- judgment cache 有效。

### 歧义慢通道

- 人物身份冲突；
- episode 合并/拆分不确定；
- 责任归因不清；
- 来源互相冲突；
- 规则方向或临界档无法由有限规则确定。

慢通道输出仍需结构化校验与人工/规则接受。

## 9. 失败语义

- 抽取失败不应标记 source cache 失败；
- post-process 失败不应把上游成功任务回滚为“未执行”；
- 下游阻断必须保留 `blocked_reason` 和 recovery action；
- 子进程退出 0 但缺输出契约，任务仍失败；
- 模型拒绝、超时、权限失败和业务校验失败必须区分。

## 10. 灾难恢复

全量重建仅允许：

- 索引或物化视图丢失；
- 领域身份算法发生批准的破坏性版本升级；
- 经审计确认无法增量修复。

要求：

- 独立 rebuild gate；
- 输入快照与 hash；
- 正常写入口冻结；
- dry-run 计数；
- 单事务或可恢复批次；
- 重建后跨层不变量审计；
- 明确释放 gate。

全量重建不得成为普通补证据、补人物或新皇帝入场的常规操作。
