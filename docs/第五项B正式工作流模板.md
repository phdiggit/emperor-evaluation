# 第五项B正式工作流模板

本模板用于第五项B《用人与授权》后续人物批量推进。它固化三人试点经验，但不替代证据卡、证据组或正式定档表。后续新增人物应按本模板执行，避免因人物光环或材料丰厚程度导致流程漂移。

## 一、适用范围

第五项B只评价以下内容：

1. 识人、拔擢、任用。
2. 授权专任、文武分工、关键任务托付。
3. 反馈入口、容谏、表达安全。
4. 人才生态、功臣/谏臣安全感、异质人才整合。

不得回填：

- 战役胜负、边疆收益、军事成果。
- 政策成效、行政执行效果、民生结果。
- 治世光环、总体历史地位、跨项功业。
- 政权安全、司法残酷、政治残酷性本身；这些只能在剥离后保留对人才安全感和表达生态的剩余影响。

## 二、标准流程

每个人物按以下顺序推进：

1. 建立或更新 `data/search_logs.jsonl` 检索线索。
2. 回源后新增或更新 `data/sources.jsonl`。
3. 只对已回源且直接相关的材料建立 `data/evidence_cards.jsonl` 原子证据卡。
4. 对同向、多卡、可裁量材料建立 `data/evidence_clusters.jsonl` 证据组。
5. 导出或刷新净证据池 Markdown。
6. 建立裁量复核视图，检查候选强度、相邻项切分与正负关系。
7. 建立净裁量草案，说明正负抵消后的净方向。
8. 建立定档前人工裁判清单。
9. 生成正式定档表。

## 三、检索包最低要求

每个人物至少应覆盖三类检索：

### 1. 正向检索

- 识人拔擢：识、器、拔、擢、举、任、拜、用、荐。
- 授权专任：持节、都督、总管、专任、委任、分兵、使、遣。
- 反馈入口：纳、从、听、求言、无讳、封事、谏、争。
- 人才结构：旧敌转用、寒门后进、宗室辅政、功臣安排、文武分工。

### 2. 负向检索

- 疑忌、诛杀、下狱、族诛、坐死、徙、牵连。
- 谏臣受压、群臣莫敢言、近臣受辱、身后追责。
- 近幸、佞臣、外戚、宦官、后宫干政。
- 错用将相、压制异见、系统性任人唯亲或唯宠。

### 3. 相邻项检索

当材料明显涉及安全、司法、行政、政策或战果时，必须同时记录应切往的相邻项，不得强行纳入第五项B。

## 四、证据卡建立规则

只有满足以下条件才建证据卡：

1. 已有明确 source_id。
2. 有原文短摘 `quote_short`。
3. `interpretation` 不超出原文短摘支撑范围。
4. 能直接归入第五项B，或剥离相邻项后仍有第五项B剩余。
5. 有明确 `cross_item_split`。
6. `scoring_effect` 只能写候选证据，不得直接入分。
7. `adjudication_status` 使用 `source_verified_pending_human_adjudication`。

只记 search_log、不建卡的情况：

- 线索未回源。
- 来源不可靠。
- 只有同类厚度补充且不产生新维度。
- 主要属于相邻项，B项剩余很弱。

## 五、证据组建立规则

证据组不是新史料，而是证据卡的裁量单元。建立条件：

1. 同一人物、同一子项、同一方向至少有一张强证或多张中证。
2. 证据能够构成某类裁量主题，如人才生态、授权体系、表达安全、功臣安全感。
3. 已完成相邻项切分。
4. 已写明候选强度、上探条件和阻断条件。

候选强度仍使用 1—4：

- 1：弱正/弱负。
- 2：中正/中负。
- 3：强正/强负。
- 4：极正/极负。

极正、极负原则上只由证据组层面人工确认，不能由单张证据卡或历史光环直接推出。

## 六、代表性覆盖与证据饱和

当某人物某子项已经覆盖核心维度，并已有强级或极级候选证据组时，后续同类正证默认只增厚元数据，不自动提高强度。

新增材料只有在以下情况下才可能改变证据组强度：

1. 提供新维度，例如寒门后进、旧敌转用、长期中枢、功臣安全、容谏制度入口。
2. 提供强负证或阻断性反证。
3. 直接改变相邻项剥离后的剩余权重。
4. 使原本单点证据变成结构性证据。

## 七、人工裁判门槛

### 1. 高位正向门槛

- 正向证据覆盖不止一个人物或事件。
- 覆盖识人、授权、反馈入口、人才生态中的多个维度。
- 已完成反向检索。
- 负证不足以直接破坏人才安全感或表达生态。

### 2. 极正门槛

- 多类型人才覆盖充分。
- 异质人才整合、授权专任、反馈入口均有强证或多中证支撑。
- 代表性覆盖达成后，仍有第五项B本项内部的极强剩余。
- 不依赖战功、治世光环或总体历史地位。

### 3. 强负门槛

- 材料直接打在人才安全感、表达安全、授权生态或反馈入口上。
- 若与政权安全、司法残酷、政治残酷性相邻，必须剥离后仍有强负剩余。
- 未回源材料不得作为硬负证。

## 八、正式定档表字段

正式定档表至少包含：

| 字段 | 用途 |
| --- | --- |
| 人物 | 评价对象 |
| 第五项B定档 | 只写档向，不写分数 |
| 稳定性 | 稳定、较稳定、中等稳定、不稳定 |
| 正向依据 | 只写本项直接证据 |
| 负向抵扣 | 写明负证剩余影响 |
| 相邻项剥离 | 写明哪些因素不得回填或压入 |
| 后续复核标记 | 记录待补证、阻断点、上探条件 |

## 九、PR 报告格式

每个第五项B任务 PR 应说明：

1. 新增或更新的 source_id。
2. 新增或更新的 evidence_id。
3. 新增或更新的 cluster_id。
4. 哪些 search_id 已转证据卡。
5. 哪些线索仍未回源或切到相邻项。
6. 是否新增净证据池、裁量复核、净裁量草案、人工裁判清单或正式定档表。
7. 是否定档；如定档，必须说明不含分数、不排名、不跨项汇总。
8. 是否运行并通过验证命令。

推荐验证命令：

```bash
python scripts/validate_evidence.py
python scripts/build_db.py
python scripts/export_md.py
pytest -q
```

## 十、批量推进原则

1. 先试点、再批量，不反过来用批量印象修正试点证据。
2. 高位人物必须先过负证拦截。
3. 低争议人物可用轻量流程，但不能跳过 source/evidence 的基本要求。
4. 同类正证饱和后不要无限堆卡。
5. 每一批结束后先做一致性复核，再进入下一批。
