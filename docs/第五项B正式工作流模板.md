# 第五项B正式工作流模板

本模板用于第五项B《用人与授权》后续人物批量推进。它固化三人试点经验，但不替代证据卡、证据组、裁量总则或正式定档表。后续新增人物应按本模板执行，避免因人物光环或材料丰厚程度导致流程漂移。

相关长期文档：

- 《史料检索总则与项目-人物双轴工作流_讨论版》：说明检索体系与裁量体系的关系。
- 《证据裁量总则_讨论版》：说明证据卡、证据组、净证据池、正负证据组结算和人工裁判触发。
- 《第五项B自动结算规则》：说明自动结算层如何把证据组映射成规则敏感点和带位方向。
- 《检索画像与检索线索字段规范》：说明 `query_profile` 与 `search_log` 的字段格式。
- 《数据层级与批次文件治理规则》：说明长期主表、批次文件、导出视图和临时草稿的留存边界。

## 一、适用范围

第五项B只评价以下内容：

1. 识人、拔擢、任用。
2. 授权专任、文武分工、关键任务托付。
3. 反馈入口、容谏、表达安全。
4. 人才生态、功臣/谏臣安全感、异质人才整合。

不得回填：

- 战役胜负、边疆收益、军事成果。
- 政策成效、行政执行效果、民生结果。
- 治世光环、总体历史地位、跨项功业。
- 政权安全、司法残酷、政治残酷性本身；这些只能在剥离后保留对人才安全感和表达生态的剩余影响。

## 二、检索画像前置规则

批量新增人物时，在建立具体 `search_logs` 之前，必须先建立或更新人物级检索画像。人物级检索画像可落入 `data/query_profiles.jsonl`，或在过渡阶段落入 `data/query_profile_batches/*.jsonl`，但必须能说明后续 search_id 的来源。

人物级检索画像至少包含：

1. 继承的通用画像或规则来源，例如 `inherits_from: QRY-I5B-001`。
2. 本人物第五项B应查的正向维度。
3. 本人物第五项B应查的负向维度。
4. 本人物最容易混入的相邻项风险。
5. 优先生成或已经生成的 search_id 列表。
6. 明确说明：query_profile 只用于生成和审计检索线索，不直接作为证据或评分依据。

具体字段格式以《检索画像与检索线索字段规范》为准。

人物级检索画像的作用是控制检索范围，防止执行时临时偏向某一类材料。例如只查“识人”与“杀功臣”会压窄第五项B，应同步覆盖授权专任、反馈入口、表达安全、人才生态、异质人才整合和相邻项切分。

## 三、标准流程

每个人物按以下顺序推进：

0. 建立或更新人物级 `query_profile`，框定检索范围与相邻项风险。
1. 由人物级 `query_profile` 派生并建立或更新 `search_log` 检索线索。
2. 回源后新增或更新 `source`。
3. 只对已回源且直接相关的材料建立 `evidence_card` 原子证据卡。
4. 对同向、多卡、可裁量材料建立 `evidence_cluster` 证据组。
5. 导出或刷新净证据池 Markdown。
6. 建立裁量复核视图，检查候选强度、相邻项切分、对象层级与正负关系。
7. 建立自动结算规则敏感点清单，抽象出可重复复用的规则问题。
8. 建立自动结算草案，输出带位方向、置信度和规则命中结果。
9. 将旧的人物级人工裁判清单改写为规则级复核清单，避免逐人回审。
10. 规则级复核/自动结算草案确认后，才可生成正式定档表。

## 四、检索包最低要求

每个人物至少应覆盖三类检索：

### 1. 正向检索

- 识人拔擢：识、器、拔、擢、举、任、拜、用、荐。
- 授权专任：持节、都督、总管、专任、委任、分兵、使、遣。
- 反馈入口：纳、从、听、求言、无讳、封事、谏、争。
- 人才结构：旧敌转用、寒门后进、宗室辅政、功臣安排、文武分工。
- 对象层级：顶级能臣、名臣、谏臣、将帅、技术官僚、异质人才。

### 2. 负向检索

- 疑忌、诛杀、下狱、族诛、坐死、徙、牵连。
- 谏臣受压、群臣莫敢言、近臣受辱、身后追责。
- 近幸、佞臣、酷吏、外戚、宦官、后宫干政。
- 错用将相、压制异见、系统性任人唯亲或唯宠。
- 对象层级：顶级能臣受压、顶级谏臣受压、顶级佞臣/酷吏/近幸被重用。

### 3. 相邻项检索

当材料明显涉及安全、司法、行政、政策或战果时，必须同时记录应切往的相邻项，不得强行纳入第五项B。

## 五、证据卡建立规则

只有满足以下条件才建证据卡：

1. 已有明确 source_id。
2. 有原文短摘 `quote_short`。
3. `interpretation` 不超出原文短摘支撑范围。
4. 能直接归入第五项B，或剥离相邻项后仍有第五项B剩余。
5. 有明确 `cross_item_split`。
6. `scoring_effect` 只能写候选证据，不得直接入分。
7. `adjudication_status` 使用 `source_verified_pending_human_adjudication`。

若证据涉及被任用、被压制或被安全压力影响的对象，应在 `interpretation`、`trigger_terms` 或 `note` 中轻量标明对象层级与对象性质，例如“顶级将帅”“顶级谏臣”“酷吏”“近幸”“异质人才”。暂不为臣子另建完整评分体系。

只记 search_log、不建卡的情况：

- 线索未回源。
- 来源不可靠。
- 只有同类厚度补充且不产生新维度。
- 主要属于相邻项，B项剩余很弱。
- 对象层级无法判定且不影响当前裁量。

## 六、证据组建立规则

证据组不是新史料，而是证据卡的裁量单元。建立条件：

1. 同一人物、同一子项、同一方向至少有一张强证或多张中证。
2. 能说明覆盖维度，而不是只堆同类材料。
3. 已完成相邻项切分。
4. 已说明候选强度和人工裁判状态。

同类材料达到代表性覆盖后，不继续按条数抬高强度；只有提供新维度、强反证、反转材料或相邻项切分价值时，才更新证据组。

## 七、第五项B专用裁量规则

### 1. 被任用对象层级只作权重标签

第五项B可以区分被任用或被压制对象的层级，但不得另建完整臣子评分体系。

可使用轻量标签：

```text
顶级 / 高级 / 中级 / 普通 / 存疑
能臣 / 名臣 / 谏臣 / 将帅 / 技术官僚 / 酷吏 / 佞臣 / 近幸 / 外戚 / 宦官 / 旧敌转用 / 异质人才
```

### 2. 正向对象层级

任用顶级能臣、将帅、谏臣、技术官僚或异质人才，可提高正向证据权重；但必须剥离其具体战功、政绩、政策成效，只保留皇帝识人、授权、纳谏、整合人才和保护表达生态的本项影响。

例如：任用顶级将帅可证明识人授权，但其战役胜负不回填第五项B。

### 3. 负向对象层级

任用顶级佞臣、酷吏、近幸，或压制顶级能臣、核心功臣、顶级谏臣，可提高负向证据权重；但必须剥离政权安全、司法残酷、政策后果和具体私德问题，只保留其对表达安全、任官生态、忠良安全、人才结构的本项影响。

### 4. 同一对象正负反转

若同一顶级对象前期被重用、后期安全预期破裂，应分维度处理：

```text
前期重用 → 识人/授权能力正证
后期反转 → 授权稳定性/人才安全生态负证
```

二者不得简单抵消。单条边界负证应先按四档自动定证，再用 `object_anchor`、`evidence_role`、`mitigation_flag`、`upper_bound_flag`、`cluster_role` 等轻量标签保留边界。只有进入证据组结算、高档位拦截或相邻项剥离争议时，才进入人工裁判。

### 5. 正负证据组结算

第五项B的正负证据组按以下方式结算：

- 普通同维度正负证，可在证据组层面部分抵消。
- 能力正证与安全生态负证，通常分维度共存，不得机械抵消。
- 强正与强负并存时，必须生成净证据池和定档前人工裁判清单。
- 负证具有群体外溢、表达寒蝉或授权可信度破裂时，应触发高档位上探拦截。
- 高档位拦截不等于低档，只表示不得因强正证据直接上探极高档。

## 八、自动结算先行规则

当同一人物的证据组已经进入净证据池时，优先先看自动结算草案，再看规则级复核清单。原则上不再把人物拆回逐条人工裁判，而是只复核规则是否命中：

1. 中负边界是否真的阻断极正上探。
2. 单一维度强正是否已经被正确封顶。
3. 强负核心是否已经压制强正。
4. 相邻项剥离后的剩余强度是否只应默认中负。

只有当规则无法抽象化、schema/回源出现错误，或自动结算明显无法解释时，才升级到人物级个案复核。

第五项B 当前自动结算时，先看规则是否命中，再看带位方向是否被强负核心压制或被边界负证放行，不再把常规审核退回人物个案。

## 九、人工裁判触发规则

以下情况不得直接生成正式定档表，必须先进入人工裁判清单：

1. 拟进入极高档或极低档。
2. 强正、强负证据组并存。
3. 同一顶级对象出现前期重用、后期反转，且其证据组结算或高档位拦截仍有争议。
4. 顶级能臣/谏臣受压，或顶级佞臣/酷吏/近幸被重用。
5. 负证可能构成高档位拦截。
6. 相邻项切分后，本项剩余强度仍有争议。

人工裁判只处理关键冲突。普通弱证、中证、重复材料和低价值线索不应全部堆给人工审核；魏征这类边界单证原则上应先自动定证，再把争议后移到证据组与定档层。
