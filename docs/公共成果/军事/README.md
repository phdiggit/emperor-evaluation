# 军事公共成果

本目录保存秦至清战役登记、武将人才等级与军事行动成本和收益登记的当前 canonical 结果，只保留当前值，历史变更由 Git 承担。文件名沿用既有稳定入口；JSON 内的 `scope` 与分区摘要声明当前实际覆盖范围。

- `01-战役登记.json`：机器读取的完整父战役登记。
- `01-战役登记.md`：战役登记人工阅读视图。
- `02-武将人才等级.json`：只消费最新战役登记生成的人才等级结果。
- `02-武将人才等级.md`：按等级与净值展示的人才等级阅读视图。
- `03-军事行动成本和收益登记.json`：秦至清“评价主体—任期窗口—父投资周期”的九轴历史裁决与审计入口，不再自动生成D档。
- `03-军事行动成本和收益登记.md`：军事行动成本和收益周期的全量精炼索引与统计阅读视图。

人才登记入口及分片声明`evidence_storage=military-talent-evidence-prefixes-v1`。同一人物的`consumed_achievements`、`capability_episode_anchors`、`negative_or_mixed_command_records`、`failure_accountability`内，字段、值及顺序完全一致的连续开头可集中保存于`talent_evidence_catalog`；原记录以`talent_evidence_ref`引用，剩余字段仍在本条`fields`中独立保存。只共享逐字段相同的内容，不按战役ID猜配，不合并个人采用关系、角色或归责；不同文字不改写、不相互覆盖。`load_talent_registry`、军事专题构建器与浏览器读取时展开完整独立对象；写回通过`write_talent_registry`确定性压缩。共享字段覆盖、悬空或越界引用、重复或未共用目录、缺失及未知存储声明均拒绝。该机制只改变存储，不重新生成或重裁人才等级。

`01-战役登记`保存跨评分项复用的战役事实，并保留`subject_phase_views`中的人物阶段经过、归责、来源及阶段成本/收益历史诊断；其中人员损害推定不是史料直接记载的伤亡。`03-军事行动成本和收益登记`保存人物—任期—父周期的历史裁决，与阶段记录颗粒不同，不能因战役或主体相同而互相覆盖。两者物理分离，不将03的整周期裁决回写或并入01。

03分片声明`source_reference_storage=battle-source-reference-lists-v1`，复用来源列表编码：仅在同一周期记录内，将顺序、重复项及内容完全相同的来源列表保存于`source_reference_catalog`，各轴与原字段以`source_list_ref`引用。该存储名称表示共享编码，不表示战役与周期合并。`formal_json_store.load_json`读取分片时展开独立列表。`formal_json_store.write_json`写入展开分片时自动调用`compact_shard`；修改后还须同步入口的分片校验和；正文、归责、九轴裁决及证据路径均保留。索引及引用以现行分片周期ID为准，不从旧任期字符串重造ID。

上述阶段和周期的旧九轴只用于阅读与裁决追溯，不允许旧Q消费，也不按P/S/M/A、SB/SN/BCP/BCN/WR逐票求和产生现行D档。现行D裁决与阶段证据的使用边界见[第三项D合同](../../分项规则/第三项军事与边疆净收益/军事成本收益比/00-规则与结算合同.md)；01的阶段诊断仍由军事专题展示，03仍有正式结果的来源引用，不能因没有自动计分入口就删除。

人员损害阅读说明由01入口的`payload_metadata.personnel_inference_reading`维护，专题索引原样传递：先列`P_observed`及其原有局限，再列现行采用边界，旧区间、中心、估档、置信度和来源在历史推定中完整保留。`P_observed`仍是原记录的摘要，不能仅凭字段名视为已核实人数。阶段引用不证明采用旧估值；失载、低置信及缺少独立下界裁决均不自动等于零损失，也不自动判定旧推定无效。现行成本人数证据按[高档与证据裁决合同§5](../../证据规则/军事成本高档与证据裁决合同.md#cost-evidence)核对，具体采用值读取正式裁决，不从旧中心推导。

当前仓库不再保留战役登记、武将人才等级或旧线性Q的D生成器；这些登记作为已验收 canonical 当前值或审计lineage保留。第三项D正式JSON是裁决唯一真源，可用轻量命令校验：

```powershell
python v4.py third-item-d-verify
```

该命令只读取D正式JSON与同值Markdown，检查人物唯一性、战略链证据、跨项去重、档位点值映射和汇总计数；不会读取AB、C或公共登记，也不会改写正式结果。

本目录不是并行历史库，不保留旧版、运行展开、checkpoint或审计中间结果。

战役登记同时声明`phase_object_storage=battle-phase-objects-v1`。同一战役内，同字段且内容、键序完全相同的各轴来源映射、人物绑定、创业账本及阶段成本/推断对象，可在净节省空间时写入`phase_object_catalog`。每个目录项显式绑定字段名，原采用位置保留`phase_object_ref`；不同人物或阶段的采用位置不合并，不跨战役共享。Python及军事专题浏览器先展开阶段对象，再展开来源列表，每处返回独立副本；未使用、跨字段、悬空及循环引用均拒绝。

战役登记入口及分片使用UTF-8无BOM的紧凑标准JSON：移除嵌套缩进与分隔空格，每条战役保留独立一行，文件仍是完整JSON对象而非JSONL。原文字符串中的空格、换行与标点不变；人工阅读以生成的Markdown视图为主。格式由`write_battle_registry`统一输出，重复写入不会恢复冗余缩进。

战役登记入口声明`source_reference_storage=battle-source-reference-lists-v1`。每条战役内，完全相同且重复出现的较长来源列表集中保存在`source_reference_catalog`，原采用位置以`source_list_ref`引用；不同列表、顺序及重复引用均保留。`load_battle_registry`校验目录并逐处展开独立副本，`write_battle_registry`只接受完整逻辑记录并确定性压缩。目录不跨战役共享；占位符越界、悬空引用、重复目录项及未共用条目均报错。评分与阅读消费者使用统一加载接口；直接读取分片只用于定位战役ID，不将压缩结构作为评分输入。

统一链横向总档改为消费“被实际击败的独立战争机器”，不再由净控制量公式决定。跨项复用的`O1—O6`定义、实际窗口与去重边界统一见[`军事对手战争机器O档合同`](../../证据规则/军事对手战争机器O档合同.md)；统一链再按最高对手层级、同级数量和复合终局落入`H1—H5`，不做复杂数值加总。

O档机器合同与非统一链补充体系位于`config/military/opponent-system-contract.json`；统一链对手实例及H档收束位于`config/military/unification-chain-opponent-calibrations.json`，并确定性进入公共战役登记。同一体系复起或残余只增强原体系韧性，不重新完整消费；内部兵变、政治交付和不可归责瓦解不产生军事击败信用。时期化区域`S/M/R`与战争净控制量继续保留：它们只证明对手根据地能支撑何种战争体系、以及战果是否真正落地；高价值地区里的松散流动军不能自动吃满该地区的军事能量。

秦至清17条统一链在战役登记 JSON 中只使用一个 `unification_campaign_portfolios` 当前合同，秦至唐与唐以后顶层字段完全一致；时期性的控制快照、区域增量和战役群控制效果只放在同构的 `control_audit` 子对象中，不保留唐前/唐后两套业务结构。

当前对手含金量总档为：`H1` 秦、西汉、唐、元；`H2` 东汉、北宋、金灭辽破宋链、明、清创业链；`H3` 晋、清再统一链；`H4` 辽；`H5` 隋与金前史石鲁整合；两个元先世局部兼并低于 `H5`，高丽链不进入当前横向比较。西汉因终结持续压制汉集团的项羽O6进入H1；唐以洛阳—虎牢复合终结王世充、窦建德两个O5进入H1，东突厥O6只进入A项统一环境压力，不因未在本统一链终结而计入H档；东汉由公孙述、隗嚣、张步、李宪四个O4命中H2，没有O5；隋灭陈对象为O4，统一后残余不另计，故为H5。净控制量仍逐区可审计，但只是辅助结果。所有统一与创业兼并记录仍只进入战役底账，国防消费为 `EXCLUDED_UNIFICATION`，不生成成本收益或安全收益结算。

单项战役与普通战役使用同一对手上限：单项实际击毁O6主力或体系，或同一连续战役群复合闭合两套O5，才可到 `S+`；单项实际击毁O5主力或体系，上限 `S`；O4上限 `S-`；O3通常上限 `A`；O1/O2通常不高于 `B`，只有建立国家核心等额外战略结果才可到 `A`。所属国家是O5/O6不表示偏师、守军、复起或残部也是同档；O档只给上限，结果闭合、对手状态和实际主力效果仍可继续下调。普通高档160项已经逐项写入对手信用审计，当前保留高档136项；残部、孤立远征军、局部守军、短期联盟和机械合并的多个政权不得冒充O4。元灭宋与明灭张士诚的父群/跨书终局已各合并一项，不重复消费。

五代十国 45 个 A 级父项已完成人物归责终态：37项按行动句、结果句和定点事实组拆成63条本人子结果及13条败责，8项因缺稳定人物身份或不能闭合单一统帅而登记 `PERSON_COMMAND_UNKNOWN`。辽朝 11 个 A 级父项也已闭合：5项形成5条本人子结果及1条败责，6项保持 `PERSON_COMMAND_UNKNOWN`。两个批次均不再保留 `PERSON_DETAIL_PENDING`。人物子结果另行裁决 `result_tier` 与 `combat_difficulty`，不得继承父项等级；`stage_executor`、`terminal_finisher` 只消费本人完成部分。人才视图中的唐以后人物均为 `evidence_lower_bound`，不冒充冻结终值。

唐以后 S 档复核已改为独立硬 Gate，并先于后续人物归责执行。九个分区原365个A项已完成结构复核，进一步应用O档上限和重复消费校验后，当前唐以后公共战役为 `S` 26项、`S-` 49项，`PENDING_S_TIER_REVIEW=0`，没有可验收的 `S+`。秦至清当前合计 `S+` 2项、`S` 48项、`S-` 150项。统一组合净控制量不会产生S档；人物子结果也不继承父级升档。当前公开战役已无 `PERSON_DETAIL_PENDING`；跨书同一终局只保留一个公共战果和一份人才信用。
