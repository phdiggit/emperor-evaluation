# G2.6D.1 契约硬化与 Graph G3 前置条件

> 状态：`accepted`
> 历史结论：D.1 contract 与纯内存执行器已完成。G2.6E 后续已执行并失败关闭，当前状态见 `13-G2.6E-Graph-Blind-Holdout结果.md`；PostgreSQL G3 继续阻断。

## 1. Review Unit 身份

PropositionCluster 必须携带结构化 `NormalizedTime`、`responsibility_family`、显式或按固定角色优先级解析的 `focal_person_ref` / `focal_role`，以及 secondary participants。Review Unit 身份由 evaluation context、focal person、focal role、responsibility family、结构化相邻时间窗和 proposition semantic hashes 构成。

展示用 `time_expression` 不参与新输入的时间排序。旧 v3 输入缺少结构化时间时标记为 `legacy_unstructured`，只作为开发诊断，不代表新 contract 已满足。

## 2. Assertion 主处置

每条 Review Unit 内的 Assertion 必须且只能有一个主处置：

- `core_of_episode`
- `context_for_episode`
- `unresolved`
- `excluded`

Relation evidence 是附加证据，不能替代主处置。禁止 core 与 unresolved/context 重叠，也禁止用 relation evidence 隐藏未处置 assertion。

## 3. Review 与缓存绑定

EpisodeBoundaryReviewResult 必须绑定：

```text
review unit ref
 review unit cache key
 ordered proposition semantic hashes
 boundary policy version
 output schema version
 model family
```

cache hit 在使用前重新校验全部字段和 assertion membership。失败只重跑缺失 unit；一个 unit 变化不得失效其他 unit。

单个清晰 PropositionCluster、canonical focal person、无 blocking ambiguity、无冲突时走确定性快通道，直接形成 proposed episode，BoundaryReview 模型调用为 0。

## 4. 无损 materialization

BoundaryMaterializationResult 同时返回：

- proposed EpisodePacket；
- versioned EpisodeRelation；
- context assertion links；
- unresolved assertions 与 follow-up；
- excluded assertions；
- 全部 AssertionDisposition；
- review provenance。

context/unresolved 不得在构造 Episode 时丢失。

## 5. 可持久化图对象

EpisodeRelation 具有稳定 relation ID、versioned endpoints、semantic fingerprint、semantic/evidence version、status、passage evidence links、lineage 和 provenance。非 `context_for` relation 不得跨 evaluation context；时间/因果关系不得形成有向环。

RuleEvidenceUnitDraft 绑定 rule version 和 aggregation policy version；成员显式区分 episode/relation 及其角色。聚合策略改变必须生成新 semantic fingerprint，不能复用旧 unit ID。Draft 不能直接成为 Judgment 或 Score。

## 6. 分层 Gate 指标

Graph scorer 同时报告 exact/pairwise/safe-fragment 指标，以及：

- cross-ruler contamination；
- passage lineage completeness；
- primary assertion disposition coverage；
- unresolved assertion rate；
- strict relation precision/recall；
- endpoint-aligned relation precision/recall。

strict relation 是放行 Gate；endpoint-aligned 只用于区分安全 fragment 导致的关系边界偏差。

## 7. 当前开发集诊断

v3 的 76 条 Assertion 仍生成 38 个 PropositionCluster 和 10 个 Review Unit。由于旧输入缺少结构化时间与 canonical focal refs，零缓存执行报告 10 个 pending unit、0 次实际模型调用；不得把 pending 数量记成模型调用数。

施琅已裁定为两个原子 episode：授水师提督；后续授靖海将军、授权攻台及首次受阻。二者以 `renews_authority` 连接，并进入同一攻台用人 RuleEvidenceUnit。六案 ontology 诊断因此达到 28/28，但 v3 正式 blind 成绩保持不变。

## 8. 下一 Gate

下一步是 G2.6E 全新双层 Graph Blind Holdout。历史 Gold 与规则 Gold 必须独立冻结，reviewer 禁止读取 Gold；在首次 graph output 冻结前不得评分。只有 G2.6E 达标后，才可启动 Episode Graph Registry 的同步事务化 shadow runner，不直接建设完整异步 worker 系统。
