# V4 项目章程

> 状态：`accepted`
> 文档版本：`v1`  
> 适用阶段：V4 初始化、三人试点与首条纵向切片

## 1. 项目目的

V4 的目标不是重新包装 V3，而是建立一条可扩展、可审计、可增量运行的历史证据与评分链：

```text
史源内容
→ 可定位段落
→ 来源断言
→ canonical historical episode
→ 规则投影
→ 结构化判断
→ 确定性计分
→ 覆盖与发布门禁
```

V4 需要同时解决三类问题：

1. **历史事实质量**：重要事件能召回、来源可定位、同一事件不重复、不同事件不误合并；
2. **工程可持续性**：新增证据和人物只触发局部增量，不因物理 ID 变化重跑整链；
3. **决策可信度**：规则判断、评分和覆盖结论都可回溯到事件、断言和史源。

## 2. 成功定义

V4 成功不是“脚本可以跑”，而是满足以下性质：

- 同一历史事件跨来源汇聚为一个当前语义主体；
- 新增同义证据不重复计分，也不默认触发模型；
- 无变化重跑不写业务数据、不调用模型；
- 每个正式判断和分数都有完整 lineage；
- 史源覆盖、事件召回、消费完整性分开度量；
- 智能体仅处理规则无法确定的歧义；
- 任一失败阶段可重试，不重跑已成功阶段；
- V3 与 V4 可并行对照且互不写入。

## 4. 非目标

当前阶段不做：

- 全部皇帝迁移；
- 全部七大项实现；
- V3 数据整库迁移；
- V3 分数、排名或判断回填；
- 生产替换、双写或自动切换；
- 通用智能体平台；
- 为未来所有可能需求预建大型 Schema；
- 用数量指标强行均衡朝代、人物或档位分布。

## 5. 决策原则

- 业务语义先于表结构。
- 稳定身份先于运行方便。
- 增量和幂等先于批量重建。
- 可解释的阻断先于“尽量跑完”。
- 正确的缺失状态优于伪造完整。
- 规则输入类型按业务本质设计，不强迫所有规则共享同一中间对象。
- 技术实现可以替换，已接受的领域契约和 lineage 不得被无版本覆盖。

## 6. 角色与批准

当前默认决策角色：

- **业务规则批准**：项目负责人；
- **史源与事件接受**：人工审查或明确规则门禁；
- **架构与契约批准**：专门设计审查；
- **生产切换批准**：独立任务、显式授权、可验证回滚。

模型、worker、CI 和脚本都不是批准者。

## 7. 阶段 Gate

### D0 文档 Gate

领域模型、证据模型、输入类型、状态机、覆盖标准、智能体边界和四份契约均 `accepted`。

### D1 最小 Schema Gate

只为首条纵向切片设计 Schema；数据库级幂等、版本、lineage 和任务 lease 均有测试。

### D2 离线纵切 Gate

三人冻结样本可从输入重复生成相同事件身份、投影和判断草案。

### D3 Shadow Gate

V4 与 V3 对同一 workset 完成差异分类和人工裁定；严重回归为零。

### D4 切换设计 Gate

仅允许提出生产切换设计，不等于批准切换。
