# 配置说明文件规范

## 背景

JSON 标准不支持 `//` 或 `/* */` 注释。本仓库的 `data/configs/**` 是可维护配置，不能把非法注释写进真实配置文件，也不能为了说明文字改变配置语义。

因此，配置说明采用旁路文件：

```text
data/configs/配置说明/<原配置文件相对路径扁平化>.comments.json
```

示例：

```text
data/configs/导出展示配置/第五项B_markdown_view.json
data/configs/配置说明/导出展示配置__第五项B_markdown_view.comments.json
```

`配置说明/` 目录和 `*.comments.json` 只供维护者阅读与 validator 检查，不参与业务逻辑加载。

## 文件格式

每个 comments 文件必须至少包含：

```json
{
  "$schema_note": "本文件为配置说明，不参与业务逻辑加载。",
  "$target_config": "data/configs/导出展示配置/第五项B_markdown_view.json",
  "$description": "该配置文件的整体中文说明。",
  "$fields": {
    "field_labels": "字段名到中文显示名的映射，用于 Markdown 导出表头和字段展示。"
  },
  "$value_notes": {
    "view_profiles.human_review.show_machine_fields": "false 表示人工审核视图隐藏机器追踪字段。"
  },
  "$safe_edit_notes": {
    "field_labels": "可补充新字段中文名，不应删除已被导出使用的字段。"
  }
}
```

字段约定：

- `$schema_note`：固定说明该文件是旁路说明，不参与业务加载。
- `$target_config`：指向被说明的真实配置文件，使用仓库相对路径。
- `$description`：说明该配置文件整体用途和边界。
- `$fields`：说明真实配置中的配置项路径，至少覆盖全部顶层 key 和重要嵌套 key。
- `$value_notes`：说明关键枚举值、布尔值或模板值的含义。
- `$safe_edit_notes`：说明哪些配置项可以安全修改，以及修改时的注意事项。

除 `$schema_note`、`$target_config`、`$description` 等元字段外，说明 key 必须能在真实配置文件中定位到对应配置项。说明文本必须包含中文。

## 覆盖规则

新增或修改 `data/configs/**/*.json` 下的真实配置时，必须同步更新对应 comments 文件。

当前 validator 会检查：

- 每个真实配置 JSON 都有稳定命名的 `.comments.json`。
- `$target_config` 指向对应真实配置文件。
- 每个真实配置 key 都有中文说明。
- 重要嵌套配置项有中文说明，例如 `view_profiles.human_review.table_fields.net_evidence_cards`。
- 说明文本包含中文。
- comments 文件不得引用不存在的配置项。
- `data/configs/配置说明/**` 不会被当作真实配置扫描。

数组型配置按数组项字段集合说明，例如 `第五项B_人物池.json` 需要说明 `person`、`subitem`、`candidate_type` 等字段。

对象型配置按对象 key 路径说明，例如 `第五项B_markdown_view.json` 需要说明 `field_labels.evidence_id`、`value_labels.source_verified`、`table_render_policy.max_inline_table_cell_chars` 等路径。

## 定位说明

要定位某个配置项的中文说明：

1. 找到真实配置文件的仓库相对路径。
2. 去掉 `.json` 后缀。
3. 将相对路径中的目录分隔符替换为 `__`。
4. 到 `data/configs/配置说明/` 下寻找同名 `.comments.json`。
5. 在 `$fields`、`$value_notes` 或 `$safe_edit_notes` 中查找对应 dotted path。

例如：

```text
data/configs/视图配置/第五项B_视图分组.json
→ data/configs/配置说明/视图配置__第五项B_视图分组.comments.json
```

## 修改后验证

修改配置或配置说明后，至少运行：

```bash
python scripts/validate_config_comments.py
```

涉及 `data/`、`scripts/`、`tests/` 或 validation 入口时，开 PR 前运行：

```bash
python scripts/validate_all.py
pytest -q tests/test_config_comments.py
pytest -q
git diff --check
```

如果全量验证生成无关副产物，先记录通过结果，再清理副产物；清理后只做 `git status`、`git diff --name-only`、`git diff --check` 等范围核对，不重复运行会再次生成副产物的命令。
