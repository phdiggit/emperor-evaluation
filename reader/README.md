# 综合阅读层：帝王三镜

将统治绩效、九轴人物画像、历史影响组织为“结果—能力—后效”的并列阅读体验。入口是人物，总览用于发现，人物页承载结论，对照页帮助理解差异，展开依据完成追溯。页面不新增评分、跨体系指数或综合排名。

第三项A的逐人经历、两轴判断、本人责任、评价时期和来源直接维护在`config/third-item/third-item-result-credit-adjudications.json`各轴的`public_reading`中；公开投影保留这些正文，仅从现行合同和正式数值刷新计算、档位说明。AB正式JSON及Markdown、人物概览、第三项详情和对照页采用同一正文，浏览器通过`third-item-a-public.js`排版，不改写历史语句。修改正文后运行`python v4.py third-fourth-item-public --write`与`python reader/build.py`；核对第三项正式结算、公开投影和阅读同值。交班基础状态与本人增量必须分开，0档必须保留；来源中的裁决记录与材料汇集不得冒称史料原文。

第三项B的具体控制对象、逐条裁决叙述、本人贡献、采用边界与来源直接维护在AB正式JSON的B1、B2、B4各轴`public_reading`中。原始率读取现行AB轴的`score_rate`，实际采用率读取结果信用裁决的`adjudicated_*_rate`，另存诊断率不覆盖前两者。公开投影保留正文并刷新空间快照、档率映射与80分合成计算，沿用现行结算取舍，不为显示改分；`third-item-b-public.js`供人物页、详情与对照共用。B4按正式镜像明确区分已确认、缺证与未登记复核，现值保留不冒称新合同复核通过；其证据窗口只到本人交班。引用使用现行区域裁决、归责记录、军事材料及规则，不恢复已退役的B1重审过程文件。验证命令同第三项A，并运行`tests/test_third_item_b_public.py`。

## 信息结构

第四项A的逐人经历、零分理由、本人责任、比较起点、定档依据与逐条引用直接维护在第四项正式JSON的A轴及A影响包`public_reading`中。`fourth-item-a-public.js`供人物概览、详情、对照和[全量单项阅读页](fourth-item-a.html)共用；浏览器只排版，不修正材料方向或拼写历史解释。展示方向按实际正负组件读取，撤销资格的材料保留事实但不参与合成。史料入口、研究页面、相关项目裁决及人物范围记录分别标明，不把相关背景当作A项结果证据。全量入口包含保留的池外单项记录，并明确综合就绪状态。修改后运行`python v4.py third-fourth-item-public --write`、`python v4.py fourth-item-a-views --write`、`python reader/build.py`，再运行对应校验与`tests/test_fourth_item_a_public.py`。刷新保留正文，缺少正文或引用脱离正式来源时失败，不自动生成替代判词。

## 数据与解释边界

- 从`config/project.yml`取得正式入口，以`ruler_id`连接。构建只读正式裁决，不重算档位。
- 统治绩效只消费正式总榜及其分项构成；人物画像与历史影响不进入总分。未入榜不补零。
- 八个能力轴逐轴读取正式档位、位置、发布状态、依据与限制。C5是独立的权力运用风格轴，不解释成能力高低。
- 历史影响直接显示正式等级、四维、性质和判断把握，不数值化，也不与人物画像字母互相换算。
- 跨体系只并列已经裁定的结论与证据，不自动生成“高能低效”“暴君”“名不副实”等额外人物标签。
- 来源链接仍返回正式记录；阅读层的术语翻译、折叠与去重只改变展示，不修改正式JSON。

## 公众展示总原则

综合阅读层默认采用“人物事实是正文，评分体系是注释”的信息层级。第一项“奠基与统一”先按此原则试点，后续再逐项推广。

- 默认层先回答“这个人做了什么、面对什么条件、留下什么结果”，内部指标代号、变量定义、公式和计分中间量统一放进“规则与计算”折叠层。
- 公众层使用稳定的人类可读标题，不把`A/B1/B2/C`、`U`、`R/O/L/D`等内部编码直接作为阅读标题或正文语言；内部记录继续原样保留，便于审计。
- 字母等级只在“越高越强”的语义一致时公开使用。负向成本不反用S—E，而单独使用“无显著代价—灾难级”的严重度刻度，并保留档内低／中／高位。
- 阅读层只能从上游正式裁决与正式归责材料做确定性提炼，不临时发明“某区域为什么重要”等解释。共享项目对公众表述为“本人所承担的成果”，必要时说明“按统一评估口径折算”，避免直接暴露“控制信用、分账”等内部术语。
- 第一项公众层展示“统一成果 / 起点、强敌与速度 / 组织与整合 / 本人统帅 / 战争代价”。A 的逐人标题与短正文分别读取正式公开成果的 `public_question`、`public_story`，默认先读人物自己的问题与成果，再展开归属，最后查看尺度、公式和证据；阅读层不得拼接事实生成正文，缺字段由上游校验阻止发布。
- A 的 `public_boundary` 可明确发布为 `null`，表示没有需要额外列出的个人范围说明；阅读层省略该字段，不补通用限制或空栏目。全国尺度百分比与共同创业者之间的分配是两种不同口径；是否分配按第一项合同§2.2，不把普通下属执行写成已从最高责任者成果中扣除。
- `reader/first-item-a.html`覆盖当前正式 A 来源的全部人物，独立于统治绩效总分是否就绪；由`reader/build.py`统一生成和检查，支持姓名、经历搜索与逐人锚点。人物主页、对照与详情使用同一份上游标题和正文。第一项专页由`home-interactions.js`负责渲染，旧异步增强不替换专页内容，防止丢失锚点与阅读位置。
- A 的全国核心统一尺度、单人／共同项目计算说明读取正式公开成果的 `reading_guide`，本人计算直接读取正式 Markdown 的“计算”字段；浏览器不另写公式或改写归责。统帅战役按战果等级降序列出，逐条标注“前线作战”或“战略统筹”、战果与难度，并直接链接军事档案；不另造“战役含金量分”。
- B1 的逐人阅读问题和正文直接读取正式 Markdown 的“公开阅读问题”“公开阅读正文”；起点、对手、效率三个分数独立展示，不把合计当作能力或纯速度。深层计算来自已校验同值的阶段与公共对手登记，浏览器不重算、补对手或改写计时。`reader/first-item-b1.html`由同一构建命令发布全部适用人物，默认正文之后依次展开事实，再展开公式与史料；人物页、对照与详情共用同一上游投影。

C 的逐人入口由正式 Markdown 明确提供，覆盖与当前 A 适用集合动态核对。`first_item_c_evidence`只从公共战役登记解析本人引用，不读取 M1 或武将汇总；`first_item_c_public`投影已维护的问题、经历、分数和证据处置。默认先读经历，再展开职责、评价与胜败，最后逐条查看公共原字段、窗口及采用理由。已定档战役使用显式公共引用，不按名称猜档案；个人证据节点不伪装成新增战争。

## 轻量加载架构

军队能力的逐轴展开直接展示所引战争事实；`public_reading.axes.*.arguments`维护每条材料为什么支持或限制该轴，引用`evidence_items`中的具体条目。`source_passages`保留既有通读记录摘录，并校验摘录位于声明的原文件与战事段落中；它不是古籍原文复核。仅引用`C-DECISION`总体评价的轴不视为已有具体战争材料，页面明确显示证据展示缺口，不以非空引用数量宣称语义整改完成。

第三项C的经历、三轴分别的依据、本人责任与逐条材料直接维护在正式C记录的`public_reading`。公开投影保留这些正文，计算说明只读取现行三轴、原始总档、资格上限、最终档与档内位置，不改变评分。人物概览、详情和对照共用`third-item-c-public.js`，直接展示全文；C2/C3原始组件保留作同源数据，不重复生成三套总评卡。`third-item-c.html`由同一构建命令覆盖全部正式C记录，包括未进入综合榜者。材料分别标为现行评价判断、既有史实摘要或史料原文；仅为相关材料汇集的，不宣称已建立逐条事实支持关系。旧任务统计不作为当前战略链数量，也不由浏览器删改来修正文义。

军事体系阅读采用逐层展开：全池页先列人物及三方面正式档位，展开人物时才加载该人的完整HTML详情，页面内复用已加载内容与并发请求。三轴分别保留完整论证及每条材料的作用，战事正文、范围、来源与摘录集中展示一次；材料链接会打开对应证据区并定位，人物与材料锚点可直接分享。全部正式正文与证据保留在`reader/data/third-item-c/`的逐人分片中，不截断、不改写。人物页与对照仍使用原共享正文。

全量C页默认搜索人物与经历；选择“完整正文与材料”并输入查询后才加载独立全文索引，不为普通浏览请求全池证据。搜索索引包含所有人物完整展示文字，不只索引摘要；索引失败显示错误并支持重试，不把失败显示成零结果。详情失败可单人重试。分片与索引URL带内容版本，构建及`--check`核对其内容、覆盖和引用，并仅清理此目录中已失效的生成分片。

军事体系的三方面档位旁同时显示正式记录的分界论证状态，明确区分现行结算值与回源支持、分界待证、缺证或须重裁等状态；未知状态不猜译。显式档内裁决须展示采用位置、原裁决理由及其替代结果质量位置后与能力余量取高的计算，各出口使用同一上游投影，不改变正式档位或分数。

全量C页的档位旁直接显示对应轴的现行档义，待定不套用0档。列表前说明三轴取短板、再受资格上限约束、不平均也不分别加分，并提供三方面0—5档含义与最终档分数区间速查。轴档义读取公开投影的`scale`，得分率区间读取现行计算组件的`GRADE_RANGES`；5档按三轴5且全部资格通过时直接50分的现行规则说明，不重算或覆盖人物分数。

深入核查提供统一术语说明。逐条论证按其`evidence_ref`直接链接材料，完整战争与相邻档判断分别列出正式关联的`evidence_refs`，不推断逐句支持关系，也不按战事名称猜配；缺少关联会明确提示。全量C页沿用材料锚点，人物页、详情与对照在当前人物区域内展开并聚焦对应材料，保留主页面路由；链接另可直接打开全量C页的相应材料。完整材料、原记录编号、采用范围、来源和摘录保留，评价判断不伪装为战争事实。

回源补齐的材料在正式C记录的`public_reading.source_reviews`中以`source_material_refs`明确关联，并与战略链写回源`formal_writeback.fields.public_reading`同步，保留摘录与具体采用范围；这只建立事实定位，不自动新增三轴`arguments`或改变评分。`boundary_material_refs`单列跨任期、仅载请求等范围核对材料，不填作本人战争事实。两类引用须指向本人物、本链已关联且带来源摘录的材料，不得混用；未具名任务或未定位到实际过程的，继续保留具体缺口。

军事体系第一方面公开称为“实战表现”。其判断说明直接按现行C合同解释目标完成程度、实际对手、完整交战过程、战果、己方战损与续战能力的关系；目标未成不自动判全役战败，有战果或主力撤回也不自动支持高档。说明由`third_item_c_public.py`统一提供，人物正文之后可展开，人物页、对照、全量C页及Markdown同源展示，不改逐人裁决与分数。

政权交接的经历、定档说明、观察窗口、本人责任、限制和逐条史源读取D1、D3正式记录。`second-item-d1-d3-public --write`只刷新结构元数据和Markdown，不从内部判词重写正文。阅读卡直接展示完整正文及来源摘录，明确区分原文转录、既有摘要和评价判断；详情与对照共用`reader_public_d`，不做中文词语替换或事实拼接。通常三年内的行政运行与最上档长期资产旁证分开说明，交接安全按约一年及同链延续边界展示。`second-item-d.html`展示全部正式交接记录，包括未进入综合榜、没有综合分项详情的对象；原文、评价、范围和来源与主阅读页同值，搜索只筛选可见人物。

第二项C的人物经历、定档理由、损害证据边界、个人限制和逐条史源直接维护在C1—C4正式JSON。`second-item-c-public --write`只同步确定性计算、元数据及四张Markdown阅读视图，不覆盖已写正文。`second-item-c-public.js`供详情和对照共用，只展示上游内容；`second-item-c.html`覆盖全部正式C记录，包括未入综合榜者。默认先读经历，定档、逐条史源、边界、计算分别展开；史料原摘录、既有摘要与裁决依据明确分列。

第二项反馈与约束的定档说明、逐条事实、方向、阶段边界及史源直接维护在正式B2记录。`second-item-b2-public --write`保留正文并同步Markdown阅读段，不从内部判词生成解释。人物概览、对照与详情共用完整正文；`second-item-b2.html`另覆盖正式全池，包括未进入综合榜者。有效机制中的零权重阶段不把整组变成背景。材料来源逐条展开，计算另列；构建与组件校验动态核对覆盖、身份及同值。

第二项制度建设正文、定档理由及逐卡来源直接读取A正式记录的`public_story`、`public_adjudication_summary`和`public_evidence_items`。默认先读人物事实及定档理由，原始指数与公式只在计算折叠层。无节点人物仍展示正式的证据边界，材料列表为空；页面不生成占位卡、数量总结，不改写、截短或拼接历史句子。人物入口和统治绩效总览链接到治国成效页，对照与详情共用同一份正文。

综合页不再把全部人物的完整证据一次性嵌入`reader/index.html`。

- `reader/index.html`只内嵌人物总览和首屏所需的轻量摘要：身份、排序字段、统治绩效概览、画像公开等级、历史影响概览等。
- `reader/data/people/<ruler_id>.json`为构建生成的逐人物完整详情分片，包含人物页与对照页需要的正式投影和该人物来源可用性状态。
- 进入单人页时只请求该人物分片；真正进入双人对照时只请求两个人物分片。
- 已加载人物会缓存到当前页面内存中，再次查看或参与对照不会重复解析整池数据。
- 刷新页面后，首次读取人物详情会向服务端校验缓存，避免新裁决说明搭配旧分值。
- 首页搜索、筛选、排序和加入对照只依赖轻量摘要，不要求先下载完整证据。
- 构建会校验详情分片数量、文件名和内容是否与当前正式数据完全同步，并删除已经失效的旧分片。

这仍然是纯静态站点：GitHub Pages只负责分发HTML/JS/JSON文件，不需要应用服务器、数据库或运行时后端。

## 构建与检查

在仓库根目录运行：

```powershell
python reader/build.py
```

只读检查生成页与所有人物详情分片是否和当前正式数据、模板、本地来源状态一致：

```powershell
python reader/build.py --check
```

主要回归检查由GitHub Actions执行，包括：正式文本硬错误审计、阅读层增强脚本和懒加载脚本的JavaScript语法检查、生成页与逐人物分片一致性、页面渲染、移动端/对照交互、本地详情JSON服务路径以及空白检查。测试约束机制和数据同源关系，不固定真实人物的分数或档位。

## 本地预览

人物详情现在通过浏览器`fetch`静态JSON分片，因此不再建议用`file://`直接双击`reader/index.html`查看完整站点。请使用仓库自带的本地服务：

```powershell
python -m pip install -r reader/requirements.txt
python reader/serve.py
```

访问：`http://127.0.0.1:8765/reader/index.html`

`reader/serve.py`仍会把正式Markdown/JSON来源转换为只读阅读页，但会对`reader/data/`下的JSON直接返回原始数据；军事档案读取正式分片时使用`?raw=1`，使本地加载与GitHub Pages一致。

军事档案先展示经过，再展示结果、难度与个人责任。`military-reading-notes.json`保存带出处的补充阅读摘要，只用于叙事和核心交战时间，不参与定档；运行`python reader/build_military_archive.py`同步军事索引。个人档位缺失时不借用整场档位；统帅总档解释直接展示当前正式记录的裁决路径、独立情境与稳定性结果。

## 等级与公众展示

人物画像能力轴公开使用E−到S+共18级；`− / 无符号 / +`表示同一字母等级中的较低、中间、较高位置。正式G档、档内位置和雷达投影仍保留在正式记录及详情数据中，但公众页面不直接展示内部G代码或雷达数字。

C5单独描述权力运用风格与克制：越接近S，代表在压力、利益和强制权条件下越能约束自身权力；越接近E，代表强制、报复、特权或程序越界更突出。它不是能力轴，也不进入八轴雷达。

总等级与四维分项采用不同刻度的提示常驻四维区域及对照表分组；技术映射折叠展示，不遮蔽正式分项或原文。

历史影响字母表示历史路径改变的量级，不是能力或功绩等级；与人物画像相同字母不表示相同尺度。证据不足、待补证、待重裁和不适用均单独展示，不用低等级代替。

历史影响的公众说明直接读取正式记录中的`public_total_basis`、四维`public_basis`与`public_boundary`；阅读层只负责排版、展开、链接和安全转义，不再从范围、深度、因果与范式字段重新拼装理由。正式记录仍按范围与深度共同确定基础量级，再看个人因果修正，政治范式只作有限补充，最后将最终量级映射为公众等级：`S+→S+`、`S→S`、`S-→A`、`A+→B`、`A→C`、`B→D`、`C→E`。最终量级不是四维中的某一个字母，也不能把四维简单平均。

画像正文中的已定义G档、材料级别、PS/DW/AM/MI代码、方向枚举及常见项目工作流术语只在公众阅读层做确定性翻译；原始字段仍保留在正式记录和详情分片中。未定义术语不猜译。


## 阅读层边界与人物摘要

上游负责事实采纳、归责、材料强度、正反作用、权衡、限制及最终裁决；阅读层只展示已有信息。二次裁决必须独立回到合同、史料与正式记录处理，不得为阅读效果补判，也不得把阅读层新写的解释直接搬入上游视为通过。

`person-reading-notes.json`采用`reader-person-overviews-v2`，只允许每人的`overview.outcome/profile/impact`三个摘要。摘要可以压缩、组织已有内容，不得新增事实或阅读规则、重分材料轻重、改变归责、遗漏影响原意的反证；不从分数、等级、人物标签或原文前几句自动生成。未覆盖者继续展示原页面。

每段只保留`text`与`evidence`；每处定位只保留`path`和`quote`。定位指向该人物当前详情中的事实文字，链接返回正式入口，引用语句原样呈现并标为项目记录，不冒充古籍原文。定位撤回时仅该摘要显示待复核，不改人物状态；定位匹配只验证来源连续性，不代替语义复查。正式改档本身不触发摘要失效。

`person-reading-notes.js`仅在人物概览加载摘要，不介入分项正文，也不包装、折叠或替换正式依据。对照页、首页和选人页不请求摘要文件。逐人编辑的事实、反证、材料区分和解释边界不得另存于此文件，校验拒绝`axes`等额外字段。需要通俗的正式解释时，应在上游经复核维护公开字段，再由各展示出口直接读取。

权力运用与克制的材料强度直接投影父情境中的`intensity`和`material_intensity`原字段，名称对应画像总合同第2.3节。只展示已经裁定的值，不从叙述、次数、正负方向或最终档位补填；缺失、未知枚举及字段冲突分别提示，原值留在专业信息中。强度描述持续性、作用范围和机制化程度，不等于分数或伤害严重性。事实正文、强度、方向与总体权衡仍各自来自正式记录。

公众文字使用中文名称，已定义的代码只作确定性名称映射；其他体系不借用画像名称。复杂判词的再解释不属于阅读层维护。原始依据及来源仍可直接展开，不能因摘要缺失、过期或加载失败而隐藏。

维护时运行`python -m pytest tests/test_reader_person_readability.py tests/test_reader_public_boundaries.py -q`，重建后运行`python reader/build.py --check`，并复验人物与对照页、缺失强度、来源撤回和摘要加载失败。测试验证来源同值、只读性和展示行为，不固定人物等级、阶段人数或批次快照。

- B2 逐人入口与窗口、本人控制链由正式 Markdown 明确给出，`first_item_b2_public`只校验并投影；三个分数按合同档位换算，不从人物名单、故事字数或画像档位生成。`reader/first-item-b2.html`与人物主页、对照、详情共用这份投影，默认正文后先展开职责，再展开三项依据、限制与史料。
