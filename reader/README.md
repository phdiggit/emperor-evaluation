# 综合阅读层：帝王三镜

以人物为入口，并列呈现统治绩效、九轴人物画像与历史影响。阅读层负责排版、导航和追溯；评分、归责、准入及跨体系边界见[共同合同](../docs/项目总纲/皇帝综合评价体系合同.md)和[项目登记的分项合同](../config/project.yml)。

## 构建与检查

在仓库根目录运行：

```powershell
python v4.py reader
```

该命令调用`build_site.py`，先生成不入Git的大型Markdown阅读视图，再依次构建军事档案、全部阅读页面与人物数据、第一项来源缓存，检查页面和缓存同值，最后将完整静态站点打包到`.tmp/pages-site/`。新检出后先构建，再预览或运行依赖生成页面的测试；只生成Markdown用`python v4.py reading-views`。

历史影响、第二项C3／C4和第三项AB／C的Markdown入口为轻量总览，人物正文在旁边同名`-逐人阅读/`目录；长正文继续分页。正文和来源完整保留，生成与校验同时覆盖索引及全部分片。需要整份导出时运行`python v4.py reading-views --combined-output .tmp/reading-views-combined`；常规预览继续打开原路径。

局部更新页面用`python reader/build.py`；第一项来源变化另运行`python reader/build_first_item_reader_cache.py`，军事登记或档案说明变化另运行`python reader/build_military_archive.py`。前两项命令加`--check`只读核对当前生成物。

整站构建与 CI 对每份输出只生成一次；`--check`用于独立核对已有产物，不在刚完成构建后重复执行。发布前由行为测试、源与阅读同值检查及站点打包完整性检查负责验收。

## 本地预览

人物详情通过`fetch`读取分片，完整浏览须使用HTTP服务：

```powershell
python -m pip install -r reader/requirements.txt
python reader/serve.py
```

访问`http://127.0.0.1:8765/reader/index.html`。本地服务把正式Markdown／JSON转为只读阅读页，对`reader/data/`直接返回原始数据；军事档案读取正式分片时使用`?raw=1`，与线上加载一致。

## 信息结构

| 页面 | 用途 |
|---|---|
| 人物总览 | 搜索、筛选、排序和选择对照；默认按历史顺序。 |
| 人物主页 | 并列查看三体系结论与提要，从分项、能力轴或影响维度进入详情。 |
| 人物详情 | 统治绩效、人物画像、历史影响分别展开事实、理由、反证和来源；支持具体能力轴与影响维度的直接链接。 |
| 并列对照 | 同一维度并排阅读；突出差异只改变强调样式，不隐藏依据。 |

筛选和展开状态保留，清除筛选不清空对照。手机端可以缩短介绍，不能裁掉人物依据。画像不排名、不算总分；历史影响同档不另排名。各体系的取证时期按各自合同，不能只凭身份页的掌权时间推断。

同一次打开页面期间，人物各体系和对照页保留依据展开状态，返回已访问地址恢复阅读位置；新章节链接优先定位目标。刷新页面重新开始，不将人物阅读记录写入浏览器持久存储。

人物总览的“绩效榜”按正式综合分排序，只展示已入综合榜对象；治理范围筛选保留全池正式名次，不另编组内名次。范围与结构复杂度并列，不折算权重。人物页和比较页将C1—C3状态、C4恢复与可归责损害、治理机制与交接分别展示，显示值来自现行正式分项投影。同范围入口可查看全部已入榜对象，附近参照按综合分接近程度选取；选择另一人时默认同范围，也可切换跨范围比较。各轴具体证据覆盖仍以其正式正文为准。

人物主页先呈现评价结果与分项展示分，文明单列有符号净增量，再读史事摘要；治理状态、原分和权重构成默认折叠。主页与对照页的分数统一由主模板渲染，治国详情增强脚本不得覆盖为原分。画像长短处按当前有效档位投影，不生成画像总分或排名；“权力运用与克制”保留醒目的独立档位和合同中文等级含义，与办事能力同样受到重视，其评价对象仍限于实际用权与自我约束，不扩大为私人品德总评。

## 数据与解释边界

数据入口由`config/project.yml`登记，以`ruler_id`连接。第一项读Markdown真源，其余读对应正式JSON。正文、理由、限制和来源在上游维护，人物页、对照页和专页使用同一份内容。

人物分片与首页按内容版本核对；第一项来源缓存、原文回退及人物摘要也核对构建时的内容版本。跨版本资料不替换当前数据，页面提示刷新。旧请求的成功或失败不得覆盖已切换的页面。

浏览器只排版、导航和转换已定义的显示标签，不编写历史判断。原文、项目判断和相关材料分别标明；有引用不等于已证明整句话，缺证或未知代码要明确显示。

人物正文优先呈现具体史事与评价理由，维护流程说明不混入史事正文。控制范围的逐条事实默认可读；控制当量、得分率与合成计算按需展开。B1公开正文的`control_measurement`保存移入计算区的量化说明，网页与Markdown共同读取；原始评定、实际采用率、来源引文和待复核状态均须保留，不能因简化阅读而改判或隐藏证据限制。

未入榜、不适用、无档结案、待补证、待重裁和零分分开显示。专页按本分项正式名单覆盖，不因综合榜未就绪而漏人；链接只指向实际存在的页面。

`presentation.py`统一合集人物身份、时间区间与覆盖标识，并从实际生成的卡片或结构化记录建立`reading_entries`。未入榜人物通过此目录阅读已有分项，不能据目录存在推定整项结算就绪。画像首页投影须保留评价状态、证据下限及未显示能力的区别；证据下限不作为已证短板，姓名和限制由首页与人物主页共用函数渲染。

治国详情的结构、分组说明和净调整由`second-item-reading.js`维护；制度、民生与交接的公开等级摘要由`second-item-public-alias.js`唯一写入，后续层不得重新写回另一套等级或指数。军事战役登记总档与具名个人结果分别呈现，不用结果方向匹配推定评价主体；未单列连续经过时明确标为行动与责任摘录。

综合榜的证据评价公开标签与正文只保存在`evidence_assessment.public_projection`。证据裁决敏感性结果通过顶层`ranking_source`声明总榜来源，不复制逐人证据评价和审慎区间；正式命令核验当前总榜并重建敏感性结果，阅读渲染显式传入总榜记录，按人物ID关联。身份缺失、重复、集合或名称不匹配、重新内嵌副本均报错；此关联不改变评分、情景计算或名次。

第三／第四项更新字段的归属由`third_fourth_public_fields.py`显式登记。评分同步按人物、轴、战略链或材料包的稳定ID保留本对象的公开字段，禁止按数组位置移接；新增对象不继承其他来源的公开副本。公开刷新只清理列明的派生字段，正文和来源目录默认保留；A／B阅读计算字段的更新及AB旧A轴正文副本的移除在调用处明确声明。新增公开字段或含公开内容的对象列表须登记维护归属与身份规则，未知字段、重复或缺失身份均报错。

第二项C4的正文只维护`public_reading_sections`六个分栏，`recovery_public_record`按既定顺序拼接阅读正文，不重复保存`public_story`。D1／D3保留原始采用引文`excerpt`及定位信息，`second_item_d1_d3_public.public_record`沿用既有格式规则生成`public_excerpt`，不另存展示副本；原始引文仍须与史源逐字核验。

第四项裁决保存在正式记录的`axis_results`内，逐结果计价并发布正负毛额与净额；公开字段从当前结果、来源与交班确定性生成，人物级不另存轴投影、材料拼接列表或汇总文案副本。读取时按轴代码定位，汇总按A/B/C顺序组装，缺失或重复轴均报错；不再由轴净档换分。

主态低谷与净恢复的逐人阅读页用`governance-state-recovery-report --write`刷新，以`governance-state-recovery-verify`核对；不额外维护跨项文件哈希。军事人才刷新保留身份和已裁档位，不从父战役重新生成裁决。

## 公众展示总原则

先讲人物做了什么、面对什么条件、留下什么结果。分项合集先列人物，按需展开正文、评分理由和出处。引文优先链接到站内相关人物或战役、外部史源；没有对应阅读页的项目引用保留可识别的卷篇与摘句。计算细节按需展开。

- 第一项按统一成果、创业条件、组织整合、本人统帅、战争代价展开；保留各项的分阶段归责和材料限制。
- 第二项按正式机制说明经历、本人作用和结果。没有合格节点就说明证据边界，不造占位卡；某阶段不另计，不等于整组材料无效。
- 第三项A分开接班基础与本人增量；B分开原始率、实际采用率和复核状态；C使用下节的共同正文。
- 第四项不计分的材料仍可保留事实；零值说明是没有独立变化、复核后不计，还是正负相抵。
- M1讲本人行动和定档，链接已登记战役、人才及比较对象；人才生涯档位不参与画像换算。比较对象不足时说明例外，不补造战绩或档案。

具体评分、归责和去重规则见上表所列合同。展示不另定义评分规则，也不从数量、篇幅或名望生成解释。

综合榜正式JSON不保存`component_details`展示副本；阅读构建通过`composite_details.reading_records`按规范池人物ID与各项正式来源生成完整明细。总榜结算仍校验各项明细与合成结果同值，阅读构建检查就绪人物集合、身份及重复ID，不回写正式记录。

画像C1、C3、M4保留的入口单元处置记录使用`profile-unit-reason-catalog-v1`理由存储格式：文件级`reason_catalog`保存完整原文，各单元按`reason_ref`引用。读取与维护使用`profile_unit_reasons.load_unit_dispositions`和`write_unit_dispositions`，写入自动合并完全相同的理由；理由不同则分别保留。目录不得存在悬空引用、未使用条目、重复正文或单元内嵌副本；不按处置状态猜测理由，不改变单元身份、来源、顺序或采用关系。

M4逐条合作过程在人物页、双人对照及Markdown阅读页中完整展开集团、利益、本人安排、兑现、反馈、退出和反证。任务作为卡片标题，方向、强度、跨轴边界与来源合并在正文后的折叠区，人物反例总述收进裁决详情。画像正文提到档内比较时明确保留高、中、低位，人物等级徽标仍使用既定符号。

C2按当前计分情境展示取得信息、理解与更新过程；过程补充、归责边界、采用史源和反证放在正文后的来源区。非计分材料单列，不能与计分过程合并；证据下限显示其有界性质和重开条件。正式记录中的`source_review`保存实际采用段落及限制，网页与Markdown同源读取；清理文案不得据渠道存在、处罚烈度或战争结果自动生成认知正负证。

第二项C1—C4不落盘`public_calculation`生成副本；`second_item_c_reading.calculation_record`按当前正式字段生成原有计算说明，供Markdown、人物详情和全池页面共用。刷新只维护元数据与阅读视图，正式校验拒绝重新内嵌计算说明；人工正文、来源说明及证据绑定仍直接维护在正式记录。

M1人才登记投影使用`m1-registry-cells-v1`存储格式，保留成果难度、战役角色两份有序原列表；两段`<br>`拼接文本及配对列表由`profile_m1_projection.registry_projection`生成。独立维护的配对展示正文仍原样保存，不以拼接文本覆盖；列表长度或编号不匹配时拒绝生成。角色裁决及父链上下文不从人才登记反推。

第二项C1—C4的完整来源说明保存在各轴`public_source_note_catalog`，每人按`public_source_note_ref`引用；不同原文分别保留。`second_item_c_source_notes.source_note_records`供读取方展开原文，`compact_source_notes`供刷新时合并完全相同的说明。缺失、悬空引用、目录未使用条目和内嵌副本均报错，不根据其他人物或来源类型猜补说明。

## 第三项C证据阅读

人物页、详情与对照使用`third-item-c-public.js`，全池页由`build_third_c_collection`生成；两者读取同一份正式`public_reading`正文。每人只展示一次连贯评价，不再逐字段重复总述、正证与反证。档位与档内位置、战事摘要、来源和计算按需展开。

公开正文的`story`、`position_explanation`及`task_titles`须在正式C记录中明确编写；页面不得猜写战名、拼接正反证或推算新的位置理由。任务标题覆盖本人现存战略链，编号继续留作引用键。战略链配置不保存公开正文副本。

`combat_delivery_grade`与`final_grade`保存同值的主评和整体档，`joint_assessment`保留正式正反证及位置裁决。阅读整改不得改写这些字段或分数。生成的量表、计分、任务与对手窗口只供投影，不重新内嵌成为第二套真源。

材料的`source_passages`保存来源摘录及定位。改写摘要与标题时保留材料ID、任务绑定、来源路径及引文；摘录能否在对应来源锚点找到，仍由来源校验核对。

材料展示原编号、采用范围、来源和摘录。`source_passages`只证明摘录能在所指通读文件中找到，不冒充已复核古籍原文。补充材料与跨任期等边界核对分别列出，不能混成本人战争事实。

档位含义读公开`scale`，分数区间读现行联合计分区间。整体档与显式档内位置分别说明，不展示已退役的三轴短板或资格上限。待定保持空分，不改写为零分。

人物与材料锚点可分享，跨入口打开后定位到对应材料，不丢失当前人物。

## 阅读层边界与人物摘要

### 展示分入口与原方案对照

综合和分项展示均由`src/emperor_v4/reader_scores.py`唯一维护，构建时附在人物阅读数据的`net.public_scores`中，首页与详情同源使用。默认采用下文的综合五档与分项校准，文明直接显示有符号净额；以下旧百分制只供“原方案”对照。正式结算原分、权重、排序和不确定性计算均不变，展示分不能相加。人物画像与历史影响继续使用各自原有尺度。

原方案保留以下固定换算锚点，不随样本最大值、人数或百分位变化：

| 量尺 | 计分原分 → 百分分数 |
|---|---|
| 总分（原方案） | 0→40，120→60，220→75，320→85，380→90，450→95 |
| 奠基（附加折算前的原分） | 0→40，40→60，80→75，120→85，155→90，190→95 |
| 治国 | 0→40，80→60，130→75，185→85，225→90，270→95 |
| 军事 | 0→40，35→60，65→75，100→85，130→90，160→95 |
| 文明净增量 | 0→60，2→75，5→85，10→90，20→95 |

区间内线性插值。超过最后锚点x后，用`100−5×exp(−(原分−x)/k)`保留顶端差别；总分、奠基、治国、军事、文明的k依次为140、50、55、50、20。原分为负时，用`零点百分值×exp(原分/k)`延伸，文明k为20，其余为100。文明是增量评价，得失相抵为60；三轴均无已确认结果时显示“未确认独立变化”，不伪造等级。奠基不适用与适用但原分为零分别处理。

S+≥98，S≥95，A≥90，B≥85，C+≥82，C≥78，C−≥75，D+≥70，D≥65，D−≥60，E+≥50，E≥40，E−<40。显示截取一位小数，最高99.9，不四舍五入跨档；显示同分不能替代正式排名。原方案对照显示百分制；默认试读的综合分与分项标示见下节。计算、分歧情景和分项明细明确标为“计分原分”。

### 五档十五级试读

综合绩效默认展示中文档位、展示分和当前名次，可切回原百分制与字母档作对照。档位表达整体水平，分数表达固定量尺上的位置，名次表达当前入榜排序；展示分不是满分占比或百分位，分差不表示成就倍数。正式原分、排名、画像和历史影响的裁决均不变；分项展示采用下节独立校准。

当前综合试读锚点为原分`0→20、80→40、220→60、325→80、400→90、450→95`。相邻锚点线性换算；两端沿用上节所述指数延伸。圣档90起、明档80起、平档60起、庸档40起、昏档低于40。圣表示综合成就卓越；明表示成绩突出；平容纳普通至中等偏上表现；庸、昏分别表示整体表现不佳、严重不佳，不能仅从低分推断具体损害。

平与明的原分界线采用325作为当前试校准值：结合综合构成、主要边界两侧的现有裁决、简评及绑定证据，收紧突出评价的准入，同时保留普通至中等偏上的容纳范围。庸／平及明／圣原分界线维持220及400。这不是由人数配额推导出的界线，也不宣称325存在历史意义上的质变。零点及高端延伸仍属展示尺度约定，不视为功过中性点或绝对完美程度。后续如边界证据不支持，应重新校准尺度，不能为维护档位反改正式裁决。

实现唯一位于`src/emperor_v4/reader_scores.py`：`SCALES.total_trial`维护量尺，`MERIT_TRIAL_BANDS`维护原分档界与档义，`merit_levels()`生成档内分界，`MERIT_BOUNDARY_DISTANCE`维护近大档提示。投影在`net.public_scores.total.trial_tier`，元数据的`merit_trial.bands[].levels`提供完整十五级展示分门槛，页面不另算一套。

每档区间三等分为上、中、下，分界向上对齐到显示的0.1分刻度；档内位置按实际显示分判断，避免相同显示分出现不同档名。上始终高于中、中高于下，昏档亦同。细分是数字位置，不是三次独立裁决；小数也不表示史料精确度。“圣、明”只评价综合绩效，不推定私人品德完美，也不代替画像或历史影响。

试读的前三个分项显示校准分数与中文评价，文明显示有符号净额及正负两侧。原方案对照保留原百分数与字母档；综合五档与当前综合量尺不随分项展示调整。新方案缺少对应校准字段时提示“展示数据待同步”，不自动混用旧分数。

近档界说明未截断分数距大档门槛的数值距离，不表示置信度或改判概率。原分零点不等于功过相抵，总分仍含合同规定的结果、过程与能力分量。当前仍是阅读尺度试校准，尚非全池逐人的语义裁决；分布及区间动态读取当前记录，分桶或结构检查不能证明语义验收。命名借鉴榜圈表达，量尺、评分与归责使用本项目口径。

### 分项展示校准

`reader_scores.py:COMPONENT_SCALES`唯一维护前三项的展示量尺，`COMPONENT_BANDS`及`FOUNDER_BANDS`定义中文分段，投影在`net.public_scores.<key>.trial_rating`，元数据为`component_trial`。不更改正式分项、奠基附加或综合公式。旧换算保留供方案对照，不参与新分段。

| 分项 | 原分 → 展示分 | 高端延伸k | 评价对象 |
|---|---|---:|---|
| 奠基与统一 | 0→0，20→20，40→40，80→60，140→80，180→90，210→95 | 30 | 本人创业贡献、组织与军事能力扣成本后的净分，非王朝最终版图或个人全部能力 |
| 治国 | 0→20，100→40，180→60，240→80，285→90，330→95 | 57 | 治理手段、民生财政、社会安全及交接合计 |
| 军事与边疆 | 0→20，20→40，70→60，120→80，170→90，220→95 | 30 | 安全、控制、体系及军事代价的合计；已由奠基消费的成果不重复加入 |

相邻锚点线性换算，95以上按同一渐近公式延伸并截取一位小数；治国、军事负原分分别按20×exp(原分/100)、20×exp(原分/40)延伸。奠基正式净分下限为0，负输入报错，零净分对应0；不适用、待补状态不补零。

60、80、90分别表达中等、突出、卓越层次。治国／军事40—不足60为不佳、低于40为很差；奠基同段改称有限／很有限，90以上称卓著，避免把较小的净贡献误读为整个人能力低劣。各项同分表达相近评价力度，不表示等量历史成果，也不能相加；分项净额中的能力、继承状态及成本仍须看构成。

锚点是阅读校准约定，不是原合同已有的总档。参照来自当前分项合同中的计分结构与合成情景，再对照边界人物的现有裁决：奠基把稳定控制、创业条件、组织与本人军事贡献合看，并扣成本，不以称帝直接加分；治理手段G3层级约90—115分，配合C1/C2/C3基本维持的74.9分及普通交接，处于约180—200原分，60分附近因而保留给基本可运行的组合；温饱、秩序与较可靠手段的组合进入240附近。军事一般安全状态的A基础、有限B控制与通常任务C执行扣成本后约70—90，可靠改善与更多控制成果的组合约120。高分段再核对强结果、实际限制和去重后的整体表现，不按名望、人数或样本极值分配档位。

文明与国家整合遵循正式逐结果正负对称线性加总，直接显示`+净额`／`−净额`，不设100上限、不用净额反推R等级。`reader/build.py`从当前第四项正式记录读取正毛额、负毛额与准入结果数，附在合计单元的`reader_signed_balance`；显示投影严格核对正减负等于第四项正式净额。首页、人物页和对照保留正负两侧；已观察正负相抵显示0与双方，复核后无准入结果显示“未确认独立变化”，不冒充相抵。完整逐结果依据仍由文明详情提供。

分项校准仍属试读，边界人物检查不代表全池重新裁决。验证动态核对现行正式源、构建投影及各页面同值，另验单调、连续、状态区别、第四项符号对称和无截断，不固化人物分数或分布。

### 简评与依据

`person-reading-notes.json`中带有可选`reading`的人物提供按主题组织的阅读正文。可按人物画像、历史影响、治国、军事、文明保存章节，章数和篇幅随人物及史事而定。每章包含标题、正文及当前字段引文。首页仍用概览，详情先读具体选择与结果，再查逐项评价、反证和史料。点击段末编号可展开并定位该段引文。其余人物沿用原结构。

正文不自创新事实、归责或档位。画像只引本人的画像材料，历史影响只引历史影响材料，绩效各项只引对应分项；构建与浏览器核对引文。正文与正式裁决不同步时停止展示正文，保留完整依据。正式池人物画像综述已覆盖全池；其余体系的主题正文按实际`reading`字段提供，不据画像覆盖推定其他体系也已全部改写。

`person-reading-notes.json`保存人物概览与已补齐的大项简评，格式为`reader-person-overviews-v2`。正式池人物有`overview.outcome/profile/impact`三个摘要，历史影响补充样本只写`overview.impact`，依据须来自本人历史影响记录。上榜人物另有`net.third/fourth`，分别用于军事、文明卡片和详情开头。治国简评沿用`second-item-summaries.json`；奠基卡片读取已有成果描述。每个阅读笔记段落含`text`和`evidence`，每处依据含`path`与`quote`。

摘要可以解释已有结论，不得增加事实、自创评分或归责，也不能省略会改变意思的反证。引用须对应本人当前详情，原样显示并链接正式入口；不按分数或原文前几句自动生成。军事总述采用独立战略、防务和成本依据，不拿含创业战争的能力旁证代替；文明总述只取本项结果，不借历史影响补写。

简评先呈现决定整体评价的主要表现，再交代重要限制；不固定正反各半，也不按字数配比或分数阈值套评语。成就突出的以成就为主线，损害主导的先讲损害，真正得失相抵的才并列展开。人物画像侧写具体选择与行为，历史影响说明延续和变化，不能统一改成政绩好坏；文明净额为零须区分得失相抵与尚无确认结果。避免“高位”“接口”“保留反证”等维护用语，同一结论在卡片与详情复用。

综述须区分继承条件、本人选择和实际结果。国家原有资源能够支撑大规模动员，不能直接写成本人的建设功绩；用于限定极端评价的局部表现，也不能升格为与主要成就或损害并列的主线。严重且反复发生的破坏须讲清其性质和责任，不能用笼统的“失误”淡化；反证按其实际重要性安排，不为追求全面而逐项平衡。

摘要加载失败时保留原页面；已发布页面遇到摘要引用失效时显示待复核提示，不展示过期正文。构建核对正式池与历史影响补充样本的摘要覆盖及引文，缺失或失效会报错，修复后才能生成新版本；此错误不表示正式评分失效。未入榜人物可引用评价池的就绪状态，不能保留已不提供的分项引用或把未入榜写成零分。来源撤回只使摘要待复核，正式改档不自动使摘要失效。`person-reading-notes.js`只处理概览，对照、首页和选人页不请求摘要，逐轴正文不另存摘要副本。

C5材料强度读正式`intensity`、`material_intensity`；缺失、未知或冲突分别提示，不从最终档位倒推。

代表情境直接读取正式过程字段：用人授权展示`evidence_title`与`lifecycle_narrative`；内部联盟按合作任务、集团、利益预期、本人选择、资源安排、交付、反馈、退出和反证分栏，保留完整过程判断及跨项边界。不以方向标签或来源链接代替过程正文；未提供正文时明确提示。

C1展示正式`cycle_basis`，按原有句段展开长过程，专题标题读取正式`evidence_title`。方向、材料用途和来源放在情境末尾；未列入正反例引用的正式代表材料仍须展示，计分材料与背景、归责及轴外边界分别呈现，不把边界材料混成负证。人物表现和定档理由说明当前判断，不叙述旧档位的升降过程。

M5按正式`process_narrative`展示完整过程与边界，沿用已有段落及任务分解等小标题；未标方向时不从标题或档位推断。归责、跨轴边界和来源置于卡片末尾，反例总述放入裁决详情，不复制整段逐案正文。Markdown同步展示所选过程的完整文字，不能只取首行。展示条目数不等于独立复杂任务数，补齐展示不改变评分依据。

C3按正式`evidence_detail`逐条展示人物或任务，小标题取自原有条目；没有逐条材料时展示`lifecycle_narrative`。方向标签、评价边界与来源合并在卡片末尾；完整过程与条目有差异时保留在其中。反例总述放入裁决详情，与逐案材料分层呈现。公众文案直接说明当前认定、理由和适用范围，不用“退出强负证”“正式剔除”等审查操作代替结论。

C3卡片标题按实际人物与任务主题书写，不因其处于第二张卡就统一标为负向；反例总述区分已证失误、独立过程证据不足与本人归责边界，不复制正向任用材料充当反例。概览引用随正文调整重新核对，仍指向说明同一事实的当前字段。

C5按正式`public_evidence_points`逐案展示，首案随定档理由展示，其余案件和正式情境的方向、强度索引可在“进一步核对”展开。案件说明区分必要制伏、威胁受控后的处分及家属扩大，不因政治竞争身份整体豁免。定档理由、情境方向、单位引用与正文必须对应同一组当前事实；旧导入审计可以保留退役情境的来源定位，但不冻结当前裁决。E3按现行C5合同核对持续性与独立情境，不用事件烈度、人数或段落数量替代覆盖。

C4展开正式`parent_chains`的全部制度过程与适用边界，按具体制度命名，保留`mechanism`以及已有的问题、选择、职责规则、运行和修订字段。方向、归责、采用范围与来源放在正文之后，反例总述、`architecture_review`的正反整体判断及`horizontal_calibration`同轴比较放入裁决详情；Markdown同步完整展开，不按字符数截断。整合设计的组成部分、背景和证据缺口不因展示成为新的独立计分设计；适用性直接读取正式`applicability`，不把材料少解释为不适用或低能力。

M2按正式`consumption_status`分别展示计分外交过程与不计分边界，读取全部`parent_chains`的标题、完整`cycle_basis`及已登记的身份转换、归责和来源采用。内部安置、婚姻背景、臣使独立成果和证据缺口不因展示而计分；旧材料的方向标签不能推翻现行采用范围。“未显示外交能力”保留其终局类别与限制，不借背景负向材料改写成已证反复失能。Markdown与人物详情共用当前正式事实，概览引文同步核对。

人物画像展开某轴后，先显示定档理由，有合适的正式代表情境时接着展示一例。其余情境、反例、档内定位和材料限制可进一步核对，正式定档原文与完整来源可按需展开。人物页与对照页共用此规则，军事统帅继续使用专属公开说明。

历史影响的主链与四维来源只消费正式`source_ref_indices`，不以人物相关资料自动补链。来源卡保留采纳段落、采用说明、使用范围、记录中的核对方式及人物／情境／字段定位；类型与核对方式标签由`historical_impact.SOURCE_DISPLAY`共享，未知代码明确提示。未单独绑定来源与已绑定项目材料但没有外部原典链接分开说明。人物页、对照页提供全部登记来源及独立的相关事实入口，正式Markdown同步展示这些信息；原史未逐句核对的边界不因链接存在而消失。

## 构建产物与维护边界

| 文件 | 职责 |
| --- | --- |
| `*.template.html`、`*.js`、`*.css` | 布局、共享排版与交互；`lazy-details.js`负责人物分片加载，`home-interactions.js`负责首页与分项路由 |
| `public-copy.json`、`second-item-summaries.json`、`person-reading-notes.json` | 人工文案及摘要；只整理已有内容，不参与评分 |
| `military-reading-notes.json` | 带出处的军事补充摘要与核心交战时间，不参与定档 |
| `build.py`、军事档案／第一项缓存构建器、`build_site.py` | 投影、分片、校验和完整站点打包 |
| 非模板HTML、`data/`、`source-revision.json` | 可重建生成物，不手工编辑、不进入Git |

第二项显示名称、档位映射和量表上限统一由`second-item-display.js`提供，先于使用它的脚本加载。`second-item-reading.js`直接输出最终分数文案；公开正文渲染器负责各自内容，不再通过后置脚本反复改写分数或页面措辞。

`GPT`相关源变化后，GitHub Actions构建、检查并发布Pages。发布前核对分支仍是已验证提交，史源链接绑定该提交；发布任务串行，不回写源码。`.tmp/pages-site/`只放运行资源，本地史源阅读使用`serve.py`。验收同时检查工作流和线上版本。

按影响选择已有测试；人物摘要重点检查`tests/test_reader_person_readability.py`和`tests/test_reader_public_boundaries.py`。冲突先解决源文件再重建。测试检查规则和展示行为，不固定人物裁决；文字是否符合史实仍由人工判断。
