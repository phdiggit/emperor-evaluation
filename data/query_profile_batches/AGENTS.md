# AGENTS.md

本文件约束 `data/query_profile_batches/**` 内检索包及其驱动的“检索包→史料→对象池”工作流。根 `AGENTS.md` 只负责路由；具体回源口径以本文件为准。

## 检索包口径

- 检索包对象层是回源基准，不是随手候选；除相邻项切分对象外，默认都应进入待回源队列。
- `core_positive_objects`、`supplemental_objects`、`negative_or_reversal_objects` 中的对象，脚本未命中不等于无史料，只表示机器第一轮未召回，必须继续人工补检或明确记录需补检。
- `adjacent_split_objects` 默认不直接入对象池；只作为相邻项剥离、风险提示或后续其他子项检索入口。
- 加工型名称不得原样污染原始对象池；如“某某等功臣团队”“相关官员”“外戚/宗室政治风险对象”，应优先拆成史料中可唯一识别的人物、群体、事件或机制对象。
- 检索包不是证据、证据卡、档位、分值或排名；不得仅凭检索包内容入库或计算。

## 回源与入库

- 原始对象必须先回源再入对象池；所有 `raw_objs` 都必须至少有一条对应史料关联。
- 对象池保持原始粒度，不提前做评分加工；对象合并、强弱判断、证据簇和公式结算留给后续计算层。
- 史料关联必须绑定到 `emp_objs.id`，不能只依赖裸 `obj_id`；同一原始对象可服务不同皇帝，但下游聚合必须走“皇帝-对象-子项”关联。
- `raw_objs.note` 只写对象的一般史料身份和回源范围，不写评分、方向、规则、相邻项切分或“需要拆分”等加工说明。
- `obj_srcs.note` 写该史料对对象性质、规则维度和方向的直接帮助；表达必须克制，不把后续档位判断写进去。
- 对来源可信度有明显疑点、与项目无关或辨伪代价过高的叙事材料，不为凑覆盖而保留；必要时删除或不入库，并保留人工判断理由。

## 摘录池工具

- `scripts/dev/source_excerpt_pool.py` 只是召回和定位工具，用来减少找网页、翻原文、截上下文的时间。
- 摘录池输出不是事实结论；必须由 Codex 继续阅读上下文、判断对象粒度、相邻项切分和规则归属。
- 摘录池应优先按检索包的 `source_targets` 过滤目标史料页；过滤过严导致无命中时，转人工补检或放宽检索，不得判定“无史料”。
- 对脚本无命中、弱命中或命中非目标源的对象，继续按检索包基准人工检索。

## 验证

- 使用对象池导入工具后，必须校验全库不存在无史料 `raw_objs`。
- `emp_objs.note` 应保持对象名本身；对象性质和层级解释放在 `raw_objs.note` 与 `obj_srcs.note`。
- 从对象池生成规则证据簇时，按 `emp_id + subitem + rule_id` 聚合，并通过 `obj_srcs.emp_obj_id -> emp_objs.id` 回到具体皇帝，避免跨皇帝串料。
- 批量处理后，应列出入库对象、跳过的相邻项对象、拆分过的加工型对象和仍需补检对象。
